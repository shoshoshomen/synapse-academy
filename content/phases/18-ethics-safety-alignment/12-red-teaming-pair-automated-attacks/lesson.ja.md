# レッドチーミング：PAIR と自動化攻撃

> Chao, Robey, Dobriban, Hassani, Pappas, Wong（NeurIPS 2023、arXiv:2310.08419）。PAIR（Prompt Automatic Iterative Refinement）は標準的な自動ブラックボックスジェイルブレイクだ。レッドチームのシステムプロンプトを持つ攻撃者 LLM が対象 LLM へのジェイルブレイクを反復的に提案し、試みと応答を自身のチャット履歴にインコンテキストフィードバックとして蓄積する。PAIR は通常 20 クエリ以内に成功し、GCG（Zou ら のトークンレベル勾配探索）より桁違いに効率的で、ホワイトボックスアクセスも必要としない。PAIR は現在 JailbreakBench（arXiv:2404.01318）および HarmBench において GCG、AutoDAN、TAP、Persuasive Adversarial Prompt と並んで標準ベースラインとなっている。


## 学習目標

- PAIR アルゴリズムを説明できる：攻撃者システムプロンプト、反復的な精緻化、インコンテキストフィードバック。
- 対象がブラックボックスの場合に PAIR が GCG よりも厳密に効率的な理由を説明できる。
- 他の四つの自動化攻撃ベースライン（GCG、AutoDAN、TAP、PAP）を挙げ、それぞれの区別的特徴を一つ述べられる。
- JailbreakBench と HarmBench の評価プロトコル、および各ベンチマークでの「攻撃成功率」の意味を説明できる。

## 問題の背景

レッドチーミングはかつて手動の活動だった。少数の専門テスターが敵対的プロンプトを構築し、どれが機能したかを追跡した。これはスケールしない：攻撃成功率には統計的サンプルが必要であり、モデルリリースごとに対象が変わる。PAIR はレッドチーミングをブラックボックス対象の最適化問題として運用化する。

## 概念

### PAIR アルゴリズム

入力：
- 対象 LLM T（攻撃対象のモデル）。
- 判定 LLM J（応答がジェイルブレイクかどうかをスコアリングする）。
- 攻撃者 LLM A（レッドチームのオプティマイザ）。
- ゴール文字列 G：「[有害な指示] に応じよ」。
- バジェット K（通常 20 クエリ）。

k = 1..K のループ：
1. A にゴール G とこれまでの（プロンプト、応答）ペアの履歴を与える。
2. A が新しいプロンプト p_k を生成する。
3. p_k を T に送信し、応答 r_k を受け取る。
4. J がゴールに対して (p_k, r_k) をスコアリングする。
5. スコア >= 閾値なら停止——ジェイルブレイク発見。
6. そうでなければ (p_k, r_k) を A の履歴に追加し、継続。

実験結果（NeurIPS 2023）：GPT-3.5-turbo、Llama-2-7B-chat に対して 50% 超の攻撃成功率；成功までの平均クエリ数は 10-20 の範囲。

### PAIR が効率的な理由

GCG（Zou ら 2023）は勾配によって敵対的トークンサフィックスを探索する；ホワイトボックスのモデルアクセスが必要で読めないサフィックスを生成する。PAIR はブラックボックスで、モデル間で転移する自然言語攻撃を生成する。PAIR のインコンテキストフィードバックにより攻撃者は各拒否から学習できる；GCG にはこれに相当するものがない（各新しいトークン更新は以前の進捗を再発見しなければならない）。

### 関連する自動化攻撃

- **GCG（Zou ら 2023、arXiv:2307.15043）。** 敵対的サフィックスへのトークンレベル勾配探索。ホワイトボックス、転移可能、読めない文字列を生成する。
- **AutoDAN（Liu ら 2023）。** 階層的目標に誘導された、プロンプトに対する進化的探索。
- **TAP（Mehrotra ら 2024）。** 枝刈りを伴う木形式攻撃——複数の PAIR スタイルのロールアウトを分岐させる。
- **PAP（Zeng ら 2024）。** Persuasive Adversarial Prompts——人間の説得技術をプロンプトテンプレートとしてエンコードする。

### JailbreakBench と HarmBench

どちらも（2024 年）評価を標準化する：

- JailbreakBench（arXiv:2404.01318）。10 の OpenAI ポリシーカテゴリにわたる 100 の有害行動。主要指標として攻撃成功率（ASR）。判定（GPT-4-turbo、Llama Guard、または StrongREJECT）が必要。
- HarmBench（Mazeika ら 2024）。7 カテゴリにわたる 510 の行動、意味論的・機能的な有害テスト付き。33 モデルに対して 18 の攻撃を比較する。

ASR は通常固定クエリバジェットで報告される。攻撃を比較するにはバジェットを揃える必要がある；200 クエリでの 90% ASR は 20 クエリでの 85% ASR と比較できない。

### 2026 年のデプロイメントにとって重要な理由

フロンティアラボはすべて、リリース前に本番モデルに対して PAIR と TAP を実行する。ASR の推移はモデルカード（レッスン 26）と安全性ケースの付録（レッスン 18）に記載される。この攻撃は特殊ではない——標準インフラだ。

### フェーズ 18 での位置づけ

レッスン 12 は自動化攻撃の基盤だ。レッスン 13（多ショットジェイルブレイク）は補完的な長さのエクスプロイトだ。レッスン 14（ASCII アート / ビジュアル）はエンコーディング攻撃だ。レッスン 15（間接プロンプトインジェクション）は 2026 年の本番攻撃面だ。レッスン 16 は対応する防御ツールを扱う。

## 使ってみる

`code/main.py` はおもちゃの PAIR ループを構築する。対象は「明らかな」有害プロンプト（キーワードフィルタ）を拒否するモッククラシファイアだ。攻撃者はパラフレーズ、ロールプレイフレーミング、エンコーディングを試みるルールベースのリファイナーだ。判定が応答をスコアリングする。攻撃者がキーワードフィルタに対して約 5-15 イテレーションで成功し、意味論的フィルタに対して失敗するのを観察できる。

## 成果物を出す

このレッスンでは `outputs/skill-attack-audit.md` を作成する。レッドチーム評価レポートが与えられた際に、どの攻撃が実行されたか（PAIR、GCG、TAP、AutoDAN、PAP）、各バジェット、どの判定が使われたか、どの有害行動セット（JailbreakBench、HarmBench、内部）に対してかを監査する。

## 演習

1. `code/main.py` を実行する。三つの組み込み攻撃者戦略の成功までの平均クエリ数を測定する。各戦略が悪用する対象防御の仮定を説明する。

2. 第四の攻撃者戦略を実装する（例：別の言語への翻訳、base64 エンコーディング）。キーワードフィルタ対象と意味論的フィルタ対象に対する新しい成功までの平均クエリ数を報告する。

3. Chao ら 2023 の図 5（PAIR 対 GCG の比較）を読む。PAIR の効率性の優位にもかかわらず GCG が好まれる二つのシナリオを説明する。

4. JailbreakBench は固定ゴールセットに対する ASR を報告する。攻撃の多様性（成功したプロンプトの分散）を測定する追加指標を設計する。多様性が防御評価にとって重要な理由を説明する。

5. TAP（Mehrotra 2024）は PAIR を分岐＋枝刈りで拡張する。`code/main.py` への TAP スタイルの拡張をスケッチし、計算コスト対成功率のトレードオフを説明する。

## キーワード

| 用語 | 一般的な呼び方 | 実際の意味 |
|------|--------------|-----------|
| PAIR | 「自動ジェイルブレイク」 | Prompt Automatic Iterative Refinement；攻撃者 LLM + 判定 LLM のループ |
| GCG | 「勾配ジェイルブレイク」 | 敵対的サフィックスへのホワイトボックストークンレベル勾配探索 |
| 攻撃成功率（ASR） | 「k クエリでの % ジェイルブレイク」 | 主要指標；クエリバジェットと判定の識別情報とともに報告必須 |
| 判定 LLM | 「スコアラー」 | 応答が有害なゴールを満たすかどうかを採点する LLM |
| JailbreakBench | 「評価」 | タグ付きカテゴリを持つ標準化された有害行動セット |
| HarmBench | 「より広いベンチ」 | 510 の行動、機能的＋意味論的有害テスト |
| TAP | 「木形式攻撃」 | 分岐＋枝刈りを伴う PAIR；より高い計算コストでより高い ASR |
