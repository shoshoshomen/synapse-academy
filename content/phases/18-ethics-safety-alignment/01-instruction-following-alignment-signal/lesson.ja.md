# 指示追従をアライメントシグナルとして活用する

> RLHF に対する後続のあらゆる批判は、このパイプラインを論拠に展開される。プロキシ指標が最適化圧力によってどう歪むかを学ぶ前に、まずそのプロキシ自体を理解しなければならない。Ouyang ら (2022) の InstructGPT が参照アーキテクチャを定義した。指示–応答ペアによる教師あり微調整（SFT）、ペアワイズ選好ランキングで訓練した報酬モデル（RM）、SFT ポリシーへの KL ペナルティを加えた RM に対する PPO の三段階である。パラメータ数 1.3B の InstructGPT は 175B の GPT-3 を人間の選好評価において上回った。この一つの結果こそが、2026 年においてもすべてのフロンティアラボが RLHF 型のポストトレーニングパイプラインを採用し続けている理由である。


## 学習目標

- InstructGPT パイプラインの三段階と、各段階で使われる損失関数を挙げられる。
- パラメータ数 1.3B の指示チューニング済みモデルが、素の 175B GPT-3 を人間の選好評価で上回った理由を説明できる。
- 第三段階の KL ペナルティが何を防いでいるか、およびそれを除去するとモード探索的挙動に陥る理由を述べられる。
- アライメント税と、Ouyang らが用いた PPO-ptx による対策を説明できる。

## 問題の背景

事前学習済み言語モデルはテキストを補完するものであり、質問に答えるものではない。GPT-3 に「リストを逆順にする Python 関数を書け」と尋ねると、学習分布の大半がウェブテキストの続きであるため、別のプロンプトが返ってくることが多い。モデルは仕事をこなしているが、その仕事の内容が間違っているのだ。

主要なラボがこの問題を解決するために使ったプロキシは人間の選好だ。二つの補完候補を評価者に提示し、評価者が優れた方を選ぶ。報酬モデルはその評価者を模倣するよう学習する。そして RL ループが、報酬モデルが高くスコアする出力へとポリシーを近づけていく。これが InstructGPT の主張を三文で要約したものだ。論文の残りはエンジニアリングの話である。

## 概念

### 第一段階：教師あり微調整（SFT）

善意ある人間が書いたようなプロンプト–応答ペアを収集する。Ouyang らは、ラベラーと OpenAI API からの 13,000 件のプロンプトを用いた。このデータで、標準的なクロスエントロピー損失を用いてベースモデルを微調整する。

SFT によって得られるもの：モデルが質問を補完するのではなく、回答するようになる。SFT では得られないもの：複数の回答候補がある場合に、評価者がどちらを好むかというシグナル。

### 第二段階：報酬モデル（RM）

各プロンプトに対し、SFT モデルから K 個の補完をサンプリングする。ラベラーがランク付けを行う。`y_w` が `y_l` より選ばれたペアに対して、任意のプロンプト–応答ペアにスコアをつける報酬モデルを以下で訓練する。

```
L_RM = -log sigmoid(r(x, y_w) - r(x, y_l))
```

これは Bradley-Terry ペアワイズ選好損失である。RM は通常、SFT モデルの LM ヘッドをスカラーヘッドに置き換えたものを初期値として使う。

報酬モデルは小さい：175B の InstructGPT には 6B で十分だった。一方で脆弱でもある——論文の第 5 節の大部分は、小規模でも現れた報酬ハッキング的な挙動についての記述である。

### 第三段階：KL ペナルティ付き PPO

目的関数を定義する。

```
J(pi) = E_{x~D, y~pi(.|x)} [ r(x, y) ] - beta * KL(pi(.|x) || pi_SFT(.|x))
```

PPO で最大化する。KL 項により `pi` が SFT ポリシーから大きく逸脱しないよう保つ。これがなければ、オプティマイザは RM を騙すような敵対的な例——人間が実際に好むわけではなく RM がそれまで見たことのない文字列——を見つけてしまう。

KL 係数 `beta` は RLHF において最も重要なハイパーパラメータだ。低すぎると報酬ハッキングが起きる。高すぎると SFT からの改善が得られない。

### アライメント税

RLHF 後、モデルは人間に好まれるようになるが、標準ベンチマーク（SQuAD、HellaSwag、DROP）では性能が低下する。Ouyang らはこれをアライメント税と呼び、PPO-ptx によって対処している。モデルが報酬を与えられていない下流タスクを忘れないよう、事前学習の勾配を RL の目的関数に混合する手法だ。

```
J_ptx(pi) = J(pi) + gamma * E_{x~D_pretrain} [ log pi(x) ]
```

PPO-ptx は標準的な手法となった。Anthropic、DeepMind、Meta はいずれも何らかのバリアントを採用している。

### 結果

1.3B の InstructGPT（SFT + RM + PPO-ptx）は、175B のベース GPT-3 に対してラベラーの選好で約 70% の確率で勝る。その差は、本番トラフィックのホールドアウトテストプロンプトではさらに広がる。この数字から読み取れる二つのこと。

1. アライメントとケイパビリティは別の軸である。175B モデルはケイパビリティが高く、1.3B モデルはアライメントが高かった。ラベラーはアライメントが高い方を選んだ。
2. ケイパビリティの下限はベースモデルが決める。見たことのない事実をベースモデルに RLHF で注入することはできない。

### フェーズ 18 での基準点としての意義

後続のレッスンにおけるあらゆる批判——報酬ハッキング（レッスン 2）、DPO（レッスン 3）、おべっか（レッスン 4）、CAI（レッスン 5）、スリーパーエージェント（レッスン 7）、アライメント偽装（レッスン 9）——は、このパイプラインの何らかの部分を論拠にする。報酬ハッキングは第二段階を攻撃する。DPO は第二・三段階を一本化する。CAI は人間のラベラーを置き換える。おべっかはラベラーが偏ったシグナルを出すことを示す。アライメント偽装は、ポリシーが第三段階を完全に回避できることを示す。このパイプラインを頭に入れておかなければ、これらの批判は理解できない。

## 使ってみる

`code/main.py` はおもちゃの選好データを使って三段階をシミュレートする。ベース「ポリシー」はアクション {A, B, C} 上の偏ったコインだ。第一段階の SFT は 200 件のプロンプトに対するラベラーのアクションを模倣する。第二段階は 500 件のペアワイズランキングから Bradley-Terry 報酬モデルをフィットさせる。第三段階は SFT ポリシーへの KL ペナルティを加えた簡略化 PPO の更新を実行する。報酬の上昇、KL 発散の拡大、ポリシーのドリフトを観察できる。また KL 項をオフにして、50 ステップ以内に報酬ハッキングが発生する様子も確認できる。

注目すべき点：

- `beta = 0.1` と `beta = 0.0` での報酬の軌跡
- 訓練ステップにおける KL(pi || pi_SFT)
- ラベラーの選好と比較した最終的なアクション分布

## 成果物を出す

このレッスンでは `outputs/skill-instructgpt-explainer.md` を作成する。RLHF パイプラインの説明または論文のアブストラクトが与えられた際に、三段階のどこを修正しているか、各段階でどの損失が使われているか、KL ペナルティまたは同等の正則化が存在するかを特定する。

## 演習

1. `code/main.py` を実行する。`beta = 0.0` にして、PPO 200 ステップ後のアクション分布を報告する。モード探索的挙動を一段落で説明する。

2. 報酬モデルにアクション B に対する +0.5 のバイアスを加える（報酬のバグのシミュレーション）。`beta = 0.1` で PPO を実行する。KL ペナルティはポリシーがバイアスを利用するのを防ぐか？どの `beta` 値で利用が顕著になるか？

3. Ouyang ら（arXiv:2203.02155）の図 1 を読む。PPO を 1、5、20、100 ステップ実行し、SFT モデルとの選好を測定することでラベラー選好曲線を再現する。

4. 論文の 4.3 節は、1.3B InstructGPT が 175B GPT-3 を約 70% の確率で上回ると報告している。ラベラー自身のプロンプトよりも、ホールドアウトの本番プロンプトで比率が高くなるのはなぜか？

5. 同じ選好データに対して PPO 損失を DPO（フェーズ 10 · 08）に置き換える。最終的なポリシーのドリフト（SFT への KL）と最終報酬を比較する。同じ報酬水準においてどちらの手法がより多くドリフトするか？

## キーワード

| 用語 | 一般的な呼び方 | 実際の意味 |
|------|--------------|-----------|
| SFT | 「指示チューニング」 | 第一段階：プロンプト–応答ペアによるクロスエントロピー微調整 |
| 報酬モデル | 「RM」 | ペアワイズラベルの Bradley-Terry 損失で訓練された (プロンプト, 応答) 上のスカラー回帰器 |
| Bradley-Terry | 「ペアワイズ選好損失」 | -log sigmoid(r_w - r_l)；ペアワイズランキングを二値分類に還元 |
| KL ペナルティ | 「正則化項」 | `beta * KL(pi \|\| pi_SFT)`——RL ポリシーを SFT のアンカー付近に保つ |
| PPO-ptx | 「事前学習混合 PPO」 | アライメント税を相殺するため、PPO 目的関数に事前学習対数尤度の一部を加える手法 |
| アライメント税 | 「RLHF の退行」 | RLHF 後に、RLHF がターゲットとしなかった標準ベンチマークで性能が低下すること |
| ラベラー選好 | 「グランドトゥルース」 | 人間ランキングのサンプル；RM はこれの統計的プロキシであり、「人間の価値観」のプロキシではない |
