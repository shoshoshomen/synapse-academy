# LLMルーティング層 — LiteLLM、OpenRouter、Portkey

> プロバイダーのロックインはコストが高い。異なるツール呼び出しワークロードには異なるモデルが適している。ルーティングゲートウェイは1つのAPIサーフェス、リトライ、フェイルオーバー、コスト追跡、ガードレールを提供する。2026年には3つのアーキタイプが主流となっている：LiteLLM（オープンソースのセルフホスト）、OpenRouter（マネージドSaaS）、Portkey（本番グレード、2026年3月にオープンソース化）。このレッスンでは判断基準を定義し、stdlibルーティングゲートウェイを説明する。


## 学習目標

- セルフホスト、マネージド、本番グレードのルーティングオプションを区別できる。
- 定義された優先順序でプロバイダー障害時にリトライするフォールバックチェーンを実装できる。
- プロバイダーをまたいでリクエストごとのコストとトークン使用量を追跡できる。
- 与えられた本番の制約に対してLiteLLM、OpenRouter、Portkeyの間で決定できる。

## 問題背景

プロバイダールーティングが重要なシナリオ：

1. **コスト。** Claude Sonnetはhaikuの3倍のコストがかかる。トリアージタスクにはHaikuで十分；総合タスクにはSonnetが価値がある。リクエストごとにルーティングする。

2. **フェイルオーバー。** OpenAIが1時間調子が悪い。すべてのリクエストが失敗する。再デプロイなしに自動的にAnthropicにフォールバックしたい。

3. **レイテンシー。** ライブチャットUIは高速な最初のトークンが必要だ。バッチサマライザーは必要ない。レイテンシーSLAでルーティングする。

4. **コンプライアンス。** EUのユーザーはEUリージョンに留まる必要がある。リージョンでルーティングする。

5. **実験。** 同じワークロードで2つのモデルをA/Bテストする。テストバケットでルーティングする。

これらすべてを統合ごとに手書きするのは繰り返しになる。ルーティングゲートウェイが1つのOpenAI互換APIを提供し、残りを処理する。

## コンセプト

### OpenAI互換プロキシの形状

すべてがOpenAIの形状で話す。ルーティングゲートウェイは `/v1/chat/completions` を公開し、OpenAIスキーマを受け取り、内部的にAnthropic / Gemini / Cohere / Ollama / 何でもにプロキシする。クライアントは気にしない。

### モデルエイリアス

`claude-3-5-sonnet-20251022` の代わりにコードは `our_smart_model` と言う。ゲートウェイがエイリアスを実際のモデルにマッピングする。AnthropicがClaude 4を出荷したら、サーバー側でエイリアスを変更し、コードは何も触らない。

### フォールバックチェーン

```
primary: openai/gpt-4o
5xx時: anthropic/claude-3-5-sonnet
5xx時: google/gemini-1.5-pro
5xx時: 拒否
```

ゲートウェイはこれを設定で定義する。リトライはフォールバックカスケードがコストを爆発させないように予算に対してカウントされる。

### セマンティックキャッシング

同一または非常に類似したプロンプトがプロバイダーの代わりにキャッシュにヒットする。繰り返しのエージェントループでの節約は30〜60パーセントになることがある。キーはエンベディングベース；ほぼ同一のプロンプトがキャッシュスロットを共有する。

### ガードレール

ゲートウェイレベル：

- **PIIの編集。** 送信前の正規表現またはMLベースのパス。
- **ポリシー違反。** 禁止コンテンツを含むプロンプトを拒否。
- **出力フィルター。** 漏洩のためのコンプリーションをスクラブ。

PortkeyとKongの両方が意見のあるガードレールを出荷している。LiteLLMはそれらをオプションとしている。

### キーごとのレート制限

1つのAPIキー = 1つのチーム。キーごとの予算により、1つのチームが共有クォータを消費するのを防ぐ。ほとんどのゲートウェイがこれをサポートしている。

### セルフホスト対マネージドのトレードオフ

| 要素 | LiteLLM（セルフホスト） | OpenRouter（マネージド） | Portkey（本番） |
|--------|----------------------|----------------------|----------------------|
| コード | オープンソース、Python | マネージドSaaS | オープンソース（2026年3月）+ マネージド |
| セットアップ | プロキシをデプロイ | サインアップ | どちらでも |
| プロバイダー | 100以上 | 300以上 | 100以上 |
| 課金 | 自分のキー | OpenRouterクレジット | 自分のキー |
| オブザーバビリティ | OpenTelemetry | ダッシュボード | フルOTel + PII編集 |
| 最適な用途 | フルコントロールが欲しいチーム | 迅速なプロトタイピング | コンプライアンスある本番 |

LiteLLMはSREチームがあってデータ主権が欲しい時に勝る。OpenRouterは単一のサブスクリプションでインフラなしが欲しい時に勝る。Portkeyはガードレールとコンプライアンスがすぐに使える形が欲しい時に勝る。

### コスト追跡

すべてのリクエストに `provider`、`model`、`input_tokens`、`output_tokens` が含まれる。ゲートウェイが管理する価格シートからモデルごとのトークンあたり価格を掛ける。ユーザーごと / チームごと / プロジェクトごとの集計。

### MCPとルーティング

ゲートウェイはLLM呼び出しとMCPサンプリングリクエストの両方をルーティングできる。サンプリングリクエストのmodelPreferencesが特定のモデルを優先する場合、ゲートウェイが適切なバックエンドに変換する。ここでフェーズ13・17（MCPゲートウェイ）とこのレッスンのルーティングゲートウェイが1つのサービスにマージされることがある。

### ルーティング戦略

- **静的優先度。** リストの最初；エラー時にフォールバック。
- **負荷分散。** ラウンドロビンまたは重み付け。
- **コスト対応。** レイテンシー / 品質を満たす最安値のモデルを選択。
- **レイテンシー対応。** 直近N分で最速のモデルを選択。
- **タスク対応。** プロンプト分類器がコーディングを1つのモデルに、要約を別のモデルにルーティング。

## 使ってみる

`code/main.py` は約150行のルーティングゲートウェイを実装している：OpenAI形状のリクエストを受け取り、プロバイダーごとのスタブに変換し、優先フォールバックチェーンを実行し、リクエストごとのコストを追跡し、入力にPII編集パスを適用する。3つのシナリオで実行する：通常のリクエスト、フォールバックをトリガーするプライマリプロバイダーの障害、編集によって捕捉されるPII漏洩。

確認すべきポイント：

- `ROUTES` 辞書：エイリアス -> 優先順序付きの具体的なプロバイダーのリスト。
- フォールバックループが5xx時にリトライ。
- コストトラッカーがトークン使用量にモデルごとのレートを掛ける。
- PII編集者がSSN形状のパターンを転送前にスクラブ。

## 成果物を出す

このレッスンでは `outputs/skill-routing-config-designer.md` を生成する。ワークロードプロファイル（レイテンシー、コスト、コンプライアンス）が与えられると、このスキルはLiteLLM / OpenRouter / Portkeyを選択し、ルーティング設定を生成する。

## 演習

1. `code/main.py` を実行する。障害シナリオをトリガーし、フォールバックが2番目のプロバイダーに着地し、コストが正しく帰属されることを確認する。

2. セマンティックキャッシングを追加する：プロンプトのSHA256がルックアップキー；キャッシュヒットは即座に返す。繰り返し呼び出しのコスト削減を測定する。

3. 「コード...」プロンプトをインテリジェンス優先のエイリアスにルーティングし、「要約...」プロンプトをスピード優先のエイリアスにルーティングするプロンプト分類器を追加する。

4. チームごとの予算を設計する：各チームに毎月の上限があり、ゲートウェイが上限を超えるとリクエストを拒否する。強制の粒度を選択する（リクエストごとまたはウィンドウ制）。

5. LiteLLM、OpenRouter、Portkeyのドキュメントを並べて読む。各自が他の2つが持っていない機能を1つ名前で挙げる。

## キーワード

| 用語 | よく言われる表現 | 実際の意味 |
|------|----------------|------------------------|
| ルーティングゲートウェイ | "LLMプロキシ" | 多くのプロバイダーの前に立つ1-APIサーフェス層 |
| OpenAI互換 | "OpenAIスキーマで話す" | `/v1/chat/completions` 形状を受け取り、任意のバックエンドに変換 |
| モデルエイリアス | "our_smart_model" | ゲートウェイが具体的なモデルにマッピングするコード内の名前 |
| フォールバックチェーン | "リトライリスト" | 障害時に試みるプロバイダーの順序付きリスト |
| セマンティックキャッシング | "プロンプトエンベディングキャッシュ" | キーはプロンプトのエンベディング；ほぼ重複がキャッシュヒットを共有 |
| ガードレール | "入出力フィルター" | PIIを編集し、ポリシー違反を拒否 |
| キーごとのレート制限 | "チーム予算" | APIキーにスコープされたクォータ |
| コスト追跡 | "リクエストごとの費用" | トークン使用量 x モデルごとの価格の集計 |
| LiteLLM | "オープンなプロキシ" | セルフホスト可能なOSSルーティングゲートウェイ |
| OpenRouter | "マネージドSaaS" | クレジットベース課金のホスト型ゲートウェイ |
| Portkey | "本番オプション" | ガードレール組み込みのオープンソース + マネージド |
