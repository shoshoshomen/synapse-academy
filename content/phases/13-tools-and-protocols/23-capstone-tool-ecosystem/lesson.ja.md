# カプストーン — 完全なツールエコシステムを構築する

> フェーズ13ですべてのピースを学んだ。このカプストーンではそれらを1つの本番形状のシステムに繋げる：ツール + リソース + プロンプト + タスク + UIを持つMCPサーバー、エッジのOAuth 2.1、RBACゲートウェイ、マルチサーバークライアント、A2Aサブエージェント呼び出し、コレクターへのOTelトレーシング、CIでのツールポイズニング検出、AGENTS.md + SKILL.mdバンドル。最後にはすべてのアーキテクチャ上の選択を守れるようになる。


## 学習目標

- ツール、リソース、プロンプト、タスク、`ui://` アプリを公開するMCPサーバーを構成できる。
- RBACとピン留めされたハッシュを強制するOAuth 2.1ゲートウェイでサーバーをフロントエンドに配置できる。
- OTel GenAI属性でエンドツーエンドにトレースするマルチサーバークライアントを書ける。
- ワークロードの一部をA2Aサブエージェントに委任し、不透明性が保持されることを確認できる。
- AGENTS.md + SKILL.mdでスタック全体をパッケージ化し、他のエージェントが操作できるようにできる。

## 問題背景

「リサーチとレポート」システムを出荷する：

- ユーザーが尋ねる：「エージェントプロトコルに関する2026年のarXiv論文で最も引用された3本を要約して。」
- システム：MCPでarXivを検索；A2Aで専門のライターエージェントに論文の要約を委任；結果を集約；MCPアプリの `ui://` リソースとしてインタラクティブなレポートをレンダリング；すべてのステップをOTelにログ記録する。

フェーズ13のすべてのプリミティブが登場する。これはおもちゃではない — 2026年にAnthropic（Claude Researchプロダクト）、OpenAI（Apps SDKのGPTs）、サードパーティが出荷した本番のリサーチアシスタントシステムはこの正確な形状を持っている。

## コンセプト

### アーキテクチャ

```
[ユーザー] -> [クライアント] -> [ゲートウェイ（OAuth 2.1 + RBAC）] -> [リサーチMCPサーバー]
                                                      |
                                                      +- MCPツール：arxiv_search（純粋）
                                                      +- MCPリソース：notes://recent
                                                      +- MCPプロンプト：/research_topic
                                                      +- MCPタスク：generate_report（長時間）
                                                      +- MCPアプリUI：ui://report/current
                                                      +- A2A呼び出し：writer-agent（tasks/send）
                                                      |
                                                      +- OTel GenAIスパン
```

### トレース階層

```
agent.invoke_agent
 ├── llm.chat（キックオフ）
 ├── mcp.call -> tools/call arxiv_search
 ├── mcp.call -> resources/read notes://recent
 ├── mcp.call -> prompts/get research_topic
 ├── a2a.tasks/send -> writer-agent
 │    └── タスク遷移（不透明な内部）
 ├── mcp.call -> tools/call generate_report（タスク拡張）
 │    └── tasks/statusポーリング
 │    └── tasks/result（completed、ui://リソースを返す）
 └── llm.chat（最終統合）
```

1つのトレースID。すべてのスパンが正しい `gen_ai.*` 属性を持つ。

### セキュリティポスチャ

- OAuth 2.1 + PKCEとリソースインジケーターによるオーディエンスのゲートウェイへのピン留め。
- ゲートウェイがアップストリームの認証情報を保持；ユーザーはそれらを見ない。
- RBAC：`alice` は `research:read`、`research:write` を持ち、すべてのツールを呼べる。`bob` は `research:read` を持ち、`generate_report` を呼べない。
- ピン留めされた説明マニフェスト：ツールのハッシュが変更されたサーバーはドロップする。
- Rule of Twoの監査：信頼できない入力、機密データ、結果的なアクションを組み合わせるツールなし。

### レンダリング

最終的な `generate_report` タスクはコンテンツブロックと `ui://report/current` リソースを返す。クライアントのホスト（Claude Desktopなど）がインタラクティブなダッシュボードをサンドボックスiframeにレンダリングする。ダッシュボードはソートされた論文リスト、引用数、ユーザーがクリックした論文に対して `host.callTool('summarize_paper', {arxiv_id})` を呼び出すボタンを含む。

### パッケージ化

すべてのものが以下としてパッケージ化される：

```
research-system/
  AGENTS.md                     # プロジェクト慣例
  skills/
    run-research/
      SKILL.md                  # トップレベルのワークフロー
  servers/
    research-mcp/               # MCPサーバー
      pyproject.toml
      src/
  agents/
    writer/                     # A2Aエージェント
  gateway/
    config.yaml                 # RBAC + ピン留めマニフェスト
```

ユーザーは `docker compose up` でデプロイする。Claude Code、Cursor、Codex、opencodeユーザーは `run-research` スキルを呼び出してシステムを操作できる。

## 使ってみる

`code/main.py` は前のレッスンのパターンを1つの実行可能なデモに組み合わせている。すべてstdlib、すべてインプロセスなので最初から最後まで読める。リサーチとレポートのシナリオの完全なフローを実行する：ゲートウェイとのハンドシェイク、OAauth 2.1のシミュレーション、tools/listのマージ、タスクとしてのgenerate_report、ライターへのA2A呼び出し、ui://リソースの返却、OTelスパンの出力。

確認すべきポイント：

- すべてのホップにわたる1つのトレースID。
- ゲートウェイのポリシーが2番目のユーザーの書き込みをブロックする。
- タスクライフサイクルがworking → completedとなり、テキストとui://コンテンツの両方を返す。
- A2A呼び出しの内部状態がオーケストレーターには不透明。
- AGENTS.mdとSKILL.mdが他のエージェントがワークフローを再現するために必要な唯一のファイル。

## 成果物を出す

このレッスンでは `outputs/skill-ecosystem-blueprint.md` を生成する。製品のニーズ（リサーチ、要約、自動化）が与えられると、このスキルは完全なアーキテクチャを生成する：どのMCPプリミティブか、どのゲートウェイコントロールか、どのA2A呼び出しか、どのテレメトリーか、どのパッケージングか。

## 演習

1. `code/main.py` を実行する。単一のトレースIDとスパンがどのようにネストされているかを確認する。デモがフェーズ13のいくつのプリミティブに触れているかを数える。

2. デモを拡張する：2番目のバックエンドMCPサーバー（例：`bibliography`）を追加し、ゲートウェイがそのツールを同じネームスペースにマージすることを確認する。

3. 偽のA2Aライターエージェントをサブプロセスで動作する本物に置き換える。Lesson 19のハーネスを使用する。

4. オーケストレーターとLLMの間のルーティングゲートウェイにPII編集ステップを追加する。ユーザークエリ内のメールがスクラブされることを確認する。

5. このシステムをメンテナンスするチームメンバーのためのAGENTS.mdを書く。5分以内に読めてCursorまたはCodexでカプストーンを操作するために必要なすべてを伝えるべきだ。
