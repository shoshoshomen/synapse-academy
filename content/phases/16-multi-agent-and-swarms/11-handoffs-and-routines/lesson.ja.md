# ハンドオフとルーティン——ステートレスなオーケストレーション

> OpenAIのSwarm（2024年10月）はマルチエージェントオーケストレーションを2つのプリミティブに凝縮した：**ルーティン**（システムプロンプトとしての命令＋ツール）と**ハンドオフ**（別のAgentを返すツール）。ステートマシンなし、分岐DSLなし——LLMが正しいハンドオフツールを呼び出すことでルーティングする。OpenAI Agents SDK（2025年3月）は本番向けの後継だ。Swarm自体は最も明確な概念的リファレンスとして残る——そのソース全体は数百行に収まる。このパターンが広まった理由はAPIサーフェスが概ね「agent = プロンプト＋ツール；handoff = エージェントを返す関数」だからだ。制限：ステートレスなので、メモリは呼び出し元の問題だ。


## 問題

すべてのマルチエージェントフレームワークは固有のDSLを学ぶよう求める：LangGraphのノードとエッジ、CrewAIのクルーとタスク、AutoGenのGroupChatとマネージャー。DSLは本物の抽象化だが、必要以上に重く感じさせる。

Swarmは反対方向に押す：モデルがすでに持っているツール呼び出し能力を使う。ハンドオフはツール呼び出しになる。オーケストレーターは現在会話を保持しているエージェントだ。ステートマシンはエージェントのシステムプロンプトに暗黙的に埋め込まれている。

## 概念

### 2つのプリミティブ

**ルーティン。** エージェントの役割と利用可能なツールを定義するシステムプロンプト。スコープされた命令セットのようなもの：「あなたはトリアージエージェントだ；ユーザーが返金について尋ねた場合、返金エージェントに引き渡せ。」

**ハンドオフ。** エージェントが呼び出せるツールで、新しいAgentオブジェクトを返す。Swarmランタイムはエージェントの戻り値を検出し、次のターンのアクティブエージェントを切り替える。

それが抽象化の全てだ。

```
def transfer_to_refunds():
    return refund_agent  # Swarm sees Agent return → switch active agent

triage_agent = Agent(
    name="triage",
    instructions="Route the user to the right specialist.",
    functions=[transfer_to_refunds, transfer_to_sales, transfer_to_support],
)
```

トリアージエージェントのシステムプロンプトにより、ユーザーメッセージに基づいて正しいハンドオフを選ぶ。LLMのツール呼び出しがルーティングを行う。

### 広まった理由

- **小さいAPI。** 学ぶべきコンセプトが2つ。
- **モデルがすでにやっていることを使う。** ツール呼び出しはすでにプロバイダー間で本番グレードだ。
- **ステートマシンの負担なし。** グラフを記述しない；エージェントのプロンプトが誰に引き渡すかを記述する。

### ステートレスのトレードオフ

Swarmは実行間で明示的にステートレスだ。フレームワークは実行中にメッセージ履歴を保持するが、何も永続化しない。メモリ、継続性、長時間実行タスク——すべて呼び出し元の問題だ。

本番（OpenAI Agents SDK、2025年3月）では、これが変わった主なことの1つだった：SDKはハンドオフプリミティブを保持しながら、組み込みのセッション管理、ガードレール、トレーシングを追加した。

### Swarm/ハンドオフが適合する場合

- **トリアージパターン。** 最前線のエージェントがユーザーをスペシャリストにルーティングする。
- **スキルベースのハンドオフ。** 「タスクにコードが必要なら、コーダーを呼ぶ；リサーチが必要なら、リサーチャーを呼ぶ。」
- **短い、限定された会話。** カスタマーサポート、FAQ→チケット、シンプルなワークフロー。

### Swarmが苦手な場合

- **共有メモリを持つ長いセッション。** ハンドオフは会話の状態を新しいエージェントのプロンプト＋履歴にリセットする。呼び出し元が管理するメモリなしでは、エージェント間の永続的な状態がない。
- **並列実行。** ハンドオフは1度に1つ——アクティブなエージェントが切り替わる。並列処理には、複数のSwarm実行をオーケストレーティングする呼び出し元が必要だ。
- **監査とリプレイ。** ステートレスな実行は正確にリプレイが難しい；LLMのハンドオフの選択は決定論的ではない。

### OpenAI Agents SDK（2025年3月）

本番向け後継は以下を追加する：

- **セッション状態。** 実行間で永続的なスレッド。
- **ガードレール。** 入出力バリデーションフック。
- **トレーシング。** すべてのツール呼び出しとハンドオフがログされる。
- **ハンドオフフィルター。** ハンドオフ時に転送されるコンテキストを制御する。

ハンドオフプリミティブは生き残る；本番のエルゴノミクスがその周りに追加される。

### Swarm対GroupChat

どちらもLLM駆動のルーティングを使うが、**誰が次を選ぶか**が異なる：

- GroupChat：セレクター（関数またはLLM）が外部から次のスピーカーを選ぶ。
- Swarm：現在のエージェントがハンドオフツールを呼び出すことで後継者を選ぶ。

Swarmは「エージェントが次を決める」；GroupChatは「マネージャーが次を決める」。Swarmの決定はアクティブエージェントのツール呼び出しにある；GroupChatの決定は`GroupChatManager`にある。

## 実装する

`code/main.py`はSwarmをゼロから実装している：AgentデータクラスとハンドオフメカニズムH（ツールがエージェントを返す）、エージェントの切り替えを検出するRunループ。

デモ：トリアージエージェントが返金、営業、またはサポートのスペシャリストにルーティングする。各スペシャリストは独自のツールを持つ。ランループが各ハンドオフを出力する。

実行：

```
python3 code/main.py
```

## 使ってみる

`outputs/skill-handoff-designer.md`は与えられたタスクのためのハンドオフトポロジーを設計する：どのエージェントが存在するか、どのハンドオフを呼び出せるか、どのコンテキストが転送されるか。

## 成果物を出す

チェックリスト：

- **ハンドオフログ。** すべてのハンドオフは送信元エージェント、送信先エージェント、コンテキストスナップショットを含むトレースイベントを書く。
- **コンテキスト転送ルール。** ハンドオフ時に何を移動するかを決める：完全な履歴（高コスト）、最後のNメッセージ、またはサマリー。
- **ハンドオフ上のガードレール。** 異なるツール権限を持つスペシャリストへのハンドオフは認証が必要——そうしなければプロンプトインジェクションが不要なハンドオフを強制できる。
- **ループ検出。** 2つのエージェントが行き来するのは一般的な失敗；シンプルな直近K回のリングチェックで検出する。
- **フォールバックエージェント。** ハンドオフ先が存在しない場合、安全なデフォルトにフォールバックする。

## 演習

1. `code/main.py`を実行し、返金エージェントにトリアージする。2番目のターンのアクティブエージェントが返金であることを確認する。
2. ループ検出ルールを追加する：同じ2つのエージェントが連続して3回ハンドオフしている場合、強制終了する。フォールバックを設計する。
3. ハンドオフフィルターに関するOpenAI Agents SDKのドキュメントを読む。「ハンドオフ時にサマリー化」バージョンを実装する：送信側のエージェントが引き渡す前にコンテキストを箇条書きサマリーに圧縮する。
4. SwarmのハンドオフとGroupChatManagerセレクターを比較する。どちらのパターンがプロンプトインジェクションをより悪化させるか、そしてなぜか？
5. Swarmクックブック（https://developers.openai.com/cookbook/examples/orchestrating_agents）を読む。SwarmがOpenAI Agents SDKで変更または保持した明示的な設計決定を1つ特定する。

## キーワード

| 用語 | よく言われること | 実際の意味 |
|------|----------------|------------------------|
| ルーティン | 「エージェントプロンプト」 | システムプロンプト＋ツールリスト。役割と利用可能なハンドオフを定義する。 |
| ハンドオフ | 「別のエージェントへの転送」 | アクティブエージェントが呼び出せるツールで、新しいエージェントを返す。ランタイムがアクティブエージェントを切り替える。 |
| ステートレス | 「実行間のメモリなし」 | Swarmは何も永続化しない；メモリは呼び出し元の責任。 |
| アクティブエージェント | 「今話している者」 | 現在会話を保持しているエージェント。ハンドオフでこれが変わる。 |
| コンテキスト転送 | 「ハンドオフ時に何が移動するか」 | 着信エージェントが見る履歴のポリシー：完全、最後のN、またはサマリー。 |
| ハンドオフループ | 「エージェントが乒乓する」 | 2つのエージェントがお互いに引き渡し続ける失敗モード。 |
| OpenAI Agents SDK | 「本番Swarm」 | 2025年3月の後継；ハンドオフプリミティブの上にセッション、ガードレール、トレーシングを追加。 |
| ハンドオフフィルター | 「転送上のゲート」 | ハンドオフ境界でコンテキストを検査・変更するSDK機能。 |
