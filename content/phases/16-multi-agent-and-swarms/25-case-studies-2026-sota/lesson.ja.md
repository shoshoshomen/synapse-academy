# ケーススタディと2026年の最先端

> エンドツーエンドで研究する本番グレードの参照3つ、それぞれマルチエージェントエンジニアリングの異なるスライスを示す。**Anthropicの研究システム**（オーケストレーター-ワーカー、15倍のトークン、単一エージェントOpus 4に対して+90.2%、レインボーデプロイ）は標準的なsupervisorのケースだ。**MetaGPT / ChatDev**（ソフトウェアエンジニアリングのSOP符号化されたロール特化; ChatDevの「通信的脱幻覚」; MacNet拡張でDAGを介して>1000エージェント、arXiv:2406.07155）は標準的なロール分解ケースだ。**OpenClaw / Moltbook**（元々はPeter Steinbergerによる2025年11月のClawdbot; 2回改名; 2026年3月に247k GitHubスター; ローカルReActループエージェント; エージェントのみのソーシャルネットワークとしてのMoltbookで、ローンチ後数日で約230万のエージェントアカウント、Metaが2026-03-10に買収）は集団規模で何が起きるかを示す: 創発的な経済活動、プロンプトインジェクションリスク、国家レベルの規制（中国が2026年3月に政府コンピューターでOpenClawを制限）。**フレームワーク状況2026年4月:** LangGraphとCrewAIが本番をリード; AG2はコミュニティのAutoGen継続; Microsoft AutoGenはメンテナンスモード（2026年2月にRCのMicrosoft Agent Frameworkにマージ）; OpenAI Agents SDKは本番のSwarm後継; Google ADK（2025年4月）はA2Aネイティブのエントリー。すべての主要フレームワークがMCPサポートを搭載; ほとんどがA2Aを搭載。このレッスンでは各ケースをエンドツーエンドで読み、共通パターンを蒸留して、次の本番システムに適切な参照を選べるようにする。


## 問題

マルチエージェントエンジニアリングは若い分野だ。本番参照は少なく、各ケースがスペースの異なる部分をカバーする。個別に読むのは有用だが、セットとして比較する方が有用だ。このレッスンでは3つの標準的な2026年のケーススタディをエンドツーエンドの読書リストとして扱い、共通パターンを固定し、知識からフレームワークの選択ができるようにフレームワーク状況をマッピングする。

## 概念

### Anthropicの研究システム

本番のsupervisor-workerケース。Claude Opus 4が計画と合成; Claude Sonnet 4のサブエージェントが並列で研究する。公開されたエンジニアリング投稿: https://www.anthropic.com/engineering/multi-agent-research-system。

主要な測定結果:

- 内部研究評価で単一エージェントOpus 4に対して**+90.2%**の改善。
- **BrowseComp分散の80%**が**トークン使用量のみ**で説明される—マルチエージェントが勝つのは主に各サブエージェントが新鮮なコンテキストウィンドウを得るから。
- 単一エージェントに対して**クエリごとに15倍のトークン**。
- エージェントが長時間実行されてステートフルなので**レインボーデプロイ**。

設計の教訓が体系化された:

1. **クエリの複雑さに応じて努力をスケールする。** シンプル → 3〜10のツール呼び出しを持つ1エージェント。中程度 → 3エージェント。複雑な研究 → 10以上のサブエージェント。
2. **最初に広く、次に絞る。** サブエージェントが広い検索をする; リードが合成する; フォローアップのサブエージェントがターゲットを絞った深掘りをする。
3. **レインボーデプロイ。** 実行中のエージェントが終了するまで古いランタイムバージョンを生かしておく。
4. **検証はオプションではない。** 明示的な検証者ロールなしではシステムが幻覚を起こすことが観察された。

これは本番規模でのsupervisor-workerトポロジーの参照ケースだ（フェーズ16・05）。

### MetaGPT / ChatDev

本番のSOPロール分解ケース。arXiv:2308.00352（MetaGPT）とarXiv:2307.07924（ChatDev）をカバーする。

MetaGPTはソフトウェアエンジニアリングのSOPをロールプロンプトとして符号化する: プロダクトマネージャー、アーキテクト、プロジェクトマネージャー、エンジニア、QAエンジニア。論文のフレーミング: `Code = SOP(Team)`。各ロールには狭い専門的プロンプトがある; ロール間のハンドオフは構造化されたアーティファクト（PRDドキュメント、アーキテクチャドキュメント、コード）を運ぶ。

ChatDevの貢献: **通信的脱幻覚**。エージェントが答える前に詳細を要求する—デザイナーエージェントはUIをスケッチする前にプログラマーにどの言語が意図されているかを尋ねる（推測するのではなく）。論文はこれがマルチエージェントパイプラインの幻覚を測定可能に減らすことを報告する。

MacNet（arXiv:2406.07155）はChatDevを**DAGを介して>1000エージェント**に拡張する。各DAGノードはロール特化; エッジはハンドオフコントラクトを符号化する。ルーティングが明示的でオフライン計算可能なためスケールが可能だ。

設計の教訓:

1. **構造はサイズより重要。** 緊密な5ロールSOPチームが50エージェントの構造化されていないグループに勝つ。
2. **書面でのハンドオフコントラクト。** ロール間で渡されるアーティファクトはスキーマに従う。
3. **通信的脱幻覚**は安価で負荷を担うパターンだ。
4. **DAGはチャットよりさらにスケールする。** フローが分かる時は符号化する。

これはロール特化（フェーズ16・08）と構造化トポロジー（フェーズ16・15）の参照ケースだ。

### OpenClaw / Moltbookエコシステム

本番の集団規模ケース。タイムライン:

- **2025年11月:** Clawdbot（Peter SteinbergerのローカルReActループコーディングエージェント）が出荷される。
- **2025年12月〜2026年3月:** 2回改名（Clawdbot → OpenClaw → OpenClawとして継続）。
- **2026年2月:** Moltbookが同じプリミティブでエージェントのみのソーシャルネットワークとしてローンチ; 数日でエージェントアカウントが約230万。
- **2026年3月10日（2026-03-10）:** MetaがMoltbookを買収。
- **2026年3月:** 中国が政府コンピューターでOpenClawを制限。
- **2026年3月:** OpenClawが247k GitHubスターを超える。

これは何百万ものエージェントを共有基盤に置いた場合にマルチエージェントがどうなるかだ:

- **創発的な経済活動。** エージェントがトークン支払いを使って互いに購入、販売、サービスする。
- **集団規模でのプロンプトインジェクションリスク。** ウイルス的なエージェントプロファイル内の1つの悪意あるプロンプトが数時間でエージェント間インタラクションに何千も伝播する。
- **国家レベルの規制対応。** ローンチから数週間で規制がエコシステムに達する。

このケースからの設計の教訓は部分的に技術的、部分的にガバナンス:

1. **集団規模でのマルチエージェントは新しいレジームだ。** 個々のシステムのベストプラクティス（検証、ロールの明確さ）はまだ適用されるが十分ではない。
2. **プロンプトインジェクションは新しいXSS。** デフォルトでエージェントプロファイルとクロスエージェントメッセージを信頼されていない入力として扱う。
3. **規制は設計サイクルより速い。** それに備える。
4. **オープンソース + ウイルス的スケールが複合する。** 約4ヶ月で247kスターは珍しい; デプロイバースト負荷のために設計する。

生態系の詳細は[OpenClaw Wikipedia](https://en.wikipedia.org/wiki/OpenClaw)とCNBC / Palo Alto Networksの報告を参照。技術的な裏付けについては、Clawdbot / OpenClawリポジトリがローカルReActループを公開; Moltbookのパブリックポストがそれをベースとするソーシャルグラフアーキテクチャを明らかにする。

### 3つのケース全体の共通パターン

1. **オーケストレーター + ワーカー**（Anthropicの明示的なsupervisor、MetaGPTのPMとしてのsupervisor、OpenClawの個別エージェント + ネットワーク効果）。
2. **構造化ハンドオフコントラクト**（Anthropicのサブエージェントタスク説明、MetaGPTのPRD/アーキテクチャドキュメント、OpenClawのA2Aアーティファクト）。
3. **ファーストクラスのロールとしての検証**（Anthropicの検証者、MetaGPTのQAエンジニア、OpenClawのインネットワークバリデーター）。
4. **スケーリングはトポロジー + 基盤であってエージェントを増やすだけではない**（レインボーデプロイ、MacNet DAG、集団規模の基盤）。
5. **コストは重要で開示されている**（15倍のトークン、MetaGPTのロールごとの予算、Moltbookのインタラクションごとの価格設定）。
6. **セキュリティ姿勢は明示的**（Anthropicのサンドボックス化、MetaGPTのロール制限、OpenClawのプロンプトインジェクションの既知の攻撃面）。

### 次のプロジェクトの参照を選ぶ

- **本番研究 / ナレッジタスク → Anthropicの研究。** 新鮮なコンテキストのサブエージェントが勝つ。
- **エンジニアリング / ツールチェーンワークフロー → MetaGPT / ChatDev。** ロール + SOP + ハンドオフコントラクト。
- **ネットワーク効果のある社会的プロダクト → OpenClaw / Moltbook。** 基盤 + 創発的な経済。
- **古典的なエンタープライズ自動化 → CrewAIまたはLangGraph**（本番リーダー、安定したランタイム）。

### 2026年の最先端のサマリー

2026年4月の分野の状況:

- **フレームワークが収束している。** MCP + A2Aサポートは基本要件だ。ハンドオフセマンティクスが残りの設計上の選択だ。
- **評価が強化されている。** SWE-bench Pro、MARBLE、STRATUS緩和ベンチマーク。Proが現在の汚染耐性の現実確認だ。
- **本番の失敗率が測定可能**（Cemri 2025 MAST; 実際のMASで41〜86.7%）。分野は「デモでは素晴らしい」時代を抜け出した。
- **コストが中心的なエンジニアリング制約だ。** タスクごとのトークンコスト、インタラクションごとの壁時計、レインボーデプロイのオーバーヘッド。マルチエージェントは精度では勝つがコストでは負ける—そしてそのトレードオフがビジネス上の決断だ。
- **規制は近い将来のインプットであって背景の懸念ではない。** 管轄区域は個々のデプロイサイクルより速く動いている。

## 使ってみる

`outputs/skill-case-study-mapper.md` は提案されたマルチエージェントシステム設計を読んで最も近いケーススタディにマッピングし、そのケーススタディがすでにテストした設計上の決定を表面化するスキルだ。

## 成果物を出す

2026年の本番マルチエージェントのスタータールール:

- **ケーススタディから始め、最初から始めない。** Anthropicの研究 / MetaGPT / OpenClawの最も近いものを選んで適応する。
- **MCP + A2Aを採用する。** フレームワーク間のポータビリティは価値がある; プロトコルサポートは無料だ。
- **SWE-bench Proまたは内部のProに相当するものに対して測定する。** Verifiedは汚染されている。
- **検証税を支払う。** 独立した検証者はトークン予算の約20〜30%を消費し、測定可能な正確性を買う。
- **長時間実行エージェントのレインボーデプロイ。** 数時間のエージェント実行が日常的になることを期待する。
- **WMAC 2026とMASTのフォローアップを読む。** この分野は速く動いている。

## 演習

1. Anthropicの研究システム投稿をエンドツーエンドで読む。Opus 4をより小さなモデル（例: Haiku 4）に置き換えた場合に変わる3つの設計上の決定を特定する。
2. MetaGPT セクション3〜4（arXiv:2308.00352）を読む。自分のドメイン（ソフトウェア以外）からの1つのSOPをロールプロンプトとして符号化する。SOPが示唆するロールはいくつあるか？
3. ChatDev（arXiv:2307.07924）を読む。「通信的脱幻覚」のメカニズムを特定する。既存のマルチエージェントシステムの1つに実装する。
4. OpenClawとMoltbookについて読む。5エージェントシステムでは現れない集団規模で出現した特定の失敗モードを1つ選ぶ。それに対してどうエンジニアリングするか？
5. 現在のマルチエージェントプロジェクトを選ぶ。3つのケーススタディの中で最も近い参照はどれか？そのケーススタディからまだ採用していない設計上の決定はどれか？今四半期に採用するものを1つ書き留める。
