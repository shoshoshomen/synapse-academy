# エージェントのためのコンセンサスとビザンチン耐障害性

> 古典的な分散システムのBFTと確率的LLMが交わる領域。2025〜2026年にかけて3つの研究方向が登場した: **CP-WBFT**（arXiv:2511.10400）は信頼度プローブによって各投票に重みを付ける; **DecentLLMs**（arXiv:2507.14928）はリーダーレス方式で並列ワーカー提案と幾何中央値集約を採用; **WBFT**（arXiv:2505.05103）は階層構造クラスタリングによる重み付き投票でCoreノードとEdgeノードに分割する。「Can AI Agents Agree?」（arXiv:2603.01213）の実証的結果は厳しい—スカラー値の合意さえ今日では脆弱であり、1つの欺瞞的エージェントがMixture-of-Agentsのコンセンサスを損なう可能性がある。BFTは必要条件であっても十分条件ではない。このレッスンでは最小限のBFTプロトコルを実装し、エージェント固有の3つの攻撃（ビザンチン嘘、追従的同調、相関エラーモノカルチャー）を注入して、各コンセンサス変種がどう対処するかを測定する。


## 問題

N個のLLMエージェントがそれぞれ答えを出す。意見が割れる。多数決が誤った答えを選ぶのは、2つのエージェントが相関しているからだ（同じベースモデル、同じ学習データ、同じ失敗パターン）。第三のエージェントは独自の方法で誤っているため、多数派は偽の多数派となる。

欺瞞的エージェントを追加する: わざと嘘をつく。あるいは追従的エージェント: 最後に発言した相手に同意する。古典的BFTでは、ビザンチンノードは `f < n/3` の割合であり、任意の動作をするという前提がある。2026年の現実では、LLMノードは正直であっても確率的であり、モデル間で相関し、互いの出力に影響を受ける。独立したベルヌーイ投票者として扱うことはできない。

古典的BFT（PBFT、1999）が間違っているわけではない—不完全なのだ。任意のビット反転は処理できる。だが「3つの正直なエージェントが同じ学習データを共有しているから同じ幻覚を持つ」は処理できない。このレッスンではPBFTの基盤から始め、2025〜2026年の3つの適応を重ねていく。

## 概念

### 古典的BFTが提供するもの

Practical Byzantine Fault Tolerance（Castro & Liskov、OSDI 1999）は `f < n/3` のビザンチンノードを許容する。プロトコルには3フェーズ（pre-prepare、prepare、commit）と2つの基本要素（署名付きメッセージ、クォーラム証明書）がある。`n >= 3f + 1` の正直または悪意のあるノード間での単一値への合意。

保証は強力だが以下を前提とする:

1. **独立した障害。** ビザンチンノードは協調しない。
2. **正直なノードは本当に正直。** 正直な出力の正確性は問題ではなく、プロトコルは不一致を調整するだけ。
3. **質問には真実の答えがある。** 誤った事実へのコンセンサスもコンセンサスである。

LLMエージェントはこの3つすべてに違反する。同じベースモデルを使う2つのエージェントは障害を共有する。「正直な」LLMでも幻覚を起こす。曖昧な質問では「真実」はエージェントが決めるものであり、外部のオラクルは存在しない。

### LLM固有の3つの攻撃

**ビザンチン嘘。** 1つのエージェントが意図的に誤った答えを出力する。`f < n/3` であれば古典的BFTが処理する。

**追従的同調。** 1つのエージェントが投票前に他の答えを読み、最後に発言した者に合わせる。悪意はないが、最も声の大きい意見と相関する。エージェントはあらゆる署名チェックを通過するため、古典的BFTはこれを防げない。

**相関エラーモノカルチャー。** 3つのエージェントが同じベースモデルを共有し、同じ誤った答えで幻覚を起こす。多数派が誤る。3つすべてが「正直に」合意しているため、古典的BFTは役に立たない。

### 2025〜2026年の対応

**CP-WBFT**（arXiv:2511.10400）— 信頼度プローブ付き重み付きBFT。各投票者は答えに信頼度プローブを添付する（自己申告の確率、または別の較正モデルの予測）。投票重みは信頼度に応じてスケーリングされる。完全グラフ上でBFT改善+85.71%を報告。緩和対象: 追従的同調（同調エージェントは自分から提示した立場への信頼度が低い傾向がある）。

**DecentLLMs**（arXiv:2507.14928）— リーダーレス。ワーカーエージェントが並列で提案し、評価エージェントが提案を採点し、最終回答はスコア付きポジションの幾何中央値。`f < n/2` で堅牢。緩和対象: ビザンチン嘘と相関エラー（幾何中央値は外れ値に頑健で、モデルバイアスの平均ではなく密なクラスターに引き寄せる）。

**WBFT**（arXiv:2505.05103）— 階層構造クラスタリングを用いた重み付きBFT。投票重みは応答品質と履歴から学習した信頼スコアで割り当てる。エージェントをCoreとEdgeにクラスタリング; Coreエージェントが先にコンセンサスを達成し、Edgeエージェントが従う。緩和対象: スケーラビリティ（Coreコンセンサスは小規模で高速）と部分的なモノカルチャー（Coreを多様性を持って選択できる）。

### 実証研究: 「Can AI Agents Agree?」（arXiv:2603.01213）

この論文は複数のフロンティアモデル間のスカラー合意（LLMエージェントが単一の数値に合意すること）を測定した。結果は不快なものだった:

- 敵対者なしでも、LLMエージェントは多くのベンチマークで30%以上の割合でスカラー質問に意見が割れる。
- 欺瞞的なペルソナを採用した単一エージェントが、Mixture-of-Agentsのコンセンサスを正直なベースラインから40ポイント以上ずらせる。
- 不一致率はモデルの多様性と相関する—異種アンサンブルは同種より不一致が多い（良い: 相関しないエラー）が、収束も遅い（悪い: 合意までの時間が長い）。

結論: BFTは出力を整合させる機械を提供するが、整合した出力が正しいかどうかは保証しない。検証（フェーズ16・08 ロール特化）、多様性（フェーズ16・15 ディベートの変種）、評価エージェント（フェーズ16・24 ベンチマーク）と組み合わせること。

### コアプロトコル（簡略版）

LLMエージェントのための最小限のBFTラウンド:

```
1. タスクが到着; 各エージェント i が答え a_i を生成
2. 各エージェントが信頼度プローブ c_i ∈ [0, 1] を添付
3. アグリゲーターが全 n エージェントから (a_i, c_i) を収集
4. アグリゲーターが意味クラスターでグループ化（同等の答え）
5. アグリゲーターが各クラスター C の重みを計算:
     w(C) = sum_{i in C} c_i
6. 勝者 = 最大重みのクラスター、max > threshold * sum(c_i) の場合
   そうでなければ: 再試行またはエスカレーション
7. 少数派クラスターはプロベナンス付きで事後監査のためにログ記録
```

意味クラスタリングのステップがLLM固有のポイント。「その研究は4.2%を報告している」と「4.2%改善」は同じクラスター。単純な文字列等価チェックではこれを見逃す。本番環境では安価な埋め込みモデルまたは明示的な正規化を使用する。

### しきい値の調整

`threshold` パラメーターは受け入れるタイミングと再試行するタイミングを決定する。低すぎる: 弱い多数決を受け入れる。高すぎる: 何も受け入れない。経験的な範囲: `n=5-7` エージェントで0.5〜0.67、`n` が小さいほど高い。しきい値を下回る場合は、人間または別のエージェントアンサンブルにエスカレーションする。

### コンセンサスが役に立たない場合

- **曖昧な質問。** 質問に真実がなければ、コンセンサスは意見だ。そう呼ぶべき。
- **複合的な質問。** 「コードを書いて説明して」— 2つの答えが必要。それぞれ独立して投票する。
- **敵対的マルチラウンド。** エージェントが過去のラウンドを観察して真似できる場合（Du 2023のディベート）、真実に関係なく互いに同意し始める。ラウンドを制限する（通常2〜3回）。

## 実装する

`code/main.py` は以下を実装する:

- `AgentVoter` — （答え、信頼度）を持つスクリプトポリシー。
- `MajorityVote` — 古典的な多数決。
- `CPWBFT` — 意味クラスタリングによる信頼度重み付き投票。
- `DecentLLMs` — スコア付き提案への幾何中央値集約。
- `Scenario` — 3つの攻撃パターン下で各アグリゲーターを実行。

実装された攻撃パターン:

1. `byzantine`: 1つのエージェントが高い信頼度で嘘をつく。
2. `sycophancy`: 1つのエージェントが最初に見た答えをコピーし、同じ信頼度を示す。
3. `monoculture`: 3つのエージェントが中程度の信頼度で同じ誤った答えを共有する（相関エラー）。

実行:

```
python3 code/main.py
```

期待される出力: (攻撃、アグリゲーター) → 最終回答の表。正しい答えが強調表示される。多数決はモノカルチャーのケースで失敗する。CPWBFTの信頼度重み付けは追従性を緩和する。DecentLLMsの幾何中央値は、モノカルチャーが人口の半分未満の場合に正直なクラスターに引き寄せる。

## 使ってみる

`outputs/skill-consensus-designer.md` は、マルチエージェントアンサンブルのコンセンサスプロトコルを設計する: クラスタリング方法、重み付け、しきい値、しきい値以下のラウンドのエスカレーションポリシー。

## 成果物を出す

コンセンサスメカニズムを出荷する前に:

- **少なくとも上記の3つのパターンで攻撃テストする。** プロトコルは予測可能に失敗すべきで、サイレントに失敗すべきではない。
- **すべての少数派クラスターをプロベナンス付きでログ記録する。** 少数派クラスターは相関エラーの早期警告システムだ。
- **ラウンドを有界に制限する。** 「合意するまで議論し続ける」はなし—それは追従性に報酬を与える。
- **合意と正確性を分離する。** コンセンサス出力は検証者へ; 検証者はアンサンブルから独立している。
- **合意率を監視する。** 急上昇は同調バイアスを意味し; 急落はモデルドリフトを意味する。

## 演習

1. `code/main.py` を実行する。モノカルチャーのモノカルチャー信頼度が0.7未満の場合、多数決がモノカルチャー攻撃に失敗するがCPWBFTが部分的に緩和することを確認する。
2. 第4の攻撃パターンを追加する: **サイレント棄権** — 1つのエージェントが答えを拒否する（「わかりません」）。各アグリゲーターは棄権をどう扱うべきか？選択を実装する。
3. 意味クラスタリングを文字列正規化から埋め込み類似度（任意のオープンソース埋め込みモデルを使用）に切り替える。追従性攻撃はどうなるか？
4. CP-WBFT（arXiv:2511.10400）を読む。信頼度プローブ較正ステップ（別の較正モデルが各エージェントの自己申告信頼度をチェックする）を実装する。モノカルチャーシナリオでの精度向上を測定する。
5. 「Can AI Agents Agree?」（arXiv:2603.01213）を読む。簡略化されたスカラー合意実験を再現する: 3つのエージェント、1つのスカラー質問、欺瞞的なペルソナプロンプト。CPWBFTまたはDecentLLMsはそれを検出するか？

## キーワード

| 用語 | よく言われること | 実際の意味 |
|------|----------------|------------------------|
| BFT | 「ビザンチン耐障害性」 | Castro-Liskov 1999年プロトコル。`f < n/3` の任意障害を持つコンセンサス。 |
| Byzantine | 「あらゆる悪い動作」 | 嘘をつき、メッセージを落とし、サイレントに失敗できるノード—安全なクラッシュ以外何でも。 |
| 信頼度プローブ | 「どのくらい確信している？」 | 投票に添付された自己申告または較正器予測の確率。 |
| 意味クラスタリング | 「同じ答え、異なる言葉」 | 投票を数える前に同等の答えをグループ化する。 |
| 幾何中央値 | 「ロバストな中心」 | サンプル点までの距離の和を最小化する点。外れ値に頑健で、平均と異なる。 |
| モノカルチャー | 「同じモデル、同じ失敗」 | エージェントが学習データまたはベースモデルを共有する場合の相関エラー。 |
| 追従的同調 | 「声の大きい意見に同意する」 | エージェントの投票が最初/最も大きな声を持った者に偏る。 |
| Core/Edge | 「階層的BFT」 | WBFTの分割: 先に小規模なCoreコンセンサス、EdgeノードがFollowする。レイテンシを制限する。 |
