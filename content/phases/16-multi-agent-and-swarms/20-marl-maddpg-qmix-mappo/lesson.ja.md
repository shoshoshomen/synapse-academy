# MARL — MADDPG、QMIX、MAPPO

> マルチエージェント協調の強化学習遺産であり、2026年でもLLMエージェントシステムに影響を与え続ける。**MADDPG**（Lowe et al.、NeurIPS 2017、arXiv:1706.02275）は中央集権的訓練・分散実行（CTDE）を導入した: 各批評家は訓練中にすべてのエージェントの状態とアクションを見る; テスト時にはローカルアクターのみが実行される。協力、競争、混合設定に機能する。**QMIX**（Rashid et al.、ICML 2018、arXiv:1803.11485）は単調混合ネットワークによる価値分解; エージェントごとのQが結合Qに組み合わされ、`argmax`がきれいに分散する—StarCraft Multi-Agent Challenge（SMAC）で支配的。**MAPPO**（Yu et al.、NeurIPS 2022、arXiv:2103.01955）は中央集権的価値関数を持つPPO; 最小の調整で粒子ワールド、SMAC、Google Research Football、Hanabiで「驚くほど効果的」。これらは分散実行しなければならないエージェントチームのためのトレーニングポリシーを支える。MAPPOは**2026年のデフォルト協力MARL基準**だ。このレッスンは小さなグリッドワールドトイから各アルゴリズムを構築し、LLMエージェントトレーニングに触れる前に3つのアイデアを身に付ける。


## 問題

LLMエージェントシステムは、いつ延期するか、いつ行動するか、どのピアを呼ぶかなど、エージェント間調整のためのポリシーをますますトレーニングしている。そのようなポリシーをトレーニングする方法を教える文献はMARLで、これはLLM波より前で支配的なアルゴリズムの小さなセットを持つ。

パターン語彙なしにMARL論文を読むのは辛い。中央集権的訓練・分散実行（CTDE）、価値分解、中央集権的批評家は流行語ではない—特定の問題への特定の答えだ:

- 独立RL（各エージェントが単独で学習）は各エージェントの視点から非定常。悪い。
- 中央集権的RL（1つのエージェントがすべてを制御）はスケールせず、実行制約に違反する。
- CTDEは両方の良い点を取る: グローバル情報でトレーニングし、ローカルポリシーでデプロイ。

## 概念

### 論文が使用する3つの環境

- **粒子ワールド（マルチエージェント粒子環境）。** 協力/競争タスクを持つシンプルな2D物理。MADDPGの元のテストベッド。
- **StarCraft Multi-Agent Challenge（SMAC）。** 協力的マイクロ管理、部分観察。QMIXのテストベッド。離散アクション、連続状態。
- **Google Research Football、Hanabi、MPE。** MAPPOのベースライン。

異なる環境には異なるアクション/観察タイプがある。アルゴリズムはそれに応じて選択する。

### MADDPG（2017）— CTDEパターン

各エージェント `i` は自分の観察をアクションにマッピングするアクター `mu_i(o_i)` を持つ。各エージェントはまた、訓練中にすべての観察とすべてのアクションを見る批評家 `Q_i(x, a_1, ..., a_n)` を持つ。アクターは批評家の評価に対してポリシー勾配によって更新される。

```
アクター更新:    grad_theta_i J = E[grad_theta mu_i(o_i) * grad_a_i Q_i(x, a_1..n) at a_i=mu_i(o_i)]
批評家更新:   次状態結合推定を与えられたQ_i(x, a_1..n)のTD
```

CTDEの理由: 訓練時には全員のアクションを知っている; それを使って各批評家の分散を減らす。デプロイ時には各エージェントは `o_i` のみを見て `mu_i(o_i)` を呼ぶ。

失敗モード: 批評家はNエージェントで成長する（入力にはすべてのアクションが含まれる）。近似なしでは約10エージェントを超えてスケールしない。

### QMIX（2018）— 価値分解

協力のみ。グローバル報酬はエージェントごとのQ値の単調関数の和:

```
Q_tot(tau, a) = f(Q_1(tau_1, a_1), ..., Q_n(tau_n, a_n)),   df/dQ_i >= 0
```

単調性は `argmax_a Q_tot` を各エージェントが `argmax_{a_i} Q_i` を独立して選択することで計算できることを保証する。それが**まさに必要な分散実行特性**だ。訓練時に混合ネットワークがエージェントごとのQから `Q_tot` を生成する。

QMIXがSMACで勝つ理由: 協力的なStarCraftマイクロ管理には同質エージェント、ローカル観察、グローバル報酬がある—価値分解に完璧に適合。

失敗モード: 単調性制約は制限的; 一部のタスクには単調分解可能でない報酬構造がある（チームのために犠牲になる1エージェント）。拡張（QTRAN、QPLEX）がこれを緩和する。

### MAPPO（2022）— 見落とされたデフォルト

マルチエージェントPPO: 中央集権的価値関数を持つPPO。各エージェントには独自のポリシーがある; すべてのエージェントは完全状態を見る共有（またはエージェントごとの）価値関数を共有する。Yu et al. 2022は5つのベンチマークでMAPPOをMADDPG、QMIX、およびそれらの拡張に対してベンチマーク化し以下を発見:

- MAPPOは粒子ワールド、SMAC、Google Research Football、Hanabi、MPEでオフポリシーMARL法と同等またはそれを上回る。
- 最小のハイパーパラメーター調整が必要。
- 安定したトレーニング; シード間で再現可能。

コミュニティはこの論文まで、オンポリシーMARLを過小評価していた。2026年では、MAPPOは協力MARLのデフォルト基準; 新しい方法はそれを上回らなければならない。

### LLMエージェントエンジニアが気にすべき理由

3つの直接的な用途:

1. **ルータートレーニング。** メタエージェントがどのサブエージェントがタスクを処理するかを選択する。これはN個の分散サブエージェントと1つの中央集権ルーターを持つMARLの問題だ。MAPPOが適合する。
2. **ロール創発。** 生成エージェントシミュレーションでは、エージェントが時間の経過とともに補完的なロールを採用するようにトレーニングすることはMARLの問題だ。QMIXスタイルの価値分解は構造的に補完性を強制する。
3. **マルチエージェントツール使用。** エージェントがツールを共有し予算を競う場合、CTDEを通じてそれらをトレーニングすると、リソース制約を尊重するデプロイ可能なローカルポリシーが生成される。

実用的な注意点: 2026年、ほとんどの本番LLMエージェントシステムはポリシーをトレーニングするのではなくプロンプトする。MARLは(a) 多くのインタラクションデータ、(b) 明確な報酬シグナル、(c) トレーニングインフラへの投資意欲がある場合に登場する。

### RLを超えた設計パターンとしてのCTDE

トレーニングなしでも、CTDEは有用なアーキテクチャパターンだ:

- *設計*中は、完全なチームの可視性を仮定する。
- *実行*時には、分散実行を強制する: 各エージェントは `o_i` のみを見る。

このパターンはエージェントごとの状態を明示的に保持し、最初から部分観察可能性を考える。多くの本番マルチエージェントシステムは至る所で共有状態を静かに仮定している—CTDEの規律がそれを防ぐ。

### 非定常性の問題

複数のエージェントが同時に学習する場合、各エージェントの環境（他者のポリシーを含む）は非定常だ。古典的な単一エージェントRLの証明が壊れる。このレッスンのMARLアルゴリズムはすべてこれに対処する:

- MADDPG: グローバル批評家がすべてのアクションを見るため、その価値推定は定常だ。
- QMIX: 価値分解が最適性が明確に定義された結合Q空間に学習を移す。
- MAPPO: 中央集権的価値関数が他者のポリシー変更からの分散を抑制する。

LLMエージェントシステムでは、非定常性は「私のエージェントは先月機能していたが、上流の別のエージェントが変わり、私のエージェントが誤動作する」として現れる。CTDEでのMARLトレーニングが原則的な修正; プロンプトレベルの修正はより速いが耐久性が低い。

### このレッスンがカバーしないもの

実際のネットワークのトレーニングはフェーズ09のトピックだ。このレッスンでは、勾配更新なしにCTDE、価値分解、中央集権的価値パターンを示すスクリプトポリシーバージョンを構築する。目標は、完全なMARLライブラリ（PyMARL、MARLlib、RLlibマルチエージェント）を手に取る前にパターンを身に付けることだ。

## 実装する

`code/main.py` は3つのパターンデモンストレーションを実装し、すべて小さな2エージェント協力グリッドワールドで:

- 環境: 4x4グリッド上の2エージェント、1つの報酬ペレット。報酬 = いずれかのエージェントがペレットに到達した場合1; タスク終了。
- `IndependentAgents` — 各エージェントが他者を環境として扱う。ベースライン。
- `MADDPGStyle` — 中央集権的批評家が結合価値を計算; アクターポリシーがそれから更新する。スクリプト化されたポリシー改善。
- `QMIXStyle` — 単調ミキサーを持つ価値分解。
- `MAPPOStyle` — 中央集権的価値関数; ポリシーが共有ベースラインに対して更新する。

4つすべてが同じエピソードを実行し、目標までの平均ステップを報告する。CTDEの変種は独立したベースラインより短いパスに収束する。

実行:

```
python3 code/main.py
```

期待される出力: 独立エージェントは平均約6ステップかかる; CTDE変種は約3.5ステップに向けて収束する（4x4グリッドの最適は3）。パターンの違いはスクリプトポリシーにもかかわらず現れる。

## 使ってみる

`outputs/skill-marl-picker.md` は与えられたマルチエージェントタスクにMARLアルゴリズムを選ぶスキルだ: 協力 vs 競争、同質 vs 異質、アクション空間タイプ、スケール、報酬シグナル。

## 成果物を出す

MARLを本番環境で使用することは稀だ。使用する場合:

- **MAPPOから始める。** 2022年の論文がこれを基準として確立した; 最初にそれを再現すると、より高度な方法を追いかける数週間を節約できる。
- **すべてのエージェントの観察とアクションストリームをログ記録する。** エージェントごとのトレースなしのMARLデバッグは絶望的だ。
- **トレーニングコードと実行コードを分離する。** CTDEは規律; 実行パスが本当に `o_i` のみを見るようにする。
- **報酬整形の警告。** MARLは報酬設計に極めて敏感だ。シェーピングに1つの協調バグがあると、エージェントはそれを悪用することを学習する。敵対的テストを実行する。
- **LLMエージェントの場合**、まずプロンプトレベルのポリシーを考慮する。インタラクションデータ + 報酬シグナル + インフラすべてが揃っている場合のみMARLトレーニングに投資する。

## 演習

1. `code/main.py` を実行する。独立エージェントとMAPPOスタイルエージェントの目標までのステップのギャップを測定する。6x6グリッドでギャップは大きくなるか小さくなるか？
2. 競争的な変種を実装する: 2エージェント、1ペレット、最初に到達したのみが報酬を受け取る。どのパターンが競争をきれいに処理するか？歴史的にMADDPG。
3. MADDPG（arXiv:1706.02275）セクション3を読む。正確な批評家更新ルールを自分の言葉で疑似コードで象徴的に実装する。
4. MAPPO（arXiv:2103.01955）を読む。なぜ著者はベンチマークで中央集権的価値 + PPOがオフポリシーMARLを打ち負かすと主張するか？3つの最も強い主張を列挙する。
5. CTDEを仮想のLLMエージェントシステム（例: 研究エージェント + 要約者 + コーダー）の設計パターンとして適用する。設計時に利用可能で実行時に利用できない結合情報は何か？

## キーワード

| 用語 | よく言われること | 実際の意味 |
|------|----------------|------------------------|
| MARL | 「マルチエージェントRL」 | マルチエージェントシステムのための強化学習。 |
| CTDE | 「中央集権的訓練、分散実行」 | グローバル情報でトレーニング; ローカルポリシーでデプロイ。 |
| MADDPG | 「マルチエージェントDDPG」 | すべての観察 + アクションを見るエージェントごとの批評家を持つCTDE。 |
| QMIX | 「価値分解」 | エージェントごとのQの単調混合。協力的。 |
| MAPPO | 「マルチエージェントPPO」 | 中央集権的価値関数を持つPPO。2026年のデフォルト基準。 |
| 価値分解 | 「個別Qの和」 | エージェントごとのQの単調関数として表現された結合Q。 |
| 非定常性 | 「動く標的」 | 各エージェントの環境が他者の学習とともに変化する。コアMARLの問題。 |
| オンポリシー / オフポリシー | 「現在 / リプレイから学習」 | PPOはオンポリシー（MAPPO）; DDPGとQ学習はオフポリシー。 |
| SMAC | 「StarCraft Multi-Agent Challenge」 | 協力的マイクロ管理ベンチマーク; QMIXの本拠地。 |
