# グループチャットとスピーカー選択

> AutoGen GroupChatとAG2 GroupChatはN個のエージェント間で1つの会話を共有する；セレクター関数（LLM、ラウンドロビン、またはカスタム）が次に話す者を選ぶ。これが創発的なマルチエージェント会話のアーキタイプだ——エージェントは静的グラフ内での役割を知らず、ただ共有プールに反応する。AutoGen v0.2のGroupChatセマンティクスはAG2フォークで保持された；AutoGen v0.4はイベント駆動アクターモデルとして書き直した。Microsoftは2026年2月にAutoGenをメンテナンスモードにして、Semantic Kernelとマージし、Microsoft Agent Framework（2026年2月RC）にした。GroupChatプリミティブはAG2とMicrosoft Agent Frameworkの両方に生き残っている——一度学べばどこでも使える。


## 問題

静的グラフ（LangGraph）はワークフローが既知の場合に優れている。実際の会話は静的ではない：コーダーがレビュアーに尋ねることもあれば、リサーチャーに、ライターにと聞くこともある。すべての可能なハンドオフをハードコーディングするとエッジの爆発が起きる。*共有プールに反応するエージェント*が欲しく、次に話す者を決める何らかの関数が欲しい。

それがまさにAutoGen GroupChatが行うことだ。

## 概念

### 形状

```
              ┌─── 共有プール ────┐
              │   m1  m2  m3  ...  │
              └─────────┬──────────┘
                        │（全員がすべてを読む）
      ┌───────┬─────────┼─────────┬───────┐
      ▼       ▼         ▼         ▼       ▼
    エージェントA エージェントB エージェントC エージェントD セレクター
                                           │
                                           ▼
                                  「次のスピーカー = C」
```

すべてのエージェントがすべてのメッセージを見る。セレクター関数が各ターンで誰が次に話すかを選ぶために呼ばれる。

### 3つのセレクターのフレーバー

**ラウンドロビン。** 固定サイクル。決定論的。Nで線形にスケールするがコンテキストを無視する——法務レビューがトピックの時でもコーダーがターンを得る。

**LLM選択。** 最近のプールを読んで最良の次のスピーカーを返すLLMへの呼び出し。コンテキスト認識だが遅い：すべてのターンにLLM呼び出しが追加される。AutoGenのデフォルト。

**カスタム。** 好きなロジックを持つPython関数。典型的：フォールバックルール付きのLLM選択（例：「コーダーの後には常にベリファイアーにターンを与える」）。

### ConversableAgent API

```
agent = ConversableAgent(
    name="coder",
    system_message="You write Python.",
    llm_config={...},
)
chat = GroupChat(agents=[coder, reviewer, tester], messages=[])
manager = GroupChatManager(groupchat=chat, llm_config={...})
```

`GroupChatManager`がセレクターを持つ。エージェントがターンを完了すると、マネージャーがセレクターを呼び出し、セレクターが次のエージェントを返す。終了条件が満たされるまでループが続く。

### 終了

3つの一般的なパターン：

- **最大ラウンド。** 総ターン数のハードキャップ。
- **「TERMINATE」トークン。** エージェントはセンチネルメッセージを発行できる；マネージャーは1つが現れると停止する。
- **目標達成チェック。** 軽量なベリファイアーが各ターンで実行され、完了したら会話を停止する。

### AutoGen → AG2の分割とMicrosoft Agent Frameworkのマージ

2025年初め、Microsoftはイベント駆動アクターモデルを中心にAutoGen（v0.4）の大規模な書き直しを始めた。コミュニティは初期採用者が統合したAPIを保持し、AutoGen v0.2のGroupChatセマンティクスをAG2としてフォークした。

2026年2月、MicrosoftはAutoGenがメンテナンスモードに入り、イベント駆動アクターモデルが**Microsoft Agent Framework**（2026年2月RC、現在Semantic Kernelとマージ済み）にマージされると発表した。GroupChatコンセプトは両方のトラックに生き残る；実装の詳細は異なる。AG2はv0.2互換コードの推奨アップストリームだ。

### GroupChatが適合する場合

- **創発的な会話。** すべての可能な次のスピーカーを事前に配線したくない。
- **役割混在タスク。** コーダーがリサーチャーに尋ね、リサーチャーがアーキビストに尋ね、アーキビストがコーダーに尋ね返す。フローはDAGではない。
- **探索的問題解決。** 「組み立てライン」ではなく「ブレインストーミングミーティング」を考える。

### 失敗する場合

- **厳密な決定論。** LLMセレクターは一貫性がない。同じプロンプト、異なる実行、異なる次のスピーカー。
- **追従カスケード。** エージェントが最も自信を持って話した者に従う。明示的にカウンタープロンプトする。
- **コンテキストの肥大化。** すべてのエージェントがすべてのメッセージを読む；10ターン後はコンテキストが巨大だ。ビューをスコープするために射影（レッスン15）を使う。
- **ホットスピーカー。** 1つのエージェントがセレクターがその専門性を好むため会話を支配する。スピーカーバランスをセレクターの機能として導入する。

### グループチャット対スーパーバイザー

同じプリミティブ、異なるデフォルト：

- スーパーバイザー：1つのエージェントが計画し、他が実行する。セレクターは「プランナーに次を何をするか尋ねる」。
- グループチャット：すべてのエージェントがピアだ；セレクターは共有プールの関数だ。

どちらもレッスン04の4つのプリミティブを使う。グループチャットはデフォルトでLLM選択オーケストレーションとフルプール共有状態を使う。

## 実装する

`code/main.py`は標準ライブラリでGroupChatをゼロから実装している。3つのエージェント（コーダー、レビュアー、マネージャー）、ラウンドロビンとLLM選択のバリアント、そして`TERMINATE`トークンでの終了。

デモは会話のトランスクリプトと両方のバリアントのセレクターの決定トレースを出力する。

実行：

```
python3 code/main.py
```

## 使ってみる

`outputs/skill-groupchat-selector.md`は与えられたタスクのためのGroupChatセレクターを設定する——ラウンドロビン対LLM選択対カスタム、そしてどのセレクター入力（最近のメッセージ、エージェントの専門性、ターン数）を使うか。

## 成果物を出す

チェックリスト：

- **最大ラウンドキャップ。** 常に。典型的なタスクで10〜20。
- **スピーカーバランス指標。** エージェントごとのターンを追跡；不均衡が閾値を超えたらアラート。
- **終了トークン。** `TERMINATE`または専用のベリファイアーエージェント。
- **射影またはスコープされたメモリ。** 約10メッセージ後、コンテキストの肥大化を防ぐために各エージェントにスコープされたビューのみを与えることを検討する。
- **セレクターログ。** LLM選択バリアントでは、セレクターの入力と選択の両方をログする。そうしなければデバッグが不可能だ。

## 演習

1. `code/main.py`を実行する。ラウンドロビンとLLM選択で会話を比較する。それぞれの下でどのエージェントが支配するか？
2. セレクターに「エージェントごとの最大発言回数」ルールを追加する。それはトランスクリプトにどう影響するか？
3. 目標達成終了を実装する：レビュアーが「承認」を返した時に停止する。ラウンドキャップの前に何回発動するか？
4. AutoGen stableのGroupChatドキュメント（https://microsoft.github.io/autogen/stable/user-guide/core-user-guide/design-patterns/group-chat.html）を読む。`GroupChatManager`が使うデフォルトセレクターを特定する。
5. AG2リポジトリ（https://github.com/ag2ai/ag2）を読み、v0.2のGroupChatをv0.4のイベント駆動バージョンと比較する。v0.4が追加する具体的なプロパティ（スループット、耐障害性、コンポーザビリティ）は何か？

## キーワード

| 用語 | よく言われること | 実際の意味 |
|------|----------------|------------------------|
| GroupChat | 「1つのチャットルームのエージェント」 | 共有メッセージプール + セレクター関数。AutoGen / AG2のプリミティブ。 |
| スピーカー選択 | 「次に話す者」 | 次のエージェントを選ぶ関数。ラウンドロビン、LLM選択、またはカスタム。 |
| GroupChatManager | 「会議のホスト」 | セレクターを持ちターンをループするAutoGenコンポーネント。 |
| ConversableAgent | 「ベースエージェント」 | AutoGenのベースクラス；メッセージを送受信できるエージェント。 |
| 終了トークン | 「「停止」の言葉」 | チャットを終了するセンチネル文字列（通常`TERMINATE`）。 |
| ホットスピーカー | 「1つのエージェントが支配する」 | セレクターが同じエージェントを選び続ける失敗モード。 |
| コンテキストの肥大化 | 「プールが無限に増える」 | 各エージェントがすべての以前のメッセージを読む；コンテキストがターンと共に増える。 |
| 射影 | 「スコープされたビュー」 | コンテキストの肥大化を防ぐための共有プールへの役割固有のビュー。 |
