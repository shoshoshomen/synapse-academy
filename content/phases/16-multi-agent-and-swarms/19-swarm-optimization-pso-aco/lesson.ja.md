# LLMのためのスワーム最適化（PSO、ACO）

> バイオインスパイアード最適化がLLMの場で復活している。**LMPSO**（arXiv:2504.09247）は各粒子の速度がプロンプトであり、LLMが次の候補を生成するPSOを使用する; 構造化シーケンス出力（数学的表現、プログラム）で良好に機能する。**Model Swarms**（arXiv:2410.11163）は各LLMエキスパートをモデル重みマニフォールド上のPSO粒子として扱い、9つのデータセット上の12のベースライン比較で**平均13.3%の向上**を200インスタンスで報告する。**SwarmPrompt**（ICAART 2025）はプロンプト最適化のためにPSO + グレーオオカミをハイブリッド化する。**AMRO-S**（arXiv:2603.12933）はマルチエージェントLLMルーティングのためのACOインスパイアードフェロモンスペシャリスト—**4.7倍の高速化**、解釈可能なルーティング証拠、推論と学習を切り離す品質ゲート付き非同期更新。このレッスンではプロンプトパラメータ空間でPSOを、エージェントルーティングでACOを実装し、これらの古典的アルゴリズムがLLM時代に適合する理由とそうでない場合を測定する。


## 問題

タスク評価でプロンプトが62%を出す。改善したい。ナイーブな方法は勾配なしの手動調整で、スケールが悪い。強化学習には報酬シグナルと十分なロールアウトが必要だ。プロンプトを通した逆伝播は実際にはできない—プロンプトは離散的な文字列であって微分可能なパラメーターではない。

古典的なバイオインスパイアード最適化—連続探索空間のためのPSO、パス選択のためのACO—はまさにこのレジームのために設計された: 勾配なし、集団ベース、評価ごとの安価なコスト。勾配なし探索ステップのためにLLMとペアリングすると、驚くほど実用的なオプティマイザーが得られる。

同じパターンはマルチエージェントシステムのエージェント*ルーティング*にも適用される。ACOスタイルのフェロモントレイルは、どのエージェントがどのタスクタイプで最も良く機能したかを記録し、ルーターがトレイルを活用し、フェロモンが減衰してルートを再発見できるようにする。

## 概念

### PSOの復習（Kennedy & Eberhart 1995）

粒子群最適化: 連続探索空間における粒子の集団。各粒子は位置 `x_i` と速度 `v_i` を持つ。各イテレーション:

```
v_i <- w * v_i + c1 * r1 * (p_best_i - x_i) + c2 * r2 * (g_best - x_i)
x_i <- x_i + v_i
fitness(x_i)を評価
改善した場合にp_best_iを更新
グローバル最高の場合にg_bestを更新
```

`p_best` は粒子自身の最高、`g_best` は群の最高、`w, c1, c2` は慣性 + 認知 + 社会重み、`r1, r2` はランダム係数。

### LLM出力上のPSO — LMPSO

arXiv:2504.09247はLLM生成構造化出力（数学的表現、プログラム）のためにPSOを適応する。各粒子は候補出力だ。速度は個人/グローバル最高に向けて現在の出力を変更する方法を説明する*プロンプト*だ。LLMは速度プロンプトから新しい出力を生成する。速度の「慣性」は「小さなインクリメンタルな変更を加える」のようなプロンプトだ。

これが良く機能する場合:
- 出力が構造化されている（解析可能、評価可能）。
- 適合度が自動的（テスト実行、算術評価）。
- 集団が小さい（約10〜30粒子）のでLLM呼び出しの合計が管理可能。

適合度に人間のレビューが必要な場合はうまく機能しない—イテレーションごとのコストが高くなりすぎる。

### Model Swarms

arXiv:2410.11163はPSOを出力レイヤーから*モデル*レイヤーに取り込む。各「粒子」はエキスパートLLM（パラメーター）だ。群は勾配なし更新によってパラメーターを集団最高に向けて移動させる。報告: 9つのデータセット、イテレーションごとに200インスタンスで12のベースラインに対して平均13.3%の向上。

鍵となる洞察は、LLMエキスパートモデルが共有パラメーターマニフォールド（アダプター重み、LoRAデルタ）でそもそも近くにあること。この低次元部分空間でのPSOは安価で効果的だ。

### ACOの復習（Dorigo 1992）

アリコロニー最適化: アリがグラフを通過する; 各パスにはフェロモントレイルがある。アリの移動確率はフェロモン強度で重み付けされる。タスクを完了したアリはソリューション品質に比例してフェロモンを堆積する。フェロモンは時間の経過とともに減衰する。

### AMRO-S — エージェントルーティングのためのACO

arXiv:2603.12933はマルチエージェントルーティングにACOを使用する。各タスクタイプは「目的地」; 各エージェントは可能なルートだ。フェロモンは良い出力を生み出すルートを強化する。主要な貢献:

- **解釈可能なルーティング証拠。** フェロモン強度は人間が読めるシグナルだ。
- **品質ゲート付き非同期更新。** 品質チェックが通過した後のみフェロモンが更新され、推論と学習が切り離される。
- マルチエージェントルーティングベンチマークで**4.7倍の高速化**。

品質ゲートが重要: それなしでは、速いが間違ったエージェントがフェロモンを蓄積し、システムが悪いルートに固定される。

### LLMにPSO/ACOを使用する場合

**PSOを使用する場合:**
- 探索空間が連続的またはそれにマッピングされるパラメーター（プロンプト埋め込み、LoRA重み、数値生成パラメーター）。
- 適合度が安価で自動的。
- 集団が小さくできる（10〜30）。

**ACOを使用する場合:**
- ルーティングまたはパス選択の問題がある。
- 決定が時間の経過とともに強化される（同じタスクタイプが戻ってくる）。
- ルーティング決定に解釈可能な証拠が必要。

**いずれも使用しない場合:**
- 適合度に人間のレビューが必要（イテレーションごとに高すぎる）。
- 探索空間がPSOがカバーしない方法で離散的で組み合わせ的（代わりに遺伝的アルゴリズムを使用）。
- リアルタイムの決定に厳格なレイテンシが必要（PSO/ACOは単一パスヒューリスティックより収束が遅い）。

### バイオインスパイアードがまだ勝つ理由

勾配ベースの方法には微分可能なシグナルが必要だ。LLM出力とルーティング決定は自明に微分可能ではない。疑似勾配法（強化学習されたルーター、DPOスタイルのプロンプトチューナー）は機能するが高価なトレーニングが必要だ。

PSOとACOは*評価者*関数のみを必要とする。候補出力またはルーティング決定をスコアリングできれば、空間を最適化できる。これにより適用可能性のバーがはるかに低くなる。

### 実用的な限界

- **集団予算。** N粒子 × Tイテレーション × 評価ごとのコスト。約$0.02/呼び出しのLLM評価では、50イテレーション実行する20粒子のPSOは約$20かかる。それに応じて計画する。
- **探索 vs 活用。** フェロモン減衰率とPSO慣性はトレードオフ; 速すぎる減衰 → ソリューションを忘れる; 遅すぎる → 初期のローカル最適に固定される。
- **壊滅的なドリフト。** 両方のアルゴリズムは、適合度の状況が変化する場合（新しいデータ分布）に収束してから発散する。最高適合度の安定性を監視する。

## 実装する

`code/main.py` は以下を実装する:

- `LMPSO` — 数値プロンプトパラメーター（温度、top_k重み）上のPSO。各粒子の「LLM生成」はスクリプト化された適合度関数としてシミュレートされる。アルゴリズムを30イテレーション実行し、g_best収束を表示する。
- `AMRO_S` — ACOスタイルのルーティング。3エージェント、4タスクタイプ、フェロモン行列、100のルーティングタスク。トレイル形成を示すために（タスクタイプ → エージェントの選択）分布を時間とともに出力する。
- 比較: 同じタスクストリームでのランダムルーティングとACOルーティング。品質とレイテンシを測定する。

実行:

```
python3 code/main.py
```

期待される出力:
- LMPSO: g_best適合度が30イテレーションでランダムからほぼ最適に改善する。
- AMRO-S: フェロモン表がタスクタイプごとに正しいエージェントに安定する; ACOルーティングは品質で約30〜40%ランダムより良く、レイテンシも削減する（再試行が減る）。

## 使ってみる

`outputs/skill-swarm-optimizer.md` はLLM/エージェント最適化問題のためにPSO、ACO、遺伝的アルゴリズム、勾配ベースのオプティマイザーから選択する。

## 成果物を出す

- **小さく始める。** 10〜20粒子、20〜50イテレーション。収束曲線が明確な向上を示す場合のみスケールアップ。
- **イテレーションごとにフェロモンまたはg_bestをログ記録する。** トレイルなしでスワームオプティマイザーをデバッグするのは辛い。
- **更新を品質ゲートする。** 特にACOルーティングの場合: 速いが間違ったエージェントはフェロモンを蓄積してはならない。
- **分布シフト時に減衰をリセットする。** 評価分布が変化する場合、古いフェロモンは古い; 一時的に減衰率をリセットまたは倍にする。
- **イテレーションごとのコストを上限にする。** コストごとのイテレーションメトリクスを出力する。$500/イテレーションのコストで0.5%の向上をするPSOは出荷できない。

## 演習

1. `code/main.py` を実行する。LMPSOの収束を観察する。集団サイズを5、10、20、50で変化させる。どのサイズで収束までの時間が飽和するか？
2. 「壊滅的なドリフト」実験を実装する: イテレーション30の後、適合度関数を変更する。PSOはどのくらい速く適応するか？ `p_best` をリセットすることは助けになるか？
3. AMRO-Sに品質ゲートを追加する: eval スコア > 0.7の実行時のみフェロモン堆積。これはゲートなしバージョンに対して収束をどう変えるか？
4. LMPSO（arXiv:2504.09247）を読む。論文の「速度としてのプロンプト」を数値速度にマッピングする。シミュレーションで失われるものと保存されるものは何か？
5. AMRO-S（arXiv:2603.12933）を読む。非同期フェロモン更新を伴う切り離された「推論高速パス」を実装する。これは持続的な負荷下でシステムのレイテンシをどう変えるか？
