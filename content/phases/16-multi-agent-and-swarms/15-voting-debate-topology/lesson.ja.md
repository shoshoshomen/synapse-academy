# 投票、自己一貫性、ディベートトポロジー

> 最も安価な集約方法: N個の独立したエージェントをサンプリングして多数決を取る。Wang et al. 2022の自己一貫性は1つのモデルをN回サンプリングすることでこれを行った。マルチエージェントはモノカルチャーから逃れるために**異種**エージェントで拡張する—異なるモデル、異なるプロンプト、異なる温度、異なるコンテキスト。多数決を超えて、ディベートトポロジーが重要だ: MultiAgentBench（arXiv:2503.01935、ACL 2025）はstar/chain/tree/graphの協調を評価し、**研究にはgraphが最適**であり、約4エージェントを超えると「協調税」が発生することを発見した。AgentVerse（ICLR 2024）は2つの出現パターンを記録している—ボランティア行動と同調行動—同調はコンセンサスを見つける機能でもあり、グループシンク（レッスン24）のリスクでもある。このレッスンはトポロジー空間をマッピングし、各変種を構築し、協調税を測定する。


## 問題

ディベートは精度を改善できる（Du et al.、arXiv:2305.14325）。悪化させることもできる。ディベートが助けになるかどうかは4つの構造的選択に依存する:

1. 誰が誰と話すか（トポロジー）。
2. ラウンド数（Du 2023: ラウンド数とエージェント数の両方が独立して重要）。
3. エージェントが異種かどうか（異なるベースモデルはモノカルチャーを壊す）。
4. 敵対的な声があるかどうか（鋼鉄のマン vs.ストローマン）。

「5つのエージェントを実行して投票する」をタスクにボルト留めするチームは、単一エージェントに対して後退することが多い。失敗はランダムではない。トポロジーと異質性を追跡する。このレッスンはトポロジーマップだ。

## 概念

### 自己一貫性: 単一モデルのベースライン

Wang et al. 2022（「Self-Consistency Improves Chain of Thought Reasoning」）は温度 > 0 で同じモデルをN回サンプリングし、推論パスの答えを多数決で決定した。GSM8K での結果: 単一の貪欲なデコードに対してN=40サンプルで大幅な向上。自己一貫性はマルチエージェント投票のシングルエージェント前身だ。

限界: 自己一貫性は1つのベースモデルを使用する。エラーは構造的に相関している。モデルに系統的なバイアスがある場合、N個のサンプルすべてがそれを共有する。

### マルチエージェント投票: 異種拡張

N個のサンプルをN個の*異なる*エージェントに置き換える。異なるベースモデル（Claude、GPT、Llama）、異なるプロンプト、異なるツールアクセス。メリット: 相関しないエラー。コスト: 異なるエージェントは異なるコストがかかる; それらを協調させるにはオーバーヘッドが増える。

2026年の異種ディベートの標準的な名前は **A-HMAD** — Adversarial Heterogeneous Multi-Agent Debate。普遍的に採用されているわけではないが、論文は「異なるモデルがディベートし、モノカルチャー崩壊からの相関エラーを減らす」という意味でこの用語を使用している。

### 4つのトポロジー

```
star                chain               tree                graph

    ┌─A─┐           A─B─C─D         ┌──A──┐              A───B
    │   │                           │     │              │ × │
    B   C                           B     C              D───C
    │   │                          / \   / \
    D   E                         D   E F   G           (完全接続)
```

Star: 1つのハブ、他はハブとのみ通信。バックチャネルなしのsupervisor-workerと等価。
Chain: 線形、各エージェントが前のエージェントの出力を見る。パイプラインのよう。
Tree: 階層的、階層型エージェントシステムに使用（レッスン06）。
Graph: 任意対任意。完全接続クリークと任意のDAGを含む。

### 協調税（MultiAgentBench）

MultiAgentBench（MARBLE、ACL 2025、arXiv:2503.01935）は研究、コーディング、計画を含むタスクスイートでstar、chain、tree、graphをベンチマーク化した。測定された主要結果:

- **Graph** トポロジーは研究タスクで勝つ。情報は任意対任意で流れ; エージェントは互いを批判できる。
- **Star** は高速な事実質問タスクで勝つ。ハブがフィルタリングして統合する。
- **Chain** は段階的パイプライン（段階的精錬）で勝つ。
- **協調税** はgraphトポロジーで約4エージェントを超えると現れる。壁時計とトークンコストが品質より速く増加する。

4エージェントの上限は経験的なものであって、根本的なものではない。2026年のLLMコンテキスト容量を反映している: 各エージェントのコンテキストはピアの出力で埋まり、エージェントN+1を追加するときの限界価値は全員が全員を見られるようになると低下する。

### マルチエージェントディベート戦略（「MADに進むべきか？」）

arXiv:2311.17371 は2023年のMAD戦略のサーベイ。他の研究でも再現された主要な発見: 自己一貫性と*構造的に類似*しているMAD変種（独立サンプリング + 集約）は、同じ予算を使用する場合に自己一貫性を下回ることが多い。MADは、エージェントが本当に異種で、ディベートに敵対的な構造（1つのエージェントが反論する）がある場合に最も助けになる。

### AgentVerseの出現パターン

AgentVerse（ICLR 2024、https://proceedings.iclr.cc/paper_files/paper/2024/file/578e65cdee35d00c708d4c64bce32971-Paper-Conference.pdf）は、明示的な設計なしでマルチエージェントディベートから出現する2つの行動を記録している:

- **ボランティア。** エージェントが促されることなく助けを申し出る（「次のステップを引き受けられます」）。有用: 最もサブタスクに適したエージェントに作業を割り当てる。
- **同調。** エージェントが批評者に合わせてスタンスを調整する。批評者が間違っている場合でも。これはディベートにおける追従性と同等（レッスン14）。

同調が合意するまでのディベートに報酬を与える理由だ。別の審判員による制限されたラウンドが緩和する。

### 異質性: 精度を実際に動かすノブ

2024〜2026年の実用的な文献のパターン: N個のエージェントの1つを異なるベースモデルに置き換えると、Nを1増やすよりも精度の向上が大きい。直観はモノカルチャー—各新しい独立したエラー源は追加の相関サンプルより価値がある。

極限では、異質性は数より勝る。3つの異なるモデルは、クリーンな真実を持つほとんどのタスクで同じモデルの5つのコピーを打ち負かす。

### ジュリーメソッド

Sibyフレームワーク（Minsky-LLM文献で引用）は、各段階で投票することで答えを精錬する小さな専門エージェントの「ジュリー」を形式化する。単純な多数決とは異なり、ジュリーにはロールがある: 1つのエージェントが反対尋問し、1つがコンテキストを提供し、1つがもっともらしさをスコアリングする。ジュリーメソッドは単純な投票（安価、モノカルチャー傾向）と完全なMAD（高価、同調傾向）の中間点だ。

### ディベート付き投票が支配する場合

- 質問に真実がある（事実、数学、コードの動作）。投票の収束が有意味だ。
- エージェントが異なるソースやツールにアクセスできる（異質性が利用可能）。
- ラウンドが制限されている（通常2〜3回）で、別の審判員または検証者がいる。
- 予算が3〜5エージェントを許可する。グラフトポロジーで5〜7を超えると協調税が支配する。

### ディベート付き投票が害になる場合

- 質問が意見形式。エージェントは最も正しく見える答えではなく、最も自信に満ちているように見える答えに収束する。
- すべてのエージェントがベースモデルを共有している。モノカルチャーはコンセンサスを無意味にする。
- ラウンドが無制限。同調が毎回勝つ。
- タスクが単純。N=5の単一エージェントの自己一貫性の方が安価で同程度に正確だ。

## 実装する

`code/main.py` は以下を実装する:

- `run_star(agents, hub, question)` — ハブが各ワーカーにポーリングして集約。
- `run_chain(agents, question)` — 順次精錬。
- `run_tree(root, children, question)` — 深さ2の集約を持つ階層的。
- `run_graph(agents, question, rounds)` — 全対全ディベート、制限されたラウンド。
- スクリプト化された異質性ダイアル: 各エージェントは系統的な誤りを示す `error_bias` を持つ。
- N=3、5、7でトポロジーを実行し、(精度、合計トークン、シミュレートされた壁時計)を報告する測定ハーネス。

実行:

```
python3 code/main.py
```

期待される出力: トポロジー × N → (精度、トークン、レイテンシ) の表。研究スタイルのタスクでgraphがN=3〜5で勝つ; starが高速事実タスクで勝つ; N=7でのgraphは協調税を示す（レイテンシが精度より速く膨らむ）。

## 使ってみる

`outputs/skill-topology-picker.md` はタスクの説明を読んで、トポロジー（star/chain/tree/graph）、N（エージェント数）、異質性プロファイル（使用するベースモデル）、ラウンド上限を推薦するスキルだ。

## 成果物を出す

アンサンブルには:

- **1つの強いベースモデルでN=5の自己一貫性**から始める。それが安価なベースラインだ。
- 精度が重要なら**N=3の異種投票**にアップグレードする。デルタを測定する。
- タスクに構造（研究、マルチステップ）があり、制限されたラウンドが実現可能な場合のみ**ディベートトポロジー**にアップグレードする。
- 常に少数派クラスターをログ記録する。少数派が持続的に正しい場合、多様性シグナルがある。
- 精度と並んで壁時計とトークンをベンチマーク化する。「10倍のコストでより良い精度」はビジネス上の決断だ。

## 演習

1. `code/main.py` を実行する。graphトポロジーの協調税曲線をプロットする: Nに対する精度、Nに対するトークン。どのNで曲線が変曲するか？
2. A-HMADを実装する: 意図的に異なるバイアスを持つ3つのエージェント。同じバイアスのベースラインはレッスン14のモノカルチャー攻撃に対してA-HMADとどう比較されるか？
3. 投票しない「審判員」ロールをgraphトポロジーに追加し、最終コンセンサスのみをスコアリングする。これは出現した同調行動を変えるか？
4. AgentVerseの論文（ICLR 2024）を読む。あなたの実装が最も強く示す出現行動を特定する。プロンプトの変更で逆の行動を引き出せるか？
5. MultiAgentBench（arXiv:2503.01935）セクション4（トポロジー実験）を読む。ハーネスを使って論文の1つのタスクで「graphが研究に勝つ」結果を再現する。
