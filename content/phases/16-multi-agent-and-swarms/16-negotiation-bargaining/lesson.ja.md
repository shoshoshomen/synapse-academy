# 交渉と取引

> エージェントはリソース、価格、タスク割り当て、条件を交渉する。2026年のベンチマークセットは明確だ: NegotiationArena（arXiv:2402.05863）はLLMがペルソナ操作（「絶望」）によって利益を約20%改善できることを示す; 「Measuring Bargaining Abilities」（arXiv:2402.15813）はバイヤーがセラーより難しく、スケールが助けにならないことを示す—彼らの**OG-Narrator**（決定論的オファー生成器 + LLMナレーター）は成立率を26.67%から88.88%に押し上げた; Large-Scale Autonomous Negotiation Competition（arXiv:2503.06416）は約18万回の交渉を実施し、**チェーンオブソートを秘匿する**エージェントが相手方から推論を隠すことで勝つことを発見した; Bhattacharya et al. 2025のハーバード交渉プロジェクト指標ではLlama-3が最も効果的、Claude-3が攻撃的、GPT-4が最も公平だとランク付けした。このレッスンはContract Net Protocol（FIPA先祖、レッスン02）を実装し、LLMスタイルのバイヤー/セラーを接続し、OG-Narratorスタイルの分解を実行し、各構造的選択で成立率がどう変化するかを測定する。


## 問題

2つのエージェントが価格に合意する必要がある。純粋な言語プロンプトだけで放置すると、2024〜2026年のLLMは驚くほど低い成立率（arXiv:2402.15813の厳密にパラメータ化された取引で約27%）で取引を成立させる。スケールはそれを修正しない: GPT-4は取引の構造においてGPT-3.5より優れていない; 取引の*言語*において優れている。

根本的な問題は、LLMがオファーを決定することとオファーをナレーションすることという2つの仕事を混同することだ。OG-Narratorはこれを分離した: 決定論的オファー生成器が数値的な手を計算し; LLMはナレーションのみ行う。成立率は約89%に跳ね上がる。

これは古典的なマルチエージェントの発見と一致する: メカニズムを通信層から切り離すことが勝つ。Contract Net Protocol（FIPA、1996年; Smith、1980年）は参照タスク市場メカニズムだ。ナレーションスロットにLLMを接続すると、現代のLLMパワードタスク市場ができる。

## 概念

### Contract Net、1段落で

Smith's 1980 Contract Net Protocol: **マネージャー**が**コール・フォー・プロポーザル（cfp）**をブロードキャストする; **ビッダー**は自分のオファーを含む**propose**メッセージで応答する; マネージャーが勝者を選び、勝者に**accept-proposal**を、負け者に**reject-proposal**を送る。勝者が作業を実行する。オプションのメッセージ: **refuse**（ビッダーが提案を辞退）。FIPAはこれを`fipa-contract-net`インタラクションプロトコルとして標準化した。

### OG-Narratorが勝つ理由

「Measuring Bargaining Abilities of Language Models」（arXiv:2402.15813）は以下を観察した:

- LLMはしばしば取引ルールを破る（非常識な価格でオファーし、相手方のZOPAを無視する）。
- アンカリングが下手（悪い最初のオファーを受け入れる; 戦略的な額ではなく象徴的な額でカウンターオファーする）。
- スケール単独ではこれを修正しない。大きなモデルは同様の戦略的エラーとともに、より説得力のある言語を作る。

OG-Narrator分解:

```
           ┌──────────────────┐        ┌──────────────────┐
  状態  → │ オファー生成器   │ 価格 → │  LLMナレーター  │ → メッセージ
           │  （決定論的）   │        │  （人間スタイルの│
           │                  │        │   付随文章を書く）│
           └──────────────────┘        └──────────────────┘
```

オファー生成器は古典的な交渉戦略: ルービンシュタイン取引モデル、Zeuthen戦略、または価格への単純なtit-for-tat。LLMはナレーションする。メッセージには決定論的な価格と自然言語フレーミングが含まれる。

成立率が跳ね上がる理由:
- 価格が取引ゾーン内に留まる。
- アンカーが感情的ではなく戦略的。
- LLMは得意なことをする: 文章を書くこと。

### NegotiationArenaの発見

arXiv:2402.05863は標準的なベンチマークを提供する。主要な発見:

- LLMはペルソナを採用することで利益を約20%改善できる（「今週までにこれを売りたくて焦っています」）—ペルソナ操作は本物の戦術だ。
- 公平/協力的なエージェントは敵対的なエージェントに搾取される; 防御には明示的な反抗姿勢が必要だ。
- 対称ペアはベンチマークシナリオの約40%で不公平な結果に収束する。

これは「LLMは取引下手」ではない。「LLMは搾取可能な部分を含む人間のように取引する」だ。

### チェーンオブソートの秘匿

Large-Scale Autonomous Negotiation Competition（arXiv:2503.06416）は多くのLLM戦略にわたる約18万回の交渉を実施した。勝者は相手方から推論を秘匿した:

- エージェントが「75ドルまでしか出せない; 予約価格は70ドルだ」と公開可能なスクラッチパッドに印刷すると、相手方がそれを読む。
- 勝者は戦略を非公開で計算する; 出力チャネルにはオファーと必要最小限のナレーションのみが含まれる。

これは古典的ゲーム理論（Aumann 1976の合理性と情報に関する研究）の2026年のエコー: 自分の私的評価を明かすことは利益を失うことになる。LLMはこれを直観しないため、相手方に見えるようになる推論トレースに喜んで自分の予約価格を打ち込む。

工学的な教訓: プライベートスクラッチパッドコンテキストとパブリックメッセージコンテキストを分離する。オプションではない。

### Bhattacharya et al. 2025 — モデルランキング

ハーバード交渉プロジェクト指標（原則的交渉、BATNA尊重、利益相互性）について:

- **Llama-3** は取引に最も効果的（成立率 + 利益）。
- **Claude-3** は最も攻撃的な交渉者（高いアンカー、遅い譲歩）。
- **GPT-4** は最も公平（ペアリング全体で利益分散が最小）。

これは2025年4月のスナップショットだ。どのモデルが2026年4月に勝つかが問題ではない—異なるベースモデルには持続的な交渉スタイルがあるということだ。異種アンサンブル（レッスン15）はこれを多様性源として含む。

### Contract Net + LLMによるタスク割り当て

LLMマルチエージェントのためのContract Netの現代的な再利用:

1. マネージャーエージェントがタスクをユニットに分解する。
2. タスクの説明とともに`cfp`をワーカーエージェントにブロードキャストする。
3. 各ワーカーがオファーを返す: `(price, eta, confidence)` ここでpriceはトークン、計算ユニット、またはドルになりうる。
4. マネージャーが勝者（タスクによって単一または複数）を選び、賞与する。
5. 落選したワーカーは他のタスクに入札できる。

協調はブロードキャスト・アンド・レスポンドであり、同期チャットではないため、100以上のワーカーにもスケールする。本番環境で使用: Microsoft Agent Frameworkのオーケストレーションパターン、一部のLangGraph実装。

### LLMステークホルダーインタラクティブ交渉

NeurIPS 2024（https://proceedings.neurips.cc/paper_files/paper/2024/file/984dd3db213db2d1454a163b65b84d08-Paper-Datasets_and_Benchmarks_Track.pdf）は**秘密スコア**と**最低受け入れしきい値**を持つマルチパーティスコア可能ゲームを導入した。各ステークホルダーにはプライベートな効用があり; LLMはメッセージからそれを推測しなければならない。これは2者間取引をN者連合形成に一般化したものだ。異種ワーカー能力を持つ本番タスク市場に関連する。

### ナレーション対メカニズムのルール

2024〜2026年のすべての交渉ベンチマークを通して、一貫した工学ルールは:

> LLMにナレーションをさせる。LLMにオファーを計算させない。

オファーが数字（価格、ETA、数量）である必要がある場合、交渉状態から決定論的に生成し、LLMにフレーミングを作成させる。オファーが提案構造（タスク分解、ロール割り当て）である必要がある場合、LLMに下書きを作らせるが、送信前にスキーマに対して検証し制約チェックを行う。

## 実装する

`code/main.py` は以下を実装する:

- `ContractNetManager`、`ContractNetTask`、`Bid` — マネージャー + ビッダー、cfpブロードキャスト、提案収集、賞与。
- `og_narrator_bargain(state, rng)` — OG-Narratorバイヤー: 中間点に向かうZeuthenスタイルの決定論的な譲歩。
- `seller_response(state, rng)` — 決定論的セラーカウンターオファーポリシー（両スタイルの構造的グラウンドトゥルース）。
- `naive_llm_bargain(state, rng)` — オールLLM取引者をシミュレート: 高い分散で価格を選び、ZOPAの外になることが多い。
- 測定: トライアルごとに新鮮な予約価格をサンプリングした1000回のトライアルにわたる成立率。

実行:

```
python3 code/main.py
```

期待される出力: naive-LLMの成立率 ~65〜75%; OG-Narratorの成立率 ~85〜95%; 15〜25ポイントのギャップはオファー生成をナレーションから切り離すことの構造的優位性。さらに3つのビッダーと1つのタスクを持つContract Netタスク市場割り当ての例。

## 使ってみる

`outputs/skill-bargainer-designer.md` は交渉プロトコルを設計する: オファーを生成するのは誰か（決定論的またはLLM）、ナレーションするのは誰か、プライベートスクラッチパッドがパブリックメッセージからどう分離されるか、成立率の監視方法。

## 成果物を出す

本番交渉チェックリスト:

- **スクラッチパッドを分離する。** プライベート状態は相手方のコンテキストに届かない。これは交渉の余地がない。
- **決定論的オファー生成。** 価格、数量、ETA: 計算する、プロンプトしない。
- **すべての受信オファーをスキーマに対して検証する。** ZOPA外のオファーをプロトコル境界で拒否する。
- **ラウンドを制限する。** 最大3〜5ラウンド; デッドロック時に調停者にエスカレーションする。
- **成立率と利益分散を継続的に測定する。** 下落する成立率は症状—しばしばプロンプトドリフトまたは相手方側の攻撃。
- **すべての拒否された提案を決定論的理由付きでログ記録する。** Contract Netマネージャーには、負けたビッダーが理由を理解する必要がある。

## 演習

1. `code/main.py` を実行する。OG-Narratorが成立率でnaive-LLMを打ち負かすことを確認する。どのくらいの差か？
2. **ペルソナベースの利益改善**（arXiv:2402.05863）を実装する—バイヤーはナレーションのみで「今週これを買いたくて焦っている」ペルソナを採用し、オファー生成器は変更しない。成立率や利益は変化するか？
3. チェーンオブソートの**秘匿**を実装する: 相手方に渡されないプライベートスクラッチパッド文字列を維持する。誤ってリークした場合（チャネルを入れ替えることでシミュレート）何が起こるか？
4. Contract Netをリザーブ価格付きのN-ビッダーオークションに拡張する。全入札がリザーブを超える場合、マネージャーはどのように最低価格と最高品質の間を決めるか？どのアワードルールを選びその理由は？
5. Bhattacharya et al. 2025のハーバード交渉プロジェクト指標について読む。異なるスタイル（攻撃的 vs 公平）の2人の取引者を実装する。対称と非対称のペアリング下での利益分散を測定する。

## キーワード

| 用語 | よく言われること | 実際の意味 |
|------|----------------|------------------------|
| Contract Net | 「タスク市場」 | Smith 1980、FIPA 1996。cfp + propose + accept/reject。標準的なタスク市場。 |
| ZOPA | 「合意可能ゾーン」 | バイヤーの最大額とセラーの最小額の重複。その外のオファーは成立できない。 |
| BATNA | 「交渉上の最善の代替案」 | この取引が失敗した場合のフォールバック。予約価格を設定する。 |
| OG-Narrator | 「オファー生成器 + ナレーター」 | 分解: 決定論的オファー、LLMナレーション。 |
| Zeuthen戦略 | 「リスク最小化の譲歩」 | リスク制限に基づいて譲歩する古典的オファー生成器。 |
| Rubinstein取引 | 「交互オファー均衡」 | 割引を伴う無限ホライズン取引のゲーム理論モデル。 |
| CoT秘匿 | 「推論を隠す」 | arXiv:2503.06416の勝者はプライベートスクラッチパッドを維持; パブリックチャネルはオファーのみを表示。 |
| ペルソナ操作 | 「感情的な姿勢」 | arXiv:2402.05863: 絶望/緊急ペルソナで約20%の利益向上。 |
