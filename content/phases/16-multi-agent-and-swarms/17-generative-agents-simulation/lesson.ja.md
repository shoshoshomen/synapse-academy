# 生成エージェントと創発的シミュレーション

> Park et al. 2023（UIST '23、arXiv:2304.03442）は25エージェントのサンドボックス**Smallville**に3部構成のアーキテクチャを組み込んだ: **メモリストリーム**（自然言語ログ）、**リフレクション**（エージェントが自分のストリームについて生成する高次の統合）、**プラン**（日次レベルの行動、その後のサブプラン）。ランドマーク的な結果はバレンタインデーのパーティーの創発だった: 「バレンタインデーのパーティーを開きたい」とシードされた1つのエージェントが、さらなるスクリプトなしに、招待状を人口全体に広め、日程を調整し、パーティーを実現した—最初は全員知らなかった24エージェントから。アブレーションは3つのコンポーネントすべてが信頼性のために必要であることを示す。記録された失敗は空間的規範エラー（閉店した店に入る、一人用バスルームを共有する）だ。これは2026年のエージェントシミュレーションとマルチエージェント社会評価の参照アーキテクチャだ。


## 問題

ほとんどのマルチエージェントシステムは厳密にスクリプト化されたチームだ: プランナーが計画し、コーダーがコーディングし、レビュアーがレビューする。これは明確に定義されたタスクには機能する。エージェントがメモリ、優先事項、オープンワールドを持つ場合に生じる創発的な、スクリプトなしの行動はキャプチャできない。研究、社会シミュレーション、そしてゲームAIにはこの2番目の種類が必要だ。

Smallvilleアーキテクチャはそれのベンチマークだ。Park 2023以前、最良のエージェントシミュレーションは浅いスクリプトフォロワーだった; その後、このパターンはオープンワールドの生成エージェントのデフォルトになった。2026年にエージェントシミュレーションを構築するなら、Smallvilleの3つのコンポーネントを使用するか、使用しない理由を明示的に正当化することになる。

## 概念

### 3つのコンポーネント

**メモリストリーム。** 観察、行動、リフレクション、プランの追記専用ログ。各エントリにはタイムスタンプ、タイプ、説明（自然言語）、導出されたメタデータが含まれる: **recency**、**importance**（エージェントによって1〜10で自己評価）、**relevance**（現在のクエリへのコサイン類似度）。

```
[2026-02-14 09:12:03] observation: Isabella Rodriguez に彼女がジャズが好きか聞かれた
[2026-02-14 09:14:22] reflection:   音楽についての長い会話が好きだ
[2026-02-14 10:05:00] plan:         今夜Isabellaのバレンタインデーのパーティーに出席する
```

メモリ取得は3つのスコアを組み合わせる: `score = w_recency * e^(-decay * age) + w_importance * importance + w_relevance * cos_sim`。上位k個のエントリが現在のプロンプトに入る。

**リフレクション。** 定期的に（N個のメモリごと、または重要なイベントで）、エージェントは最近のメモリから高次の統合を生成する。リフレクションエントリはストリームに戻り、他のメモリと同様に取得可能だ。これがエージェントが「理解」を構築する方法だ—アーキテクチャの長期的な信念に相当する。

**プラン。** トップダウン分解。最初に大まかな日次プラン（「仕事に行き、Klausと夕食をとる」）。次に時間レベルのプラン。次にアクションレベルのプラン。プランは改訂可能: 観察がプランと矛盾する場合、影響を受けるセグメントのみを再プランする（全体ではない）。

### 3つのコンポーネントすべてが重要な理由（アブレーション）

Park et al. は観察、リフレクション、プランのそれぞれを削除したアブレーションを実行した。各アブレーションは信頼性を損なう:

- **観察**がないとエージェントはコンテキストを見逃し、古い信念に基づいて行動する。
- **リフレクション**がないとエージェントは高次の信念を形成できない; インタラクションが浅くなる。
- **プラン**がないと行動が反応的なノイズになり; 目標が消散する。

人間の評価者からの信頼性スコアは3つすべてで最も高い; いずれかを削除すると測定可能な回帰が生じる。

### バレンタインデーの創発

1人のエージェント、Isabella Rodriguezが「2月14日の17時にHobbs Cafeでバレンタインデーのパーティーを開きたい」という目標でシードされる。他の24エージェントはそのようなシードを受け取らない。シミュレートされた日数をかけて:

1. Isabellaのプランには人々を招待することが含まれる。
2. 各招待は近隣のメモリストリームの観察になる。
3. その近隣のリフレクションが信念を生成する: 「Isabellaがパーティーを開いている」。
4. 近隣のプランが「2月14日にパーティーに出席する」を組み込む。
5. 近隣が他の近隣に話す。招待は中央調整なしに広がる。
6. 2月14日の17時、いくつかのエージェントがHobbs Cafeに集まる。

これは技術的な意味での創発だ: システムレベルの行動（パーティー）は中央オーケストレーターなしに局所的な相互作用（二者間招待 + 個別計画）から生じた。

### 記録された失敗モード

Park et al. は明示的に記録した:

- **空間的規範エラー。** エージェントが閉店した店に歩いて入る。エージェントが同じ一人用バスルームを使おうとする。エージェントが食事に意図されていない部屋で食事をする。モデルは環境からだけでは社会的・物理的規範を推論しない。
- **メモリオーバーフロー。** 深いシミュレーション実行によりメモリ取得コストが増加する。実用的な対処法: 定期的なメモリコンパクション（要約してプルーニング）と低重要度エントリの減衰。
- **リフレクション幻覚。** リフレクションはメモリストリームに存在しない関係を発明することがある。緩和策: リフレクションプロンプトにソースメモリIDを含め、取得時に検証する。

これらは本番関連の失敗モードだ: 2026年のエージェントシミュレーションはそれらを継承する。

### 3コンポーネント実装ルール

1. **メモリは追記専用。** メモリエントリを変更しない。修正は新しいエントリだ。
2. **重要度スコアは安価。** 書き込み時にLLMを呼び出して重要度1〜10を評価する。スコアをキャッシュする。
3. **取得はランク付けであって、フィルタリングではない。** 複合スコアによる上位k; ハードフィルターは使用しない（コンテキストが失われる）。
4. **リフレクションは定期的に実行する。** 未処理メモリの重要度の合計がしきい値（例: 150）を超えた時にトリガーする。
5. **プランは改訂可能。** 新しい観察がプランと矛盾する場合、影響を受けるセグメントのみを再生成し、プラン全体ではない。

### Smallvilleを超えた生成エージェント

2024〜2026年のフォローアップ文献はアーキテクチャを拡張する:

- **ポリシー/市場調査のためのマルチエージェント社会シミュレーション。** Smallvilleのような集団がフィーチャーへの反応でユーザー行動をシミュレートする。A/Bテストより高速; 精度は議論の余地がある。
- **ゲームのNPC AI。** Smallvilleエージェントを持つRPGがスクリプト化されたクエストの代わりに創発的なストーリーラインを生成する。
- **生成エージェント評価ベンチマーク。** タスク精度ではなく、メトリクスは長い実行全体での行動の信頼性 + 一貫性になる。

アーキテクチャが参照だ。拡張はコンポーネントを交換する（メモリ用ベクトルストア、取得拡張リフレクション、ニューロシンボリックプラン）が、3部構造を維持する。

### マルチエージェントエンジニアリングにとってこれが重要な理由

Smallvilleはコンポーネントが正しい場合にマルチエージェントの創発が安価であることの概念実証だ。アーキテクチャはオープンソースモデルで再現されている（小さなLLMは信頼性を急激にではなく緩やかに失う）。**創発的な社会的行動**が必要な本番システムはこの形状を使用する。**厳密なタスク実行**が必要なシステムは、このフェーズの前半のsupervisor/roles/primitivesパターンを使用する。

## 実装する

`code/main.py` はstdlib Pythonでスクリプト化されたエージェントポリシー（実際のLLMなし）で3つのコンポーネントを実装する。デモはバレンタインデーパーティーの創発をミニチュアで再現する:

- `MemoryStream` — recency/importance/relevance取得を持つ追記専用ログ。
- `reflect(stream)` — 最近の高重要度メモリからのスクリプト化されたリフレクション。
- `plan(agent_state)` — 現在の信念に基づく日次および時間次プラン。
- シナリオ: 5エージェント。エージェント1が「17時にパーティーを開く」でスタート。シミュレートされたティックをかけて招待が広がり、エージェントが集まる。

実行:

```
python3 code/main.py
```

期待される出力: ティックごとのトレース。最終ティックまでに、5エージェントのうち少なくとも3つがプランにパーティーを表示し、パーティーの場所に集まる。単一のシードがオーケストレーターなしに協調した到着を生み出した。

## 使ってみる

`outputs/skill-simulation-designer.md` は生成エージェントシミュレーションを設計する: エージェント数、メモリスキーマ、リフレクションケイデンス、プランホライズン、評価メトリクス。

## 成果物を出す

本番シミュレーションのルール:

- **メモリはデータベース。** スケールで実際のストア（ベクトルDB、Postgres）を選ぶ。インメモリstdlibはプロトタイプ用だ。
- **取得トレースをログ記録する。** すべてのアクションについて、それを駆動した上位kのメモリをログ記録する。これがデバッグ能力だ。
- **エージェントごとのトークンを予算化する。** ティックごとの各エージェントの取得 + リフレクション + プランはO(k)のLLM呼び出しだ。Nエージェント × Tティック × ティックごとの呼び出しは予算を圧迫しうる。
- **定期的にメモリをコンパクションする。** 低重要度エントリを要約してプルーニングする。保持ポリシーは設計上の決定であって詳細ではない。
- **空間的/社会的規範違反を明示的に検出する。** アーキテクチャはそれらを学習しない。

## 演習

1. `code/main.py` を実行する。3つ以上のエージェントがパーティーに集まることを確認する。エージェントを10に増やす—創発はまだ起こるか？
2. リフレクションステップを削除する。行動はどのように見えるか？Park 2023のアブレーション発見にマッピングする。
3. 競合するシードされた目標を導入する（「Klausが17時に研究発表をしたい」）。エージェントは分裂するか、1つの目標が支配するか？何がそれを決定するか？
4. 空間的制約を追加する: Hobbs Cafeは最大4エージェントを収容できる。シミュレーションはオーバーフローを適切に処理するか、それとも「一人用バスルーム」の失敗パターンに当たるか？
5. Park et al.（arXiv:2304.03442）セクション6（創発的行動実験）を読む。あなたのミニチュアで再現できない1つの行動を特定する。アーキテクチャのどのコンポーネントを強化する必要があるか？

## キーワード

| 用語 | よく言われること | 実際の意味 |
|------|----------------|------------------------|
| メモリストリーム | 「エージェントの日記」 | 観察、行動、リフレクション、プランの追記専用ログ。 |
| Recency | 「メモリの新しさ」 | 年齢による指数関数的減衰スコア。 |
| Importance | 「エージェントがどれだけ気にするか」 | 書き込み時に1〜10で自己評価。キャッシュされる。 |
| Relevance | 「現在のクエリにどれだけ関連するか」 | コサイン類似度（埋め込みベース）。 |
| リフレクション | 「高次の信念」 | 最近のメモリから生成された統合、新しいメモリとして再取り込みされる。 |
| プラン | 「日/時間/アクション分解」 | トップダウンのプランツリー。観察が矛盾する時に改訂可能。 |
| Smallville | 「Park 2023のサンドボックス」 | バレンタインデーの創発を生み出した25エージェントシミュレーション。 |
| 信頼性 | 「品質メトリク」 | 行動がもっともらしいエージェントのように見えるかどうかの人間評価スコア。 |
