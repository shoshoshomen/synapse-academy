# インペインティング、アウトペインティングと画像編集

> テキスト→画像は新しいものを作る。インペインティングは古いものを修正する。プロダクションでは請求可能な画像作業の70%が編集だ——背景を交換、ロゴを削除、キャンバスを拡張、手を再生成。インペインティングは拡散がその役割を果たす場所だ。


## 問題

クライアントが、目障りな看板が背景にある完璧な商品写真を送ってくる。看板を消してそれ以外はピクセルそのままにしたい。テキスト→画像をゼロから実行することはできない——結果は異なる色、異なる照明、異なる商品の角度を持つだろう。マスクされた領域*のみ*を再生成したい。そして再生成が周囲のコンテキストを尊重してほしい。

これがインペインティングだ。バリアント：

- **インペインティング。** マスク内を再生成し、外側のピクセルを保持する。
- **アウトペインティング。** マスクの外側（またはキャンバスの外側）を再生成し、内側を保持する。
- **画像編集。** 画像全体を再生成するが、元に対して意味的または構造的な忠実度を保つ（SDEdit、InstructPix2Pix）。

2026年のすべての拡散パイプラインはインペインティングモードを出荷する。Flux.1-Fill、Stable Diffusion Inpaint、SDXL-Inpaint、DALL-E 3 Edit。それらは同じ原理で動く。

## 概念

![インペインティング：コンテキスト保持の再注入を伴うマスク対応のデノイズ](../assets/inpainting.svg)

### ナイーブなアプローチ（そしてなぜ間違っているか）

マスク付きで標準のテキスト→画像を実行する。各サンプリングステップで、ノイジーな潜在変数のマスクされていない領域を前方拡散された清潔な画像に置き換える。機能はするが……悪くだ。境界アーティファクトが滲み出る。モデルがマスクされた領域の内容についての情報を持っていないからだ。

### 適切なインペインティングモデル

4チャンネルではなく9チャンネルの入力を取る修正U-Netを訓練する：

```
input = concat([ noisy_latent (4ch), encoded_image (4ch), mask (1ch) ], dim=channel)
```

追加チャンネルは、VAEエンコードされたソース画像のコピーと単一チャンネルのマスクだ。訓練時にはランダムに画像領域をマスクし、マスクされた領域だけをデノイズするよう訓練する。マスクされていない領域はクリーンな条件付けシグナルとして与えられる。推論時に、モデルはマスクされた領域を囲むものを「見る」ことができ、コヒーレントな補完を生成する。

SD-Inpaint、SDXL-Inpaint、Flux-Fillはすべてこの9チャンネル（またはアナログ）入力を使う。Diffusers `StableDiffusionInpaintPipeline`、`FluxFillPipeline`。

### SDEdit（Meng et al.、2022）——フリーな編集

ソース画像に中間的な `t` までノイズを加え、その後新しいプロンプトで `t` から0まで逆連鎖を実行する。再訓練なし。開始 `t` の選択が忠実度と創造的な自由度をトレードする：

- `t/T = 0.3` → ソースとほぼ同一、小さなスタイルの変化
- `t/T = 0.6` → 中程度の編集、粗い構造を保持
- `t/T = 0.9` → ほぼノイズから生成、ソースの保存が最小

### InstructPix2Pix（Brooks et al.、2023）

`(入力画像、指示、出力画像)` トリプルで拡散モデルをファインチューンする。推論時に入力画像とテキスト指示（「夕日にして」、「ドラゴンを追加して」）の両方で条件付けする。2つのCFGスケール：画像スケールとテキストスケール。

### RePaint（Lugmayr et al.、2022）

標準の無条件拡散モデルをそのまま使う。各逆ステップで再サンプリング——時々よりノイジーな状態に戻って再生成する。境界アーティファクトを回避する。訓練済みのインペインティングモデルがないときに使う。

## 実装する

`code/main.py` は5次元データ上のおもちゃの1次元インペインティングスキームを実装する。5次元混合データ（各サンプルは2つのクラスターの1つからの5つの浮動小数点数）でDDPMを訓練する。推論時に5次元のうち2次元を「マスク」し、各ステップでマスクされていない3次元のノイジーなフォワードバージョンを注入し、マスクされた次元のみを再生成する。

### ステップ1：5次元DDPMデータ

```python
def sample_data(rng):
    cluster = rng.choice([0, 1])
    center = [-1.0] * 5 if cluster == 0 else [1.0] * 5
    return [c + rng.gauss(0, 0.2) for c in center], cluster
```

### ステップ2：全5次元でデノイザーを訓練する

標準DDPM。ネットは5次元のノイジーな入力に対して5次元のノイズ予測を出力する。

### ステップ3：推論時のマスク対応の逆

```python
def inpaint_step(x_t, mask, clean_image, alpha_bars, t, rng):
    # replace unmasked dims with a freshly noised version of the clean source
    a_bar = alpha_bars[t]
    for i in range(len(x_t)):
        if not mask[i]:
            x_t[i] = math.sqrt(a_bar) * clean_image[i] + math.sqrt(1 - a_bar) * rng.gauss(0, 1)
    # ...then run the normal reverse step on x_t
```

これはナイーブなアプローチで、1次元のおもちゃデータでは機能する。実際の画像インペインティングはテクスチャのコヒーレンスがより重要なため9チャンネル入力を使う。

### ステップ4：アウトペインティング

アウトペインティングはマスクが反転したインペインティングだ：新しい（以前は存在しなかった）キャンバスをマスクし、残りは元で埋める。訓練目的は同一だ。

## 落とし穴

- **継ぎ目。** マスクを越えて勾配情報が流れないため、ナイーブなアプローチは目に見える境界を残す。修正：マスクを8〜16ピクセル拡大するか、適切なインペインティングモデルを使う。
- **マスクのリーク。** 条件付け画像のマスクされていない領域が低品質またはノイジーな場合、マスク内の生成を汚染する。わずかにデノイズまたはブラーする。
- **CFGがマスクサイズと相互作用する。** 小さいマスクで高CFG = 飽和したパッチ。小さな編集ではCFGを下げる。
- **SDEditの忠実度崖。** `t/T = 0.5` から `t/T = 0.6` に移行すると、題材のアイデンティティが失われることがある。スウィープしてチェックポイントする。
- **プロンプトの不一致。** プロンプトは新しいコンテンツだけでなく*画像全体*を説明すべきだ。「猫がいます」でなく「椅子に座っている猫」。

## 使ってみる

| タスク | パイプライン |
|------|----------|
| オブジェクトを削除、小さいマスク | SD-InpaintまたはFlux-Fill、標準プロンプト |
| 空を置き換える | SD-Inpaint + 「夕方の青空」 |
| キャンバスを拡張する | SDXLアウトペイントモード（8pxフェザー）またはアウトペイントマスク付きFlux-Fill |
| 手 / 顔を再生成する | 題材を再説明するプロンプト + ControlNet-OpenposeでSD-Inpaint |
| ある領域のスタイルを変える | マスクされた領域での `t/T=0.5` でSDEdit |
| 「夕日にして」 | InstructPix2PixまたはFlux-Kontext |
| 背景置換 | SAMマスク → SD-Inpaint |
| 超高忠実度 | 最難のケースにはFlux-FillまたはGPT-Image（ホスト型） |

SAM（MetaのSegment Anything、2023）＋拡散インペインティングは2026年の背景除去パイプラインだ。SAM 2（2024）は動画で動作する。

## 演習

1. **易。** `code/main.py` でマスクされた次元の割合を0.2から0.8まで変える。どの割合でインペイント品質（マスクされた次元の残差）が無条件の生成と等しくなるか？
2. **中。** RePaintを実装する：10番目の逆ステップごとに5ステップ戻り（ノイズを追加）再デノイズする。マスクエッジでの境界残差が減少するかを測定する。
3. **難。** Hugging Face diffusersを使って比較する：SD 1.5 Inpaint + ControlNet-Openpose対Flux.1-Fillを20件の顔再生成タスクで。ポーズの順守とアイデンティティの保持を別々にスコアリングする。

## プロダクションノート：編集パイプラインはレイテンシに敏感だ

画像を編集するユーザーは5秒以内のラウンドトリップを期待する。1024²での30ステップのSDXL-Inpaintは3〜4秒（L4上）、プラスSAMマスク生成（約200ms）とVAEエンコード/デコード（約500ms合計）。プロダクションの観点でこれはスループット制限よりもTTFT制限だ——バッチ1、低並行性、すべてのステージを最小化する：

- **SAM-Hが遅いやつだ。** SAM-Hは1024²で約200ms；SAM-ViT-Bはわずかな品質低下で約40ms。SAM 2（動画）は時間的なオーバーヘッドを追加する；単一画像の編集には使わない。
- **可能な場合はエンコードをスキップする。** `pipe.image_processor.preprocess(img)` は潜在変数にエンコードする。前の生成からの潜在変数がある場合（反復編集UIで典型的）、`latents=...` で直接渡してVAEエンコードを1つスキップする。
- **マスクの拡張はスループットにも重要だ。** 小さいマスクはU-Netフォワードパスの大部分が無駄になることを意味する（マスクされていないピクセルはどうせクランプされる）。`diffusers`の`StableDiffusionInpaintPipeline`はフルU-Netを実行する；9チャンネルの適切なインペインティングバリアントのみがマスクされた計算を利用する。
- **Flux-KontextはSSSの2025年の答えだ。** `(ソース画像、指示)` 上の単一フォワードパス——別のマスクなし、SDEditノイズスウィープなし。H100で約1.5秒で編集を出荷する。アーキテクチャの教訓：ステージを折りたたむ。
