# GAN — ジェネレータ対ディスクリミネータ

> Goodfellowが2014年に考えた妙案は、密度を完全にスキップすることだった。2つのネットワーク。一方が偽物を作る。もう一方がそれを見破る。偽物が本物と区別できなくなるまで戦い続ける。機能するはずがない。実際よく機能しない。機能するとき、そのサンプルは狭いドメインではまだ文献中で最もシャープだ。


## 問題

VAEはMSEデコーダ損失が*平均*画像に対してベイズ最適だからぼやけたサンプルを生成する——多数の妥当な数字の平均はぼやけた数字だ。あなたが欲しいのは*もっともらしさ*に報いる損失であり、特定の目標への画素ごとの近接性ではない。もっともらしさの閉形式はない。学習しなければならない。

Goodfellowのアイデア：本物の画像と偽物を区別する分類器 `D(x)` を訓練する。`D` を騙すジェネレータ `G(z)` を訓練する。`G` への損失シグナルは、現在 `D` が何を本物らしく見せているかだ。このシグナルは `G` が改善されるにつれて更新され、動く目標を追いかける。両方のネットワークが収束すれば、`G` は `log p(x)` を書き下さずに分布を学習したことになる。

これが敵対的訓練だ。数学はミニマックスゲームだ：

```
min_G max_D  E_real[log D(x)] + E_fake[log(1 - D(G(z)))]
```

2026年においてGANはもはやSOTAジェネレータではない（拡散とフローマッチングがその王冠を奪った）。しかしStyleGAN 2/3は出荷された中で最もシャープな顔モデルのままであり、GANのディスクリミネータは拡散訓練での*知覚的損失*として使われ、敵対的訓練はリアルタイム拡散を出荷できる高速1ステップ蒸留（SDXL-Turbo、SD3-Turbo、LCM）を支えている。

## 概念

![GAN訓練：ミニマックスにおけるジェネレータとディスクリミネータ](../assets/gan.svg)

**ジェネレータ `G(z)`。** ノイズベクトル `z ~ N(0, I)` をサンプル `x̂` にマッピングする。デコーダ型のネットワーク（密結合または転置畳み込み）。

**ディスクリミネータ `D(x)`。** サンプルをスカラー確率（またはスコア）にマッピングする。本物→1、偽物→0。

**損失。** 2つの交互更新：

- **`D` の訓練：** `loss_D = -[ log D(x) + log(1 - D(G(z))) ]`。本物=1、偽物=0の二値交差エントロピー。
- **`G` の訓練：** `loss_G = -log D(G(z))`。Goodfellowが使った*非飽和*形式（元の `log(1 - D(G(z)))` は `D` が確信を持つと飽和して勾配が消える）。

**訓練ループ。** `D` の1ステップ、`G` の1ステップ。繰り返す。

**なぜ機能するか。** `G` が `p_data` を完全にマッチすれば、`D` はチャンスより良くできず0.5を出力する；`G` はもはや勾配を得ない。均衡。

**なぜ壊れるか。** モード崩壊（`G` が `D` が分類できない1つのモードを見つけて永遠にそれを生成する）、勾配消失（`D` が早く学習しすぎ `log D` が飽和する）、訓練の不安定性（学習率、バッチサイズ、何でも）。

|------|------------|-----|

## 実装する

`code/main.py` は1次元データ（2つのガウス分布の混合）に対して小さなGANを訓練する。ジェネレータとディスクリミネータは単一の隠れ層MLPだ。フォワード、バックワード、ミニマックスループを手で実装する。目標は2つの主要な失敗モード（モード崩壊＋勾配消失）を発生しながら確認することだ。

### ステップ1：非飽和損失

バニラGoodfell損失 `log(1 - D(G(z)))` は、DがGの偽物を高い確信で偽物と分類したときに0に近づく。その時点でGの勾配は基本的にゼロ——Gは改善できない。非飽和形式 `-log D(G(z))` は反対の漸近線を持つ：Dが確信を持つと爆発し、Gに強いシグナルを与える。

```python
def g_loss(d_fake):
    # maximize log D(G(z))  <=>  minimize -log D(G(z))
    return -sum(math.log(max(p, 1e-8)) for p in d_fake) / len(d_fake)
```

### ステップ2：ジェネレータステップごとに1つのディスクリミネータステップ

```python
for step in range(steps):
    # train D
    real_batch = sample_real(batch_size)
    fake_batch = [G(z) for z in sample_noise(batch_size)]
    update_D(real_batch, fake_batch)

    # train G
    fake_batch = [G(z) for z in sample_noise(batch_size)]  # fresh fakes
    update_G(fake_batch)
```

Gには新鮮な偽物を渡す。そうしないと勾配が古い。

### ステップ3：モード崩壊を監視する

```python
if step % 200 == 0:
    samples = [G(z) for z in sample_noise(500)]
    mode_a = sum(1 for s in samples if s < 0)
    mode_b = 500 - mode_a
    if min(mode_a, mode_b) < 50:
        print("  [!] mode collapse: one mode is starved")
```

典型的な症状：2つの本物のモードのうち1つが生成されなくなる。ディスクリミネータはそれを偽物として見たことがないため修正しなくなる。

## 落とし穴

- **ディスクリミネータが強すぎる。** Dの学習率を2〜5倍削減するか、インスタンス/レイヤーノイズを追加する。Dが>95%の精度に達したら、Gは死んでいる。
- **ジェネレータがモードを暗記する。** Dの入力にノイズを追加し、ミニバッチディスクリミネータ層を使うか、WGAN-GPに切り替える。
- **バッチ正規化が統計を漏らす。** 本物のバッチ＋偽物のバッチが同じBN層を通ると統計が混ざる。代わりにインスタンス正規化またはスペクトル正規化を使う。
- **Inception-scoreのゲーミング。** FIDとISはサンプル数が少ないとノイジーだ。評価時には≥10kサンプルを使う。
- **ワンショットサンプリングは条件付きタスクでは嘘だ。** 使えるアウトプットを得るには、CFGスケール、トランケーショントリック、リサンプリングが依然として必要だ。

## 使ってみる

2026年のGANスタック：

| 状況 | 選択 |
|-----------|------|
| フォトリアルな人間の顔、固定ポーズ | StyleGAN3（最もシャープ、最小） |
| アニメ / スタイライズされた顔 | StyleGAN-XL または Stable Diffusion LoRA |
| 画像間変換 | Pix2Pix / CycleGAN（フェーズ8・04）またはControlNet（フェーズ8・08） |
| 高速1ステップテキスト→画像 | 拡散の敵対的蒸留（SDXL-Turbo、SD3-Turbo） |
| 拡散トレーナー内の知覚的損失 | 画像クロップに対する小さなGANディスクリミネータ |
| マルチモーダル、オープンエンドな何でも | やめろ——拡散またはフローマッチングを使え |

GANはシャープだが狭い。ドメインが広がったとき——写真、任意のテキストプロンプト、動画——拡散に切り替える。敵対的トリックはコンポーネント（知覚的損失、蒸留）として生き続けるが、スタンドアローンのジェネレータとしてではない。

## 演習

1. **易。** デフォルト設定で `code/main.py` を実行する。次に `D_LR = 5 * G_LR` を設定して再実行する。Gの損失が定数に崩壊するまでどのくらい速いか？
2. **中。** GoodfellowのBCE損失をWGAN損失に置き換える：`loss_D = E[D(fake)] - E[D(real)]`、`loss_G = -E[D(fake)]`、DのウェイトをClip `[-0.01, 0.01]`。訓練はより安定するか？ウォールクロックの収束を比較する。
3. **難。** 1次元の例を2次元データ（リング上の8つのガウス混合）に拡張する。ジェネレータが1k、5k、10kステップで8つのモードのうちいくつをカバーするかを追跡する。ミニバッチディスクリミネーションを実装して再測定する。

## キーワード

| 用語 | 一般的な言い方 | 実際の意味 |
|------|-----------------|-----------------------|
| ジェネレータ | "G" | ノイズ→サンプルネットワーク、`G: z → x̂`。 |
| ディスクリミネータ | "D" | 分類器 `D: x → [0, 1]`、本物対偽物。 |
| ミニマックス | 「ゲーム」 | `min_G max_D` の結合目的関数。 |
| 非飽和損失 | 「修正」 | Gには `log(1 - D(G(z)))` の代わりに `-log D(G(z))` を使う。 |
| モード崩壊 | 「Gが1つのものを暗記した」 | ジェネレータが多様なデータにもかかわらず少数の出力しか生成しない。 |
| WGAN | 「Wasserstein」 | BCEをEarth-Mover距離＋勾配ペナルティに置き換え；よりスムーズな勾配。 |
| スペクトル正規化 | 「Lipschitzトリック」 | Dのウェイトノルムを制約してその傾きを制限；訓練を安定化する。 |
| StyleGAN | 「機能するやつ」 | マッピングネットワーク＋AdaIN；顔で最高水準、2026年においても。 |

## プロダクションノート：ワンショット推論がGANの長所として残る

GANはオープンドメイン生成のサンプル品質では勝てなくなったが、推論コストでは依然として勝っている。プロダクション推論の文脈では、GANは：

- **プリフィルもデコードステージもない。** 単一の `G(z)` フォワードパス。TTFT ≈ 総レイテンシ。
- **KVキャッシュの圧力なし。** 唯一の状態はウェイトだ。バッチサイズはキャッシュではなく活性化メモリで制限される。
- **自明な連続バッチング。** すべてのリクエストが同じ固定FLOPsを取るため、サーバーの目標占有率での静的バッチが通常最適だ。インフライトスケジューラは不要。

これがGAN蒸留（SDXL-Turbo、SD3-Turbo、ADD、LCM）が2026年における高速テキスト→画像の主要技術である理由だ：20〜50ステップの拡散パイプラインを1〜4回のGAN式フォワードパスに折りたたみ、拡散ベースの分布を保持する。敵対的損失は遅いジェネレータを速いものに変えるための訓練時ノブとして生き続ける。
