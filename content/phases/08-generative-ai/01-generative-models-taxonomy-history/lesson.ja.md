# 生成モデル — 分類と歴史

> 画像モデル、テキストモデル、動画モデル、3Dモデルはすべて5つのカテゴリのどれかに収まる。間違ったカテゴリを選べば何週間も数学と格闘することになる。正しいカテゴリを選べば、この分野の過去12年間の進歩が頭の中に綺麗に積み重なっていく。


## 問題

生成モデルの仕事はひとつだ：未知の分布 `p_data(x)` から抽出されたトレーニングサンプルをもとに、同じ分布から来たように見える新しいサンプルを出力すること。顔、文章、MIDIファイル、タンパク質構造――目を細めれば全部同じ問題だ。

難しいのは、`p_data` が何百万次元もの空間（512x512のRGB画像は約78万6千次元）に存在し、サンプルがその空間の薄い多様体上に集中していて、手元にあるデータはせいぜい1,000万件程度だということだ。密度をブルートフォースで求めるのは不可能。あらゆる生成モデルは、ある難問を別の少しだけマシな難問に置き換えるトレードオフだ。

過去12年間で5つのファミリーが生き残った。各ファミリーがどんなトレードオフをしているかを知れば、なぜ特定のタスクで勝ち、他では崩れるのかが分かる。

## 概念

![生成モデルの5つのファミリー — モデル化対象による分類](../assets/taxonomy.svg)

**1. 明示的密度、厳密に計算可能。** `log p(x)` を実際に評価できる和として書く。自己回帰モデル（PixelCNN、WaveNet、GPT）は `p(x) = ∏ p(x_i | x_<i)` と因子分解する。正規化フロー（RealNVP、Glow）はシンプルな基底からの可逆変換として `p(x)` を構築する。利点：正確な尤度、クリーンな訓練損失。欠点：自己回帰的な推論は逐次的（長いシーケンスでは遅い）、フローには可逆なアーキテクチャが必要（構造的に制約が多い）。

**2. 明示的密度、近似。** `log p(x)` を下から（ELBO）バウンドし、そのバウンドを最適化する。VAE（Kingma 2013）は変分事後分布を持つエンコーダ・デコーダを使う。拡散モデル（DDPM、Ho 2020）は重み付きELBOを暗黙的に最適化するデノイザーを訓練する。2026年において、拡散は画像・動画・3Dの主流バックボーンだ。

**3. 暗黙的密度。** 密度を完全にスキップし、サンプルを生成するジェネレータ `G(z)` と本物と偽物を区別するディスクリミネータ `D(x)` を学習する。GAN（Goodfellow 2014）。推論は速い（1回のフォワードパス）が、訓練中は悪名高いほど不安定。StyleGAN 1/2/3は、2026年においても固定ドメインのフォトリアリズム（顔、寝室）で最高水準を維持している。

**4. スコアベース・連続時間。** 対数密度の勾配 `∇_x log p(x)`（スコア）を直接学習する。Song & Ermon（2019）は、スコアマッチングが拡散をSDEに一般化することを示した。フローマッチング（Lipman 2023）は2024〜2026年のホットトピックだ：シミュレーション不要な訓練、より直線的なパス、DDPMより4〜10倍速いサンプリング。Stable Diffusion 3、Flux、AudioCraft 2はすべてフローマッチングを使っている。

**5. 離散コードに対するトークンベース自己回帰。** VQ-VAEや残差量子化器で高次元データを短い離散トークン列に圧縮し、Transformerでトークン列をモデル化する。Parti、MuseNet、AudioLM、VALL-E、Soraのパッチトークナイザーはすべてこれを使う。これはバケット1に学習済みトークナイザーを加えたものだ。

## 5つの質問によるトリアージ

新しい生成モデルの論文が出たら、手法セクションを読む前にこの5つの質問に答えよ。

1. **何がモデル化されているか？** ピクセル、潜在変数、離散トークン、3Dガウシアン、メッシュ、波形？
2. **密度は明示的か暗黙的か？** `log p(x)` を書き下しているか？
3. **サンプリング：ワンショットか反復的か？** 反復的なら推論が遅くなる；ワンショットは通常、敵対的または蒸留されたものを意味する。
4. **条件付け：無条件、クラス、テキスト、画像、ポーズ？** これが損失とアーキテクチャの足場を決める。
5. **評価：FID、CLIPスコア、IS、人間の好み、タスク精度？** それぞれに既知の失敗モード（レッスン14参照）がある。

このフェーズの各レッスンでこの5つを再び答えていく。最後には反射的にできるようになるだろう。

## 実装する

このレッスンのコードは軽量な可視化だ：1次元の混合ガウス分布をサンプルから3つのおもちゃ的アプローチ（カーネル密度推定、離散ヒストグラム、最近傍サンプル「GAN的」ジェネレータ）でフィットし、1画面に収まる問題で明示的対暗黙的密度の違いを確認できる。

`code/main.py` を実行すると、2000サンプルを2モードのガウス混合から生成し、次を出力する：

```
explicit density (histogram): p(x in [-0.5, 0.5]) ≈ 0.38
approximate density (KDE):     p(x in [-0.5, 0.5]) ≈ 0.41
implicit (nearest-sample gen): 20 new samples printed, no p(x)
```

注目してほしいのは：最初の2つは「この点はどれほどありそうか？」と問えること。3つ目はできない。これが以降のすべてのレッスンで重要になる*明示的対暗黙的*の区別だ。

## 使ってみる

2026年において、どのファミリーがどのタスクに最適か？

| タスク | 最適ファミリー | 理由 |
|------|-------------|-----|
| フォトリアルな顔、狭いドメイン | StyleGAN 2/3 | 最も鮮明、最速の推論。 |
| 汎用テキスト→画像 | 潜在拡散＋フローマッチング | SD3、Flux.1、DALL-E 3。 |
| 高速テキスト→画像 | Rectified flow＋蒸留 | SDXL-Turbo、SD3-Turbo、LCM。 |
| テキスト→動画 | 拡散Transformer＋フローマッチング | Sora、Veo 2、Kling。 |
| 音声＋音楽 | トークンベースAR（AudioLM、VALL-E、MusicGen）またはフローマッチング（AudioCraft 2） | 離散トークンは安価にスケールする。 |
| 3Dシーン | Gaussian Splattingフィット、拡散プライア | 3D-GSは再構成用、拡散は新視点合成用。 |
| 密度推定（サンプリング不要） | フロー | `log p(x)` が正確なのはこのファミリーだけ。 |
| シミュレーション / 物理 | フローマッチング、スコアSDE | 直線的なパス、滑らかなベクトル場。 |

## 演習

1. **易。** 以下の5つの製品それぞれについて、ファミリーとバックボーンを特定せよ：ChatGPT image、Midjourney v7、Sora、Runway Gen-3、ElevenLabs。根拠は公開されている技術レポートから。
2. **中。** 明日読む予定の論文が「拡散より100倍速いサンプリング」を主張しているとする。条件付けと高解像度でその高速化が維持されるかを確認するための3つの質問を書き下せ。
3. **難。** 自分が興味のあるドメイン（タンパク質構造、CAD、分子、軌跡など）を1つ選べ。そのドメインの現在のSOTAモデルに対して5つの質問トリアージに答え、より優れたモデルが何を変えるかをスケッチせよ。

## キーワード

| 用語 | 一般的な言い方 | 実際の意味 |
|------|-----------------|-----------------------|
| 生成モデル | 「新しいものを作る」 | `p_data(x)` のサンプラーを学習し、オプションで `log p(x)` を公開する。 |
| 明示的密度 | 「評価できる」 | モデルが閉形式または計算可能な `log p(x)` を提供する。 |
| 暗黙的密度 | 「GAN式」 | サンプラーのみ——与えられた点の `p(x)` を評価する方法がない。 |
| ELBO | 「証拠下限」 | `log p(x)` の計算可能な下限；VAEと拡散はこれを最適化する。 |
| スコア | 「対数密度の勾配」 | `∇_x log p(x)`；拡散とSDEモデルはこの場を学習する。 |
| 多様体仮説 | 「データは表面上にある」 | 高次元データは低次元多様体上に集中する；次元削減が機能する理由。 |
| 自己回帰 | 「次の要素を予測する」 | 結合分布を条件付き分布の積として因子分解する。 |
| 潜在変数 | 「圧縮コード」 | デコーダが入力を再構成できる低次元表現。 |

## プロダクションノート：5つのファミリー、5つの推論形状

各ファミリーは異なる推論サーバーのコストカーブに対応する。プロダクション推論の文献ではLLM推論をプリフィル＋デコードとして説明するが、同じ分解がここでも適用できる：

- **自己回帰（バケット1と5）。** 逐次的なデコードがレイテンシを支配する；KVキャッシュ、連続バッチング、投機的デコーディングはすべてそのまま適用できる。
- **VAE / 拡散 / フローマッチング（バケット2と4）。** LLM的な意味のデコードはない。コスト = `ステップ数 × ステップコスト`、`ステップコスト` はフル潜在解像度でのTransformerまたはU-Netのフォワードだ。プロダクションの調整ノブは、ステップ数（DDIM / DPM-Solver / 蒸留）、バッチサイズ、精度（bf16 / fp8 / int4）だ。
- **GAN（バケット3）。** 1回のフォワードパス。スケジュールなし、KVキャッシュなし。TTFT ≈ 総レイテンシ。これがStyleGANが狭いドメインのUXで依然として勝っている理由だ。

論文アブストラクトに「拡散より高速」とあれば、「ステップ数が少ない × 同じステップコスト」または「同じステップ数 × 安いステップコスト」と読み替えること。それ以外はマーケティングだ。
