# フローマッチングとRectified Flow

> 拡散モデルはノイズからデータへの曲がったパスを歩くため、20〜50のサンプリングステップが必要だ。フローマッチング（Lipman et al.、2023）とRectified Flow（Liu et al.、2022）は直線パスを訓練した。直線パスはより少ないステップを意味し、より速い推論を意味する。Stable Diffusion 3、Flux.1、AudioCraft 2はすべて2024年にフローマッチングに切り替えた。


## 問題

DDPMの逆プロセスは `N(0, I)` からデータ分布への1,000ステップの確率的歩行だ。DDIMはそれを20〜50ステップの決定論的ステップに縮めた。さらに少ないステップが欲しい——理想的には1ステップ。ブロッカーは逆プロセスを解くODEが硬いことだ；パスが曲がっている。

ノイズからデータへのパスが*直線*になるようモデルを訓練できれば、`t=1` から `t=0` への単一のオイラーステップで機能するだろう。フローマッチングはこれを直接構築する：`x_1 ∼ N(0, I)` から `x_0 ∼ data` への直線補間を定義し、その時間微分にマッチするベクトル場 `v_θ(x, t)` を訓練し、推論時に積分する。

Rectified Flow（Liu 2022）はさらに進む：パスを反復的に直線化する再フロー手順で、徐々に直線に近いODEを生成する。2回の再フローイテレーションの後、2ステップサンプラーが50ステップのDDPM品質にマッチする。

## 概念

![フローマッチング：ノイズとデータ間の直線補間](../assets/flow-matching.svg)

### 直線フロー

定義する：

```
x_t = t · x_1 + (1 - t) · x_0,   t ∈ [0, 1]
```

ここで `x_0 ~ data`、`x_1 ~ N(0, I)`。この直線に沿った時間微分は定数だ：

```
dx_t / dt = x_1 - x_0
```

ニューラルベクトル場 `v_θ(x_t, t)` を定義し、この微分にマッチするよう訓練する：

```
L = E_{x_0, x_1, t} || v_θ(x_t, t) - (x_1 - x_0) ||²
```

これが**条件付きフローマッチング**損失（Lipman 2023）だ。訓練はシミュレーション不要：ODEをアンロールしない。単に `(x_0, x_1, t)` をサンプリングして回帰する。

### サンプリング

推論時に、学習済みベクトル場を時間*逆向き*に積分する：

```
x_{t-Δt} = x_t - Δt · v_θ(x_t, t)
```

`x_1 ~ N(0, I)` から始め、`t=0` まで欧風ステップする。

### Rectified Flow（Liu 2022）

直線フローは機能するが学習されたパスは*実際には直線でない*——多くの `x_0` が同じ `x_1` にマッピングできるため曲がる。Rectified Flowの再フローステップ：

1. ランダムペアリングでフローモデル v_1 を訓練する。
2. N組の `(x_1, x_0)` を v_1 を `x_1` から着地点 `x_0` まで積分してサンプリングする。
3. それらのペアの例で v_2 を訓練する。ペアが「ODE対応」なので、それらの間の直線補間は本当により平坦だ。
4. 繰り返す。

実際には2回の再フローイテレーションでほぼ線形になり、2〜4ステップの推論を可能にする。SDXL-Turbo、SD3-Turbo、LCMはすべてフローマッチングモデルから蒸留されている。

### 2024年に画像でこれが勝った理由

3つの理由：

1. **シミュレーション不要の訓練**——訓練中にODEをアンロールしない、実装が自明。
2. **より良い損失の幾何学**——直線パスはスケジュールの端で信号対ノイズ比が一定；DDPM ε損失はスケジュールの端でSNRが悪い。
3. **より速い推論**——SDXL-Turbo品質で4〜8ステップ；Consistency蒸留で1ステップ。

## フローマッチング対DDPM——正確な関係

ガウス条件付きパスを持つフローマッチングは*特定のノイズスケジュールを持つ*拡散だ。`x_t = α(t) x_0 + σ(t) x_1` スケジュールを選ぶと、フローマッチングは `v = α'·x_0 - σ'·x_1` を持つStratonovich再定式化の拡散を回復する。2つはガウスパスで代数的に等価だ。

フローマッチングが追加したもの：ターゲット（単純な速度）の*明確さ*、よりクリーンな損失、非ガウス補間を実験するライセンス。

## 実装する

`code/main.py` は2モードガウス混合に対する1次元フローマッチングを実装する。ベクトル場 `v_θ(x, t)` は直線ターゲットで訓練された小さなMLPだ。推論時に1、2、4、20のオイラーステップを積分してサンプル品質を比較する。

### ステップ1：訓練損失

```python
def train_step(x0, net, rng, lr):
    x1 = rng.gauss(0, 1)
    t = rng.random()
    x_t = t * x1 + (1 - t) * x0
    target = x1 - x0
    pred = net_forward(x_t, t)
    loss = (pred - target) ** 2
    # backprop + update
```

### ステップ2：マルチステップ推論

```python
def sample(net, num_steps):
    x = rng.gauss(0, 1)
    for i in range(num_steps):
        t = 1.0 - i / num_steps
        dt = 1.0 / num_steps
        x -= dt * net_forward(x, t)
    return x
```

### ステップ3：ステップ数を比較する

4ステップサンプラーが既に20ステップ品質にマッチすることを期待する——レイテンシにとって大きなことだ。

## 落とし穴

- **時間パラメータ化。** フローマッチングは `t ∈ [0, 1]`（`t=0` がデータ、`t=1` がノイズ）を使う。DDPMは `t ∈ [0, T]`（`t=0` がデータ、`t=T` がノイズ）を使う。同じ方向、異なるスケール。論文はこれを常に間違える。
- **スケジュールの選択。** Rectified Flowの直線は「ザ」フローマッチングスケジュールだが、より良いスケール網羅のためにコサインまたはlogit-正規 t-サンプリング（SD3がこれをする）を使える。
- **再フローのコスト。** 再フロー用のペアデータセットを生成するにはサンプルごとに完全な推論パスが必要だ。本当に1〜2ステップ推論が必要な場合にのみ再フローを行う。
- **Classifier-free guidanceは依然として適用される。** 線形結合でεをvに交換するだけ：`v_cfg = (1+w) v_cond - w v_uncond`。

## 演習

1. **易。** `code/main.py` を実行して1ステップ対20ステップのMSE対真のデータ分布を比較する。
2. **中。** 均一な `t` サンプリングをlogit-正規（中間 t にサンプリングを集中）に切り替える。モデル品質は向上するか？
3. **難。** 1回の再フローイテレーションを実装する：最初のモデルを積分してペア (x_0, x_1) を生成し、ペアで2番目のモデルを訓練し、1ステップサンプル品質を比較する。

## キーワード

| 用語 | 一般的な言い方 | 実際の意味 |
|------|-----------------|-----------------------|
| フローマッチング | 「直線拡散」 | 補間に沿って `x_1 - x_0` にマッチするよう `v_θ(x, t)` を訓練する。 |
| Rectified Flow | 「再フロー」 | 学習済みフローを直線化する反復手順。 |
| 速度場 | "v_θ" | モデルの出力——`x_t` を動かす方向。 |
| 直線補間 | 「パス」 | `x_t = (1-t)·x_0 + t·x_1`；自明なターゲット微分。 |
| オイラーサンプラー | 「1次ODEソルバー」 | 最も単純な積分器；パスが直線のとき良く機能する。 |
| logit-正規 t | 「SD3サンプリング」 | 勾配が最も強い中間値に向けて `t` サンプリングを集中する。 |
| Consistency蒸留 | 「1ステップサンプラー」 | 任意の `x_t` を `x_0` に直接マッピングする生徒を訓練する。 |
| 速度付きCFG | 「v-CFG」 | `v_cfg = (1+w) v_cond - w v_uncond`；同じトリック、新しい変数。 |

## プロダクションノート：Flux.1-schnellは最速のフローマッチングだ

フローマッチングのプロダクションでの勝利はFlux.1-schnell——1〜4推論ステップに蒸留されながらFlux-dev品質を保持するフローマッチングDiTだ。Nielsの「8GBマシンでFluxを実行する」ノートブックがリファレンスのデプロイメントレシピだ：T5 + CLIPエンコード、量子化されたMMDiTのデノイズ（devの50対schnellの4ステップ）、VAEデコード。コスト計算：

| バリアント | ステップ | L4での1024²のレイテンシ | 総FLOPs（相対） |
|---------|-------|------------------------|------------------------|
| Flux.1-dev（生） | 50 | 約15秒 | 1.0× |
| Flux.1-schnell | 4 | 約1.2秒 | 0.08×（12倍速い） |
| SDXL-base | 30 | 約4秒 | 0.25× |
| SDXL-Lightning 2ステップ | 2 | 約0.3秒 | 0.03× |

プロダクションのルール：**フローマッチングベース＋蒸留 = 2026年の高速テキスト→画像のデフォルト。** すべての主要ベンダーがこの組み合わせを出荷する：SD3-Turbo（SD3 + フロー + 蒸留）、Flux-schnell（Flux-dev + Rectified Flow直線化）、CogView-4-Flash。純粋な拡散ベースはレガシーチェックポイントにのみ存在する。
