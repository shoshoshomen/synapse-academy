# 3D生成

> 3Dは2D→3Dのレバレッジが最も強いモダリティだ。2023年のブレークスルーは3D Gaussian Splattingだった。2024〜2026年の生成的な推進力は、単一のプロンプトまたは写真からオブジェクトとシーンを生成するために、マルチビュー拡散＋3D再構成をその上に重ねた。


## 問題

3Dコンテンツは厄介だ：

- **表現。** メッシュ、点群、ボクセルグリッド、符号付き距離場（SDF）、ニューラルラジアンスフィールド（NeRF）、3Dガウシアン。それぞれにトレードオフがある。
- **データの希少性。** ImageNetには1,400万枚の画像がある。最大のクリーンな3Dデータセット（Objaverse-XL、2023）には約1,000万のオブジェクトがあるが、ほとんど品質が低い。
- **メモリ。** 512³のボクセルグリッドは1.28億ボクセル；有用なシーンNeRFはレイあたり100万サンプルが必要だ。生成は再構成より難しい。
- **教師信号。** 2D画像ではピクセルがある。3Dでは通常少数の2Dビューしかなく、3Dにリフトしなければならない。

2026年のスタックは2つの問題を分離する。まず、拡散モデルで*2Dマルチビュー画像*を生成する。次に、それらの画像に*3D表現*（通常はGaussian splatting）をフィットさせる。

## 概念

![3D生成：マルチビュー拡散＋3D再構成](../assets/3d-generation.svg)

### 表現：3D Gaussian Splatting（Kerbl et al.、2023）

シーンを約100万の3Dガウシアンのクラウドとして表現する。各ガウシアンは59個のパラメータを持つ：位置（3）、共分散（6、または四元数4＋スケール3）、不透明度（1）、球面調和カラー（次数3で48、次数0で3）。

レンダリング = 投影＋アルファ合成。高速（4090で1080pで約100fps）。微分可能。グラウンドトゥルース写真に対する勾配降下法でフィット。シーンのフィットはコンシューマGPUで5〜30分。

上に積み重ねた2つの2023〜2024年のイノベーション：
- **生成的ガウシアンスプラット。** LGM、LRM、InstantMeshなどのモデルが1枚または数枚の画像からガウシアンクラウドを直接予測する。
- **4D Gaussian Splatting。** 動的シーン用のフレームごとのオフセット付きガウシアン。

### マルチビュー拡散

事前学習済みの画像拡散モデルをファインチューンして、テキストプロンプトまたは単一の画像から同じオブジェクトの複数の一貫したビューを生成する。Zero123（Liu et al.、2023）、MVDream（Shi et al.、2023）、SV3D（Stability、2024）、CAT3D（Google、2024）。通常オブジェクトの周りに4〜16のビューを出力し、Gaussian splattingまたはNeRFで3Dにリフトする。

### NeRF（文脈のため）

ニューラルラジアンスフィールド（Mildenhall et al.、2020）。小さなMLPが `(x, y, z, 視点方向)` を取り、`(色、密度)` を出力する。レイを統合してレンダリングする。品質ではメッシュベースの新規視点合成を上回るが、レンダリングが100〜1000倍遅い。リアルタイム用途のほとんどでGaussian splattingに置き換えられたが、リサーチでは依然として主流。

## 実装する

`code/main.py` はおもちゃの2D「Gaussian splatting」フィットを実装する：合成ターゲット画像（スムーズなグラジエント）を2Dガウシアンスプラットの和として表現する。ターゲットにマッチするよう勾配降下法で位置、色、共分散を最適化する。2つの中核的な操作を見る：フォワードレンダリング（スプラット＋アルファ合成）と勾配降下法によるフィット。

### ステップ1：2Dガウシアンスプラット

```python
def gaussian_at(x, y, gaussian):
    px, py = gaussian["pos"]
    sigma = gaussian["sigma"]
    d2 = (x - px) ** 2 + (y - py) ** 2
    return math.exp(-d2 / (2 * sigma * sigma))
```

### ステップ2：スプラットを合算してレンダリング

```python
def render(image_size, gaussians):
    img = [[0.0] * image_size for _ in range(image_size)]
    for g in gaussians:
        for y in range(image_size):
            for x in range(image_size):
                img[y][x] += g["color"] * gaussian_at(x, y, g)
    return img
```

本物の3D Gaussian splattingは深度でガウシアンをソートしてアルファ合成する。おもちゃの2Dは単純に合算する。

### ステップ3：勾配降下法でフィット

```python
for step in range(steps):
    pred = render(size, gaussians)
    loss = mse(pred, target)
    gradients = compute_grads(pred, target, gaussians)
    update(gaussians, gradients, lr)
```

## 落とし穴

- **ビューの不整合。** 4つのビューを独立して生成し、それらがオブジェクト構造について異なる場合、3Dフィットはぼやける。修正：共有アテンションを持つマルチビュー拡散。
- **裏側の幻覚。** 単一画像→3Dは見えない側を発明しなければならない。品質は大きく異なる。
- **ガウシアンスプラットの爆発。** 制約のない訓練は1,000万スプラットに成長して過学習する。元の3D-GS論文からの密度化＋刈り取りヒューリスティックが必須だ。
- **トポロジーの問題。** 暗黙的フィールド（SDF）からのメッシュには穴や自己交差が多い。出荷前にリメッシャー（例：blenderのボクセルリメッシュ）を実行する。
- **訓練データのライセンス。** Objaverseのライセンスは混在している；商用使用はモデルごとに異なる。

## プロダクションノート：3Dにはまだ共通の基盤がない

画像（潜在拡散＋DiT）や動画（時空間DiT）とは異なり、3Dには2026年において単一の支配的なランタイムがない。プロダクションの決定木は表現で分岐する：

- **NeRF / トリプレーン。** 推論はレイマーチング＋サンプルあたりのMLPフォワード。512²のレンダリングには何百万ものMLPフォワードが必要だ。レイサンプルを積極的にバッチ；SDPA/xformersが適用できる。
- **マルチビュー拡散＋LRM再構成。** 2ステージパイプライン。ステージ1（マルチビューDiT）はレッスン07と同じ拡散サーバー。ステージ2（LRM Transformer）はビュー上での1ショットフォワードパス。全体のレイテンシプロファイルは「拡散＋1ショット」——ステージごとのサービングプリミティブを選ぶ。
- **SDS / DreamFusion。** リクエストハンドラではなく、ジョブ単位の最適化。バッチジョブ、リクエストハンドラではない。

ほとんどの2026年のプロダクションでは、正解は「リクエスト時にマルチビュー拡散モデルを実行し、非同期的に3DGSに再構成し、リアルタイム表示のために3DGSを提供する」ことだ。これはGPU推論サーバー（速い）とオフライン最適化器（遅い）の間でワークロードをきれいに分割する。
