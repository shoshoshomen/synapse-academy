# エージェントフレームワークのトレードオフ — LangGraph vs CrewAI vs AutoGen vs Agno

> どのフレームワークも同じデモを売り込む（リサーチエージェントがレポートを作る）し、同じバグを隠す（状態スキーマがオーケストレーション層と衝突する）。自分の問題の形状に合った抽象化を持つフレームワークを選べ; それ以外はすべて二度書くグルーコードだ。


## 問題

複数のLLM呼び出しを必要とするタスクがある。リサーチワークフロー（計画、検索、要約、引用）かもしれない。コードレビューパイプライン（差分解析、批評、パッチ、検証）かもしれない。フライトの予約、メールの作成、経費精算を行うマルチターンアシスタントかもしれない。フレームワークを選ぶ。

3日後、フレームワークの抽象化が漏れていることに気づく。CrewAIはロールを提供してくれるが、「リサーチャー」が「ライター」に構造化されたプランを渡す必要があるときに立ちはだかる。AutoGenはエージェント間のチャットを提供してくれるが、ファーストクラスの状態がないため、チェックポイントが会話ログのpickleになる。LangGraphは状態グラフを提供してくれるが、エージェントが何をするかわからないうちにすべての遷移に名前をつけるよう強制する。Agnoは単一エージェント抽象化を提供してくれるが、3つのワーカーに並列ファンアウトしようとすると悲鳴を上げる。

解決策は「最良のフレームワークを選ぶ」ことではない。フレームワークのコア抽象化を問題の形状に合わせることだ。このレッスンでそのマップを描く。

## 概念

![エージェントフレームワークマトリクス: コア抽象化と問題の形状](../assets/framework-matrix.svg)

2026年の状況では4つのフレームワークが主流だ。それらのコア抽象化は同じではない。

| フレームワーク | コア抽象化 | ベストフィット | ワーストフィット |
|---------------|------------|--------------|----------------|
| **LangGraph** | `StateGraph` — 型付き状態、ノード、条件付きエッジ、チェックポインター。 | 明示的な状態とヒューマンインザループ割り込みを持つワークフロー; タイムトラベルデバッグを必要とする本番エージェント。 | トポロジーが不明な、ゆるいロール駆動のブレインストーミング。 |
| **CrewAI** | `Crew` — ロール（目標、バックストーリー）、タスク、プロセス（シーケンシャルまたは階層的）。 | 短い線形/階層的プランを持つロールプレイングやペルソナ駆動のワークフロー。 | クルーのターン履歴を超えるステートフルなもの; 複雑な分岐。 |
| **AutoGen** | `ConversableAgent` ペア — 終了条件になるまでターンごとに話す2つ以上のエージェント。 | 思考がチャットから生まれるマルチエージェント*ダイアローグ*（教師-生徒、提案者-批評家、アクター-レビュアー）。 | 既知のDAGを持つ決定論的ワークフロー; 再起動間で耐久性のある状態を必要とするもの。 |
| **Agno** | `Agent` — 単一のLLM + ツール + メモリ、チームへの合成可能。 | 素早く構築できる単一エージェントと軽量チーム; 強力なマルチモダリティと組み込みストレージドライバー。 | カスタムリデューサーを持つ深く明示的に分岐したグラフ。 |

### 「抽象化」が実際に意味すること

フレームワークのコア抽象化とは、アーキテクチャをピッチするときにホワイトボードに描くものだ。

- **LangGraph** → グラフを描く。ノードはステップ、エッジは遷移、各ポイントの状態オブジェクトは型付きだ。メンタルモデルはステートマシン。
- **CrewAI** → 組織図を描く。各ロールは職務記述書を持ち、マネージャーがタスクをルーティングする。メンタルモデルは専門家の小チーム。
- **AutoGen** → Slack DMを描く。2つのエージェントが互いにメッセージを送り合い、モデレーターが必要なら3つ目が加わる。メンタルモデルはチャット。
- **Agno** → ツールをぶら下げた単一のボックスを描く。チームのためにボックスを並べる。メンタルモデルは「バッテリー同梱のエージェント」。

### 状態の問題

状態は、本番でほとんどのフレームワーク選択が崩れる場所だ。

- **LangGraph。** 型付き状態（`TypedDict` またはPydanticモデル）、フィールドごとのリデューサー、ファーストクラスのチェックポインター（SQLite/Postgres/Redis）。再開、割り込み、タイムトラベルが無料でつく。*（フェーズ11・16参照。）*
- **CrewAI。** 状態は `context` フィールドを通じてタスク間を文字列として流れるか、`output_pydantic` を通じて構造化される。クルーが再起動を生き残らなければならない場合、ボルトオンが必要; すぐに使えるクルーごとの耐久ストアはない。
- **AutoGen。** 状態はチャット履歴とユーザー定義の `context`。会話トランスクリプトは永続化される; アダプターを書かない限り、任意のワークフロー状態は永続化されない。
- **Agno。** `storage=` を通じて `Agent` にアタッチされた組み込みストレージドライバー（SQLite、Postgres、Mongo、Redis、DynamoDB）—— 会話セッションとユーザーメモリが自動的に永続化される。完全なグラフチェックポインターではなく、セッションストア。

### 分岐の問題

すべての非自明なエージェントは分岐する。誰が分岐を決めるかが重要だ。

- **LangGraph** — あなたが決める、条件付きエッジを通じて。ルーティングは名前付き分岐を持つPython関数だ。分岐はコンパイル済みグラフでファーストクラス; チェックポインターはどの分岐が取られたかを記録する。
- **CrewAI** — 階層モードではマネージャーが決める; シーケンシャルモードではビルド時にあなたが決める。ルーティングはタスクリストに暗黙的; マネージャーのプロンプトの外にファーストクラスの「if」はない。
- **AutoGen** — エージェントがチャットを通じて決める。分岐は誰が次に話すかから創発する。`GroupChatManager` が次のスピーカーを選択する; `speaker_selection_method` を手書きできるが、デフォルトはLLM駆動だ。
- **Agno** — エージェントが次に呼び出すツールを決める。チームにはコーディネーター/ルーター/コラボレーターモードがある; それを超えた分岐は開発者の責任だ。

### オブザーバビリティの問題

- **LangGraph** — LangSmithまたは任意のOTelエクスポーター経由のOpenTelemetry。すべてのノード遷移はトレーススパン; チェックポイントはリプレイ可能なトレースとして機能する。LangSmithはファーストパーティオプション; Langfuse/Phoenixもアダプターを持つ。
- **CrewAI** — 2025年末以降のファーストクラスOpenTelemetry; Langfuse、Phoenix、Opik、AgentOpsとの統合。
- **AutoGen** — `autogen-core` 経由のOpenTelemetry統合; AgentOpsとOpikにコネクターあり。トレースの粒度はノードごとではなくエージェントメッセージごと。
- **Agno** — 組み込みの `monitoring=True` フラグとOpenTelemetryエクスポーター; セッショントレースのためのLangfuseとのタイトな統合。

### コストとレイテンシ

4つのフレームワークはすべて呼び出しごとのオーバーヘッド（フレームワークロジック、バリデーション、シリアライゼーション）を追加する。オーバーヘッドの増加順の概算: Agno ≈ LangGraph < CrewAI ≈ AutoGen。差はフレームワークが行う追加のLLMルーティングの量によって支配される。CrewAIの階層マネージャーは誰が次に行くかを決めるためにトークンを費やす; AutoGenの `GroupChatManager` も同様だ。LangGraphは `llm.invoke` を書いた場所でのみトークンを費やす。Agnoの単一エージェントパスは薄い。

実行ごとのコストが重要な場合、LLM選択ルーティング（LangGraphエッジ、AutoGenの `speaker_selection_method`）よりも明示的なルーティングを好む。

### 相互運用性

- **LangGraph** ↔ **LangChain** ツール、リトリーバー、LLM。ファーストクラスのMCPアダプター（MCPサーバーとしてインポートされたツール）。
- **CrewAI** ↔ ツールは `BaseTool` を継承する; LangChainツール、LlamaIndexツール、MCPツールはすべてアダプターで対応。`allow_delegation=True` によるCrew間委任。
- **AutoGen** → `FunctionTool` が任意のPython callableをラップする; MCPアダプター利用可能。エージェント間パターンのAG2エコシステムとの密結合。
- **Agno** → `@tool` デコレーターまたはBaseToolサブクラス; MCPアダプター; ツールはエージェントとチーム間で共有可能。

## スキル

> 与えられたエージェント問題に対して特定のフレームワークがなぜ正しいかを1文で説明できる。

構築前チェックリスト:

1. **形状を描く。** これはグラフ（型付き状態、名前付き遷移）か? ロールプレイ（専門家が仕事を引き渡す）か? チャット（エージェントが終わるまで話す）か? ツールを持つ単一エージェントか?
2. **誰が分岐するかを決める。** 開発者決定の分岐 → LangGraph。マネージャーエージェント決定 → CrewAI階層的。チャット創発 → AutoGen。ツール呼び出し決定 → Agno。
3. **状態バジェットを確認する。** チェックポイントからの再開が必要か? タイムトラベルは? 実行途中での人間の割り込みは? もしそうなら、LangGraphがデフォルト; Agnoセッションは会話スコープの状態をカバーする。
4. **コストバジェットを確認する。** LLM選択ルーティングはターンごとに追加トークンを費やす。エージェントが1日に何千回も実行される場合、明示的なルーティングを好む。
5. **フレームワークのオーバーヘッドを予算に入れる。** すべてのフレームワークはもう1つの依存関係だ。タスクが2つのLLM呼び出しと1つのツールなら、30行の普通のPythonを書く; フレームワークなしよりも安いフレームワークはない。

グラフ、組織図、チャット、またはエージェントボックスを描けるようになる前にフレームワークに手を伸ばすことを拒否する。実際に必要なものに対してその状態モデルと戦うことを強いるものを選ぶことを拒否する。

## 判断マトリクス

| 問題の形状 | 推奨フレームワーク | 理由 |
|-----------|-----------------|------|
| 型付き状態、人間の承認、長時間実行のワークフローDAG | LangGraph | ファーストクラスの状態、チェックポインター、割り込み、タイムトラベル。 |
| 異なるロールを持つリサーチ/ライティングパイプライン | CrewAI（シーケンシャル）またはLangGraphサブグラフ | タスクごとのロールはCrewAIで安価に表現できる; 分岐が複雑になったらLangGraphにスケールアップ。 |
| 提案者-批評家または教師-生徒ダイアローグ | AutoGen | 2エージェントチャットがその自然な形状。 |
| ツール、セッション、メモリを持つ単一エージェント | Agno | 最薄のセットアップ、組み込みのストレージとメモリ。 |
| リデューサーを持つ数千の並列ファンアウト | LangGraph + `Send` | ファーストクラスの並列ディスパッチAPIを持つ唯一のもの。 |
| クイックプロトタイプ、フレームワークへのコミットなし | 普通のPython + プロバイダーSDK | フレームワークなしが最も速いフレームワーク。 |

## 演習

1. **Easy（簡単）。** 同じタスク——「Anthropicの本社をリサーチして200ワードのブリーフを書き、ソースを引用する」——をLangGraph（4ノード: plan、search、write、cite）とCrewAI（3ロール: リサーチャー、ライター、エディター）で実装する。実行ごとのトークンコストとコード行数を報告する。
2. **Medium（中級）。** 同じタスクをAutoGen（リサーチャー ↔ ライターチャット、エディターが `GroupChat` 経由で参加）とAgno（`search_tools` と `write_tools` を持つ単一エージェントにセッションストアを追加）で構築する。4つの実装を(a)実行ごとのコスト、(b)クラッシュ後の再開能力、(c)書き込みステップ前に人間の承認を注入する能力でランク付けする。
3. **Hard（上級）。** 短い問題の説明（JSON: `{has_typed_state, has_roles, has_dialogue, has_parallel_fanout, needs_resume}`）を受け取り、1文の理由とともに推奨を返す決定ツリースクリプト `pick_framework.py` を構築する。自分で設計した6つのケースで検証する。

## キーワード

| 用語 | よく言われる表現 | 実際の意味 |
|------|-----------------|-----------------------|
| オーケストレーション | 「エージェントの調整方法」 | 次に実行するノード/ロール/エージェントを決めるレイヤー。 |
| 耐久状態 | 「再起動後の再開」 | プロセスの死を生き残る状態、チェックポイントまたはセッションストアにアタッチされる。 |
| LLM選択ルーティング | 「モデルに決めさせる」 | プランナーLLMがターンごとに次のステップを選ぶ; 柔軟だが毎回の決定でトークンを払う。 |
| 明示的ルーティング | 「開発者が決める」 | Python関数または静的エッジが次のステップを選ぶ; 安価で監査可能。 |
| クルー | 「CrewAIのチーム」 | ロール + タスク + プロセス（シーケンシャルまたは階層的）が単一の実行可能なものに束ねられる。 |
| GroupChat | 「AutoGenのマルチエージェントチャット」 | スピーカーセレクターを持つN個のエージェント間の管理された会話。 |
| チーム（Agno） | 「マルチエージェントAgno」 | エージェントセットのルート/コーディネート/コラボレートモード。 |
| StateGraph | 「LangGraphのグラフ」 | 型付き状態、ノード、条件付きエッジ、チェックポインター抽象化。 |
