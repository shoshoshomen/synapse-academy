# 人間参加型：提案-コミット

> 2026年のHITLに関するコンセンサスは具体的だ。「エージェントが聞いて、ユーザーが承認をクリックする」ではない。それは提案-コミットだ：提案されたアクションは冪等キーを持つ永続ストアに保持され；意図、データリネージ、触れた権限、ブラストラジウス、ロールバック計画をレビュアーに提示され；肯定的な確認後のみコミットされ；実行後に副作用が実際に発生したか確認される。LangGraphの`interrupt()`とPostgreSQLチェックポイント、Microsoft Agent Frameworkの`RequestInfoEvent`、Cloudflareの`waitForApproval()`はすべて同じ形を実装している。標準的な失敗モードはゴムスタンプ承認だ：「承認？」はレビューなしにクリックされる。文書化された軽減策は明示的なチェックリストによるチャレンジアンドレスポンスだ。


## 問題

エージェントがアクションを取る。ユーザーは決定しなければならない：承認か拒否か。決定が即座なら、おそらくレビューではない。決定が構造化されているなら、遅いが信頼できる。エンジニアリングの問いは、構造化されたレビューを最も抵抗の少ないパスにする方法だ。

2023年代のHITLパターンは同期プロンプトだった：「エージェントはXにYの本文でメールを送りたい——承認？」ユーザーは承認をクリックする。誰もがシステムが安全だと感じる。実際にはこのサーフェスは大量のゴムスタンプが押される：ユーザーは速く承認し、承認はほとんど予測せず、エージェントがおかしくなったとき、監査証跡はユーザーが覚えていない長い承認の履歴を示す。

2026年のパターン——提案-コミット——はHITLを永続的な基板の上に移動し、構造化されたメタデータを添付し、肯定的なコミットを要求する。すべてのマネージドエージェントSDKはバージョンを出荷する：LangGraph `interrupt()`、Microsoft Agent Framework `RequestInfoEvent`、Cloudflare `waitForApproval()`。API名は異なる；形は異ならない。

## コンセプト

### 提案-コミットステートマシン

1. **提案。** エージェントが提案されたアクションを生成する。永続ストア（PostgreSQL、Redis、Durable Object）に保持される。含む：
   - 意図（エージェントがなぜこれをしているか）
   - データリネージ（この提案につながった情報源）
   - 触れた権限（どのスコープ/ファイル/エンドポイント）
   - ブラストラジウス（最悪のケースは何か）
   - ロールバック計画（コミットされた場合、どのように元に戻すか）
   - 冪等キー（提案ごとにユニーク；再提出は同じレコードを返す）
2. **提示。** レビュアーはすべてのメタデータと一緒に提案を見る。レビュアーは人間（エージェント自身がレビューするのではない）。
3. **コミット。** 肯定的な確認。アクションが実行される。
4. **確認。** 実行後、副作用が読み返されて実際に発生したことが確認される。確認ステップが失敗したら、システムは既知の悪い状態にあり、アラートが発動する。

### 冪等キー

冪等キーなしに、一時的な障害後のリトライが承認されたアクションを二重実行できる。具体的な例：ユーザーは「AからBに$100を移動する」を承認する。ネットワークの中断。ワークフローがリトライする。ユーザーは1度承認したが転送が2度実行される。冪等キーは承認を単一のユニークな副作用に結びつける；2度目の実行はノーオペレーションだ。

これはStripeとAWS APIが使用するのと同じ冪等パターンだ。Microsoft Agent Frameworkのドキュメントでエージェントの承認にそれを再利用することを明示している。

### 永続性：承認がプロセスを超えて持続する理由

承認の待合室はエージェントが所有しない状態の部分だ。ワークフローは一時停止される（レッスン12）。承認が届いたとき、ワークフローはその正確なポイントから再開する。これはLangGraphが`interrupt()`とPostgreSQLチェックポイントをペアにする理由だ——2日後の承認はワークフローをインタクトに見つける。

### ゴムスタンプ承認とチャレンジアンドレスポンスの軽減

HITLのデフォルトのUI（「承認」/「拒否」ボタン）は本当のレビューなしに速い承認を生成する。文書化された軽減策：承認ボタンが有効になる前に特定の質問への肯定的な答えを要求するチャレンジアンドレスポンスチェックリスト。具体的な形：

- 「これが触れるリソースを理解していますか？ [ ]」
- 「ブラストラジウムが許容できることを確認しましたか？ [ ]」
- 「失敗した場合のロールバック計画はありますか？ [ ]」

それ自体のための官僚主義ではない——強制的な関数だ。ボックスにチェックできないレビュアーは説明を求めるか（昇格）、拒否する（安全なデフォルト）。Anthropicのエージェント安全研究はゴムスタンプ承認パターンの軽減策としてチェックリスト駆動のHITLを明示的に引用する。

### 重大と見なされるもの

すべてのアクションが提案-コミットを必要とするわけではない。2026年のガイダンス：

- **重大なアクション**（常にHITL）：不可逆な書き込み、金融取引、アウトバウンドコミュニケーション、本番データベースの変更、破壊的なファイルシステム操作。
- **可逆なアクション**（時々HITL）：ローカルファイルへの編集、ステージング環境の変更、明確なロールバックを持つ可逆な書き込み。
- **読み取りと検査**（HITLなし）：ファイルの読み取り、リソースのリスト表示、読み取り専用APIの呼び出し。

### アクション後の確認

「コミットが実行された」は「副作用が発生した」と同じではない。ネットワークのパーティションと競合状態は、成功したと思っているがバックエンドが永続しなかったワークフローを生成できる。確認ステップは実際に副作用が発生したことを確認するために実行後にターゲットリソースを読み返す。これはデータベーストランザクションの`RETURNING`句やAWSの`PutObject`後の`GetObject`と同じパターンだ。

### EU AI Act第14条

第14条はEUの高リスクAIシステムに対して効果的な人間の監視を義務付けている。「効果的」は装飾的ではない。規制言語はゴムスタンプパターンを明示的に除外する。Microsoft Agent Governance Toolkitのコンプライアンスドキュメントで、チャレンジアンドレスポンス付きの提案-コミットは第14条の審査を生き延びる形だ。

## 使ってみる

`code/main.py`はstdlib Pythonで提案-コミットステートマシンを実装する。永続ストアはJSONファイルだ。冪等キーは（thread_id、アクションシグネチャ）のハッシュだ。ドライバーは3つのケースをシミュレートする：クリーンな承認フロー、一時的な障害後のリトライ（二重実行してはいけない）、ゴムスタンプのデフォルト対チャレンジアンドレスポンスフロー。

## 成果物を出す

`outputs/skill-hitl-design.md`は提案されたHITLワークフローを提案-コミットの形でレビューし、欠けているメタデータ、冪等性、確認、またはチャレンジアンドレスポンスレイヤーにフラグを立てる。

## 演習

1. `code/main.py`を実行する。承認された提案のリトライが永続レコードを使用して再実行しないことを確認する。今冪等キーにタイムスタンプを含めてリトライが二重実行することを示す。

2. 提案レコードに`rollback`フィールドを拡張する。確認ステップが失敗する実行をシミュレートする。ロールバックが自動的に発火することを示す。

3. Microsoft Agent Frameworkの`RequestInfoEvent`ドキュメントを読む。おもちゃのエンジンが欠けているAPIが含む1つのメタデータフィールドを特定する。それを追加して、何を保護するかを説明する。

4. 特定のアクションのチャレンジアンドレスポンスチェックリストを設計する（例：「公開Twitterアカウントへの投稿」）。レビュアーが答えなければならない3つの質問は何か？なぜその3つか？

5. 同期「承認？」プロンプトで十分なケース（永続ストア不要）を1つ選ぶ。理由を説明し、受け入れているリスクのクラスに名前をつける。

## キーワード

| 用語 | よく言われること | 実際の意味 |
|---|---|---|
| 提案-コミット | 「2フェーズ承認」 | 永続された提案 + 肯定的なコミット + 確認 |
| 冪等キー | 「リトライセーフトークン」 | 提案ごとにユニーク；2回目の実行はノーオペレーション |
| データリネージ | 「どこから来たか」 | 提案につながった特定の情報源コンテンツ |
| ブラストラジウム | 「最悪のケース」 | アクションがおかしくなった場合の効果の範囲 |
| ゴムスタンプ | 「速い承認」 | 本当のレビューなしにクリックされた「承認」 |
| チャレンジアンドレスポンス | 「強制チェックリスト」 | レビュアーが特定の質問を肯定的に確認しなければならない |
| RequestInfoEvent | 「MS Agent Frameworkプリミティブ」 | 構造化されたメタデータを持つ永続的なHITLリクエスト |
| `interrupt()` / `waitForApproval()` | 「フレームワークプリミティブ」 | 同じ形のLangGraph / Cloudflareの等価物 |
