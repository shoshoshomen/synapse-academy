# アクション予算、イテレーションキャップ、コストガバナー

> 中規模のEコマースエージェントの月次LLMコストが「注文追跡」スキルを有効にした後、$1,200から$4,800に跳ね上がった。それは価格設定のバグではない。それは新しいループを見つけてその中で支出を続けたエージェントだ。Microsoft Agent Governance Toolkit（2026年4月2日）はこのクラスに対する防御を体系化する：リクエストごとの`max_tokens`、タスクごとのトークンとドル予算、1日/月ごとのキャップ、イテレーションキャップ、階層型モデルルーティング、プロンプトキャッシュ、コンテキストウィンドウイング、高価なアクションへのHITLチェックポイント、予算違反時のキルスイッチ。AnthropicのClaude Code Agent SDKは同じプリミティブを異なる名前で出荷する。財務速度制限——例：10分で$50超えたらアクセスをカット——は月次キャップよりも速くループを捕捉する。


## 問題

自律エージェントは毎ターン本物のお金を使う。チャットボットの悪い出力は悪い返信だ；エージェントの悪いループは請求書だ。業界で文書化された失敗モードの用語は「Denial of Wallet」——エージェントは推論し続け、ツールを呼び続け、請求し続け、何も止めない。なぜならその設計がなかったから。

修正は1つの数字ではない。それは異なる時間スケールと粒度での制限のスタックだ：リクエストごと、タスクごと、時間ごと、日ごと、月ごと。よく設計されたスタックは暴走ループを数分以内に捕捉し、緩やかな漏れを数時間以内に、悪いリリースを1日以内に捕捉する。同じスタックはエージェントがロングホライズンで自律的なときにすべての予算を保持する。

これはエンジニアリングのレッスンだ：数学は些細で、規律はチームが失敗するところだ。以下の制限のリストはMicrosoft Agent Governance ToolkitまたはAnthropic Claude Code Agent SDKのドキュメントのいずれかに名前が挙げられている。

## コンセプト

### コストガバナースタック

1. **リクエストごとの`max_tokens`。** シンプル。単一の呼び出しが無制限の補完を発することを防ぐ。
2. **タスクごとのトークン予算。** 実行全体にわたって、Nトークンを超えない。キャップでハードストップ。
3. **タスクごとのドル予算。** トークンと同じだが通貨で。Claude Codeの`max_budget_usd`。
4. **ツール呼び出しごとのキャップ。** `WebFetch`呼び出しはN回以下、`shell_exec`呼び出しはN回以下など。
5. **イテレーションキャップ（`max_turns`）。** エージェントループの総反復数；無限推論ループを防ぐ。
6. **1分/1時間/1日/月ごとのキャップ。** ローリングウィンドウ。異なる時間スケールで漏れを捕捉する。
7. **財務速度制限。** 例：「10分で$50を超えたら、アクセスをカット」。月次キャップが発火する前にループベースの燃焼を捕捉する。
8. **階層型モデルルーティング。** 小さなモデルをデフォルトにする；分類器がタスクにふさわしいと判断した場合のみ大きなモデルに昇格する。
9. **プロンプトキャッシュ。** システムプロンプトと安定したコンテキストをプロバイダーキャッシュに保存；再送信のトークンコストはほぼゼロ。
10. **コンテキストウィンドウイング。** アクティブなコンテキストを閾値以下に保つためのコンパクション/要約；直接的なトークンコスト削減。
11. **高価なアクションへのHITLチェックポイント。** 高価なアクション（長いツール呼び出し、大きなダウンロード、コストのかかるモデルアップグレード）の前に、人間のタップを要求する。
12. **予算違反時のキルスイッチ。** いずれかのキャップが発火するとセッションが中止される。キャップが記録され；個別の再有効化パスが必要だ。

### スタック、1つのキャップではない理由

単一の月次キャップは財布がなくなってからのみ暴走エージェントを捕捉する。単一のリクエストごとのキャップはセッションレベルで何も捕捉しない。異なる失敗モードは異なる時間スケールを必要とする：

- **暴走ループ**（5秒のリトライでスタックしたエージェント）：速度制限で捕捉。
- **緩やかな漏れ**（タスクごとに期待の約2倍の作業をするエージェント）：日次キャップで捕捉。
- **悪いリリース**（新しいバージョンが5倍のトークンを使用）：週次/月次キャップで捕捉。
- **正当なサージ**（バグではなく実際の需要）：明確なログを持つ時間/日次キャップで捕捉。

### Claude Codeの予算サーフェス

Claude Code Agent SDKが公開している（公開ドキュメント）：

- `max_turns` — イテレーションキャップ。
- `max_budget_usd` — ドルキャップ；違反でセッションが中止。
- `allowed_tools` / `disallowed_tools` — ツールアローリストとデナイリスト。
- カスタムコストアカウンティングのためのツール使用前のフックポイント。

権限モードのはしご（レッスン10）と組み合わせる。`max_budget_usd`なしの`autoMode`セッションは管理されていない自律性だ。Anthropicはオートモードが予算コントロールを必要とすると明示的にフレーミングしている；分類器はコストとは直交する。

### EU AI Act、OWASP Agentic Top 10

Microsoft Agent Governance ToolkitはOWASP Agentic Top 10とEU AI Act第14条（人間による監視）の要件をカバーしている。EUでの本番では、ロギングとキャップの適用はオプションではない。

### 観察された$1,200 → $4,800のケース

Microsoftのドキュメントの実際のケース：新しいツールが追加された後に月次コストが3倍になったEコマースエージェント。ツールはすべてのセッション中に注文状態をポーリングすることを許可した。ループ検出なし。ツールごとのキャップなし。週次成長への警告なし。修正はツールごとのキャップと日次成長アラートだった。これはテンプレート：すべての新しいツールサーフェスは新しい潜在的なループ；すべての新しいツールには独自のキャップと独自のアラートが必要だ。

## 使ってみる

`code/main.py`は重ねられたコストガバナースタックありとなしでエージェント実行をシミュレートする。シミュレートされたエージェントは数ターン後にポーリングループにドリフトする；重ねられたスタックは速度ウィンドウ内で捕捉し、一方で単一の月次キャップは数日後まで発火しない。

## 成果物を出す

`outputs/skill-agent-budget-audit.md`は提案されたエージェント展開のコストガバナースタックを監査し、欠けているレイヤーにフラグを立てる。

## 演習

1. `code/main.py`を実行する。速度制限がポーリングループ軌跡でイテレーションキャップの前に発火することを確認する。次に速度制限を無効にして、イテレーションキャップがそれを捕捉するまでエージェントが「使う」額を測定する。

2. ブラウザエージェント（レッスン11）のツールごとのキャップセットを設計する。どのツールが最も厳しいキャップを必要とするか？どのツールがリスクなしで無制限に実行できるか？

3. Microsoft Agent Governance Toolkitのドキュメントを読む。ツールキットが名前を挙げるすべてのキャップタイプをリストアップする。各失敗モード（暴走ループ、緩やかな漏れ、悪いリリース、サージ）に各キャップをマッピングする。

4. 現実的なタスク（例：「リポジトリの50のイシューをトリアージする」）の一夜の無人実行を価格設定する。`max_budget_usd`をポイント見積もりの2倍に設定する。2倍を正当化する。

5. Claude Codeの`max_budget_usd`はセッション集計コストで発火する。外部で適用する補完的な速度制限を設計する。何がカットオフをトリガーし、再有効化はどのように見えるか？

## キーワード

| 用語 | よく言われること | 実際の意味 |
|---|---|---|
| Denial of Wallet | 「暴走請求書」 | 止めるキャップなしにエージェントループが支出を生成する |
| max_tokens | 「リクエストごとのキャップ」 | 単一の補完のサイズの上限 |
| max_turns | 「イテレーションキャップ」 | セッションのエージェントループ反復の上限 |
| max_budget_usd | 「ドルキルスイッチ」 | セッションコストキャップ；違反で中止 |
| 速度制限 | 「レートキャップ」 | 短いウィンドウごとの支出制限（例：10分で$50） |
| 階層型ルーティング | 「最初に小さなモデル」 | 安価なモデルがデフォルト；分類器がふさわしいと判断した場合のみ昇格 |
| プロンプトキャッシュ | 「キャッシュされたシステムプロンプト」 | プロバイダー側のキャッシュが再送信トークンコストをほぼゼロに削減 |
| HITLチェックポイント | 「人間の承認ゲート」 | 高価なアクションの前に人間のタップが必要 |
