# 自律的コーディングエージェントの全体像（2026年）

> SWE-bench Verifiedは3年も経たないうちに4%から80.9%に達した。同じClaude Sonnet 4.5がSWE-agent v1で43.2%を記録し、Cline自律モードでは59.8%を記録した——モデルを取り巻く足場が今やモデル自体と同じくらい重要だ。OpenHands（旧OpenDevin）は最も活発なMITライセンスのプラットフォームで、CodeActループはJSONツール呼び出しの代わりにサンドボックス内でPythonアクションを直接実行する。トップラインの数字は方法論的な問題を隠している：SWE-bench Verifiedの500タスクのうち161は1〜2行の変更しか必要とせず、同じフロンティアモデルのSWE-bench Pro（10行以上のタスク）は23〜59%だ。


## 問題

「どのコーディングエージェントが最善か」は間違った問いだ。正しい問いは：私の作業に合ったタスク分布で、本番で実行する足場で、どのエンドツーエンドの信頼性が得られるか？

2022年から2026年の間に、フィールドはスキャフォールディング——検索レイヤー、プランナー、サンドボックス、編集検証ループ、フィードバックフォーマット——が重要だということを学んだ。Claude Sonnet 4.5はSWE-agent v1でSWE-bench Verifiedの43.2%を記録した；同じモデルがClineの自律足場の中では59.8%を記録した。絶対値で16.6ポイントの差、同じ重みで。ベースモデルはコンポーネント；ループが製品だ。

付随する問題は、ベンチマークの飽和が回帰を隠すことだ。SWE-bench Verifiedはほぼ飽和に近く、簡単なタスクの末尾（161/500タスクが≤2行）がトップスコアを引き上げている。現実世界の品質は、同じリーダーが依然として23〜59%に座るSWE-bench Pro（10行以上の変更）のような分布でより適切に測定される。

## コンセプト

### SWE-bench、一段落で

SWE-bench（Jimenez他）は実際のGitHubのイシューをグラウンドトゥルースのパッチと共に取り上げ、エージェントにテストスイートを通過させるパッチを生成するよう求める。SWE-bench Verified（OpenAI、2024）は曖昧でブロークンなタスクを除去した、人間が精選した500タスクのサブセットだ。SWE-bench Proはより難しい後継で——10行以上の変更を必要とするタスクで、現在のフロンティアエージェントが23〜59%に座る。

### 2022 → 2026の曲線が実際に示すもの

- **2022年**：生のSWE-benchで約4%の研究モデル。
- **2024年**：Devinスタイルの足場を持つGPT-4が約14%；SWE-agentが約12%。
- **2025年**：AiderとSWE-agentの中のClaude 3.5/3.7 Sonnetが40〜55%の範囲に入る。
- **2026年**：Claude Sonnet 4.5とフロンティアの競合がSWE-bench Verifiedで70〜80%+。Epoch AIのリーダーボードがこれをライブで追跡する。

傾斜は3つの複合するソースから来た：より良いベースモデル、より良い足場（CodeAct、リフレクション、ベリファイアループ）、より良いベンチマーク（Verifiedがノイズを除去）。

### CodeAct対JSONツール呼び出し

OpenHands（All-Hands-AI、arXiv:2407.16741、旧OpenDevin）は特定のアーキテクチャ上の賭けをした：モデルがホストがデコードして実行するJSONツール呼び出しを発するのではなく、モデルはPythonコードを発し、Jupyterスタイルのカーネルがサンドボックスで実行する。エージェントは1つのアクション内でファイルをループし、ツールを連鎖させ、自身の例外を捕捉できる。

トレードオフ：

- **JSONツール呼び出し**：すべてのアクションは1ターン；監査が容易；限られた合成可能性；各呼び出しが明示的なバリデーターを通るためデフォルトで安全。
- **CodeAct**：1つのアクションが完全なプログラムになれる；合成可能；強化されたサンドボックスが必要（OpenHandsはDockerアイソレーションを使用）；失敗モードはサンドボックスランタイムが許可することを含む。

両方のアーキテクチャが本番にある。CodeActはオープンプラットフォーム（OpenHands、smolagents）で支配的だ。JSONツール呼び出しはマネージドサービス（Anthropicマネージドエージェント、OpenAI Assistants）で支配的なまま。プロバイダーが実行者を制御する場所だ。

### 2026年の足場の全体像

| 足場 | ライセンス | 実行モデル | 注目のプロパティ |
|---|---|---|---|
| OpenHands（OpenDevin） | MIT | Docker内のCodeAct | 最も活発なオープンプラットフォーム；イベントストリームの再生可能 |
| SWE-agent | MIT | エージェント・コンピュータ・インターフェース（ACI） | 最初のエンドツーエンドSWE-bench足場 |
| Aider | Apache-2 | ローカルリポジトリでの差分による編集 | 最小限の足場、強力な回帰安定性 |
| Cline | Apache-2 | ツールポリシーを持つVSCodeエージェント | Sonnet 4.5で最高スコアのオープン足場 |
| Devin（Cognition） | プロプライエタリ | マネージドVM + プランナー | 最初の「AIソフトウェアエンジニア」製品カテゴリ |
| Claude Code | プロプライエタリ | 権限モード + ルーティン | レッスン10がエージェントループの詳細をカバー |

### 足場が支配する理由

コーディング実行はロングホライズン軌跡だ（レッスン1）。信頼性がステップをまたいで複合する。足場がポイントを買う3つの場所：

1. **検索**：読むべき正しいファイルを見つけることが静かなボトルネックだ。SWE-agentのACI、OpenHandsのファイルインデックス、Aiderのリポジトリマップがすべてこれに取り組む。
2. **ベリファイアループ**：テストを実行し、スタックトレースを読み、再試行することはSWE-benchで10ポイント以上のデルタだ。
3. **失敗の封じ込め**：エラーでロールバックするサンドボックスは複合的なダメージを防ぐ。ベリファイアループありとなしの同じモデルは2つの異なる製品のように見える。

### ベンチマークの飽和と実際の分布

OpenHandsの著者とEpoch AIはともにSWE-bench Verifiedに簡単な末尾があると指摘する：500/161タスクが1〜2行の変更しか必要としない。高いスコアはこの末尾によって部分的に駆動される。SWE-bench Proは10行以上の変更に制限し、同じフロンティアシステムに対して23〜59%の範囲でスコアを戻す。本番の分布はほぼ確実にVerifiedよりProに近い。

エージェントを選ぶための含意：自身のバグバックログの Pro のようなサブセットを実行する。重要なスコアは出荷するものを代表するタスクのスコアだ。

## 使ってみる

`code/main.py`は固定されたミニタスク分布で2つのおもちゃのエージェント足場を比較する：

1. ターンごとに1つのアクションを取る**JSONツール呼び出し**足場。
2. アクションごとに小さなPythonスニペットを発することができる**CodeAct**足場。

両方はスタブの「モデル」（決定論的なルール）を使用するため、比較はモデルの品質から足場を分離する。出力はCodeAct足場がアクションごとのより大きなブラストラジウスのコストで少ないターンでより多くのタスクを解決することを示す。

## 成果物を出す

`outputs/skill-scaffold-audit.md`は採用前に提案されたコーディングエージェント足場を監査するのに役立つ：検索品質、ベリファイアの存在、サンドボックスアイソレーション、ベンチマークから分布への適合。

## 演習

1. `code/main.py`を実行する。各足場は同じタスクセットで何ターンかかるか？それぞれのアクションごとのブラストラジウスは何か？

2. OpenHandsの論文（arXiv:2407.16741）を読む。論文はCodeActが複雑なタスクでJSONツール呼び出しを上回ると主張している。論文が認める1つの失敗モードを特定し、そのモードが本番でいつ支配するかについて1文書く。

3. 2ファイルにわたって10行以上の変更を必要とするバグバックログから1つのタスクを選ぶ。（a）JSONツール呼び出しと（b）CodeActの下でフロンティアモデルのエンドツーエンドの成功確率を見積もる。ギャップを正当化する。

4. SWE-bench Verifiedには161の1ファイル、1〜2行のタスクがある。それらを除外するスコアを構築する。リーダーボードはどう変わるか？

5. 「SWE-bench Verifiedの紹介」（OpenAI）を読む。曖昧なタスクを削除するために使用された特定の方法論を説明し、キュレーションが見逃すカテゴリを1つ挙げる。

## キーワード

| 用語 | よく言われること | 実際の意味 |
|---|---|---|
| SWE-bench | 「コーディングベンチマーク」 | グラウンドトゥルースのパッチとテストスイートを持つ実際のGitHubのイシュー |
| SWE-bench Verified | 「クリーンなサブセット」 | 500の人間が精選したタスク、簡単な末尾あり |
| SWE-bench Pro | 「より難しいサブセット」 | 10行以上の変更；フロンティアは23〜59% |
| CodeAct | 「アクションとしてのコード」 | エージェントがPythonを発する；Jupyterスタイルのカーネルがサンドボックスで実行 |
| JSONツール呼び出し | 「関数呼び出し」 | 各アクションは実行前に検証される構造化されたJSONペイロード |
| 足場 | 「エージェントフレームワーク」 | ベースモデルを取り巻く検索 + プランナー + 実行器 + ベリファイアループ |
| ACI（エージェント・コンピュータ・インターフェース） | 「SWE-agentのフォーマット」 | LLMのエルゴノミクスのために設計されたコマンドセット、人間のシェルではない |
| ベリファイアループ | 「テストと再試行」 | テストを実行し、出力を読み、パッチを修正する；最大の非モデル信頼性向上 |
