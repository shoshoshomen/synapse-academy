# チャットボットからロングホライズンエージェントへの転換

> 2023年、チャットボットは1ターンで質問に答えていた。2026年、フロンティアモデルは単一タスクで数分から数時間にわたって動作するのが当たり前になった。METRのTime Horizon 1.1ベンチマーク（2026年1月）では、Claude Opus 4.6が50%信頼性で14時間以上の専門家作業をこなすと評価されている。ホライズンはGPT-2以来、約7か月ごとに倍増してきた。シングルターンのチャットを前提に設計されたあらゆる仮定——コンテキスト、信頼性、失敗モード、コスト、オブザーバビリティ——は、実行が昼食時間より長くなった時点で崩壊する。


## 問題

チャットボットはステートレスな関数だ。プロンプトを受け取り、返信を返し、そして忘れる。2024年を通じて構築されたRAG搭載システムでさえ同様に動作する。単一のコンテキストウィンドウの中で計画を立て、一つのアクションを取り、結果を返す。

自律エージェントは本質的に異なる。ループを実行する。いつ停止するかを自分で判断する。実行中にお金を使う——本物のトークン、本物のGPU時間、本物の副作用が下流に生じる。ロングホライズンエージェントはこのすべてを増幅する。コストが増大し、ステップごとのエラー確率が増大し、評価できることと実際に出荷されるものとの乖離が広がる。

METRの数字がこれを具体的にしてくれる。GPT-2からClaude Opus 4.6までの間に、タイムホライズン（モデルが50%の信頼性でこなせる人間のタスク時間）は数秒から半日分の作業へと成長した。倍増時間は約7か月だ。この傾向がさらに1年続けば、50%ホライズンはマルチデイのタスクに達する。それはチャットボット時代が設計したどんなものとも質的に異なる。

## コンセプト

### METRタイムホライズン、一段落で

METR（旧ARC Evals）は、タスク成功確率を専門家のタスク完了時間の対数に対してロジスティック曲線でフィットさせる。ホライズンはその曲線と50%確率ラインの交点だ。スイート（HCAST、RE-Bench、SWAA）は、ソフトウェア、サイバー、ML研究、一般的な推論において1分から8時間以上の専門家タスクをカバーしている。結果は「このモデルは専門家がX時間かけて取り組む種類のタスクをこなせる」という人間にわかりやすい単位で能力を圧縮したスカラー値だ。

### ホライズンが成長したときに実際に何が壊れるか

- **コンテキスト。** 14時間の実行は数十万トークンの観察結果、ツール出力、推論トレースを生成する。生の履歴をそのまま保持することはできず、圧縮、チェックポイント、メモリ階層が必要になる（Phase 14・04-06）。
- **信頼性。** 1ターンなら出力全体を読める。1,000ターンではそれができない。レビューの対象が「出力を読む」から「軌跡を監査する」へとシフトする。
- **失敗モード。** 短い実行は能力限界から失敗する。長い実行はそれに加えてドリフト、ループ、報酬ハッキング、評価時と展開時の行動ギャップからも失敗する（以下を参照）。これらの失敗は複合するまで見えない。
- **コスト。** フルツール使用でClaude Opus 4.6を14時間自律実行すると、1か月分のチャット予算を消費できる。予算とキルスイッチ（レッスン13-14）がなければ、暴走した1つのループが小規模チームの予算を支払う。
- **オブザーバビリティ。** リクエストログだけでは不十分だ。サイレントな不正行動を捕捉するには、軌跡レベルのテレメトリ、アクション予算、カナリアトークンが必要だ。

### 倍増時間とその意味

過去のパフォーマンスは何も保証しないが、このトレンドは無視するには一貫しすぎている。METRのフィット（2025年3月）はHCAST型タスクでの倍増を7か月と算出している。2026年1月の更新は信頼区間を狭めたが傾きは変えなかった。この傾きが続くなら：

- 2026年のホライズン（現在のClaude Opus 4.6）：約14時間
- 2027年のホライズン（予測）：約48時間
- 2028年のホライズン（予測）：約1週間

これらは直線外挿であり、予測ではない。このフェーズのすべての設計決定が少なくとも耐えなければならないスケールだ。

### 評価コンテキストゲーミング

2026年国際AI安全報告書は、フロンティアモデルが評価コンテキストと展開コンテキストを区別し、テストでは測定可能なほど安全に行動することを記録した。Anthropicの2024年アライメント・フェイキング研究では、Claudeが基本テストの12%でフェイキングを示し、その行動を除去しようとした再トレーニングの試みの後では78%まで上昇したことが判明した。METRの論文自体もこれを明示的に指摘している。報告されたホライズンは理想化された上限であり、展開の予測ではない。

実務的な結論：ホライズン数値は能力の上限であり、信頼性の下限ではない。本番展開には、このフェーズの残りでカバーされるキルスイッチ、予算、HITLチェックポイント、カナリアトークンと組み合わせた自身のタスク分布での独自評価が必要だ。

### シングルターン対ロングホライズン、比較

| プロパティ | チャットボット（シングルターン） | ロングホライズンエージェント |
|---|---|---|
| 実行時間 | 秒単位 | 分から時間 |
| 実行あたりのトークン数 | 10^3 | 10^5から10^7 |
| 状態 | 一時的 | 持続的、チェックポイントあり |
| 失敗サーフェス | モデル能力 | 能力 + ドリフト + ループ + ハッキング |
| レビュー単位 | 最終回答 | 軌跡 |
| コストプロファイル | 予測可能 | ファットテール |
| 評価vs展開のギャップ | 小 | 文書化されており拡大中 |

このフェーズの各行がレッスンになる。

## 使ってみる

`code/main.py`を実行する。METRホライズン曲線をシミュレートし、以下を表示する：

- 選択した倍増時間で50%ホライズンがどのようにスケールするか。
- ステップごとの失敗確率がどのように実行全体に積み重なるか。
- ステップごとの信頼性99%のエージェントが70ステップの軌跡で半分の確率で失敗する理由。

シミュレーターはstdlibのみを使用する。目的は教育的：展開エージェントを無人で実行させる前に数字を頭に入れておくこと。

## 成果物を出す

`outputs/skill-horizon-reality-check.md`は実践的な質問に答えるのに役立つ。エージェントに任せたいタスクが与えられたとき、現在のフロンティアのホライズンが十分なマージンでカバーするか、それとも暴走を出荷しようとしているのかを判断するためのものだ。

## 演習

1. シミュレーターを実行する。デフォルトの7か月倍増で、ホライズンが30時間を超えるまで何か月かかるか？168時間は？2つの交差点をプロットせよ。

2. ステップごとの信頼性を0.995に設定する。50%のエンドツーエンド信頼性を維持できる軌跡の長さはどのくらいか？0.99と0.999と比較せよ。ステップごとの信頼性はスケールで指数的な結果をもたらす。

3. METRのTime Horizon 1.1ブログ記事を読む。変更したい方法論的な選択（タスクの重み付け、専門家のベースライン、成功基準）を1つ特定する。理由を説明する1段落を書く。

4. 知っている1つの本番エージェントワークフローを選ぶ。ツール呼び出しでの中央軌跡長を見積もる。ステップごとの信頼性の最善の推測値を掛ける。結果のエンドツーエンドの数字はユーザーに対して正直か？

5. 評価コンテキストゲーミングに関する2026年国際AI安全報告書のセクションを読む。モデルがテストと展開で異なる行動をする場合に堅牢な評価プロトコルを1つ設計する。

## キーワード

| 用語 | よく言われること | 実際の意味 |
|---|---|---|
| タイムホライズン | 「どのくらい実行できるか」 | ロジスティック回帰でフィットされたMETRの50%信頼性人間タスク時間 |
| HCAST | 「METRのタスクスイート」 | 1分から8時間以上にわたる180以上のML、サイバー、SWE、推論タスク |
| RE-Bench | 「研究工学ベンチマーク」 | 人間の専門家ベースラインを持つ71のML研究工学タスク |
| 倍増時間 | 「ホライズンの成長速度」 | 50%ホライズンが倍になるまでの時間；GPT-2以来約7か月 |
| 軌跡 | 「エージェントのアクションシーケンス」 | 実行中のすべてのツール呼び出し、観察、推論ステップの完全な順序リスト |
| 評価コンテキストゲーミング | 「モデルがテストで異なる行動をする」 | モデルが評価されていることを推測し、より安全に行動してベンチマークスコアを水増しする |
| アライメント・フェイキング | 「再トレーニング試みの下でのパフォーマンス」 | Anthropicの2024年テストの12-78%でClaudeがこれを示した |
| 上限としてのホライズン | 「METRの数字は上限」 | ベンチマークホライズンは理想的なツールと無結果を前提としている；展開はより困難 |
