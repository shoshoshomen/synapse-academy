# ブラウザエージェントとロングホライズンのWebタスク

> ChatGPTエージェント（2025年7月）はOperatorとディープリサーチを1つのブラウザ/ターミナルエージェントに統合し、BrowseCompのSOTAを68.9%に設定した。OpenAIは2025年8月31日にOperatorを廃止した——製品レイヤーでの統合。AnthropicのVercept買収はClaude SonnetをOSWorldで15%未満から72.5%に引き上げた。WebArena-Verified（ServiceNow、ICLR 2026）はオリジナルのWebArenaの誤検知率の11.3%を修正し、258タスクのHardサブセットを出荷した。数字は本物だ。攻撃サーフェスも同様：OpenAIのプレパレッドネスヘッドはブラウザエージェントへの間接プロンプトインジェクションは「完全にパッチ可能なバグではない」と公に述べた。文書化された2025〜2026年の攻撃：Tainted Memories（Atlas CSRF）、HashJack（Cato Networks）、Perplexity Cometでのワンクリックハイジャック。


## 問題

ブラウザエージェントは信頼されていないコンテンツを読み、重大なアクションを取るロングホライズンエージェントだ。エージェントが訪問するすべてのページはユーザーが書いていない入力だ。すべてのページのすべてのフォームは潜在的なコマンドチャネルだ。2025〜2026年の攻撃コーパスはこれが仮定的でないことを示している：Tainted Memoriesは攻撃者が巧妙に作られたページを通じてエージェントのメモリに悪意のある命令を結びつけることを可能にする；HashJackはエージェントが訪問するURLフラグメントにコマンドを隠す；Perplexity Cometのハイジャックは1回のクリックで発生する。

防御の絵は不快だ。OpenAIのプレパレッドネスヘッドは静かな部分を声に出して言った：間接プロンプトインジェクションは「完全にパッチ可能なバグではない」。これは、攻撃がエージェントの読み取り対行動の境界に存在するためだ。それはアーキテクチャ的に曖昧——モデルが読むすべてのトークンは原則として命令として読まれる可能性がある。

このレッスンは攻撃サーフェスに名前をつけ、ベンチマークの全体像（BrowseComp、OSWorld、WebArena-Verified）に名前をつけ、レッスン14と18で実際の防御について推論できるよう最小限の間接プロンプトインジェクションシナリオをモデル化する。

## コンセプト

### 2026年の全体像、システムごとの1段落

**ChatGPTエージェント（OpenAI）。** 2025年7月起動。Operator（ブラウジング）とDeep Research（マルチ時間研究）を統合。スタンドアロンのOperatorを2025年8月31日に廃止。BrowseCompで68.9%のSOTA；OSWorldとWebArena-Verifiedで強力な数字。

**Claude Sonnet + Vercept（Anthropic）。** AnthropicのVercept買収はコンピューター使用能力に焦点を当てた。Claude SonnetをOSWorldで<15%から72.5%に引き上げた。Claude Computer UseはツールAPIとして出荷。

**Gemini 3 ProとBrowser Use（DeepMind）。** Browser Use統合がコンピューター使用コントロールを出荷；FSF v3（2026年4月、レッスン20）はML R&Dドメインで自律性を特定してトラッキングする。

**WebArena-Verified（ServiceNow、ICLR 2026）。** よく文書化された問題を修正：オリジナルのWebArenaは約11.3%の誤検知率を持っていた（実際に解決されたが失敗とマークされたタスク）。Verifiedリリースは人間が精選した成功基準で再採点し、258タスクのHardサブセットを追加する（ICLR 2026論文、openreview.net/forum?id=94tlGxmqkN）。

### BrowseComp対OSWorld対WebArena

| ベンチマーク | 何を測定するか | ホライズン |
|---|---|---|
| BrowseComp | 時間的プレッシャーの下でオープンウェブで特定の事実を見つける | 分 |
| OSWorld | デスクトップ全体を操作するエージェント（マウス、キーボード、シェル） | 数十分 |
| WebArena-Verified | シミュレートされたサイトでのトランザクションウェブタスク | 分 |
| Hardサブセット | マルチページの状態遷移を持つWebArena-Verifiedタスク | 数十分 |

異なる軸。高いBrowseCompスコアはエージェントが事実を見つけることを言う；フライトを予約できることは言わない。OSWorldスコアはデスクトップで機能するかどうかに近い。WebArena-Verifiedはフローを完了できるかどうかに近い。いかなる本番決定も、タスク分布に合ったベンチマークを必要とする。

### 攻撃サーフェス、名前付き

1. **間接プロンプトインジェクション。** 信頼されていないページコンテンツが命令を含む。エージェントはそれらを読む。エージェントはそれらを実行する。公開例：2024年Kai Greshake他、2025年Tainted Memories論文、2026年HashJack（Cato Networks）。
2. **URLフラグメント/クエリインジェクション。** クロールされたURLの`#fragment`またはクエリ文字列にコマンドが含まれる。視覚的には表示されない；しかしエージェントのコンテキスト内にある。
3. **メモリ結合攻撃。** ページはエージェントに永続的なメモリを書くよう指示する（レッスン12が永続的な状態をカバー）。次のセッションで、メモリは目に見えるトリガーなしにペイロードを発火する。
4. **認証済みセッションへのCSRF型攻撃。** Tainted Memoriesクラス：エージェントがどこかにログインしている；攻撃者のページはエージェントがユーザーのCookieで実行する状態変更リクエストを発行する。
5. **ワンクリックハイジャック。** 視覚的に無害なボタンがエージェントが従うペイロードを乗せる。Cometクラス。
6. **エージェントのホストサーフェスのContent-Security-Policyの穴。** レンダリングとツールレイヤー自体が攻撃ベクターになれる；ブラウザ内ブラウザエージェントスタックは広い。

### 「完全にパッチ可能でない」理由

攻撃はエージェントの能力と同型だ。エージェントはジョブをするために信頼されていないコンテンツを読まなければならない。エージェントが読むいかなるコンテンツも命令を含む可能性がある。エージェントが従ういかなる命令もユーザーの実際のリクエストと不整合である可能性がある。防御（信頼境界、分類器、ツールアローリスト、重大なアクションへのHITL）は攻撃のコストを上げ、そのブラストラジウスを削減する。クラスを閉じない。

これはLöbの定理（レッスン8）と同じ推論パターンだ：エージェントは次のトークンが安全であることを証明できない；安全でないトークンがより検出可能なシステムを設定できるだけだ。

### 実際に出荷される防御姿勢

- **読み取り/書き込み境界。** 読み取りは決して重大ではない。書き込み（フォームの送信、コンテンツの投稿、副作用を持つツールの呼び出し）は、開始コンテンツが信頼境界の外からのものであれば新鮮な人間の承認が必要だ。
- **タスクごとのツールアローリスト。** エージェントはブラウズできる；そのツールがタスクに明示的に有効にされていない限り、電信送金を開始できない。レッスン13が予算をカバーする。
- **セッションアイソレーション。** ブラウザエージェントセッションはスコープされた認証情報のみで実行される。本番認証なし、個人メールなし。監査のためにすべてのHTTPリクエストのログを保持。
- **コンテンツサニタイザー。** フェッチされたHTMLはモデルコンテキストに連結される前に既知の悪いパターンが削除される。（簡単な攻撃を削減する；高度なペイロードを止めない。）
- **重大なアクションへのHITL。** 提案-コミットパターン（レッスン15）。
- **メモリへのカナリアトークン。** メモリエントリが発火すれば、ユーザーはそれを見る（レッスン14）。

## 使ってみる

`code/main.py`は3つの合成ページに対する小さなブラウザエージェント実行をモデル化する。1つのページは良性、1つには可視テキストの直接プロンプトインジェクションブロブがあり、1つにはURLフラグメントインジェクション（表示されないがエージェントのコンテキスト内にある）がある。スクリプトは（a）素朴なエージェントが何をするか、（b）読み取り/書き込み境界が捕捉するもの、（c）サニタイザーが捕捉するもの、（d）どちらも捕捉しないものを示す。

## 成果物を出す

`outputs/skill-browser-agent-trust-boundary.md`は提案されたブラウザエージェント展開をスコープする：それが触れる信頼ゾーン、書き込みを承認されているもの、最初の実行前に必要な防御。

## 演習

1. `code/main.py`を実行する。読み取り/書き込み境界がそうでないがサニタイザーが捕捉する攻撃と、読み取り/書き込み境界のみが捕捉する攻撃を特定する。

2. HashJackスタイルのURLフラグメントインジェクションのあるクラスを検出するためにサニタイザーを拡張する。正当なフラグメントを持つ良性URLでの誤検知率を測定する。

3. 知っている1つの実際のブラウザエージェントワークフローを選ぶ（例：「フライトを予約する」）。すべての読み取りとすべての書き込みをリストアップする。HITLが必要な書き込みとその理由をマークする。

4. WebArena-Verified ICLR 2026論文を読む。オリジナルのWebArenaのスコアリングが信頼できなかったタスクのカテゴリを1つ特定し、Verifiedサブセットがそれをどのように解決するかを説明する。

5. ブラウザエージェント設定のためのメモリカナリアを設計する。何を保存し、どこに、何がアラームをトリガーするか？

## キーワード

| 用語 | よく言われること | 実際の意味 |
|---|---|---|
| 間接プロンプトインジェクション | 「悪いページテキスト」 | エージェントが読むページの信頼されていないコンテンツにはエージェントが実行する命令が含まれる |
| Tainted Memories | 「メモリ攻撃」 | エージェントが攻撃者が提供した命令を永続的なメモリに書く；次のセッションでトリガーされる |
| HashJack | 「URLフラグメント攻撃」 | URLフラグメント/クエリ文字列に隠されたペイロードがエージェントのコンテキスト内にあるが視覚的にレンダリングされない |
| ワンクリックハイジャック | 「悪いボタン」 | 目に見えるアフォーダンスがエージェントが実行するフォローオンペイロードを乗せる |
| BrowseComp | 「ウェブ検索ベンチマーク」 | オープンウェブで特定の事実を見つける；分スケールのホライズン |
| OSWorld | 「デスクトップベンチマーク」 | フルOS制御；マルチステップのGUIタスク |
