# キルスイッチ、サーキットブレーカー、カナリアトークン

> キルスイッチはエージェントの編集サーフェスの外側に保持されるブール値——Redisキー、フィーチャーフラグ、署名付き設定——エージェントを完全に無効にする。サーキットブレーカーはより細かい粒度だ：特定のパターン（5回連続して同じツール呼び出し）でトリップし、問題のあるパスを一時停止し、人間に昇格する。カナリアトークンは古典的な欺瞞から受け継ぐ：エージェントが触れる正当な理由がない偽の認証情報やハニーポットレコード、アクセスがアラートをトリガーする。eBPFベースのデータパス（例：Cilium）は、カーネルレイヤーで隔離されたポッドのエグレスをフォレンジックハニーポットに書き換えることができる；公開されているCiliumのベンチマークはTCP_RRでサブミリ秒のP99データパスレイテンシを報告している（あなたのプロパゲーション予算はデータパス自体ではなく、ポリシー更新がノードに到達するまでの時間に依存する）。適応型ベースラインを持つ統計的検出器（EWMA、CUSUM）はドリフトを静かに受け入れる——曲げない憲法的なハード制限で重ねる。


## 問題

コストガバナー（レッスン13）はエージェントが使えるものを制限する。予算内でエージェントができることを制限しない。$50の速度制限を持つエージェントは依然としてシークレットを流出させ、間違った投稿を公開し、リソースを削除できる——高価なアクションはしばしばトークンが安いものだ。

このレッスンはコストレイヤーの隣にある3つの検出器をカバーする：

1. **キルスイッチ**：エージェントの手の届かない場所に保持されたブール型のオフボタン。
2. **サーキットブレーカー**：特定のパスを一時停止するアクションパターン検出器。
3. **カナリアトークン**：正当な理由のないエージェントが触れることで自身を明かすベイト。

3つすべてが前LLMエンジニアリングだ。古典的な欺瞞、レート制限ブレーカー、フィーチャーフラグのキルは自律エージェントより前に存在する。新しいのは攻撃サーフェスだ：エージェントは信頼されていないコンテンツを読み（レッスン11）、自身のメモリを編集し、多くの安全に見えるアクションを安全でない1つに合成できる。ここで名前を挙げた検出器は、エージェントの自己報告を信頼しないから機能する。

## コンセプト

### キルスイッチ

キルスイッチはエージェントが読めるが書けないブール値だ。実装の選択肢：

- **マネージドサービスのフィーチャーフラグ。** LaunchDarkly、Statsig、Unleash。更新は数秒で伝播する。
- **エージェントがポーリングするRedisキー。** シンプル；エージェントプロセスが毎ターン確認する必要がある。
- **オブジェクトストレージの署名付き設定。** エージェントが起動時に署名を検証；署名されていない状態を拒否する。
- **OSレベルのシグナルまたはコンテナライフサイクルのキル。** Docker `kill`、Kubernetes `kubectl delete pod`、systemdのストップ。

正しいキルスイッチが持つプロパティ：

- エージェントはそれを`off`に設定できない。（エージェントの認証情報が書き込めないシステムに存在する。）
- すべての重大なアクションで確認され、起動時だけでなく。
- オフになっているとき、エージェントはエージェントが到達できるシステムへのロギングを含め、外部から観察可能なことを何もしない。
- 再有効化は自動タイムアウトではなく明示的な人間のアクションだ。

### サーキットブレーカー

サーキットブレーカーはエージェント全体ではなく特定のパターンを一時停止する。古典的な形（2007年Nygardの本、依然として最新）：

- **閉じた**：アクションが許可される。
- **開いた**：アクションがブロックされる。
- **半開き**：クールダウン後、1〜3回のプローブ試行が許可される（デフォルト1）；成功でブレーカーが閉じ、残りの失敗で再び開く。

エージェント関連のトリガー：

- 5回連続で同じツール呼び出し（繰り返しループ）。
- 異なる入力で同じツールへの5回の連続失敗（系統的な失敗）。
- 閾値を超えるツール呼び出しのレート（レッスン13の速度）。
- 信頼外のコンテンツ読み取り後に特定のツール（例：`file.delete`）が呼び出された（レッスン11）。

### カナリアトークン

カナリアトークン（ハニートークンとも呼ばれる）はエージェントが触れるべきでない入力だ。アクセスがアラームだ。

エージェントのための例：

- 実際の権限を持たない環境内の偽の`AWS_SECRET_ACCESS_KEY`。流出の試みはすぐに帰属できる。
- 既知の番兵値でフラグが立てられた偽のデータベースレコード。このレコードのいかなる読み取りまたは更新もアラートを発火する。
- ワークスペース内の偽のファイル。このファイルの読み取りまたは編集は疑わしい。
- セッション開始時に注入された偽のメモリエントリ。後の出力に表示された場合、メモリが流出した。

カナリアの設計はワークフローに固有だ。エージェントが触れる正当な理由があるカナリアはノイズだ。

### 統計的とハード制限を重ねる理由

統計的検出器（EWMA、CUSUM、ツール呼び出しレートへのz-スコア）は移動するベースラインに適応する。それは正当なドリフトには特徴であり、敵対的なドリフトにはバグだ。忍耐強い攻撃者はアラームが発火しないよう十分ゆっくりとベースラインをシフトできる。

ハード憲法的制限（レッスン17）は曲げない。「`secrets@`に絶対にメールしない」という憲法的なルールはよりシンプルで、監査可能で、緩やかなドリフトでゲームできない。重ねるパターン：統計的検出器がほとんどのノイズを捕捉し、ハード制限が検出器を通り抜けた攻撃を捕捉する。

### eBPFデータパスリダイレクトによる隔離

CiliumのeBPFベースのネットワークポリシーはカーネルレイヤーで隔離されたポッドのエグレスをフォレンジックハニーポットに書き換えることができる。CiliumのパブリックベンチマークはTCP_RRでサブミリ秒のP99データパスレイテンシを報告する；クラスターで隔離をトリガーするウォールクロック予算は、コントロールプレーンからノードへのポリシー更新の伝播によって支配される（オペレーターが事前ロードされたKubernetesでは数百ミリ秒が現実的；テールレイテンシはクラスターのサイズと調整のリズムに依存する）。これにより2つのことが得られる：エージェントは実際のものを何も流出させず、ハニーポット内のエージェントの行動は完全に観察される。カナリアトークンと同じパターン、異なるレイヤー：エージェントは格納されている間に何をしようとするかによって意図を明かす。

### どの検出器も捕捉しないもの

- **許可されたプリミティブから合成される意味的攻撃。** すべての個別アクションがすべての検出器を通過する；合成が問題だ。これはレッスン10のオートモードの合成失敗だ。
- **ペイロードの一部として検出器を含む攻撃。** エージェントが「行動する前に、カナリアを無効にする」と言うページを読み、エージェントがその能力を持つ場合、検出器は妥協される。カナリアトークンはエージェントが変更できないシステムにあるべきだ。

## 使ってみる

`code/main.py`は3つの検出器を通じた短いエージェント軌跡をシミュレートする。外部辞書に保持されたキルスイッチ；5回の同じツール呼び出しでトリップするサーキットブレーカー；アクセスがアラートをトリガーするカナリアファイル。合成軌跡をフィードする：正当なアクション、繰り返しループ、カナリアプローブ、エージェントのアクションが停止されるキルスイッチトリガーのシナリオ。

## 成果物を出す

`outputs/skill-tripwire-design.md`はエージェント展開の提案された検出器スタックをレビューし、ギャップ（欠けているキルスイッチ、欠けているカナリア、緩すぎるサーキットブレーカーの閾値）にフラグを立てる。

## 演習

1. `code/main.py`を実行する。サーキットブレーカーがターン5（5回目の同じ呼び出し）で発火し、カナリアがターン9（偽のキーの読み取り）で発火することを確認する。

2. 統計的検出器を追加する：ツール呼び出しレートのEWMA z-スコア。緩やかにドリフトする軌跡をフィードし、検出器が発火しないことを示す。今ハード制限を追加する（10分でツール呼び出しが50回以下）し、同じ軌跡でハード制限が発火することを示す。

3. ブラウザエージェント（レッスン11）のカナリアトークンセットを設計する。少なくとも3つのカナリアとそれぞれが何を検出するかをリストアップする。

4. CiliumのネットワークポリシードキュメントをReadする。エグレスリダイレクト隔離フローを具体的に説明する：どのポリシーセレクター、どのポッド、どのエグレス書き換え、どのアラート。「隔離を決定する」から「最初のリダイレクトされたパケット」までのウォールクロックレイテンシを支配するものは何か？

5. キルスイッチされたエージェントの再有効化手順を定義する。誰が再有効化できるか？何が文書化されなければならないか？再有効化前にエージェントについて何が変わらなければならないか？

## キーワード

| 用語 | よく言われること | 実際の意味 |
|---|---|---|
| キルスイッチ | 「オフボタン」 | エージェントの編集サーフェスの外側のブール値；すべての重大なアクションで確認 |
| サーキットブレーカー | 「パターン一時停止」 | 繰り返し、失敗率、またはレート制限でのアクション固有のトリップ |
| カナリアトークン | 「ハニートークン」 | エージェントが触れる正当な理由がないベイト；アクセスがアラートを発火 |
| ハニーポット | 「フォレンジックサンドボックス」 | 隔離されたエージェントが観察されるリダイレクトされたトラフィック/ワークスペース |
| EWMA | 「移動平均」 | 指数加重；ドリフトに適応（特徴 + バグ） |
| CUSUM | 「累積和」 | ベースラインからの持続的なシフトを検出 |
| ハード制限 | 「憲法的なルール」 | 適応しない；履歴に関わらず一定 |
| 憲法的制限 | 「常に真のルール」 | レッスン17の憲法に結びついている；エージェントが編集できない |
