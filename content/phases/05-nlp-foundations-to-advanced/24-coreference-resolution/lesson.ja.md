# 共参照解析

> 「彼女が彼に電話した。彼は出なかった。医者は昼食中だった。」2人の人物への3つの参照があり、誰一人名前が出てこない。共参照解析は誰が誰なのかを解明する。


## 問題設定

300語の記事からApple Inc.のすべての言及を抽出する。記事が「Apple」と書いている時は簡単だ。「その会社」、「彼ら」、「クパチーノのテクノロジー大手」、「ジョブズの会社」と書いている時は難しい。これらの言及を同じエンティティに解決せずに放置すると、NERパイプラインは言及の60〜80%を見逃す。

共参照解析は同じ現実世界のエンティティを参照するすべての表現を一つのクラスターにリンクする。表層レベルのNLP（NER、構文解析）と下流のセマンティクス（情報抽出、QA、要約、KG）の間の接着剤だ。

2026年に重要な理由：

- 要約：「CEOが発表した...」対「ティム・クックが発表した...」— 要約はCEOの名前を記載すべきだ。
- 質問応答：「彼女は誰に電話したか？」は「彼女」の解決が必要。
- 情報抽出：「PER1がAppleを設立した」と「ジョブズがAppleを設立した」が別々のエントリとして入っている知識グラフは間違いだ。
- マルチドキュメント情報抽出：同じイベントについての記事をまたいで言及をマージすることはクロスドキュメント共参照だ。

## 概念

![共参照クラスタリング：言及 → エンティティ](../assets/coref.svg)

**タスク。** 入力：文書。出力：各クラスターが一つのエンティティを参照する言及（スパン）のクラスタリング。

**言及タイプ。**

- **固有表現。** 「Tim Cook」
- **名詞句。** 「CEO」、「その会社」
- **代名詞。** 「彼」、「彼女」、「彼ら」、「それ」
- **同格。** 「Tim Cook、AppleのCEO、」

**アーキテクチャ。**

1. **ルールベース（Hobbs、1978年）。** 文法規則を使った構文ツリーベースの代名詞解決。良いベースライン。代名詞では驚くほど上回るのが難しい。
2. **言及ペア分類器。** 言及のペア(m_i, m_j)ごとに、共参照しているかどうかを予測する。推移閉包でクラスタリング。2016年以前の標準。
3. **言及ランキング。** 各言及について、候補の先行詞（「先行詞なし」を含む）をランク付けする。トップを選ぶ。
4. **スパンベースのエンドツーエンド（Lee et al.、2017年）。** トランスフォーマーエンコーダー。長さの上限まですべての候補スパンを列挙する。言及スコアを予測する。各スパンの先行詞確率を予測する。貪欲にクラスタリングする。現代のデフォルト。
5. **生成的（2024年以降）。** LLMにプロンプトを送る：「このテキストのすべての代名詞とその先行詞を列挙してください。」簡単なケースでは機能し、長文書と稀な参照では苦手。

**評価指標。** 標準的な5つの指標（MUC、B³、CEAF、BLANC、LEA）は、単一の指標がクラスタリング品質を捉えることができないため。最初の3つの平均をCoNLL F1として報告する。CoNLL-2012での2026年の最先端：約83 F1。

**既知の難ケース。**

- 数ページ前に紹介されたエンティティを参照する確定記述。
- 橋渡し照応（「車輪」→ 以前に言及された車）。
- 中国語や日本語のようなゼロ照応言語。
- 前方照応（代名詞が参照の前に来る）：「彼女が入ってきた時、メアリーは微笑んだ。」

## 実装する

### ステップ1: 事前学習済みニューラル共参照（AllenNLP / spaCy-experimental）

```python
import spacy
nlp = spacy.load("en_coreference_web_trf")   # experimentalモデル
doc = nlp("Apple announced new products. The company said they would ship soon.")
for cluster in doc._.coref_clusters:
    print(cluster, "->", [m.text for m in cluster])
```

より長い文書では次のような結果が得られる：
- クラスター1: [Apple, The company, they]
- クラスター2: [new products]

### ステップ2: ルールベースの代名詞リゾルバー（教育目的）

stdlibのみの実装は`code/main.py`を参照：

1. 言及を抽出する：固有表現（大文字で始まるスパン）、代名詞（辞書ルックアップ）、確定記述（「the X」）。
2. 各代名詞について、直前のK個の言及を見て以下でスコアリングする：
   - 性/数の一致（ヒューリスティック）
   - 近接性（近い方が優先）
   - 構文的役割（主語が優先）
3. 最高スコアの先行詞をリンクする。

ニューラルモデルとは競合しない。しかし探索空間とエンドツーエンドモデルが行う決定を示している。

### ステップ3: 共参照にLLMを使用する

```python
prompt = f"""Text: {text}

List every pronoun and noun phrase that refers to a person or company.
Cluster them by what they refer to. Output JSON:
[{{"entity": "Apple", "mentions": ["Apple", "the company", "it"]}}, ...]
"""
```

注意すべき2つの失敗モード。まず、LLMは過剰にマージする（2人の異なる人物を指す「彼」と「彼女」を同一視する）。次に、LLMは長文書で言及を暗黙的に落とす。常にスパンオフセットチェックで検証する。

### ステップ4: 評価

標準のconll-2012スクリプトはMUC、B³、CEAF-φ4を計算し、平均を報告する。社内評価では、注釈付きテストセットでのスパンレベルの精度と再現率から始め、言及リンクF1を追加する。

## ピットフォール

- **シングルトン爆発。** 一部のシステムはすべての言及を独自のクラスターとして報告する。B³は緩やか。MUCはこれを罰する。常に3つすべての指標を確認する。
- **長いコンテキストでの代名詞。** 2,000トークンを超える文書でパフォーマンスが約15 F1低下する。慎重にチャンキングする。
- **性別の仮定。** ハードコードされた性別ルールはノンバイナリの参照対象、組織、動物で壊れる。学習済みモデルまたは中立的なスコアリングを使用する。
- **長文書でのLLMドリフト。** 単一のAPI呼び出しは50段落以上にわたって言及を確実にクラスタリングできない。スライディングウィンドウ + マージを使用する。

## 演習

1. **易。** `code/main.py`のルールベースリゾルバーを5つの手作りの段落で実行する。グラウンドトゥルースに対して言及リンクの精度を測定する。
2. **中。** 事前学習済みニューラルcorefモデルをニュース記事で使用する。クラスターを自分の手動注釈と比較する。どこで失敗したか？
3. **難。** coref強化NERパイプラインを構築する：最初にNER、次にcorefクラスターでマージ。100記事でNERのみと比較してエンティティカバレッジの改善を測定する。

## キーワード

| 用語 | 一般的な説明 | 実際の意味 |
|------|------------|----------|
| 言及 | 参照 | エンティティを参照するテキストのスパン（名前、代名詞、名詞句）。 |
| 先行詞 | 「それ」が参照するもの | 後の言及が共参照する前の言及。 |
| クラスター | エンティティの言及 | 同じ現実世界のエンティティを参照するすべての言及のセット。 |
| 照応 | 後方参照 | 後の言及が前の言及を参照する（「彼」→「ジョン」）。 |
| 前方照応 | 前方参照 | 前の言及が後の言及を参照する（「彼が到着した時、ジョンが...」）。 |
| 橋渡し | 暗黙的な参照 | 「車を買った。車輪が悪かった。」（その車の車輪。） |
| CoNLL F1 | リーダーボードの数字 | MUC、B³、CEAF-φ4のF1スコアの平均。 |
