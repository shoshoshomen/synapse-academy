# Flamingoとゲートクロスアテンションによるfew-shot VLM

> DeepMindのFlamingo（2022年）は誰よりも早く2つのことを実現した。単一のモデルが画像、ビデオ、テキストの任意にインターリーブされた列を処理できることを示した。そしてVLMがインコンテキスト学習できることを示した――（画像、キャプション）の3ペアのfew-shotプロンプトを与えるだけで、グラジェントステップなしに新しい画像にキャプションを付ける。メカニズム：ゲートクロスアテンション層をフリーズLLMの既存層の間に挿入し、初期化時にゼロから始まるtanh gateでLLMのテキスト能力を維持する。このレッスンではFlamingoのPerceiver resamplerとゲートクロスアテンションアーキテクチャを読み解く――Geminiのインターリーブ入力とIdefics2のビジュアルトークンの祖先だ。


## 学習目標

- ゲートクロスアテンションがtanh(gate) = 0によって初期化時にフリーズLLMのテキスト能力を維持する方法を説明する。
- Perceiver resamplerを追う：N個の画像パッチ → クロスアテンションによるK個の固定「潜在」クエリ。
- Flamingoが画像の配置を尊重する因果マスキングでインターリーブ画像テキスト列を処理する方法を説明する。
- few-shotマルチモーダルプロンプト構造を再現する（3つの画像キャプション例、その後にクエリ画像）。

## 問題

BLIP-2は32個のビジュアルトークンをフリーズLLMの入力層に渡す。1プロンプトあたり1画像には機能する。しかし「ここに画像A、キャプションを付けよ；ここに画像B、キャプションを付けよ；ここに画像C、キャプションを付けよ」のように*多数の*画像をテキストとインターリーブさせたい場合はどうか？LLMの自己注意は画像トークンとテキストトークンを単一ストリームで処理する必要があり、どの位置がどの画像に注意を向けられるかという問題が煩雑になる。

Flamingoの答え：LLMの入力ストリームを全く変えない。既存のLLMブロックの間に追加のクロスアテンション層を挿入する。テキストトークンは従来通りLLMの因果自己注意を流れる。いくつかのLLMブロックの間に、テキストトークンは新しいゲート層を介して画像特徴にもクロスアテンションする。ゲート（ゼロで初期化）はステップゼロで新しい層がno-opになることを意味する――モデルは事前学習済みLLMとまったく同じように振る舞う。学習が進むにつれゲートが開き、ビジュアル情報が流れ始める。

Flamingoが答えた2つ目の問いは：プロンプトあたり可変数（0、1、または多数）の画像をどう処理するか？Perceiver resampler――可変数のパッチを受け取り固定数のビジュアル潜在トークンを生成する小さなクロスアテンションモジュール。LLMのクロスアテンション層はプロンプト内の画像数に関わらず同じ形状を見る。

## 概念

### フリーズLLM

FlamingoはフリーズしたChinchilla 70B LLMから始まる。700億の重みはすべて未変更。既存のテキスト自己注意とFFNは通常通り動作する。

### Perceiver resampler

プロンプト内の各画像に対して、ViTはNパッチトークンを生成する。Perceiver resamplerはK個の固定学習可能な潜在変数を持つ（Flamingoはk=64を使用）。各resamplerブロックは2つのサブステップだ：

1. クロスアテンション：K個の潜在変数がNパッチトークンに注意を向ける（潜在変数からQ、パッチからK/V）。
2. 潜在変数内での自己注意 + FFN。

6つのresamplerブロック後、出力はViTが生成したパッチ数に関わらずK=64個のビジュアルトークン（次元1024）だ。224×224の画像（196パッチ）と480×480の画像（900パッチ）はどちらも64個のresamplerトークンとして出力される。

ビデオの場合、resamplerは時間的に適用される：各フレームのパッチが64個の潜在変数を生成し、時間的位置エンコーディングでt=0とt=Nを区別できる。完全なビデオはT×64個のビジュアルトークンになる。

### ゲートクロスアテンション

フリーズLLMのM層ごとに（Flamingoはm=4を使用）、新しいゲートクロスアテンションブロックを挿入する：

```
x_after_llm_block = llm_block(x_before)
cross = cross_attn(x_after, resampler_output)
gated = tanh(alpha) * cross + x_after
x_before_next_block = gated
```

- `alpha`はゼロで初期化される学習可能なスカラー。
- `tanh(0) = 0`なので初期化時ゲートブランチの寄与はゼロ。
- `alpha`がゼロから離れるにつれクロスアテンションの寄与が滑らかに増える。
- 残差接続は完全に開いたゲートでもLLMのテキスト表現を上書きしないことを意味する；視覚情報をその上に追加するだけだ。

これがFlamingoで最も重要な設計選択だ：視覚的条件付けは加算的で、ゲート付きで、初期化時にゼロだ。ステップ0のFlamingoはテキストのみの入力で完璧なChinchilla 70Bだ。

### インターリーブ入力のためのマスクされたクロスアテンション

「<画像A> キャプションA <画像B> キャプションB <画像C> ?」のプロンプトでは、各テキストトークンは列内でそれより前に来た画像だけを見るべきだ。クロスアテンションマスクが強制する：位置`t`のテキストトークンは画像インデックス`i < i_t`の画像resamplerトークンにのみ注意を向けられ、ここで`i_t`は位置`t`の前にある最も最近の画像だ。「前の最後の画像のみを見る」または「前のすべての画像を見る」はどちらも有効な選択；Flamingoは前者を選んだ。

### インコンテキストfew-shot学習

Flamingoのプロンプトはこのようなものだ：

```
<image1> A photo of a cat. <image2> A photo of a dog. <image3> A photo of a
```

モデルは補完パターンを見て「bird」（またはimage3が示すもの）を出力する。グラジェントステップなし。フリーズLLMのインコンテキスト学習能力がゲートクロスアテンションを通じて維持される――これが論文のオチで、なぜ重要かの理由だ。

### 学習データ

Flamingoは3つのデータセットで学習した：

1. MultiModal MassiveWeb（M3W）：インターリーブされた画像とテキストを持つ4300万ウェブページ、読書順を再構築。
2. 画像テキストペア（ALIGN + LTIP）：44億ペア。
3. ビデオテキストペア（VTP）：2700万の短いビデオクリップ。

OBELICS（2023年）はインターリーブWebコーパスのオープン再現で、Idefics、Idefics2、ほとんどのオープンな「Flamingo類似」モデルがこれで学習する。

### OpenFlamingoとOtter

OpenFlamingo（2023年）はオープン再現だ。アーキテクチャは同一（フリーズLlamaまたはMPT上のPerceiver resampler + ゲートクロスアテンション）。3B、4B、9Bのチェックポイント。品質は小さなベースLLMとデータが少ないためFlamingoに劣る。

Otter（2023年）はOpenFlamingoの上にMIMIC-IT（マルチモーダル命令のデータセット）での命令チューニングを構築し、ゲートクロスアテンションが命令追従にも機能することを示した。

### 派生

- Idefics / Idefics2 / Idefics3：Hugging Faceのゲートクロスアテンション系統、段階的に簡素化（Idefics2は適応プーリングによる直接パッチトークンを採用しresamplerを廃止）。
- FlamingからChameleonへの移行：2024年までに多くのチームがearly-fusion（レッスン12.11）に移行；Flamingoスタイルのゲートクロスアテンションはバックボーンのフリーズが必要な場合にプロダクションで残る。
- Geminiのインターリーブ入力：概念的にFlamingoのインターリーブフォーマットの柔軟性を継承するが、正確なメカニズムは非公開。

### BLIP-2との比較

| | BLIP-2 | Flamingo |
|---|---|---|
| ビジュアルブリッジ | 入力での1回のQ-Former | M層ごとのゲートクロスアテンション |
| ビジュアルトークン | 1画像あたり32個 | クロスアテンション層ごとに1画像あたり64個 |
| フリーズLLM | あり | あり |
| few-shotインコンテキスト | 弱い | 強い――論文の目玉 |
| インターリーブ入力 | ネイティブサポートなし | あり、設計目標 |
| 学習データ | 1.3億ペア | 13億ペア + 4300万インターリーブページ |
| パラメータ数 | 1.88億学習済み | 約100億学習済み（クロスアテンション層） |
| 計算量 | 8枚のA100で数日 | 何千ものTPUv4で数週間 |

シングル画像VQAの予算にはBLIP-2を選べ。インターリーブ、few-shot、マルチ画像推論にはFlamingo/Idefics2を選べ。

## 使ってみる

`code/main.py`のデモ内容：

1. 36個のフェイクパッチトークン上の8個の学習可能な潜在変数を持つPerceiver resampler（pure Pythonクロスアテンション）。
2. `alpha = 0`のゲートクロスアテンションステップ → 出力 = 入力（LLM変更なし）、次に`alpha = 2.0` → ビジュアル寄与が混合。
3. 「(画像1) (テキスト1) (画像2) (テキスト2)」列の2D注意マスクを生成するインターリーブマスクビルダー。

## 成果物を出す

このレッスンは`outputs/skill-gated-bridge-diagnostic.md`を生成する。オープンVLMの設定（resamplerあり/なし、クロスアテンション頻度、ゲートスキーム）が与えられた場合、Flamingo系統の要素を特定してフリーズ戦略を説明する。ファインチューニングがテキスト性能を低下させた理由のデバッグに役立つ（答え：ゲートが早すぎて大きく開いた）。

## 演習

1. Flamingo-9Bのビジュアルパラメータ数を計算せよ：9B LLM + 1.4Bゲートクロスアテンション層 + 64M resampler。全パラメータのうち何パーセントが学習済みか？

2. ゲート残差`y = tanh(alpha) * cross + x`をPyTorchで実装せよ。`alpha=0`で`y==x`が初期化時に完全に成立することを実験的に示せ。

3. OpenFlamingo Section 3.2（arXiv:2308.01390）で、各プロンプトが異なる画像数を持つ場合にバッチ内の複数画像を処理する方法を読め。パディング戦略を説明せよ。

4. Flamingoのクロスアテンションマスクが前のすべての画像ではなく*最後の*前の画像にのみテキストトークンを注意させる理由は？Flamingo論文Section 2.4を読んでトレードオフを説明せよ。

5. インコンテキストfew-shot：新しいFlamingo変種に「画像 → メインオブジェクトの色」の4つの例のプロンプトを構築せよ。例の数を0から8に変化させた場合の精度パターンを説明せよ。

| 用語 | よく言われること | 実際の意味 |
|------|----------------|------------------------|
