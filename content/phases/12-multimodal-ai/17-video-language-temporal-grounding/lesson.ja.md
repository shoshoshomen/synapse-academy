# 動画言語モデル：時間トークンとグラウンディング

> 動画は写真の積み重ねではない。5秒のクリップには、画像モデルが表現できない因果的な順序、動作動詞、イベントのタイミングがある。Video-LLaMA（Zhang et al.、2023年6月）は、音声視覚グラウンディングを持つ最初のオープン動画LLMを公開した。VideoChatとVideo-LLaVAはそのパターンをスケールさせた。2025年までにQwen2.5-VLのTMRoPEがフロンティアの独自モデルとのギャップを縮めた。各システムは時間トークンを異なる方法で解決した。クリップごとのQフォーマー、フレームごとの連結プーリング、トークンごとのTMRoPE。このレッスンではパターンを読み解き、均一対動的FPSフレームサンプラーを構築し、時間グラウンディングタスクで評価する。


## 学習目標

- 時間位置エンコーディングが視覚エンコーダーとは独立して動画VLMの性能を変える理由を説明する。
- 均一、動的FPS、イベント駆動のフレームサンプリングを、1秒あたりのトークン数対グラウンディング精度で比較する。
- クリップごとのQフォーマー（Video-LLaMA）対フレームごとのプーリング（Video-LLaVA）対トークンごとのMRoPE（Qwen2.5-VL）の設計を説明する。
- 4つの動画ベンチマークを挙げる：VideoMME、TempCompass、EgoSchema、Video-MMMU。

## 問題設定

30FPSの1分間の動画は1800フレームだ。ViT-B（224）でフレームあたり196ビジュアルトークンとすると、352kトークンになる。2024年代のどのLLMコンテキストよりも大きい。

3つの削減戦略が存在する。

1. フレームをサブサンプリングする（コンテンツによって1〜8FPS）。
2. 各フレームのパッチトークンを積極的にプーリングする（3x3または4x4双線形プーリング）。
3. 16フレームクリップを取り込んで64トークンを出力するQフォーマーで圧縮する。

各トレードオフは異なる。サブサンプリングは時間的詳細を失う。プーリングは空間的詳細を失う。Qフォーマーは両方を少し失うが、トークンを節約する。

時間位置エンコーディングはもう一つの軸だ。モデルはフレーム5がフレーム6より前に来たことをどうやって知るのか？選択肢には、単純な1D時間RoPE（Video-LLaMA）、学習済み時間埋め込み（Video-LLaVA）、TMRoPE（Qwen2.5-VL、完全3D）がある。

## 概念

### Video-LLaMA：クリップごとのQフォーマー + 音声ブランチ

Video-LLaMA（2023年）は最初のオープン動画LLMだった。アーキテクチャ：

- 2FPSの16フレームクリップ（8秒）。
- フレームごとのViT特徴 → 16フレームすべてにクロスアテンションするビデオQフォーマー → 32個の学習クエリ → LLM。
- 並列音声ブランチ：波形 → ImageBind音声エンコーダー → 音声Qフォーマー → 32クエリ → LLM。

強み：音声視覚の共同推論。弱み：固定クリップ長、任意の時間グラウンディングなし。

### VideoChatとVideo-LLaVA

VideoChatはVideo-LLaMAのアイデアを維持したが、音声を削除してシンプル化した。Video-LLaVA（Lin et al.、2023年）は画像と動画フレームの両方で単一のビジュアルエンコーダーを訓練し（「プロジェクション前のアライメント」）、統一された表現を提供した。どちらも凍結CLIPエンコーダー + MLP + LLMだ。

どちらも長い動画には対応しない。どちらも8〜16フレームのシステムだ。

### Qwen2.5-VLとTMRoPE

Qwen2.5-VLはTMRoPEを導入した。時間モダリティ回転位置埋め込み（Temporal-Modality Rotary Position Embedding）。各パッチトークンはtが実際のタイムスタンプ（フレームインデックスではない）である(t, h, w)位置を持つ。

単純な時間埋め込みとの主な違い：

- フレームインデックスではなく絶対時刻。モデルは「15フレーム目」ではなく「4.2秒時点」と認識する。
- クリップごとではなくトークンごとの回転。各ビジュアルトークンはそのタイムスタンプで独立して回転する。
- 動的FPSとの互換性。ここで2FPS、あちらで4FPSとサンプリングしても、TMRoPEは不均一な間隔をネイティブに処理する。

TMRoPEにより「猫がジャンプするのは何秒か？」というクエリが可能になる。モデルは「4.2秒」と出力できる。Video-LLaMAは「クリップの早い段階で」としか言えなかった。

### フレームサンプリング戦略

均一：持続時間にわたってNフレームを均等にサンプリングする。シンプルだが動きのピークを失う。

動的FPS：動きの強度に基づいてアダプティブにサンプリングする。オプティカルフローまたはフレーム差分がより高密度なサンプリングのために高動き部分を選ぶ。Qwen2.5-VLはこれで訓練される。

イベント駆動：軽量な検出器を実行し、アクションが起きる場所でより多くサンプリングする。VideoAgentが使用する。

キーフレーム + コンテキスト：ショット境界 + 隣接する数フレームをサンプリングする。映画的コンテンツに使用される。

### フレームごとのプーリング

1FPS・フレームあたり576トークンで、5分間のクリップは172,800トークンになる。Qwen2.5-VL-72Bの128kコンテキストで処理可能だが高コストだ。

3x3双線形プーリングでフレームあたり64トークンに削減 → 5分で19,200トークン。ほとんどのタスクのスイートスポット。

空間的詳細よりも重要性が低いエージェントワークフローでは、さらに積極的にプーリングする（6x6 → フレームあたり16トークン）。

### 4つの動画ベンチマーク

- VideoMME：短い + 中程度 + 長い動画、包括的な動画理解。
- TempCompass：「前」/「後」の質問による細粒度の時間推論。
- EgoSchema：長い水平線の一人称視点動画。
- Video-MMMU：マルチモーダル多分野の動画質問。

完全な動画VLM評価はすべての4つを評価する。それらは異なる軸を強調する。TempCompassは順序付けについてのみ、EgoSchemaは3分以上の推論、VideoMMEは持続時間にまたがる。

### グラウンディング出力形式

時間グラウンディングの出力形式：

- 自由テキスト：「猫は4秒あたりでジャンプします。」解析しやすいが不正確。
- 構造化JSON：`{"event": "jump", "start": 4.1, "end": 4.3}`。Qwen2.5-VLはこれを訓練する。
- トークンベース：回答にインターリーブされた特殊な`<time>4.1</time>`トークン。Qwen2.5-VLの内部形式。

トークンベースは下流での使用に最も正確だ。Qwen2.5-VLのJSON出力形式は直接解析できる。

### 2026年のベストプラクティス

2026年の動画VLMでは：

- エンコーダー：M-RoPEまたはTMRoPEを持つSigLIP 2（Qwen2.5-VL）。
- フレームサンプリング：動的FPS（動きによって1〜4）、最大フレーム数上限あり。
- フレームごとのプーリング：3x3双線形。
- 出力：時刻 + イベントフィールドを持つ構造化JSON。
- ベンチマーク：一般用途にVideoMME + TempCompass。長い水平線にはEgoSchema。

## 使ってみる

`code/main.py`に含まれるもの：

- 均一と動的FPSフレームサンプラー。
- おもちゃの時間グラウンディング評価器：時刻Tでの「正解」イベントとモデル出力を与えられたとき、許容誤差で精度をスコアリングする。
- Video-LLaMA（16フレーム、Qフォーマー）、Video-LLaVA（8フレーム、MLP）、Qwen2.5-VL（動的FPS + TMRoPE）の比較。

## 成果物を出す

このレッスンでは`outputs/skill-video-vlm-frame-planner.md`を作成する。動画タスク（監視、アクション認識、時間グラウンディング、要約）を与えられたとき、フレームサンプラー、プーリングファクター、出力形式、期待される精度水準を選択する。

## 演習

1. 3分間の料理デモに対して、均一対動的FPSを選択せよ。トークン数で正当化せよ。

2. TMRoPEは単純な時間埋め込みテーブルにはできない何を具体的に追加するか？

3. VLMが学習して出力できる時間グラウンディングのJSONスキーマを書け。エラーケースを含めよ。

4. Video-LLaVAのセクション3「プロジェクション前のアライメント」を読め。なぜこれが別々の画像と動画エンコーダーを訓練するよりも優れているのか？

5. VideoMMEリーダーボードを考慮して、2026年時点のトップオープンモデルとトップ独自モデルのギャップはどれくらいか？そのギャップはどの程度が時間エンコーディングに起因し、どの程度がベースLLMスケールに起因するか？

## キーワード

| 用語 | よく使われる表現 | 実際の意味 |
|------|-----------------|------------|
| 時間グラウンディング | "時刻特定の回答" | VLMがイベントが発生する特定のタイムスタンプ範囲を出力する |
| TMRoPE | "時間マルチモーダルRoPE" | 絶対タイムスタンプを持つ3D回転位置。Qwen2.5-VLが使用 |
| 動的FPS | "動き認識サンプリング" | 高動き部分でより多くフレームをサンプリングし、静的な部分では少なくする |
| フレームプーリング | "フレームごとの空間圧縮" | LLMの前に双線形補間でフレームあたりのパッチを削減する |
| 動画Qフォーマー | "クリップコンプレッサー" | Nフレームを学習済みクエリKにマッピングするクロスアテンションボトルネック |
| VideoMME | "動画ベンチ" | 包括的な短/中/長動画ベンチマーク、2500以上のサンプル |
