# LLaVAとビジュアル命令チューニング

> LLaVA（2023年4月）は地球上で最もコピーされたマルチモーダルアーキテクチャだ。BLIP-2のQ-Formerを2層MLPに置き換え、Flamingoのゲートクロスアテンションをナイーブなトークン連結に置き換え、テキストのみのキャプションからGPT-4が生成した15万8千件のビジュアル命令ターンで学習した。2023年から2026年にかけてVLMを構築したすべての実践者は何らかのLLaVA変種を構築した。LLaVA-1.5がAnyResを追加した。LLaVA-NeXTが解像度を引き上げた。LLaVA-OneVisionが画像、マルチ画像、ビデオを1つのレシピに統合した。このレッスンではそのレシピを読み解き、プロジェクターを実装し、「シンプルな方が勝った」理由を説明する。


## 学習目標

- ViTパッチ埋め込み（次元1024）をLLMの埋め込み次元（次元4096）にマッピングする2層MLPプロジェクターを構築する。
- LLaVAの2段階レシピを追う：(1)55万8千キャプションペアでのプロジェクター整合、(2)GPT-4生成の15万8千ターンでのビジュアル命令チューニング。
- 画像トークンプレースホルダー、システムプロンプト、ユーザー/アシスタントターンを持つLLaVA形式のプロンプトを構築する。
- Q-Formerのトークンバジェット上の優位性にもかかわらず、コミュニティがなぜQ-FormerからMLPに移行したかを説明する。

## 問題

BLIP-2のQ-Former（レッスン12.03）は画像を32トークンに圧縮する。クリーンで効率的でベンチマーク良好。しかし2つの問題がある。

第一に、Q-Formerは学習可能だがその損失は最終タスクではない。ステージ1はITC+ITM+ITGを学習する。ステージ2はLM損失を学習する。クエリはLLMがデコードしなければならない中間表現を学習する。情報はボトルネックで失われる。

第二に、Q-Formerは1.88億パラメータを要し、LLaVAの2023年のスケールではターゲットLLMと共同設計する必要があった。LLMを変えると、Q-Formerを再学習する。ビジョンエンコーダーを変えると、再学習する。すべての組み合わせが別々のR&Dプロジェクトになる。

LLaVAの答えはそのシンプルさが恥ずかしいほどだった：ViTの576パッチトークンを取り、各トークンを2層MLP（`1024 → 4096 → 4096`）に通し、576個すべてをLLMの入力列にダンプする。ボトルネックなし。ステージ1の奇妙な目標での事前学習なし。ただ直接LM損失でMLPを学習させる。

データはどこから来るのか？LLaVAの第二の洞察：GPT-4（テキストのみ）を使って命令データを生成する。COCO画像のテキスト説明（5つの人間キャプション + バウンディングボックスリスト）をGPT-4に渡し、会話、説明、複雑な推論質問を生成させる。15万8千件の命令応答ターンを無料で。人間のアノテーションなし。

結果：8枚のA100で1日学習するVLMで、MMMUでFlamingoを上回り、コミュニティが拡張できるオープンチェックポイントをリリースした。2023年末には50以上のフォークを生んだ。

## 概念

### アーキテクチャ

LLaVA-1.5（13B）：
- ビジョンエンコーダー：CLIP ViT-L/14 @ 336（ステージ1ではフリーズ、ステージ2では任意でアンフリーズ）。
- プロジェクター：GELU活性化付き2層MLP、`1024 → 4096 → 4096`。
- LLM：Vicuna-13B（後にLlama-3.1-8B）。

画像 + テキストプロンプトのフォワードパス：

```
img -> ViT -> 576 patches of dim 1024
patches -> MLP -> 576 tokens of dim 4096
prompt: system + "<image>" placeholder + user question
replace <image> token with the 576 projected tokens
feed the full sequence to the LLM
decode response
```

画像はLLMコンテキストの576トークンを占有する。2048コンテキストでは1472トークンがテキスト用に残る。32kコンテキストでは誤差範囲内だ。

### ステージ1：プロジェクター整合

ViTをフリーズ。LLMをフリーズ。2層MLPのみを学習させる。データセット：55万8千の画像キャプションペア（LAION-CC-SBU）。損失：射影された画像トークンを条件としたキャプションの言語モデリング。

バッチ128で1エポック、数時間で完了する。プロジェクターがViT空間からLLM空間へのマッピングを学習する。タスク固有の教師信号なし。

### ステージ2：ビジュアル命令チューニング

プロジェクターをアンフリーズ（引き続き学習可能）。LLMをアンフリーズ（通常は完全に、時々LoRA）。15万8千件のビジュアル命令ターンで学習。

命令データが肝心だ。Liuらはこれを次の方法で生成した：
1. COCO画像を取る。
2. テキスト説明を抽出する（5つの人間キャプション + バウンディングボックスリスト）。
3. 3つのプロンプトテンプレートでGPT-4に送る：
   - 会話：「この画像についてユーザーとアシスタントの対話を生成せよ」
   - 詳細な説明：「画像の豊かで詳細な説明を与えよ」
   - 複雑な推論：「画像について推論を必要とする質問を作り、それに答えよ」
4. GPT-4の出力を（命令、応答）ペアに解析する。

これは一切画像に直接触れない――テキスト説明のみ。GPT-4はもっともらしい画像コンテンツを「幻覚」する。いくらかのノイズはあるが機能した：15万8千ターンは対話を解放するのに十分だった。

### コミュニティがこれをコピーした理由

- チューニングするステージ1固有の損失がない。最初からLM損失。
- プロジェクターは数日ではなく数時間で学習する。
- LLMを交換できる（LLaVA-Llama2、LLaVA-Mistral、LLaVA-Llama3）：プロジェクターを再学習するだけ。
- ビジュアル命令データパイプラインはGPT-4を使用し、新しいドメイン向けに再生成が安価。

### LLaVA-1.5とLLaVA-NeXT

LLaVA-1.5（2023年10月）が追加：
- 学術タスクデータ（VQA、OKVQA、RefCOCO）を命令チューニングに混合。
- より良いシステムプロンプト。
- 2048 → 32kコンテキスト。

LLaVA-NeXT（2024年1月）が追加：
- AnyRes：高解像度画像を2×2または1×3の336×336クロップグリッドに分割し、1つのグローバル低解像度サムネイルを追加。各クロップが576トークンになり；合計で約2880ビジュアルトークン/画像。OCRとチャートタスクが向上。
- ShareGPT4V（高品質GPT-4Vキャプション）とのより良い命令データ混合。
- より強力なベースLLM（Mistral-7B、Yi-34B）。

### LLaVA-OneVision

レッスン12.08がOneVisionを詳しく説明する。短いバージョン：同じプロジェクターだが、シングル画像、マルチ画像、ビデオを共有ビジュアルトークンバジェットで1モデルにカバーするカリキュラムで学習。

### Q-Formerとの比較

| | Q-Former (BLIP-2) | MLP (LLaVA) |
|---|---|---|
| 1画像あたりのビジュアルトークン | 32 | 576（ベース）または2880（AnyRes） |
| 学習可能パラメータ | 1.88億 + LM | 4000万 + LM |
| ステージ1損失 | ITC+ITM+ITG | LMのみ |
| LLMのドロップイン | 再学習が必要 | 最小限の再学習で交換 |
| マルチ画像 | 不自然 | 自然（連結） |
| ビデオ | 不自然 | 自然（フレームごとの連結） |
| トークンバジェット | 小さい | 大きい |

MLPはシンプルさとトークンの柔軟性で勝つ。Q-Formerはトークンバジェットで勝つ。2023年末にはトークンバジェットがもはや制約ではなくなり（LLMコンテキストが32k〜128k+に成長）、シンプルさが支配した。

### プロンプト形式

```
A chat between a curious human and an artificial intelligence assistant. The assistant gives helpful, detailed, and polite answers to the human's questions. USER: <image> Describe this image in detail. ASSISTANT: The image shows ...
```

`<image>`はプレースホルダートークンだ。トークン化の前に576個のビジュアルトークン（またはAnyResで2880個）に置き換えられる。トークナイザーは学習時よりわずかに長い列を見るが、ステージ1で教えたためLLMは新しい入力を処理できる。

### パラメータ経済性

LLaVA-1.5-7Bの内訳：
- CLIP ViT-L/14 @ 336：3億パラメータ（ステージ1でフリーズ、ステージ2で多くの場合アンフリーズ）。
- プロジェクター（2×線形）：約2200万学習可能。
- Llama-7B：70億。
- 合計：73億パラメータ。ステージ2での学習可能：完全70億 + 2200万プロジェクター。

ステージ2の学習コスト：8×A100で約20時間。これが重要な数字だ――1日、1ノード、再現可能。それがLLaVAが広まった理由だ。

## 使ってみる

`code/main.py`の実装内容：

1. pure Pythonによる2層MLPプロジェクター（トイスケールで次元16→32→32）。
2. プロンプト構築パイプライン：システムプロンプト + N個の射影トークンに置き換えられた`<image>` + ユーザーターン + アシスタント生成プレースホルダー。
3. 576トークンのビジュアルブロックがLLMコンテキスト（2k / 32k / 128k）の何パーセントを占めるかを視覚化するビジュアライザー。

## 成果物を出す

このレッスンは`outputs/skill-llava-vibes-eval.md`を生成する。LLaVAファミリーのチェックポイントが与えられた場合、10プロンプトのvibseval スイート（キャプション3つ、VQA3つ、推論2つ、拒否2つ）を実行して人間が読めるスコアカードを報告する。ベンチマークではなく；プロジェクターとLLMがうまく接続されていることを確認するスモークテストだ。

## 演習

1. `1024 → 4096 → 4096`の2層MLPプロジェクターの学習可能パラメータ数を計算せよ。GELUとバイアスを含めると、LLaVA-13Bの何パーセントを占めるか？

2. 「拒否」ケース（画像に個人が含まれる）のLLaVAプロンプトを構築せよ。予想されるアシスタントの応答を書け。LLaVAがゼロショットでなぜ拒否すべきで、拒否を強化するにはどんな学習データが必要か？

3. LLaVA-NeXTブログのAnyResセクションを読め。AnyResで1344×672の画像のビジュアルトークン数を計算せよ。336×336での基本576トークンと比べよ。

4. LLaVAのステージ1プロジェクターはキャプションのLM損失で学習される。ステージ1をスキップしてステージ2（ビジュアル命令チューニング）に直接行くとどうなるか？Prismatic VLMsのアブレーション（arXiv:2402.07865）で答えを引用せよ。

5. LLaVA-Instruct-150kはCOCOキャプションを持つGPT-4を使って命令を生成する。新しいドメイン（医療X線、衛星画像）向けの4ステップのデータパイプラインを説明せよ。各ステップで何が問題になりうるか？

## キーワード

| 用語 | よく言われること | 実際の意味 |
|------|----------------|------------------------|
| プロジェクター | "MLPブリッジ" | GELU付き2層MLPでViT次元をLLM次元にマッピング |
| 画像トークン | "<image>プレースホルダー" | 推論前にN個の射影ビジュアルトークンに置き換えられるプロンプトマーカー |
| ビジュアル命令チューニング | "LLaVAステージ2" | GPT-4生成の（画像、命令、応答）トリプレットでの学習 |
| ステージ1整合 | "プロジェクター事前学習" | ViTとLLMをフリーズし、キャプションのLM損失でプロジェクターを学習 |
| AnyRes | "マルチクロップタイリング" | 高解像度画像をタイルグリッドに分割し、各タイルのビジュアルトークンを連結 |
| LLaVA-Instruct | "GPT-4生成" | COCOキャプション + GPT-4から合成された15万8千件の命令応答ペア |
| ビジョンエンコーダーのフリーズ | "バックボーンロック" | CLIPの重みはステージ1では更新されず、ステージ2でも更新されないことが多い |
| ShareGPT4V | "より良いキャプション" | GPT-4Vが生成した100万件の密なキャプション；より高品質な整合に使用 |
| VQA | "ビジュアル質問応答" | 画像についての自由形式の質問に答えるタスク |
