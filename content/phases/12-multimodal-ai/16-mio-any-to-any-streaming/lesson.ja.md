# MIOと任意対任意ストリーミングマルチモーダルモデル

> GPT-4oが提供するプロダクトは、ほとんどのオープンモデルが再現できないものだ：声を聞き、映像を見て、リアルタイムで応答するエージェント。2024年末のオープンエコシステムの回答がMIO（Wang et al.、2024年9月）だ。MIOはテキスト、画像、音声、音楽をトークン化し、1つの因果トランスフォーマーでインターリーブされた系列を学習し、任意のモダリティから任意のモダリティへと生成する。AnyGPT（Zhan et al.、2024年2月）が概念実証だったとすれば、MIOはそのスケールアップ版であり、Unified-IO 2（Allen AI、2023年12月）は視覚 + 行動グラウンディングを持つ従兄弟だ。このレッスンでは任意対任意のパターンを読み解く。4つのトークナイザー、1つのトランスフォーマー、ストリーミングフレンドリーなデコード。


## 学習目標

- テキスト、画像、音声、音楽のトークンを衝突なく収容する共有語彙を設計する。
- SEED-Tokenizer（画像）とSpeechTokenizer残差VQ（音声）を圧縮率と再構成のトレードオフで比較する。
- 任意対任意の生成を構築する4段階カリキュラムを説明する。
- 3つのオープンな任意対任意のレシピとその主なトレードオフを挙げる：MIO、AnyGPT、Unified-IO 2。

## 問題設定

統合マルチモーダルモデルは主張しやすく、大規模に構築するのは難しい。2024年までの「任意対任意」システムのほとんどはパイプライン型だった。視覚モデル → テキスト表現 → 音声モデル → 音声。各ホップで情報が失われ、遅延が増し、学習が複雑になる。GPT-4oのデモ動画は、1秒未満の応答でシングルモデルの代替を示した。オープンシステムはその後何ヶ月も遅れを取った。

エンジニアリング上の課題：

- トークナイザーはあらゆるモダリティに対して存在し、再構成のためにほぼ無損失で圧縮し、トランスフォーマーが消費できる速度でトークンを生成しなければならない。
- 単一の語彙はテキスト（32k以上）、画像（16k以上）、音声（4k以上）、音楽（8k以上）のためのスペースを割り当てなければならない。最低でも4万以上のエントリが必要だ。
- 学習データはすべての入出力ペア（テキスト→画像、画像→音声、音声→画像など）をカバーするか、モデルが組み合わせを行う必要がある。
- 推論は会話レイテンシ（最初の音声バイトまでの時間500ms未満）のために十分高速に出力トークンをストリーミングしなければならない。

## 概念

### 4つのモダリティのための4つのトークナイザー

MIOのトークナイザースタック：

- テキスト：標準BPE、語彙約32000。
- 画像：SEED-Tokenizer（2023年）— 離散コードブックを持つ量子化VAE、4096エントリ、画像あたり32x32トークン。
- 音声：SpeechTokenizer残差VQ（2023年）— 16kHz波形を8つの階層的コードブックにエンコード。第1レベルは粗いコンテンツ、後のレベルはプロソディとスピーカーアイデンティティを追加する。
- 音楽：同様の残差VQ（MetaのMusicGen / Encodecファミリー）、4〜8コードブック。

各モダリティは整数トークンを生成する。トークンは共有語彙でIDの範囲が重ならない。

```
テキスト:   0..31999
画像:       32000..36095  (4096画像トークン)
音声:       36096..40191  (4096音声ベーストークン、残差レイヤー含む)
音楽:       40192..48383  (8192音楽トークン)
区切り:     48384..48390  (<image>, <speech>, <music>, </...>等)
```

合計：約48kの語彙。入力埋め込みと出力プロジェクションはそのすべてにまたがる。

### ストリーミングデコード

音声生成は残差VQを使用する。トランスフォーマーはベース（レイヤー0）の音声トークンを予測し、並列デコードされた残差量子化器が後続のレイヤーを予測する。各レイヤー0トークンは16kHzで約50msの音声に相当する。

ストリーミングパターン：

1. ユーザーがマイクに話しかける。リアルタイム音声トークナイザーが50msごとに音声トークンを出力する。
2. MIOはトークンが届くたびに消費する（プロンプトのプリフィルと段階的なフォワード）。
3. 生成された出力トークンはストリームとして出力され、並列音声デコーダーがそれらを約50〜150msのレイテンシで音声サンプルに変換する。
4. 最初の音声バイトまでの時間：MIOの論文では約300〜500ms、GPT-4oの約250msに近づく。

Mini-Omni（arXiv:2408.16725）、GLM-4-Voice（arXiv:2412.02612）、Moshi（arXiv:2410.00037）は補完的なストリーミング音声LLM設計だ。特にMoshiはシングルGPUで160msのラウンドトリップを達成する。

### 4段階カリキュラム

MIOの学習カリキュラム：

1. ステージ1 — アライメント。大規模なモダリティペアコーパス：テキスト-画像、テキスト-音声、テキスト-音楽。各ペアはそれ自身のトークン語彙セグメントを使用する。共有語彙を訓練する。
2. ステージ2 — インターリーブ。複数モダリティのインターリーブされたドキュメント（画像と映像を含むブログ、トランスクリプトを含むポッドキャストなど）。クロスモダリティコンテキストを訓練する。
3. ステージ3 — 音声強化。テキスト能力を失わずに音声品質を高めるための追加音声データ。
4. ステージ4 — SFT。モダリティにまたがるインストラクションチューニング：VQA、キャプション生成、ナレーション、音声対音声対話。

ステージを飛ばすと特定の能力が低下する。ステージ2を飛ばすとモデルはクロスモダリティコンテキストを失い、ステージ3を飛ばすと音声が劣化する。

### 視覚的思考連鎖

MIOは視覚的思考連鎖（chain-of-visual-thought）を導入する。モデルは推論ステップとして中間画像トークンを出力する。「猫は木を登っているか？」という問いに対して、モデルは：

1. シーンを描画する`<image>`トークンを出力する（入力画像またはスケッチから）。
2. スケッチを分析するテキストを出力する。
3. 最終回答を出力する。

描画された中間画像がメモ帳として機能する。空間推論タスクのベンチマークが改善する。このアイデアはテキスト推論における思考連鎖を反映している。

### 任意対任意の競合製品

- AnyGPT（arXiv:2402.12226）：4つのモダリティ（テキスト、画像、音声、音楽）、同様の設計。
- Unified-IO 2（arXiv:2312.17172）：視覚アクション出力、深度、法線を追加。タスクの多様性が高く、スケールは小さい。
- NExT-GPT（arXiv:2309.05519）：LLM + モダリティ固有の拡散デコーダー。シングルモデルアプローチではない。
- CoDi（arXiv:2305.11846）：合成可能な拡散。共有潜在変数を通じた任意対任意。

MIOは純粋なトークン任意対任意に最も近い。AnyGPTはその概念的な先祖だ。

### レイテンシバジェット

会話型プロダクトでは、すべてのコンポーネントのレイテンシが重要だ。

- マイクから音声トークンまで：約50ms。
- プリフィル（音声トークン + 履歴）：8Bモデルで約100ms。
- 最初の出力トークン：約50ms。
- 並列残差VQ + 音声デコーダー：約100〜150ms。

最初の音声バイトまでの合計時間：最小約300ms。GPT-4oは約250msを主張する。Moshiは160msを主張する。MIO/AnyGPTは公開ベンチマークで400〜600msの範囲にある。

### 任意対任意が依然として難しい理由

2026年においてもオープンな任意対任意モデルはクローズドモデルに2つの軸で遅れを取っている。

- 音声品質。残差VQトークナイザーは損失があり、会話音声はElevenLabsクラスの音声と比べてロボット的に聞こえる。
- クロスモダリティ推論。「見えているものについて歌って」とモデルに頼むと、純粋な視覚タスクよりもまだ失敗することが多い。

これらはオープンな研究課題だ。Qwen3-Omni（レッスン12.20）は2025年における最も進んだオープンな試みだ。

## 使ってみる

`code/main.py`：

- 4つのモダリティ語彙割り当てを定義して出力する。
- マルチモーダル入力のリスト（テキスト、画像、音声クリップ、音楽）をトークナイザールーターを通じてルーティングする。
- レイテンシカウントを含むテキスト対音声応答のストリーミングデコードをシミュレートする。
- エンコーダー、プリフィル、デコーダーのレイテンシを考慮した最初の音声バイトまでの期待時間を計算する。

## 成果物を出す

このレッスンでは`outputs/skill-any-to-any-pipeline-auditor.md`を作成する。会話型プロダクト仕様（入力モダリティ、出力モダリティ、レイテンシ目標）を与えられたとき、MIOファミリーの設計選択を監査してレイテンシバジェットを計算する。

## 演習

1. プロダクトは音声入力を受け付け、音声出力を返す。エンドツーエンドのレイテンシバジェット目標はいくらか？時間を消費するコンポーネントをリストアップせよ。

2. SpeechTokenizer残差VQは8つのコードブックを使用する。残差レベルの並列デコードがなぜ必要か（逐次的ではなく）、そしてそれがもたらすレイテンシ節約について提案せよ。

3. 語彙は32kのテキスト + 4kの画像 + 4kの音声を持つ。8kの音楽と約10個の区切り記号を追加する。隠れ次元4096での埋め込み行列のパラメータコストはいくらか？

4. 視覚的思考連鎖は中間画像を出力する。どのような質問が利益を得るか？どのような質問が余分なトークンによって損をするか？

5. Moshi（arXiv:2410.00037）を読め。その「内なる独り言」技術を説明し、MIOの視覚的思考連鎖と比較せよ。
