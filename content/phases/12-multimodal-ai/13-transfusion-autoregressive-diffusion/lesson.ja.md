# Transfusion：1つのTransformerで自己回帰テキスト + 拡散画像

> ChameleonとEmu3はすべてを離散トークンに賭けた。機能するが、量子化のボトルネックが見える――画像品質は連続空間拡散モデルを下回る水準で頭打ちになる。Transfusion（Meta、Zhouら、2024年8月）は反対の賭けをする：画像を連続のままにし、VQ-VAEを完全に廃棄し、2つの損失を持つ1つのTransformerを学習させる。テキストトークンは次トークン予測を得る。画像パッチはflow-matching / 拡散損失を得る。両方の目標が同じ重みを最適化する。Stable Diffusion 3の基盤にあるアーキテクチャ（MMDiT）は近い親戚だ。このレッスンではTransfusionの命題を読み解き、トイの2損失トレーナーを構築し、1つのTransformerが両方の仕事をできるようにする注意マスクを追う。


## 学習目標

- テキストトークンに対するNTP損失と画像パッチに対する拡散MSE損失の2つを、1つのバックボーンで実行するTransformerを接続する。
- 画像パッチをまたぐ双方向アテンションとテキストトークンに対する因果アテンションが正しいマスク選択である理由を説明する。
- Transfusionスタイル（連続画像、拡散損失）をChameleonスタイル（離散画像、NTP）と（計算量、品質、コードの複雑さ）で比較する。
- MMDiTの貢献を挙げる：各ブロックでのモダリティ固有の重み、残差ストリームでのジョイントアテンション。

## 問題

離散対連続画像トークンの論争はLLMより古い。連続表現（生ピクセル、VAE潜在変数）は詳細を保持する。離散トークン（VQインデックス）はTransformerのネイティブ語彙に合うが量子化ステップで詳細を失う。

Chameleon / Emu3は離散に進んだ：1つの損失、1つのアーキテクチャ、ただし画像の忠実度はトークナイザー品質に制限される。

拡散モデルは連続に進んだ：卓越した画像品質、ただしLLMとは別のモデル、複雑なノイズスケジュールエンジニアリング、テキスト生成との明確な統合なし。

Transfusionが問う：両方を持てるか？画像を連続のままにし、まだ1つのモデルを学習させ、1つのグラジェントステップに縫い付けられた2つの損失を使う。

## 概念

### 2損失アーキテクチャ

単一のデコーダーのみTransformerが以下を含む列を処理する：

- テキストトークン（離散、BPE語彙から）。
- 画像パッチ（連続、16×16ピクセルブロックが線形埋め込みで隠れ次元に射影――ViTエンコーダーの入力と同じ）。
- 連続パッチが住む場所を示す`<image>`と`</image>`タグ。

フォワードパスは1回実行される。損失はトークンごとに2つのヘッドのうちの1つを選ぶ：

- テキストトークンの場合：語彙ロジットヘッドでの標準クロスエントロピー。
- 画像パッチの場合：連続パッチに対する拡散損失――各パッチに追加されたノイズを予測する。

グラジェントは共有Transformerボディを流れる。両方の損失が同時に共有重みを改善する。

### 注意マスク：因果テキスト + 双方向画像

テキストトークンは因果でなければならない――テキストトークンが将来のテキストに注意を向けさせてはいけない、さもなくば教師強制が壊れる。しかし画像パッチは1つのスナップショットを表す；同じ画像ブロック内で双方向に互いに注意を向けるべきだ。

マスク：

```
M[i, j] = 1 if:
  (i is text and j is text and j <= i)   # テキストの因果
  OR (i is image and j is image and same_image_block(i, j))   # 画像内双方向
  OR (i is text and j is image and j < i_image_end)   # テキストは前の画像に注意
  OR (i is image and j is text and j < i_image_start)   # 画像は先行するテキストに注意
```

学習と推論時にブロック三角マスクとして実装される。

### Transformer内の拡散損失

拡散損失は標準：画像パッチにノイズを追加し、モデルにノイズ（または等価的にクリーンなパッチ）を予測させる。TransfusionのバージョンはFlow Matchingを使用――ノイズからクリーンデータへの速度場を予測する。

学習時：
1. 各画像パッチx0に対して、ランダムなタイムステップtをサンプリングする。
2. ノイズεをサンプリングし、xt = (1-t) × x0 + t × ε（Flow Matchingの線形補間）を計算する。
3. Transformerがv_theta(xt, t)を予測；損失 = MSE(v_theta(xt, t), ε - x0)。
4. 同じ列からのテキストNTP損失と並行してバックプロップ。

推論時、生成は：
- テキストトークン：標準自己回帰サンプリング。
- 画像パッチ：先行するテキストトークンを条件とした拡散サンプリングループ（典型的に10〜30ステップ）。

### MMDiT：Stable Diffusion 3の変形

Stable Diffusion 3（Esserら、2024年3月）はTransfusionとほぼ同時にMMDiT（Multimodal Diffusion Transformer）をリリースした。アーキテクチャは兄弟だ。

MMDiTの主な違い：

- ブロックごとのモダリティ固有の重み。各Transformerブロックはテキストトークン対画像パッチに対して別々のQ、K、V、MLP重みを持つ。アテンションはジョイント（クロスモダリティ）；それ以外はすべてモダリティ固有だ。
- Rectified flow学習。DDPMよりシンプルな数学と既知のサンプリングを持つ特定のflow-matching変形。
- スケール。MMDiTはSD3（20億および80億パラメータ変形）のバックボーンだ。Transfusionの論文は70億までスケールする。

両方が同じコアアイデアに収束する：1つのTransformerがテキストにNTPを実行し、連続画像表現に拡散を実行する。

### Chameleonスタイルを上回る理由

連続拡散と離散NTPの画像生成の品質ギャップは測定可能だ。Transfusion論文が報告する：

- 70億パラメータで、同サイズのChameleonスタイルモデルよりFIDで3〜5ポイント上回る。
- トークナイザー学習不要――画像エンコーダーはシンプル（ViTの入力層と同じ隠れへの線形射影）。
- 推論は画像パッチのデノイズを並列化できる、自己回帰画像トークンと違って。

デメリット：Transfusionはデュアル損失モデルで、学習ダイナミクスがよりトリッキーになる。損失の重みのチューニングが必要だ。NTPと拡散のスケジュールの不一致で、1つのヘッドが支配することがある。

### ダウンストリームにあるもの

Janus-Pro（レッスン12.15）は、理解と生成のビジョンエンコーダーを分離しながら（理解にはSigLIP、生成にはVQ）、Transformerボディを共有することでTransfusionのアイデアを洗練させる。Show-o（レッスン12.14）は拡散を離散拡散（マスク予測）に交換する。Transfusion後、統合生成ファミリーは急速に分岐する。

画像を出力する2026年のプロダクションVLM――Gemini 3 Pro、GPT-5、Claude Opus 4.7の画像生成パス――はほぼ確実にこのファミリーの何らかの子孫を使用する。詳細は非公開だ。

## 使ってみる

`code/main.py`はトイのMNISTライクな問題でトイのTransfusionを構築する：

- テキストキャプションは数字（0〜9）を説明する短い整数列。
- 画像はバイトの4×4グリッド。
- 共有重みの線形射影のペアがTransformerスタンドインとして機能；テキストにはNTP損失、ノイズの多いパッチにはMSE損失。
- 学習ループが2つの損失を交互に使用し、注意マスクが明示的だ。
- 生成は1回のフォワードパスでテキストキャプションと4×4画像を生成する。

Transformerはトイだ。2損失の配管、注意マスク構築、推論ループが実際のアーティファクトだ。

## 成果物を出す

このレッスンは`outputs/skill-two-loss-trainer-designer.md`を生成する。新しいマルチモーダル学習タスク（テキスト + 画像、テキスト + 音声、テキスト + ビデオ）が与えられた場合、2損失スケジュール（損失重み、マスク形状、共有対モダリティ固有ブロック）を設計して実装リスクをフラグする。

## 演習

1. Transfusionスタイルモデルが70%テキストトークンと30%画像パッチで学習する。画像拡散損失のマグニチュードはテキストNTP損失の約10倍だ。それらを均衡させる損失重みはいくつか？

2. 列`[T, T, <image>, P, P, P, P, </image>, T]`のブロック三角マスクを実装せよ。各エントリを0または1とマークせよ。

3. MMDiTはモダリティ固有のQKV重みを持つ。TransfusionのFULL共有Transformerと比べてこれが追加するパラメータ数オーバーヘッドはいくつか？70億パラメータで、それは価値があるか？

4. 生成：テキストプロンプトが与えられると、モデルは50トークンのNTPを実行し、次に`<image>`に達し、次に20デノイズステップで256パッチに拡散を実行する。フォワードパスの合計は何回か？

5. SD3論文Section 3を読め。Rectified flowとは何か、なぜDDPMより少ない推論ステップで収束するか説明せよ。

## キーワード

| 用語 | よく言われること | 実際の意味 |
|------|----------------|------------------------|
| 2損失学習 | "NTP + 拡散" | 単一のTransformerが同じグラジェントステップでテキストトークンのクロスエントロピーと連続画像パッチのMSEの両方を最適化 |
| Flow Matching | "Rectified flow" | ノイズからクリーンデータへの速度場を予測する拡散変形；DDPMよりシンプルな数学 |
| MMDiT | "マルチモーダルDiT" | Stable Diffusion 3のアーキテクチャ：ジョイントアテンション、モダリティ固有のMLPとNorm |
| ブロック三角マスク | "因果テキスト + 双方向画像" | テキストをまたがって因果だが画像領域内では双方向の注意マスク |
| 連続画像表現 | "VQなし" | 整数コードブックインデックスではなく実数値ベクトルとしての画像パッチ |
| 速度予測 | "v-パラメータ化" | ネットワーク出力はノイズ自体ではなくノイズとデータの間の速度場 |
