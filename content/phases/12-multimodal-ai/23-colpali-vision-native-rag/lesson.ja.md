# ColPaliとビジョンネイティブ文書RAG

> 従来のRAGはPDFをテキストに解析し、チャンクに分割し、チャンクを埋め込み、ベクトルを保存する。各ステップでシグナルが失われる。OCRはチャートデータを落とし、チャンキングは表の行を切断し、テキスト埋め込みは図を無視する。ColPali（Faysse et al.、2024年7月）はより単純な問いを立てた：なぜテキストを抽出するのか？PaliGemmaでページ画像を直接埋め込み、ColBERTスタイルの遅延インタラクションで検索し、文書が持つすべてのレイアウト、図、フォント、フォーマットシグナルを保持する。公開ベンチマーク：視覚的に豊かな文書でのエンドツーエンド精度がテキストRAGより20〜40%優れている。ColQwen2、ColSmol、VisRAGがそのパターンを拡張した。このレッスンではビジョンネイティブRAGの考え方を読み解き、小さなColPali風インデクサーを構築する。


## 学習目標

- バイエンコーダー検索（文書あたり1ベクトル）と遅延インタラクション検索（文書あたり多数のベクトル）の違いを説明する。
- ColBERTのMaxSim操作と、ColPaliがそれをテキストトークンから画像パッチに一般化する方法を説明する。
- 小さなColPali風インデクサーを構築する：ページ → パッチ埋め込み → クエリ用語埋め込みに対するMaxSim → トップkページ。
- ColPali + Qwen2.5-VLジェネレーター対テキストRAG + GPT-4を請求書 / 財務レポートのユースケースで比較する。

## 問題設定

PDFのテキストRAGは文書のほとんどを捨てる。財務レポートのQ3収益成長は通常チャートにある。医療レポートの所見は注釈付き画像にある。法的契約の署名ブロックはレイアウトの事実であり、テキストの事実ではない。

テキストRAGパイプライン：

1. PDF → OCR / pdftotextによるテキスト。
2. テキスト → 300〜500トークンのチャンク。
3. チャンク → バイエンコーダー埋め込み（1ベクトル）。
4. ユーザークエリ → 埋め込み → コサイン類似度 → トップkチャンク。
5. チャンク + クエリ → LLM。

5つの損失ステップ。チャートは捉えられない。表はチャンクをまたいで切断される。多段組みレイアウトはフラット化される。図の注釈は消える。

ColPaliの修正：OCRをスキップし、ページ画像を直接埋め込む。クエリ時にモデルが細粒度のパッチにアテンションできるようにColBERTスタイルの遅延インタラクションを使う。

## 概念

### ColBERT（2020年）

ColBERT（Khattab & Zaharia、arXiv:2004.12832）はテキスト検索手法だ。文書あたり1ベクトルではなく、トークンあたり1ベクトルを生成する。クエリ時に：

- クエリトークンは独自の埋め込み（Nqベクトル）を取得する。
- 文書トークンは埋め込み（Ndベクトル、通常はキャッシュ済み）を取得する。
- スコア = クエリトークンについての和、文書トークンについての最大コサイン類似度：Σ_i max_j cos(q_i, d_j)。

これがMaxSim操作だ。各クエリトークンは最もよくマッチする文書トークンを「選ぶ」。最終スコアは和だ。

利点：強いリコール、用語レベルの意味を処理する。欠点：文書あたりNdベクトル、ストレージが高コスト。

### ColPali

ColPali（Faysse et al.、arXiv:2407.01449）はColBERTのパターンを画像に適用する。

- 各ページはPaliGemma（ViT + 言語）によってパッチ埋め込みにエンコードされる：ページあたりNpベクトル。
- 各ユーザークエリ（テキスト）はクエリトークン埋め込みにエンコードされる：Nqベクトル。
- スコア = Σ_i max_j cos(q_i, p_j)、つまりクエリテキストトークンとページ画像パッチに対するMaxSim。
- 合計スコアでトップkページを検索する。

文書取り込み時：PaliGemmaですべてのページを埋め込み、すべてのパッチ埋め込みを保存する。クエリ時：クエリトークンを埋め込み、保存されたすべてのページ埋め込みに対してMaxSimを計算し、トップkページを返す。

利点：エンドツーエンドが視覚的に豊かな文書でテキストRAGを20〜40%超える。各パッチベクトルはローカルなレイアウトとコンテンツを捉える。

欠点：ページあたりNpパッチ × 4バイトfloat × D次元ベクトル = ストレージが急増する。PQ / OPQ量子化で軽減される。

### ColQwen2とColSmol

ColQwen2（illuin-tech、2024〜2025年）はPaliGemmaをQwen2-VLに置き換える。より良いベースエンコーダー、より良い検索。

ColSmolはローカル / エッジ使用のための小規模変形だ。約1BパラメータのColSmolリトリーバーはコンシューマーGPUで動作する。

### VisRAG

VisRAG（Yu et al.、arXiv:2410.10594）は別の変形だ。パッチに対するMaxSimの代わりに、VLMで各ページを単一ベクトルにプーリングしてバイエンコーダーで検索する。より高速なインデキシング + 小さいストレージ、弱いリコール。

品質対コストのトレードオフ：品質にはColPali、スケールにはVisRAG。

### M3DocRAG

M3DocRAG（Cho et al.、arXiv:2411.04952）は複数ページ・複数文書の推論にマルチモーダル検索を拡張する。文書をまたいでページを検索し、VLMのために複数ページのコンテキストを構成する。

### ViDoRe — ベンチマーク

ColPaliの companion ベンチマーク。Visual Document Retrieval Evaluation（視覚的文書検索評価）。タスクは財務レポート、科学論文、行政文書、医療記録、マニュアルを含む。メトリック：nDCG@5。

ColPali-v1はViDoReで約80% nDCG@5をスコアする。同じ文書のテキストRAGは約50〜60%をスコアする。

### エンドツーエンドのRAGパイプライン

ビジョンネイティブRAGでは：

1. 取り込み：PDF → ページ画像 → PaliGemmaエンコーディング → すべてのパッチ埋め込みを保存する。
2. クエリ：ユーザーテキスト → クエリトークン埋め込み → インデックス化されたすべてのページに対するMaxSim → トップkページ。
3. 生成：トップkページ画像 + クエリ → VLM（Qwen2.5-VLまたはClaude）→ 答え。

OCRはどこにもない。図、チャート、フォント、レイアウトがすべて答えに流れ込む。

### ストレージ計算

729パッチ/ページ、128次元埋め込みの50ページの財務レポート：

- ColPali：50 * 729 * 128 * 4バイト = 生で約18 MB、PQ後に約4 MB。
- テキストRAG：50チャンク * 768次元 * 4バイト = 約150 kB。

ColPaliは文書あたり約30倍多くのストレージ。大規模では、OPQ / PQで約5〜10倍に削減され、通常は許容できる。

### テキストRAGがまだ勝つ場合

- レイアウトシグナルのない純粋テキスト文書（wikiの記事、チャットログ）。テキストRAGはシンプルでストレージが安い。
- ストレージがコストを支配する数百万ページのアーカイブ。
- 検索と並んで抽出可能なOCRテキストを要求する厳格な規制要件。

2026年の他のすべてのもの（財務レポート、科学論文、法的契約、医療記録、UXドキュメント）ではビジョンネイティブRAGが勝つ。

## 使ってみる

`code/main.py`：

- おもちゃのパッチエンコーダー：「ページ」（特徴ベクトルの小さなグリッド）をパッチ埋め込みの配列にマッピングする。
- MaxSimスコアラー：クエリトークン埋め込みセットとページパッチセット間のColBERTスタイルスコアを計算する。
- 5つのおもちゃのページをインデックス化し、3つのクエリを実行し、スコア付きのトップkを返す。

## 演習

1. ページあたり729パッチ、128次元emb、4バイトfloatの200ページの年次報告書。生のストレージとPQ圧縮後（8倍）のストレージを計算せよ。

2. MaxSimはΣ_i max_j cos(q_i, p_j)だ。この和が単純な平均類似度では捉えられない何を捉えるか？

3. ColPaliはページをパッチセットとしてインデックス化する。代わりに単語レベルでインデックス化する（ColBERTのように）と何が変わるか？トレードオフは？

4. クエリあたり500msのレイテンシバジェットで100万ページのコーパスのエンドツーエンドパイプラインを設計せよ。ColQwen2 / VisRAGを選択して正当化せよ。

5. M3DocRAG（arXiv:2411.04952）を読め。複数ページのアテンションパターンを説明し、それが単一ページのColPali検索とどう異なるかを述べよ。

## キーワード

| 用語 | よく使われる表現 | 実際の意味 |
|------|-----------------|------------|
| 遅延インタラクション | "ColBERTスタイル" | トークンまたはパッチごとの埋め込み + MaxSim、単一の文書ベクトルではない |
| MaxSim | "パッチに対する最大" | 各クエリトークンに対して最も高い類似度の文書トークンを選ぶ。クエリにわたる和 |
| バイエンコーダー | "単一ベクトル" | 文書あたり1つのベクトル。より高速だが細粒度を失う |
| マルチベクトル | "文書あたり多数のベクトル" | 文書 / ページあたりNpベクトルを保存。ストレージコストは増えるがリコールが改善 |
| パッチ埋め込み | "ページ特徴" | ページあたりキャッシュされたVLMエンコーダーからの画像パッチごとの1ベクトル |
| ViDoRe | "視覚文書ベンチ" | ColPaliのビジュアル文書検索のためのベンチマークスイート |
| PQ量子化 | "積量子化" | ストレージを約8倍縮小しながらベクトル類似度を維持する圧縮 |
