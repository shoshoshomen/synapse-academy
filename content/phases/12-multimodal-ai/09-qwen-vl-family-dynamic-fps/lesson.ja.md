# Qwen-VLファミリーと動的FPSビデオ

> Qwen-VLファミリー――Qwen-VL（2023年）、Qwen2-VL（2024年）、Qwen2.5-VL（2025年）、Qwen3-VL（2025年）――は2026年で最も影響力のあるオープンビジョン言語モデルの系統だ。各世代は、残りのオープンエコシステムが12か月以内にコピーした単一の決定的なアーキテクチャの賭けを行った：M-ROPEによるネイティブ動的解像度、絶対時間整合を伴う動的FPSサンプリング、ViTのウィンドウアテンション、構造化されたエージェント出力形式。Qwen3-VLでレシピは安定した：ネイティブアスペクト比入力を持つ2D-RoPE-ViTエンコーダー、大きなQwen3言語ベースへのMLPプロジェクター、OCR、グラウンディング、エージェント動作を一級ターゲットとして重視する学習ステージ。このレッスンでは各ノブがどこにあるかを理解するためにファミリーを時系列で読む。


## 学習目標

- M-ROPEの3軸回転（時間、高さ、幅）を計算し、なぜ3つすべてが必要かを説明する。
- ビデオの動的FPSサンプリング戦略を選択し、1秒あたりのトークン対イベント検出精度について推論する。
- 4つのQwen-VL世代のアップグレードを順番に挙げ、それぞれが何を可能にしたかを説明する。
- Qwen2.5-VLスタイルのJSONエージェント出力形式を接続し、VLM応答から構造化ツール呼び出しを解析する。

## 問題

Qwen-VLは2023年8月にLLaVA-1.5とBLIP-2への直接回答としてリリースされた。Qwenチームがターゲットにしたギャップは3つだった：解像度、ビデオ、構造化出力。

解像度：LLaVA-1.5は336×336で動作した。写真には良く、中国語の請求書や密なスプレッドシートのスクリーンショットには使えない。Qwen-VLの最初のイノベーションは448×448とグラウンドされたバウンディングボックス出力で、モデルが物を指せるようにした。

ビデオ：Video-LLaMAはフレームごとのエンコーダーをスタックしてLLMに渡した。短いクリップには機能したが、時間軸がシグナルである数分のビデオには機能しなかった。Qwenチームは時間を理解する単一のエンコーダーが欲しかった。

構造化出力：LLaVAは自由形式のテキストを出力した。エージェントにはJSONが必要だ。Qwen-VLはテキストとしてのバウンディングボックス座標を含む明示的なJSON出力形式で学習した。

すべてのQwen-VL世代はこれら3つの軸のうちの1つを拡張する。

## 概念

### Qwen-VL（2023年8月）

第一世代：エンコーダーとしてOpenCLIP ViT-bigG/14（25億パラメータ）、LLama互換のQ-Former（256クエリの1ステップ）、Qwen-7Bベース。貢献：

- 448×448解像度（当時オープンVLMのSOTA）。
- グラウンディング：明示的な座標トークン出力を持つ画像テキストペアで学習。「猫は<box>(112, 204), (280, 344)</box>にいる」。
- 中国語 + 英語の多言語学習を最初から。

当時のベンチマーク：英語ではGPT-4Vと競争力があり、中国語で支配的。グラウンディング教師信号が本当のヘッドラインだった。

### Qwen2-VL（2024年9月）――M-ROPEとネイティブ解像度

Qwen2-VLは固定解像度 + Q-Formerスタックをネイティブ動的解像度ViTエンコーダーに置き換えた。主要な変更：

- ネイティブ動的解像度。ViTは28で割り切れる任意のHxWを受け取る（2倍空間マージのパッチ14）。1120×672の画像（40×24のマージパッチ）は960ビジュアルトークンを生成する。リサイズなし、タイリングなし、サムネイルなし。
- M-RoPE（Multimodal RoPE）。各トークンが1Dではなく3D位置（t, h, w）を保持する。画像の場合t=0、ビデオの場合t = フレームインデックス。RoPEは軸ごとに周波数でクエリ/キーベクトルを回転させる。位置埋め込みテーブルなし。
- MLPプロジェクター。Q-Formerを廃棄；マージされたパッチトークン上の2層MLPを使用。
- 動的FPSによるビデオ。デフォルトで1〜2FPSサンプリング、ただし任意のフレーム数を受け取る。

結果：Qwen2-VL-7BはいくつかのマルチモーダルベンチマークでGPT-4oに匹敵し、DocVQAで上回った（94.5 vs 88.4）。アーキテクチャの変更が決定的な動きだった。

### Qwen2.5-VL（2025年2月）――動的FPS + 絶対時間

Qwen2.5-VLの大きな変化はビデオだった。動的FPSは単に「必要なときにより多くのフレームをサンプリング」ではない。論文は形式化した：

- 絶対時間トークン。位置インデックス（フレーム0、1、2...）の代わりに実際のタイムスタンプを使用。「0:04に猫が跳んだ」。モデルはフレームトークンと交互に`<time>0.04</time>`トークンを見る。
- 動的FPS。スロー映像には1FPS、アクションには4FPS以上。ユーザーまたはトレーナーが選択；M-ROPEが適応する。
- ViTのウィンドウアテンション。空間アテンションはスループットのためにウィンドウ化（ブロック内のローカル）；数層ごとにグローバルアテンション。
- 明示的なJSON出力形式。ツール呼び出しデータで学習：`{"tool": "click", "coords": [380, 220]}`。すぐ使えるエージェント対応。
- MRoPE-v2スケーリング。10分のビデオが周波数範囲を超えないよう最大入力サイズで位置がスケールする。

ベンチマーク：Qwen2.5-VL-72BはほとんどのビデオベンチマークでGPT-4oを上回り、文書ではGemini 2.0に匹敵し、GUIグラウンディングのオープンモデルSOTAを設定した（ScreenSpot：84%精度 vs GPT-4oの38%）。

### Qwen3-VL（2025年11月）

Qwen3-VLは再発明ではなく統合する段階的なアップグレードだ：より大きなLLMバックボーン（Qwen3-72B）、拡張された学習データ、改善されたOCR、Qwen3の「思考モード」による強化された推論。ViTとM-ROPEは変わらない。論文はアーキテクチャよりデータと学習の改善に焦点を当てる。

系統の教訓：2025年までにQwen-VLアーキテクチャが安定した。追加の世代はプリミティブではなく計算とデータをスケールする。

### M-ROPEの数学

古典的なRoPEは次元`d`のクエリ`q`を位置`m`で対ペアの座標を使って回転させる：

```
q_rot[2i]   = q[2i]   * cos(m * theta_i) - q[2i+1] * sin(m * theta_i)
q_rot[2i+1] = q[2i]   * sin(m * theta_i) + q[2i+1] * cos(m * theta_i)
theta_i     = 10000^(-2i/d)
```

M-ROPEは隠れ次元を3つのバンドに分割する。`d = 96`とすると、時間に32次元、高さに32次元、幅に32次元を割り当てる。各バンドは自身の軸位置で回転する。(t=5, h=10, w=20)のパッチは3つのバンドに回転`R_t(5)`、`R_h(10)`、`R_w(20)`が適用される。

テキストトークンは`t = テキストインデックス, h = 0, w = 0`（または正規化された選択）を使用して互換性を保つ。ビデオフレームは`t = フレーム時間, h = 行, w = 列`を使用する。シングル画像は`t = 0`を使用する。

利点：1つの位置エンコーディングがコードの分岐や異なる位置テーブルなしでテキスト、画像、ビデオを処理する。

### 動的FPSサンプリングロジック

持続時間`T`秒のビデオとターゲットトークンバジェット`B`が与えられた場合：

1. 支払える最大FPSを計算：`fps_max = B / (T * tokens_per_frame)`。
2. `fps <= fps_max`を満たす`{1, 2, 4, 8}`からターゲットFPSを選ぶ。
3. モーションが高ければ（オプティカルフロー発見的手法または明示的なユーザーリクエスト）、より高いFPSを選ぶ。モーションが低ければ、より低いFPSを選ぶ。
4. 選んだFPSで均一にサンプリング；フレーム間に`<time>t</time>`トークンを挿入。

Qwen2.5-VLはこのロジックを暗黙的に学習する；推論時にユーザーは`fps`パラメータで制御する。81トークン/フレームで4FPSの60秒アクションシーンは19440トークン、32kコンテキストで管理可能。

### 構造化エージェント出力

Qwen2.5-VLのエージェント学習は明示的に構造化ツール呼び出しをターゲットにする：

```
{
  "tool": "mouse_click",
  "coords": [1024, 512],
  "button": "left",
  "modifier": null
}
```

解析は決定論的：モデルの出力に対するJSON.parse。座標の正規表現と曖昧性処理が必要な自由形式の「(1024, 512)でクリック」と比べて。このシフトがQwen2.5-VLのScreenSpotスコアがQwen2-VLの55%から84%に上昇した理由だ。

## 使ってみる

`code/main.py`の実装内容：

- テキスト、画像パッチ、ビデオフレームを混合したパックされた列のM-RoPE位置計算。
- 動的FPSサンプラー：（持続時間、バジェット、モーションレベル）が与えられた場合、FPSを選んでフレームタイムスタンプを出力。
- 座標フィールドを持つツール呼び出し応答を処理するトイQwen2.5-VL JSONパーサー。

実行して、5分間のビデオに固定FPSと動的FPSを使った場合の差を体感しよう。

## 成果物を出す

このレッスンは`outputs/skill-qwen-vl-pipeline-designer.md`を生成する。ビデオタスク（監視、エージェント、行動認識、アクセシビリティ）が与えられた場合、Qwen2.5-VL設定（フレームバジェット、FPS戦略、ウィンドウアテンションフラグ、エージェント出力モード）とレイテンシ推定を出力する。ビデオ製品にQwen-VLファミリーモデルをデプロイするときはいつでも使う。

## キーワード

| 用語 | よく言われること | 実際の意味 |
|------|-----------------|------------------------|
| M-RoPE | "マルチモーダルRoPE" | 隠れ次元に時間、高さ、幅のバンドを持つ3次元回転位置埋め込み |
| 動的FPS | "スマートサンプリング" | モーション、持続時間、トークンバジェットに基づいてビデオごとに選ばれるフレームサンプリングレート |
| 絶対時間トークン | "タイムスタンプトークン" | フレームインデックスではなく実際の秒数をモデルが見るよう列にインターリーブされる`<time>t</time>` |
| ウィンドウアテンション | "ローカルアテンション" | スピードのために小さなウィンドウに制限された空間自己注意；定期的にグローバルアテンション追加 |
| 構造化エージェント出力 | "JSONモード" | 座標とツール名を含む解析可能なJSONを出力するようVLMを教える学習データ教師信号 |
| min_pixels / max_pixels | "解像度境界" | 総ピクセル数とトークン数をキャップするQwen2.5-VLのリクエストごとの制御 |
| グラウンディング | "指し示し" | バウンディングボックス座標をテキストトークンとして出力；Qwen-VL v1から使用 |
