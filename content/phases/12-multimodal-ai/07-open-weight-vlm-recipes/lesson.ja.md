# オープンウェイトVLMレシピ：本当に重要なこと

> 2024〜2026年のオープンウェイトVLM文献はアブレーション表の森だ。AppleのMM1は画像エンコーダー、コネクター、データミックスの13通りの組み合わせをテストした。Allen AIのMolmoは詳細な人間キャプションがGPT-4V蒸留を上回ることを証明した。Cambrian-1は20以上のエンコーダー比較を実行した。Idefics2は5軸設計空間を形式化した。Prismatic VLMsは管理されたベンチマークで27種類の学習レシピを比較した。そのすべてのノイズから、論文をまたがって持ちこたえる結果の小さなセットが得られる：画像エンコーダーはコネクターアーキテクチャより重要で、データミックスはどちらよりも重要で、詳細な人間キャプションは同じトークン数での蒸留合成データを上回る。このレッスンではそれらの表を読み解くのでのちに自分で読む必要がない。


## 学習目標

- VLMの5軸設計空間を挙げる：画像エンコーダー、コネクター、LLM、データミックス、解像度スケジュール。
- MM1 / Idefics2 / Cambrian-1のアブレーション表を読んで、どのノブが特定のベンチマークを動かすかを予測する。
- 計算バジェットとタスクミックスが与えられた場合に新しいVLMのレシピ（エンコーダー、コネクター、データ、解像度）を選択する。
- 詳細な人間キャプションが同じトークン数でGPT-4V蒸留を上回る理由を説明する。

## 問題

数百のオープンウェイトVLMが存在する。「良い」と「最先端」の差のほとんどはアーキテクチャではない。データ、解像度スケジュール、エンコーダー選択だ。最初にどのノブを回すかを知ることで、500万GPU時間の間違いを防げる。

2023年の波（LLaVA-1.5、InstructBLIP、MiniGPT-4）はキャプションペア事前学習 + LLaVA-Instruct-150kで動作した。良いベースライン。MMMU 35%前後で頭打ち。

2024年の波（MM1、Idefics2、Molmo、Cambrian-1、Prismatic VLMs）は徹底的なアブレーションを実行した。結果は驚くべきで実用的だった。

## 概念

### 5軸設計空間

Idefics2（Laurençonら、2024年）が軸を命名した：

1. 画像エンコーダー。CLIP ViT-L/14、SigLIP SO400m/14、DINOv2 ViT-g/14、InternViT-6B。エンコーダーはパッチサイズ、解像度、事前学習目標が異なる。
2. コネクター。MLP（2〜4層）、Q-Former（32クエリ + クロスアテンション）、Perceiver Resampler（64クエリ）、C-Abstractor（畳み込み + バイリニアプーリング）。
3. 言語モデル。Llama-3 8B / 70B、Mistral 7B、Phi-3、Gemma-2、Qwen2.5。LLMサイズが支配的なパラメータコスト。
4. 学習データ。キャプションペア（CC3M、LAION）、インターリーブ（OBELICS、MMC4）、命令（LLaVA-Instruct、ShareGPT4V、PixMo、Cauldron）。
5. 解像度スケジュール。固定224/336/448、AnyRes、ネイティブダイナミック。学習中に段階的に増加するか一定か。

すべてのプロダクションVLMは各軸で選択を行う。MMMUスコアの分散のほとんどは軸1、4、5で説明される――どのコネクターを選んだかではない。

### 軸1：エンコーダー > コネクター

MM1 Section 3.2は示した：CLIP ViT-L/14からSigLIP SO400m/14への交換で+3ポイントのMMUU。コネクターをMLPからPerceiver Resamplerに交換しても1ポイント未満。Idefics2が再現：SigLIP > CLIP、Q-Former ≈ MLP ≈ 同じトークン数でのPerceiver。

Cambrian-1の「Cambrian Vision Encoders Match-Up」（Tongら、2024年）はビジョン中心ベンチマーク（CV-Bench）で20以上のエンコーダーを実行した。リーダーボードの上位はDINOv2とSigLIPの混合；CLIPは中程度；ImageBindとViT-MAEは下位。CLIP ViT-LからDINOv2 ViT-g/14のギャップはCV-Benchで約5〜7ポイント。

2026年のオープンVLMのデフォルトエンコーダーは、セマンティック + 密な特徴のSigLIP 2 SO400m/14で、時にDINOv2 ViT-g/14特徴と連結（CambrianのSpatial Vision Aggregatorがこれを行う）。

### 軸2：コネクター設計は互角

MM1、Idefics2、Prismatic、MM-Interleavedはすべて同じ結論に達した：固定ビジュアルトークン数では、コネクターアーキテクチャはほとんど重要でない。平均プールされたパッチ上の2層MLPは同じトークンバジェットで32クエリQ-Formerの1ポイント以内のパフォーマンスを発揮する。

重要なのはトークン数だ。より多いビジュアルトークン = より多いLLM計算 = ある点まで性能向上し、その後は逓減。1画像あたり64トークンはOCRに少なすぎる。576〜1024トークンがほとんどのオープンVLMのスウィートスポット。2048以上は文書とチャートにのみ役立つ。

Q-Former vs MLPはコストの問題であり、品質の問題ではない：Q-Formerは画像解像度に関わらずトークンを32〜64に制限；MLPはすべてのパッチトークンを出力する。高解像度入力ではQ-FormerがLLMコンテキストを節約；低解像度では差は誤差範囲内だ。

### 軸3：LLMサイズが上限を設定

LLMを7Bから13Bに倍増させると、すべてのVLM論文でMMMUに2〜4ポイント確実に加わる。70Bではほとんどのベンチマークが飽和する。VLMのマルチモーダル推論上限はLLMのテキスト推論上限だ――ビジュアルエンコーダーはそれを供給できるだけで、推論はできない。

これがQwen2.5-VL-72BとClaude Opus 4.7がMMMU-ProとScreenSpot-Proを圧倒する理由だ：言語の脳が大きい。巧みなコネクター設計で7B VLMが70B VLMを代替することはできない。

### 軸4：データ――詳細な人間キャプションが蒸留を上回る

Molmo + PixMo（Deitkeら、2024年）は2024年ですべての人が読むべき結果だ。Allen AIは人間の注釈者に1〜3分の密な音声テキスト変換で画像を説明させ、71万2千枚の密なキャプション付き画像を生成した。学習データにGPT-4V蒸留はない。

Molmo-72BはLlama-3.2-90B-Visionを11/11ベンチマークで上回った。差はアーキテクチャではなく、キャプション品質だ。詳細な人間キャプションは短いWebキャプションより1画像あたり5〜10倍多くの情報を含み、GPT-4V蒸留が幻覚する場所で事実的に基礎付けられたままだ。

ShareGPT4V（Chenら、2023年）とCauldron（Idefics2）は同じプレイブックに従い、人間 + GPT-4Vキャプションを混合した。トレンドは明確：2026年のフロンティアでは、キャプション密度 > キャプション量 > 蒸留の便利さ。

### 軸5：解像度とスケジュール

Idefics2のアブレーション：384 → 448で1〜2ポイント向上。448 → 画像分割（AnyRes）付き980でOCRベンチマークでさらに3〜5ポイント。フラットな解像度学習は中程度の精度で頭打ち；解像度ランピング（224から始め、448またはネイティブで終了）はより速く学習してより高く終了する。

Cambrian-1は解像度 vs トークンのトレードオフを実行した：固定計算量で、低解像度でより多くのトークンを持つか、高解像度でより少ないトークンを持つかを選べる。高解像度はOCRで勝つ；低解像度でより多いトークンは一般的なシーン理解で勝つ。

2026年のプロダクションレシピ：ステージ1は384固定、ステージ2はOCR重タスクに最大1280の動的解像度。

### 制御された比較Prismatic

Prismatic VLMs（Karamchetiら、2024年）はすべての軸を制御した論文だ。同じ13B LLM、同じ命令データ、同じ評価――一度に1軸だけ変化させる。結果：

- 1画像あたりのビジュアルトークン数が分散の約60%を説明。
- エンコーダー選択が約20%を説明。
- コネクターアーキテクチャが約5%を説明。
- その他すべて（データミックス、スケジューラー、LR）が残り約15%。

これは大まかな分解だが、文献における「最初に何をアブレーションすべきか」への最も明確な答えだ。

### 2026年の選択ガイド

証拠に基づき、2026年の新しいプロジェクトのデフォルトオープンVLMレシピ：

- エンコーダー：NaFlex付きネイティブ解像度のSigLIP 2 SO400m/14、セグメンテーション/グラウンディングが必要な場合はDINOv2 ViT-g/14の密な特徴と連結。
- コネクター：パッチトークン上の2層MLP。トークン制約がない限りQ-Formerをスキップ。
- LLM：Qwen2.5 / Llama-3.1 / Gemma 2、コストには7B、品質には70B、ターゲットレイテンシで選択。
- データ：PixMo + ShareGPT4V + Cauldron、タスク固有の命令データで補完。
- 解像度：動的（最長辺最小256、最大1280ピクセル）。
- スケジュール：ステージ1整合（プロジェクターのみ）、ステージ2完全ファインチューニング、ステージ3タスク固有ファインチューニング。

それらのデフォルトはすべて、このレッスン末尾で引用した論文の測定されたアブレーションに遡ることができる。

## 使ってみる

`code/main.py`はアブレーション表パーサーとレシピピッカーだ。MM1とIdefics2のアブレーション表（要約版）をエンコードし、クエリできる：

- 「バジェットXとタスクYで何のレシピが勝つか？」
- 「7B LlamaでSigLIPをCLIPに交換した場合、期待されるMMMUの差は？」
- 「80%の確信度の答えを得るために最初に何をアブレーションすべきか？」

出力は期待されるベンチマーク差と「最初にアブレーション」推薦を含むランク付きレシピリストだ。

## 成果物を出す

このレッスンは`outputs/skill-vlm-recipe-picker.md`を生成する。ターゲットタスクミックス、計算バジェット、レイテンシターゲットが与えられた場合、各選択を正当化するアブレーションへの引用とともに完全なレシピ（エンコーダー、コネクター、LLM、データミックス、解像度スケジュール）を出力する。新しいVLMプロジェクトが始まるたびにIdefics2アブレーション表を再発明するエンジニアを止める。

## 演習

1. MM1 Section 3.2を読め。バジェット5000万画像での固定2B LLMで、どのエンコーダーが勝つか？その答えは13B LLMでひっくり返るか？なぜ？

2. Cambrian-1はDINOv2 + SigLIPを連結するとビジョン中心ベンチマークでどちらか単体より優れるが、MMMUには信号を追加しないことを発見した。どのベンチマークが向上し、どれが横ばいになるかを予測せよ。

3. ターゲットは2B LLMでのモバイルUIエージェントだ。エンコーダー、コネクター、解像度、データミックスを選択せよ。各選択を特定のアブレーション表で正当化せよ。

4. Molmoは4Bと72Bモデルをリリースした。4Bはクローズド7B VLMと競争力があり；72BはLlama-3.2-90B-Visionを11/11ベンチマークで上回る。それはLLMサイズプラトー仮説について何を示しているか？

5. エンコーダー品質からデータミックス品質を分離するアブレーション表を設計せよ。最低何回の学習実行が必要か？4つの軸設定を提案せよ。

## キーワード

| 用語 | よく言われること | 実際の意味 |
|------|-----------------|------------------------|
| アブレーション | "1つのノブを回す" | 1つの設計空間の軸だけが異なり、他はすべて固定の複数学習実行 |
| コネクター | "ブリッジ" / "プロジェクター" | ビジョンエンコーダー出力をLLMのトークン空間にマッピングする学習可能なモジュール（MLP、Q-Former、Perceiver） |
| 詳細な人間キャプション | "密なキャプション" | 通常80〜300トークンの複数文の人間が書いた説明；Webのalt textより豊か |
| 蒸留 | "GPT-4Vキャプション" | より強力な専有VLMによって生成された学習データ；便利だが引き継いだ幻覚に弱い |
| AnyRes / 動的解像度 | "高解像度パス" | エンコーダーのネイティブ解像度より大きな画像をタイリングまたはM-ROPEで渡す戦略 |
| 解像度ランプ | "カリキュラム" | 低解像度から始まり増加する学習スケジュール；整合学習を加速 |
| ビジョン中心ベンチ | "CV-Bench / BLINK" | 言語重視の推論よりも細粒度の視覚的知覚を強調する評価 |
| PixMo | "Molmoのデータ" | Allen AIの71万2千枚の密なキャプション付き画像データセット；密なキャプションに変換した人間の音声 |
