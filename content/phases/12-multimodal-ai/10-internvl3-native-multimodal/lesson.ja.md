# InternVL3：ネイティブマルチモーダル事前学習

> InternVL3以前のすべてのオープンVLMは同じ3ステップレシピに従っていた：兆を超えるテキストトークンで学習したテキストLLMを取り、ビジョンエンコーダーを接続し、つなぎ目をファインチューニングする。機能するが整合負債がある――テキストLLMは完全な事前学習バジェットを純粋なテキストに費やし、ビジュアルトークンをネイティブに理解しない。ビジョンを後付けで追加すると、LLMはテキストを忘れずにビジュアル入力をテキスト推論と関連付ける方法を再学習する必要がある。InternVL3（Zhuら、2025年4月）は後付けアプローチを拒否する：1回の事前学習実行で、テキストとマルチモーダルが最初から交互に処理される。結果は78Bパラメータでオープン版としてGemini 2.5 ProのMMUU-Proに匹敵する。このレッスンではネイティブ事前学習の根拠と、それを行うと何が変わるかを読み解く。


## 学習目標

- 後付けVLM学習が整合負債を蓄積する理由を、3つの測定可能な症状（壊滅的忘却、答えのドリフト、視覚テキストの不整合）を引用して説明する。
- InternVL3のネイティブ事前学習コーパスミックスと、テキスト：インターリーブ：キャプションの比率が重要な理由を説明する。
- V2PE（可変ビジュアル位置エンコーディング）をQwen2-VLのM-ROPEと比較する。
- Visual Resolution Router（ViR）とDecoupled Vision-Language（DvD）デプロイ最適化を挙げる。

## 問題

後付けVLM学習がデフォルトだ。LLaVA、BLIP-2、Qwen-VL、Idefics――すべてがすでに事前学習されたLLM（Llama、Vicuna、Qwen、Mistral）を取ってビジョンを追加する。学習ステージは通常次のようなものだ：

1. フリーズLLM + フリーズビジョンエンコーダー + 学習可能なプロジェクター、キャプションペアで埋め込みを整合させる。
2. LLMをアンフリーズし、命令データ（LLaVA-Instruct、ShareGPT4V）で学習する。
3. オプションのタスク固有ファインチューニング。

整合負債の3つの症状が現れる：

- 壊滅的忘却。後付けVLMはテキストのみのスキルを忘れる。GSM8Kスコアが5〜10ポイント低下する。Hellaswagスコアが低下する。純粋テキストエージェントが退行する。
- 答えのドリフト。同じビジュアル質問の小さな言い回しの違いが異なる答えを得る。ビジョンエンコーダーはLLM自身のトークンよりも弱い結合でLLMに接続する。
- 視覚テキストの不整合。VLMは画像を正しく説明でき、次に自身の説明と矛盾する質問に答えることがある。ビジュアルトークンはテキストと同様にLLMの内部整合性チェックに参加しない。

これらの症状は十分に記録されている。MM1.5 Section 4はそれらを定量化する。LLaVA-OneVisionのアブレーションがそれらを示唆する。ネイティブ事前学習が答えだ。

## 概念

### ネイティブマルチモーダル事前学習

InternVL3は最初のステップからネイティブにマルチモーダルなコーパスで一からの学習を行う。ミックスは：

- 40%テキストのみデータ（FineWeb、Proof-Pile-2など）
- 35%インターリーブ画像テキストデータ（OBELICS、MMC4スタイル）
- 20%ペア画像キャプションデータ
- 5%ビデオテキストデータ

ビジョントークン、テキストトークン、クロスモーダルインタラクションはすべて最初のグラジェントステップから同じ損失に参加する。整合事前学習なし、プロジェクターのフリーズステージなし、壊滅的忘却からの回復なし。

学習はベースモデルのシングルステージ。命令チューニングが続くが、ベースモデルはすでにビジュアルトークンを一級市民として理解する。

### V2PE（可変ビジュアル位置エンコーディング）

Qwen2-VLはM-ROPEで固定軸配分を使用する。InternVL3はV2PEを導入する：位置エンコーディングがモダリティタイプ（テキスト、画像、ビデオ）ごとに学習可能なスケーリングで変化する。実際には：

- テキストトークンは1D位置（テキストインデックス）を得る。
- 画像パッチは2D位置（行、列）を得る。
- ビデオフレームは3D位置（時間、行、列）を得る。

3つは同じROPE周波数ベースを共有するが、バンドあたりの隠れ次元配分は固定分割ではなく学習可能なパラメータだ。事前学習中に時間的対空間的周波数分解能をトレードオフする自由度がある。

V2PEのアブレーション主張：同じ計算量でM-ROPEよりビデオベンチマークで1〜2ポイント。革命ではないが、よりクリーン。

### Visual Resolution Router（ViR）

デプロイ最適化。すべての画像がフル解像度エンコーディングを必要とするわけではない。低詳細の1オブジェクト写真は1280pxネイティブでエンコードされても無駄にトークンを使う。ViRはエンコード前に質問に答えるのに必要な最低解像度を予測する小さな分類器だ。

ルーティングは3段階：低解像度（256トークン）、中解像度（576）、高解像度（2048以上）。プロダクショントラフィックの60%のクエリで、低または中が十分だ。正味効果：同品質で2〜3倍のスループット。

### Decoupled Vision-Language デプロイ（DvD）

大きなVLMを提供するとき、ビジョンエンコーダーは1枚の画像あたり1回だけ実行されるが、LLMはすべての出力トークンに対して自己回帰的に実行される。2つのコンポーネントには異なるボトルネックがある（ビジョン = 畳み込み + アテンションのGPUメモリ帯域幅；LLM = KVキャッシュ）。DvDはストリーミングで別々のGPUに分割する。

8B + 4億エンコーダーモデルで、DvDは同位置のものと比べてノードあたりのスループットをほぼ2倍にする。

### シングルステージ vs マルチステージの品質

InternVL3の主要ベンチマーク主張：78Bパラメータで、Gemini 2.5 ProのMMMU-Proに匹敵する。38Bで、GPT-4oに匹敵する。8Bで、オープン8Bリーダーボードをリードする。すべてシングルステージ事前学習 + 命令チューニングレシピで。

整合負債の仮説は測定可能だ：InternVL3-8Bは、ビジョンベンチマーク向上単位あたりQwen2.5-VL-7Bよりも少ないテキストベンチマーク（MMLU、GSM8K）ポイントを失う。学習が1つのピースであったため、モデルはより多目的だ。

### InternVL3.5とInternVL-U

InternVL3.5（2025年8月）はレシピをスケールする。同じネイティブ事前学習アプローチ、より多くのデータ、より多くのパラメータ。MMMUの改善は段階的だ。

InternVL-U（2026年）は同じバックボーン上にMMDiTヘッドを介した統合生成を追加する。「U」は「理解 + 生成」を意味し、Transfusionスタイルの統合モデル（レッスン12.13）を追う。同じネイティブ事前学習バックボーンが理解と生成の両方のヘッドをサポートする。

### ネイティブ事前学習のトレードオフ

ネイティブ事前学習は無料ではない：

- 計算量。新しいVLMを一から学習するコストはテキストLLMを学習するのと同じ――数百万GPU時間。後付け適応は既存のLLM重みを再利用し、ほとんどのコストを節約する。
- データ。スケールでのインターリーブ画像テキストコーパスは希少だ。OBELICSは1.41億ドキュメント；MMC4は5.71億。テキスト単独は15兆トークンで提供される。マルチモーダル事前学習データの希少性は制約だ。
- ベースLLMの再利用。ネイティブ事前学習は後でLLaMA-3.1をLlama-4に交換するオプションを放棄する。後付けではアダプターだけを再学習してLLMを交換できる。

InternVL3が行う賭け：整合負債は再利用の損失より悪い。ベンチマークが主張を支持する。生産コストの高さが将来のラボが安価に複製することを妨げる。後付けVLMは多くのプロジェクトに安価な理由で存在し続けるだろう。

## 使ってみる

`code/main.py`は学習コーパスミキサーとViRルーターシミュレーターだ：

- ターゲットコーパスミックス（%テキスト、%インターリーブ、%キャプション、%ビデオ）を取り、モダリティごとの期待ステップを計算する。
- クエリのバッチでViRルーティングをシミュレート（分布：50%低詳細、30%中程度、20%高詳細）して平均トークン数を報告する。
- エンコーダー対LLM FLOPsが与えられたDvDスループット推定を報告する。
- 後付け対ネイティブ事前学習をパラメータ、計算量、データ、期待整合負債症状で並べて印刷する。

## 成果物を出す

このレッスンは`outputs/skill-native-vs-posthoc-auditor.md`を生成する。提案されたVLM学習計画が与えられた場合、ネイティブか後付けかを監査し、整合負債のリスクをフラグし、コーパスミックスを推薦する。新しいオープンVLMプロジェクトをサイジングして学習戦略を選ぶ必要があるときに使う。

## 演習

1. InternVL3-8B（ネイティブ事前学習）とLLaVA-OneVision-7B（後付け）の計算量の差を推定せよ。GPU時間の比率は概算でどのくらいか？差は何で説明されるか？

2. InternVL3は40%テキスト / 35%インターリーブ / 20%キャプション / 5%ビデオと報告する。ターゲットタスクがビデオ重視なら、新しい比率を提案し、ベースモデルがまだかなりのテキストとキャプションデータを必要とする理由を論ぜよ。

3. 忘却に関するMM1.5 Section 4を読め。後付け学習が最大の退行を示した正確なベンチマークを挙げよ。退行はどのくらいのコストだったか？

4. ViRはトラフィックの60%を低解像度エンコーディングにルーティングする。どんな種類のクエリを誤ルーティングするか（高解像度が必要なのに低解像度に送る）？3つのルーター失敗モードを提案せよ。

5. DvDはビジョンとLLMを別々のGPUに分割する。どんなトラフィックパターンでDvDがスループットを助けるのではなく傷つけるか？

## キーワード

| 用語 | よく言われること | 実際の意味 |
|------|-----------------|------------------------|
| ネイティブマルチモーダル事前学習 | "最初から一緒に" | テキスト + 画像 + ビデオトークンがステップ1から損失に参加し、後付けではない |
| 整合負債 | "後付けペナルティ" | フリーズLLMにビジョンを接続することから生じる、テキストスキルと答えの整合性の測定可能な退行 |
| V2PE | "可変ビジュアル位置エンコーディング" | モダリティごとの学習可能な位置エンコーディング配分；InternVL3のM-ROPEの後継 |
| ViR | "解像度ルーター" | エンコード前にクエリごとに必要な最小解像度を選ぶ小さな分類器、推論トークンを節約 |
| DvD | "デカップルドデプロイ" | ビジョンエンコーダーは1台のGPU、LLMは別のGPU、ストリームハンドオフ付き；大規模VLMのスループットを2倍に |
| InternVL-U | "統合理解 + 生成" | ネイティブ事前学習バックボーンに画像生成ヘッドを追加する2026年のフォローアップ |
| インターリーブコーパス | "OBELICS / MMC4" | 自然な読書順でテキストと画像を持つドキュメント；ネイティブ事前学習の原材料 |
