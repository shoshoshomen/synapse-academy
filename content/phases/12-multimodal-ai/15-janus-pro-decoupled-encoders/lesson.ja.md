# Janus-Pro：統合マルチモーダルモデルのための分離エンコーダー

> 統合マルチモーダルモデルには避けられない緊張がある。理解は意味的な特徴を求め、SigLIPやDINOv2の出力ベクトルには概念レベルの豊富な情報が詰まっている。生成は再構成に適したコードを求め、鮮明なピクセルに合成できるVQトークンが必要だ。この2つの目標は単一エンコーダーでは両立しない。DeepSeekによるJanus（2024年10月）とJanus-Pro（2025年1月）は、諦めることが解決策だと主張する。2つのエンコーダーを切り離すのだ。タスク間でトランスフォーマー本体を共有しつつ、理解はSigLIPを通じて、生成はVQトークナイザーを通じてルーティングする。7Bのモデルで、Janus-ProはGenEvalでDALL-E 3を超えながら、MMUMUではLLaVAに匹敵する。このレッスンでは、なぜ2つのエンコーダーが1つのエンコーダーが失敗するところで機能するのかを読み解く。


## 学習目標

- 単一の共有エンコーダーが理解または生成品質のいずれかを損なう理由を説明する。
- Janus-Proのルーティングを説明する：理解のための入力側ではSigLIP特徴、生成のための入力と出力の両方ではVQトークン。
- Janus-ProがJanusが成功しなかった場所で成功するデータミックスのスケーリングを追跡する。
- 分離型（Janus-Pro）、結合連続型（Transfusion）、結合離散型（Show-o）のアーキテクチャを比較する。

## 問題設定

統合モデルはトランスフォーマー本体を理解と生成にまたがって共有する。以前の試み（Chameleon、Show-o、Transfusion）はすべて、両方向に1つのビジュアルトークナイザーを使う。トークナイザーは妥協の産物だ。

- 再構成に最適化（生成）：VQ-VAEは細粒度のピクセル詳細を捉えるが、意味的整合性が弱いトークンを生成する。
- 意味論に最適化（理解）：SigLIP埋め込みは「猫」の画像を「猫」トークンの近くにグループ化するが、良い再構成は許さない。

Show-oとTransfusionはどちらか一方の方向に目に見える品質のコストを支払う。Janus-Proの問いかけは：タスクが異なるニーズを持つのに、なぜ1つのトークナイザーを要求するのか？

## 概念

### 分離されたビジュアルエンコーディング

Janus-Proのアーキテクチャは2つのエンコーダーを分離する。

- 理解パス：入力画像 → SigLIP-SO400m → 2層MLP → トランスフォーマー本体。
- 生成パス：入力画像（既存の画像を条件にする場合）→ VQトークナイザー → トークンID → トランスフォーマー本体。
- 出力生成：トランスフォーマーが予測した画像トークン → VQデコーダー → ピクセル。

トランスフォーマー本体は共有される。本体の上流と下流のすべてはタスク固有だ。

入力はプロンプト形式で区別される。`<understand>`タグはSigLIPを通じてルーティングされ、`<generate>`はVQを通じてルーティングされる。またはルーティングはタスクから暗黙的に決まる。

### なぜこれが機能するのか

理解損失はSigLIP特徴を受け取る。これはCLIPスタイルの事前学習が意味的類似性のためにチューニングしたものだ。入力特徴がタスクに対してより優れているため、モデルの知覚ベンチマークはShow-o / Transfusionを上回る。

生成損失はVQトークンを受け取る。これはトークナイザーが再構成のためにチューニングしたものだ。VQコードが明確にピクセルに合成されるため、画像品質はShow-oを上回る。

共有トランスフォーマー本体は2つの入力分布（SigLIPとVQ）を見て、両方で機能することを学習する。主張は：十分なデータと十分なパラメータがあれば、本体は切り替えを吸収するというものだ。

### データスケーリング — JanusとJanus-Pro

Janus（オリジナル、arXiv 2410.13848）は分離を導入したが、小規模だった（1.3Bパラメータ、限られたデータ）。Janus-Pro（arXiv 2501.17811）はスケールアップした。

- 7Bパラメータ（1.3Bから）。
- ステージ1（アライメント）の画像テキストペアを9000万（7200万から）。
- ステージ2（統合）を7200万（2600万から）。
- ステージ3のために20万件の画像生成インストラクションサンプルを追加。

結果：Janus-Pro-7BはMMUMUでLLaVAに匹敵し（60.3対約58）、GenEvalでDALL-E 3を超える（0.80対0.67）。1つのオープンモデルで統合スペクトルの両側で競争力がある。

### JanusFlow — 整流フロー変形

JanusFlow（arXiv 2411.07975）はVQ生成パスを整流フロー生成パス（連続）に置き換える。分離は理解のためのSigLIP + 生成のための整流フローとなる。品質の上限がさらに上がる。アーキテクチャは分離エンコーダー・共有本体のままだ。

### 共有本体の役割

トランスフォーマー本体は統合された系列を処理するが、2つの入力分布を持つ。その役割は以下の通り。

- 理解の場合：SigLIP特徴 + テキストトークンを消費 → テキストを自己回帰的に出力する。
- 生成の場合：テキストトークン + （オプションの画像VQトークン）を消費 → 画像VQトークンを自己回帰的に出力する。

本体にはブロックごとのモダリティ固有の重みはない。QwenやLlamaの内部に見られるテキストスタイルのトランスフォーマーに、2つの入力アダプターが加わったものだ。

興味深いことに、これはJanus-Proの本体が事前学習済みLLMから初期化できることを意味する。Janus-ProはDeepSeek-MoE-7Bから初期化する。この選択は重要で、LLMは純粋にゼロから訓練した統合モデルが苦労する推論能力をもたらす。

### InternVL-Uとの比較

InternVL-U（レッスン12.10）は2026年のフォローアップだ。以下を組み合わせる。

- ネイティブマルチモーダル事前学習（InternVL3バックボーン）。
- 分離エンコーダールーティング（SigLIP入力、VQ + 拡散ヘッド出力）。
- 統合された理解 + 生成 + 編集。

InternVL-UはJanus-Proのアーキテクチャの選択を大規模なフレームワークに取り込む。分離エンコーダーの考え方は今やスケールでの統合モデルのデフォルトとなっている。

### 限界

分離エンコーダーはアーキテクチャの複雑さを増す。訓練すべきトークナイザーが2つ、維持すべき入力パスが2つ、失敗モードが2セットある。生成を必要としないプロダクトでは、Janus-Proは過剰設計だ。LLaVAファミリーの理解モデルを選べばよい。

理解を必要としないプロダクトでは、Janus-Proは過剰品質だ。Stable Diffusion 3 / Fluxモデルを選べばよい。

両方が必要なプロダクトでは、Janus-Proが今やリファレンスのオープンアーキテクチャだ。

## 使ってみる

`code/main.py`はJanus-Proのルーティングをシミュレートする。

- 2つのモックエンコーダー：SigLIP風（256次元の意味ベクトルを生成）とVQ風（整数コードを生成）。
- タスクタグに基づいてエンコーダーを選択するプロンプトルーター。
- どちらのエンコーダーが生成したかに関係なく、トークン系列を処理する共有本体（代用）。
- ステージ1（アライメント）からステージ3（インストラクションチューニング）へのサンプルスケジュール切り替え。

3つの例のルーティングされたパスを出力する：画像QA、T2I、画像編集。

## 成果物を出す

このレッスンでは`outputs/skill-decoupled-encoder-picker.md`を作成する。フロンティア品質に近い統合生成 + 理解を求めるプロダクトに対して、Janus-Pro、JanusFlow、またはInternVL-Uを選び、具体的なデータスケールの推奨事項を示す。

## 演習

1. Janus-Pro-7BはGenEvalでDALL-E 3を超える。7Bのオープンモデルが理解ではなく生成においてフロンティアの独自モデルに匹敵できる理由を説明せよ。

2. ルーター関数を実装せよ：プロンプトテキストを与えられたとき、`understand`または`generate`に分類する。「説明してからスケッチして」のような曖昧なプロンプトをどう処理するか？

3. JanusFlowはVQパスを整流フローに置き換える。トランスフォーマー本体は今何を出力し、損失はどう変わるか？

4. Janus-Proアーキテクチャが1つ以上の分離エンコーダーで処理できる4番目のタスクを提案せよ。例：画像セグメンテーション（DINOスタイル）、深度推定（MiDaSスタイル）。

5. Janus-Proのセクション4.2のデータスケーリングについて読め。どのデータステージがJanusと比べたT2I品質向上に最も貢献しているか？

## キーワード

| 用語 | よく使われる表現 | 実際の意味 |
|------|-----------------|------------|
| 分離エンコーディング | "2つのビジュアルエンコーダー" | 方向ごとに別々のトークナイザーまたはエンコーダー：理解には意味的、生成には再構成的 |
| 共有本体 | "1つのトランスフォーマー" | どちらのエンコーダーの出力も処理する単一のトランスフォーマー。モダリティ固有の重みなし |
| 理解のためのSigLIP | "意味的特徴" | 豊富な概念特徴を提供するCLIPファミリーのビジョンタワーだが再構成は苦手 |
| 生成のためのVQ | "再構成コード" | ピクセルにきれいにデコードされるベクトル量子化トークン |
| JanusFlow | "整流フロー変形" | VQの代わりに連続フローマッチング生成ヘッドを持つJanus-Pro |
| ルーティングタグ | "タスクタグ" | 入力エンコーダーを選択するプロンプトマーカー（`<understand>` / `<generate>`） |
