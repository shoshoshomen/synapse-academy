# CLIPからBLIP-2へ――Q-Formerによるモダリティブリッジ

> CLIPは画像とテキストを整列させるが、キャプション生成、質問応答、会話はできない。BLIP-2（Salesforce、2023年）は小さな学習可能なブリッジでこれを解決した：32個の学習可能なクエリベクトルがクロスアテンションでフリーズしたViTの特徴に注意を向け、フリーズしたLLMの入力ストリームに直接挿入される。1億8800万パラメータのブリッジが110億のLLMをViT-g/14に接続した。2026年に至るすべてのアダプターベースVLM（MiniGPT-4、InstructBLIP、LLaVAの派生）は子孫だ。このレッスンではQ-Formerのアーキテクチャを読み解き、2段階学習を説明し、ビジュアルトークンをフリーズしたテキストデコーダーに渡すトイバージョンを構築する。


## 学習目標

- フリーズしたビジョンエンコーダーとフリーズしたLLMの間に学習可能なボトルネックを置くことが、コストと安定性においてエンドツーエンドのファインチューニングより優れる理由を説明する。
- 固定の学習可能なクエリが外部の画像特徴に注意を向けるクロスアテンションブロックを実装する。
- BLIP-2の2段階事前学習を追う：表現学習（ITC + ITM + ITG）→生成学習（フリーズデコーダーでのLM損失）。
- Q-FormerをLLaVAで使われているシンプルなMLPプロジェクターと比較し、それぞれが優位な場合を論じる。

## 問題

フリーズしたViTがあり、画像あたり256個のパッチトークン（次元1408）を生成する。フリーズした7B LLMがあり、次元4096のトークン埋め込みを期待する。明白なブリッジ――1408から4096への線形層――は機能するが、LLMのコンテキストに256個のパッチトークンをすべて渡すと、1画像あたり256トークンを消費する。32枚の画像バッチでは、ビジュアルモダリティだけで8192トークンが消費される。

BLIP-2の問い：256トークンの画像表現を、はるかに少ないトークン（例えば32個）に圧縮しながら、LLMがキャプション生成、質問応答、画像推論をするのに十分な情報を保持できるか？フリーズしたバックボーンに触れずに、ブリッジのパラメータだけを学習コストに留めてこれを学習できるか？

答え：Q-Formerだ。ViTのパッチトークンにクロスアテンションする32個の学習可能な「クエリ」ベクトルで、LLMが消費する32トークンのビジュアルサマリーを生成する。総計1億8800万パラメータ。LLMに接触する前に、コントラスティブ、マッチング、生成目標で学習される。

## 概念

### 学習可能なクエリ

Q-Formerの核心的なトリック：LLMのテキストトークンが画像パッチに注意を向ける代わりに、32個の学習可能なクエリベクトル`Q`を新たに導入してそれらが画像パッチに注意を向けさせる。クエリはモデルのパラメータだ――学習中に習得され、すべての画像で同じ32個のクエリが使われる。

クロスアテンション後、各クエリは画像の圧縮サマリーを保持する――「メインオブジェクトを説明せよ」、「背景を説明せよ」、「オブジェクトを数えよ」など。クエリは文字通りセマンティックラベルに特化するわけではない；ダウンストリーム損失を下げるようなエンコーディングを学習する。

### アーキテクチャ

Q-Formerは小さなTransformer（12層、約1億パラメータ）で2つのパスを持つ：

1. クエリパス：32個のクエリベクトルが自己注意（相互間）を通り、フリーズしたViTのパッチトークンに対するクロスアテンション、そしてFFNを経る。
2. テキストパス：BERTスタイルのテキストエンコーダーがクエリパスと自己注意とFFNの重みを共有する。テキストパスではクロスアテンションが無効化される。

学習時は両パスが動作する。クエリとテキストは共有自己注意を通じて相互作用するため、クエリはITM、ITGのように必要なタスクでテキストを条件とすることができる。VLMハンドオフの推論時には、クエリだけが流れ、32個のビジュアルトークンを生成する。

### 2段階学習

BLIP-2は2段階で事前学習する：

ステージ1：表現学習（LLMなし）。3つの損失：
- ITC（画像テキストコントラスティブ）：プールされたクエリトークンとテキストCLSトークン間のCLIPスタイルのコントラスティブ学習。
- ITM（画像テキストマッチング）：二値分類器――この画像テキストペアはマッチするか？ハードネガティブマイニング済み。
- ITG（画像グラウンドテキスト生成）：クエリを条件としたテキストの因果LMヘッド。クエリにテキスト生成可能なコンテンツをエンコードさせる。

Q-Formerだけが学習する。ViTはフリーズ。LLMは不使用。

ステージ2：生成学習。フリーズしたLLM（OPT-2.7BまたはFlan-T5-XLなど）を接続する。32個のクエリ出力を小さな線形層でLLMの埋め込み次元に射影する。テキストプロンプトの前に追加する。連結されたプロンプト + 画像 + キャプション列のLM損失で線形射影とQ-Formerだけを学習させる。

ステージ2後、Q-Former + 射影が完全なビジュアルアダプターになる。推論時：画像 → ViT → Q-Former → 線形射影 → テキストの前に追加 → フリーズしたLLMが出力を生成。

### パラメータ経済性

BLIP-2：ViT-g/14（11億、フリーズ）+ OPT-6.7B（67億、フリーズ）+ Q-Former（1.88億、学習済み）= 80億合計、1.88億学習済み。Q-Formerだけで全スタックパラメータの約2.4%だ。学習コストはこれを反映する：少数のA100数日間 vs エンドツーエンドの数週間。

品質：BLIP-2はゼロショットVQAでFlamingo-80Bに匹敵または超え、50倍小さい。ブリッジは機能する。

### InstructBLIPと命令認識Q-Former

InstructBLIP（2023年）はQ-Formerに追加入力として命令テキスト自体を拡張した。クロスアテンション時、クエリは画像パッチと命令の両方にアクセスできる。クエリは単一の固定サマリーを学習する代わりに命令ごとに特化できる（「車を数えよ」、「雰囲気を説明せよ」）。保留タスクでのベンチマーク向上。

### MiniGPT-4とプロジェクターのみアプローチ

MiniGPT-4はQ-Formerを維持したが、他のすべてをフリーズさせながら出力線形射影だけを学習させた。安価だが品質コストがある――クエリはBLIP-2のものであって自分のものではない。素早い反復には良いが最良のアーキテクチャではない。

### LLaVAがよりシンプルに行った理由

LLaVA（2023年、レッスン12.05）はQ-Formerを普通の2層MLPに置き換え、すべてのViTパッチトークンをLLM空間に射影する――24×24グリッドで576トークン、すべてLLMに渡される。圧縮は劣るが、LLMが生のパッチに注意を向けられる。当時これは議論を呼んだ；2023年末には支配的になった。ビジュアル命令データ（LLaVA-Instruct-150k）がMLPは十分なシグナルを保持するよう学習できることを証明したからだ。トレードオフ：LLaVAのコンテキストが速く埋まるが、マルチ画像とビデオに自然にスケールする。

2026年時点でフィールドは分かれた：Q-Formerはトークンバジェットが重要な場所（長いビデオ、多数画像）で生き残り；MLPプロジェクターはトークンあたりの生品質が優先される場所で支配的だ。

### ゲートクロスアテンション：Flamingo、祖先

Flamingo（レッスン12.04）はBLIP-2より先行し、同じクロスアテンションアイデアを使ったが、1つのブリッジとしてではなく、すべてのフリーズLLM層で使った。BLIP-2は入力層だけに圧縮しても機能することを示した。GeminiとIdeficsは両方を組み合わせる：インターリーブ入力トークンと、インコンテキストのfew-shotのためのオプションのゲートクロスアテンション。

### 2026年の派生

- Q-Former：BLIP-2、InstructBLIP、MiniGPT-4、およびトークンバジェット上の理由からほとんどのビデオ言語モデル。
- Perceiver resampler：Flamingoの変形（レッスン12.04）；Ideficsファミリー、Eagle、OmniMAE。
- MLPプロジェクター：LLaVA、LLaVA-NeXT、LLaVA-OneVision、Cambrian-1。
- アテンションpool：VILA、PaliGemma。

4つともすべて有効だ。決め手の問いは、トークンバジェットとトークンあたりの品質のどちらで制約されているかだ。

## 使ってみる

`code/main.py`はstdlib Q-Formerスタイルのクロスアテンションを構築する：

1. 256個の画像パッチトークン（次元128）をシミュレート。
2. 32個の学習可能なクエリ（次元128）を初期化。
3. スケールドドットプロダクトのクロスアテンションを実行（クエリからQ、パッチからK/V）。
4. 線形層でLLM次元（512）に射影。
5. 32個のLLM準備済みビジュアルトークンを出力。

すべての数学はpure Pythonのネストされたループ。トイだが形状は正確だ。注意重み行列が印刷されるので各クエリがどのパッチから引き出したかを確認できる。

## 演習

1. PyTorchでクロスアテンションブロックを実装せよ。32個のクエリと256個のキー/値で、注意重み行列が32×256でsoftmax後に各行が1に合計されることを確認せよ。

2. BLIP-2のステージ1ではQ-FormerがITC、ITM、ITGの3つの損失を同時に実行する。各損失のforwardシグネチャを疑似コードで書け。どの損失がテキストエンコーダーパスを有効にする必要があるか？

3. パラメータ数を比較せよ：Q-Former（12層、768隠れ）対2層MLPプロジェクター（1408→4096、2層）。どのLLMスケールで1.88億のQ-Formerコストが学習効率でペイするか？

4. BLIP-2論文（arXiv:2301.12597）のSection 3.2でQ-Formerの初期化方法を読め。BERT-base（ランダムではなく）から初期化することが収束を加速する理由を説明せよ。

5. 1FPSでサンプリングされた10分のビデオで60フレームを処理する場合、Q-Former（32トークン/フレーム）対MLPプロジェクター（576トークン/フレーム）のフレームあたりトークンコストを計算せよ。どちらが128kトークンのLLMコンテキストウィンドウに収まるか？

## キーワード

| 用語 | よく言われること | 実際の意味 |
|------|----------------|------------------------|
| Q-Former | "Querying Transformer" | フリーズしたViT特徴にクロスアテンションする32個の学習可能なクエリベクトルを持つ小さなTransformer |
| 学習可能なクエリ | "ビジョンのソフトプロンプト" | クロスアテンションのクエリ側として機能するパラメータの固定セット；モデルごとに学習され、すべての入力で共有される |
| クロスアテンション | "QはここからK/VはあそこHere" | クエリ、キー、バリューが異なるソースから来るアテンション；クエリがViTパッチから引き出す方法 |
| ITC | "画像テキストコントラスティブ" | Q-FormerのプールされたクエリとテキストCLSに適用されるCLIPスタイルの損失 |
| ITM | "画像テキストマッチング" | ハードネガティブマイニング済みペアの二値分類器；クエリに細かいミスマッチを識別させる |
| ITG | "画像グラウンドテキスト生成" | テキストがクエリを条件として生成される因果LM損失；クエリにテキスト解読可能なコンテンツをエンコードさせる |
| 2段階事前学習 | "表現学習から生成学習へ" | ステージ1はQ-Former単独で学習（ITC/ITM/ITG）；ステージ2はフリーズLLMを接続して射影 + Q-Formerのみ学習 |
| フリーズバックボーン | "ファインチューニングしない" | ビジョンエンコーダーとLLMの重みは固定；ブリッジだけが学習する |
| 射影ヘッド | "LLM次元への線形変換" | Q-Formerの出力をLLMの埋め込み次元にマッピングする最終線形層 |
| Perceiver resampler | "Flamingoのバージョン" | 同様の学習可能なクエリのクロスアテンション、単一ブリッジとしてではなくFlamingo全体の層で使用 |
