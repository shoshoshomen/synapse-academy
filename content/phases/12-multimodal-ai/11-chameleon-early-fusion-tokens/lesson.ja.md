# Chameleonとearly-fusionトークンのみマルチモーダルモデル

> これまで見てきたすべてのVLMは画像とテキストを分離したままにする。ビジュアルトークンはビジョンエンコーダーから来てプロジェクターに流れ、LLMの中でテキストと出会う。ビジョンとテキストの語彙は決して重ならない。Chameleon（Meta、2024年5月）が問うた：もし重なったら？画像を共有語彙からの離散トークンの列に変換するVQ-VAEを学習させる。すべてのマルチモーダル文書は今や1つの列――テキストトークンと画像トークンが交互に、単一の自己回帰損失。副作用：モデルは混合モダリティの出力を生成できる――1回の推論呼び出しでテキストと画像トークンを交互に。このレッスンではearly-fusionの命題を読み解き、トイバージョンをエンドツーエンドで構築する。


## 学習目標

- 共有語彙 + 単一損失がモデルにできることを何を変えるかを説明する。
- VQ-VAEが画像をTransformerの次トークン目標と互換性のある離散列にトークン化する方法を説明する。
- Chameleonの学習安定性のトリックを挙げる：QK-Norm、ドロップアウト配置、LayerNorm順序。
- ChameleonをBLIP-2のQ-Formerアプローチと比較し、それぞれが適切な選択である場合を説明する。

## 問題

アダプターベースのVLM（LLaVA、BLIP-2、Qwen-VL）はテキストと画像を2つの異なるものとして扱う。テキストトークンは`embed(text_token)`を通る；画像は`visual_encoder(image) → projector → ... pseudo_tokens`を通る。モデルは途中でマージする2つの入力パスを持つ。

3つの結果：

1. LLMは画像を消費できるが、出力できない。出力はテキストのみ。
2. 混合モダリティ文書（段落と画像が交互の記事のような）が不自然――モデルの外でマルチモーダル入力を解析するか生成をチェーンするかのどちらか。
3. 分布のミスマッチ。ビジュアルトークンとテキストトークンは隠れ空間の異なる領域に住み、微妙な整合問題を生む。

Chameleonは前提を拒否する：画像は共有語彙からの離散トークンの列だ。インターリーブ文書でモデルを学習させ、1つの損失、1つの自己回帰デコーダーで、混合モダリティ生成を無料で解放する。

## 概念

### 画像トークナイザーとしてのVQ-VAE

トークナイザーはベクトル量子化変分オートエンコーダーだ。アーキテクチャ：

- エンコーダー：画像を空間特徴マップにマッピングするCNN + ViT、例えば256次元の32×32特徴。
- コードブック：K個のベクトルの学習可能な語彙（Chameleonは8192を使用）、次元も256。
- 量子化：各空間特徴について、L2距離で最も近いコードブックエントリを検索する。連続特徴を整数インデックスに置き換える。
- デコーダー：量子化された特徴をピクセルに戻すCNN。

学習：VAE再構築損失 + コミットメント損失 + コードブック損失。コードブックインデックスが画像の離散アルファベットを形成する。

Chameleonの場合：1枚の画像が8192語彙の32×32 = 1024トークンになる。LLMのBPE語彙（例えば32000）のテキストトークンと連結する。最終語彙：40192。Transformerは1つの列、1つの損失を見る。

### 共有語彙

Chameleonの語彙はテキストトークン、画像トークン、モダリティセパレーターを組み合わせる。各トークンは単一のIDを持つ。入力埋め込み層はすべてのIDをD次元の隠れベクトルにマッピングする。出力射影は隠れを語彙ロジットにマッピングする。Softmaxが次のトークンをどんなモダリティでも選ぶ。

セパレーターが重要だ：`<image>`と`</image>`タグが画像トークン列を括る。生成時、モデルが`<image>`を出力すると、下流ソフトウェアは次の1024トークンがピクセルレンダリングのためにデコーダーに送る必要があるVQインデックスであることを知る。

### 混合モダリティ生成

推論は共有語彙での次トークン予測だ。プロンプトの例：「猫を描いて説明せよ」。Chameleonが出力する：

```
<image> 4821 1029 2891 ... (1024 image tokens) </image>
The cat is orange, sitting on a windowsill...
```

モデルが順序を自律的に選ぶ――画像を先にテキストを後に、テキストを先に画像を後に、またはインターリーブすることもある。同じデコーダー、同じ損失。

テキストのみの生成のアダプターVLMと比べよ。Chameleonはモデル出力モダリティの問いを再開する。

### 学習安定性――QK-Norm、ドロップアウト、LayerNorm順序

early-fusion学習はスケールで不安定だ。Chameleonの論文は3つのトリックを記録する：

- QK-Norm。ドットプロダクトの前にアテンション内のクエリとキー射影にLayerNormを適用する。深さでのロジット大きさの爆発を防ぐ。2024年以降の複数の大型モデルで使用。
- ドロップアウト配置。アテンションとMLPの後だけでなく、すべての残差加算後にドロップアウト。画像トークンからのグラジェントが支配できる場合、より多くの正則化が必要。
- LayerNorm順序。残差ブランチのPre-LN（標準）、さらに最後のブロックのスキップ接続に追加のLN。最終層のグラジェント流れを安定させる。

これらのトリックなしに、34Bパラメータ Chameleonの学習は複数のチェックポイントで発散した。これらを使えば収束する。学習レシピがアーキテクチャと同様の貢献だ。

### トークナイザーの再構築上限

VQ-VAEはロッシー。8192コードブックエントリと512×512画像あたり1024トークンで、再構築のPSNRは約26〜28dBが上限だ。これは認識可能な画像生成には十分だが、連続空間拡散より明らかに劣る（Stable Diffusion 3は32dB以上を達成）。

トークナイザーがボトルネックだ。より良いトークナイザー（MAGVIT-v2、IBQ、SBER-MoVQGAN）が上限を引き上げる。Emu3（レッスン12.12）はより良いトークナイザーだけでSDXLレベルの品質を達成する。

### Chameleon vs BLIP-2 / LLaVA

Chameleon（early fusion、共有語彙）：
- 1つの損失、1つのデコーダー。
- 混合モダリティ出力を生成する。
- トークナイザーが品質上限。
- 高コスト：推論パスで生成画像あたりVQ-VAEデコーダー。

BLIP-2 / LLaVA（late fusion、別々のタワー）：
- ビジョン入力、テキスト出力のみ。
- 事前学習済みLLMを再利用。
- 理解のためのトークナイザーボトルネックなし。
- 低コスト：シングルフォワードパス。

タスクで選べ。画像生成が必要なら、Chameleonファミリー。理解のみが必要なら、アダプターVLMはより単純で事前学習済みの計算をより多く再利用する。

### FuyuとAnyGPT

Fuyu（Adept、2023年）は関連するアプローチ：別々のビジョンエンコーダーを完全にスキップし、生の画像パッチをトークンであるかのようにLLMの入力射影に通す、トークナイザーなし。Chameleonより単純だが、共有語彙出力生成を失う。

AnyGPT（Zhanら、2024年）はChameleonを4つのモダリティ（テキスト、画像、音声、音楽）に拡張する。各モダリティに同じVQ-VAEトリック、共有Transformer。任意から任意の生成。レッスン12.16でより詳しく説明。

## 使ってみる

`code/main.py`はトイのエンドツーエンドearly-fusionモデルを構築する：

- 8×8パッチをコードブックインデックス（K=16）にマッピングするトイVQ-VAEスタイル量子化器。
- （テキストids 0..31）+（画像ids 32..47）+（セパレーター 48、49）の共有語彙。
- 合成キャプション + 画像トークン列で学習するトイ自己回帰デコーダー（バイグラムテーブル）。
- プロンプトが与えられた場合にテキスト + 画像トークンを交互に出力するサンプリングループ。

コードはTransformerを意図的に小さく（バイグラム）保つことで、シグナルフローをエンドツーエンドで追跡できる。

このレッスンは`outputs/skill-tokenizer-vs-adapter-picker.md`を生成する。製品仕様（理解のみ対理解 + 生成、必要な画像品質、コストバジェット）が与えられた場合、Chameleonファミリー（early fusion）とLLaVAファミリー（late fusion）から選んで定量的な経験則で正当化する。

## 演習

1. Chameleonは512×512の画像あたりK=8192コードブックエントリと1024トークンを使用する。24ビットRGB画像との圧縮比を推定せよ。ロッシーか？どのくらいロッシーか？

2. 同じVQ-VAE密度での4K画像（3840×2160）は何個の画像トークンを生成するか？Chameleonスタイルモデルが1回の推論呼び出しで4K画像を生成できるか？最初に何が壊れるか――コンテキスト、トークナイザー品質、またはKVキャッシュ？

3. pure PythonでQK-Normを実装せよ。64次元のクエリとキーで、LayerNorm前後のドットプロダクトを示せ。大きさ制御が深さでなぜ重要か？

4. 学習安定性に関するChameleon Section 2.3を読め。QK-Normなしで34Bで論文が観察した正確な失敗モードを説明せよ。「ノルム爆発」のシグネチャは何だったか？

5. テキストのみのプロンプトが与えられた場合に混合モダリティ応答を出力するようトイデコーダーを拡張せよ。学習データ分布60%テキスト優先 / 40%画像優先でモデルが画像優先対テキスト優先を選ぶ頻度を測定せよ。

## キーワード

| 用語 | よく言われること | 実際の意味 |
|------|----------------|------------------------|
| Early fusion | "統合トークン" | 画像が最初のステップからTransformerの語彙を共有する離散トークンに変換される |
| VQ-VAE | "画像トークナイザー" | Transformerが予測できる整数インデックスに画像をマッピングするCNN + ViT + コードブック |
| 共有語彙 | "1つの辞書" | テキスト + 画像 + モダリティセパレーターをカバーする単一のトークンID空間 |
| QK-Norm | "アテンション安定化器" | ドットプロダクト前にクエリとキーに適用されるLayerNorm；ノルム爆発を防ぐ |
| 混合モダリティ生成 | "テキスト + 画像出力" | 1回のパスで自律的にインターリーブされたテキストと画像トークンを生成する推論 |
| コードブックサイズ | "Kエントリ" | VQ-VAEが量子化できる離散ベクトルの数；圧縮と忠実度をトレードオフ |
| トークナイザー上限 | "再構築限界" | VQトークンをデコードして達成可能な最良PSNR；モデルの画像品質を制限 |
