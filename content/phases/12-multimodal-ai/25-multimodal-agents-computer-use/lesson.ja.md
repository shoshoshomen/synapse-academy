# マルチモーダルエージェントとコンピューター使用（カプストン）

> 2026年のフロンティアプロダクトは、スクリーンショットを読み、ボタンをクリックし、ウェブUIをナビゲートし、フォームを入力し、ワークフローをエンドツーエンドで完了するマルチモーダルエージェントだ。SeeClickとCogAgent（2024年）はGUIグラウンディングのプリミティブを証明した。Ferret-UIはモバイルを追加した。ChartAgentはチャートのビジュアルツール使用を導入した。VisualWebArenaとAgentVista（2026年）はフロンティアが追うベンチマークだ。Gemini 3 ProとClaude Opus 4.7でさえ、AgentVistaの難しいタスクで約30%しかスコアしない。このカプストンはフェーズ12のすべての糸を引き寄せる：知覚（高解像度VLM）、推論（ツール使用を持つLLM）、グラウンディング（座標出力）、長い水平線メモリ、評価。


## 学習目標

- マルチモーダルエージェントループを設計する：知覚 → 推論 → 行動 → 観察 → 繰り返し。
- GUIグラウンディング出力スキーマ（クリック座標、テキスト入力、スクロール、ドラッグ）をVLMがJSONとして出力できるよう構築する。
- スクリーンショット専用エージェント対アクセシビリティツリーエージェント対ハイブリッドエージェントを比較する。
- 小さなVisualWebArenaスライスでマルチモーダルエージェントベンチマーク評価を設定する。

## 問題設定

予約サイトのワークフロー：「4月15日の東京への便を、通路側座席で800ドル以下で見つけて予約して。」

マルチモーダルエージェントには以下が必要だ。

1. ブラウザのスクリーンショットを撮る。
2. スクリーンショット + URL + 目標を計画に解析する。
3. 構造化アクションを出力する：クリック（x,yで）、「東京」と入力（要素Eで）、スクロールダウン、選択（ラジオボタン）。
4. ブラウザにアクションを適用する。
5. 新しい状態（次のスクリーンショット）を観察する。
6. タスクが完了するまで繰り返す。

各ステップはマルチモーダルVLM呼び出しだ。VLMの出力は解析可能なJSONでなければならない。エラーはステップをまたいで蓄積されるため、リカバリが重要だ。

## 概念

### GUIグラウンディング — プリミティブ

GUIグラウンディングは：スクリーンショットと自然言語指示を与えられて、クリックする(x, y)座標（またはその他のアクション）を出力する。

SeeClick（arXiv:2401.10935）は大規模での最初のオープン結果だった：合成 + 実際のGUIデータでVLMをファインチューニングし、座標をプレーンテキストトークンとして出力する。機能する。

CogAgent（arXiv:2312.08914）は密なUIのために1120x1120の高解像度エンコーディングを追加した。スコア：ウェブナビゲーションで約84%。

Ferret-UI（arXiv:2404.05719）はモバイルUIに焦点を当て、iOSアクセシビリティデータと統合する。

出力形式は通常JSON：

```json
{"action": "click", "x": 384, "y": 220, "element_desc": "Search button"}
```

`element_desc`はリカバリを助ける。スクリーンショット間で座標がずれる場合、セマンティックなヒントがシステムに再グラウンドさせる。

### アクションスキーマ

典型的なアクションスキーマには6〜10のアクションタイプがある：

- `click`：(x, y)
- `type`：(text, x?, y?)
- `scroll`：(direction, amount)
- `drag`：(x0, y0, x1, y1)
- `select`：(option_index)
- `hover`：(x, y)
- `navigate`：(url)
- `wait`：(ms)
- `done`：(success, explanation)

エージェントはステップごとに1つのアクションを出力する。ブラウザラッパーが実行して新しい状態を返す。

### スクリーンショット専用対アクセシビリティツリー

2つの入力モード：

- スクリーンショット専用：フルイメージ、構造情報なし。最も汎用的。あらゆるアプリで機能する。
- アクセシビリティツリー：構造化DOM / iOSアクセシビリティ情報。グラウンディングにははるかに信頼性が高い。ツリーが利用可能な場合に機能する。
- ハイブリッド：両方。アトミックアクションの信頼性の高いグラウンダーとしてツリーを使用し、意味的コンテキストにはスクリーンショットを使用する。

本番エージェントはできる場合はハイブリッドを使用する。ブラウザ自動化（Selenium + アクセシビリティ）は常にツリーを持つ。デスクトップアプリは時々持つ。

### 長い水平線メモリ

20ステップのワークフローは20枚のスクリーンショットを生成する。VLMのコンテキストはすぐに満杯になる。3つの圧縮戦略：

- サマリーチェーン：5ステップごとに何が起きたかを要約し、古いスクリーンショットを削除する。
- スキップフレーム：最初、最後、3枚ごとのスクリーンショットを保持する。
- ツール記録ログ：アクションを実行し、何をしたかのテキストログを保持する。古いスクリーンショットは再確認しない。

ClaudeのコンピューターユースAPIはログパターンを使用する。シンプルで信頼性が高い。

### ビジュアルツール使用

ChartAgent（arXiv:2510.04514）はチャート理解のためのビジュアルツール使用を導入する：クロップ、ズーム、OCR、外部検出を呼び出す。エージェントは「領域(100, 200, 300, 400)をクロップしてOCRを呼び出す」をツール呼び出しとして出力できる。ツールがテキストを返し、VLMが推論を続ける。

このパターンは一般化する：set-of-markプロンプティング、領域注釈、外部検出ツールはすべて同じ「ツール呼び出しを出力し、構造化応答を受け取る」スキーマに収まる。

### 2026年のベンチマーク

- ScreenSpot-Pro：約1kのウェブスクリーンショットでGUIグラウンディング。オープンSOTA Qwen2.5-VL-72B 約85%。フロンティア 約90%。
- VisualWebArena：エンドツーエンドのウェブタスク（ショップ、フォーラム、広告）。オープンSOTA 約20%。Gemini 3 Pro 約27%。
- AgentVista（arXiv:2602.23166）：2026年最も難しいベンチマーク。12ドメインにわたる現実的なワークフロー。フロンティアモデルは27〜40%。オープンモデルは10〜20%。
- WebArena / WebShop：古いベンチマーク。フロンティアで飽和。

### なぜまだ難しいのか

エージェント性能のボトルネック：

1. 細かいスケールでのビジュアルグラウンディング。「小さなXをクリックして」はモバイル解像度では頻繁に失敗する。
2. 長い水平線計画。10回のアクション後、エージェントが目標からずれる。
3. エラーリカバリ。クリックが失敗した（間違いボタン）とき、検出 + リカバリはほとんど訓練データがない。
4. クロスページコンテキスト。タブ間のジャンプや長いフォームが状態を失う。

研究の方向：メモリアーキテクチャ、明示的な再計画、マルチモーダル検証（アクション成功のためのスクリーンショットマッチング）。

### カプストンの実装

カプストンタスク：以下のコンピューターユースエージェントを構築する。

1. 予約サイトのモックページのHTML + スクリーンショットを読む。
2. マルチステップシーケンスを計画する：検索 → 選択 → フォーム入力 → 送信。
3. アクションスキーマに合ったJSONアクションを出力する。
4. 固定の10タスクスライスで評価する。

レッスンは実際のブラウザに簡単に拡張できるスキャフォルドコードを提供する。

## 使ってみる

`code/main.py`はカプストンスキャフォルドだ：

- アクションスキーマのJSON定義（10アクション）。
- 辞書としてのモックブラウザ状態。
- エージェントループスケルトン：状態を受け取り、アクションを出力し、適用し、ループする。
- エンドツーエンドの成功率を測定する10タスクのミニベンチマーク（合成ページ）。
- アクションが失敗したときのエラーリカバリフック。

## 成果物を出す

このレッスンでは`outputs/skill-multimodal-agent-designer.md`を作成する。コンピューターユースプロダクト（ドメイン、アクションセット、評価目標）を与えられたとき、完全なエージェントループ、メモリ戦略、グラウンディングモード、期待されるベンチマークスコアを設計する。

## 演習

1. `screenshot_region`ツール（クロップ + ズーム）でアクションスキーマを拡張せよ。どのようなタスクが利益を得るか？

2. AgentVista（arXiv:2602.23166）を読め。最も難しいタスクカテゴリを説明し、フロンティアモデルがまだ失敗する理由を述べよ。

3. 長い水平線メモリ圧縮：ライブに保持されるスクリーンショットが4枚以下、任意の数がログされるサマリーチェーンを設計せよ。

4. エラーリカバリフックを構築せよ：アクション失敗（ボタンが見つからない）時、エージェントは次に何をするか？

5. スクリーンショット専用Claude 4.7対ハイブリッドスクリーンショット + アクセシビリティツリーQwen2.5-VLを10のウェブタスクで比較せよ。どちらがどのタスクで勝つか？

## キーワード

| 用語 | よく使われる表現 | 実際の意味 |
|------|-----------------|------------|
| GUIグラウンディング | "クリック座標" | モデルがスクリーンショット上の指示のターゲットの(x,y)を出力する |
| アクションスキーマ | "ツール定義" | 有効なアクション（クリック、入力、スクロール、ドラッグ）のJSON記述 |
| アクセシビリティツリー | "構造化DOM" | ブラウザ/iOS APIからの機械可読UIの階層 |
| ハイブリッドエージェント | "スクリーンショット + ツリー" | 画像と構造化情報の両方を使用。どちらか単独より信頼性が高い |
| ビジュアルツール使用 | "ズーム/クロップ/検出" | エージェントが計画中に外部ビジョンツール（OCR、検出）を呼び出す |
| サマリーチェーン | "メモリ圧縮" | 定期的なテキスト要約が長いスクリーンショット履歴を置き換える |
| VisualWebArena | "E2Eウェブベンチ" | エンドツーエンドのウェブタスクの2024ベンチマーク |
| AgentVista | "2026年の難しいベンチ" | 12ドメインの現実的なワークフロー。Gemini 3 Proでも約30%のスコア |
