# マルチトークン予測（MTP）

> GPT-2からLlama 3まですべての自己回帰LLMは位置ごとに1つの損失で学習する：次のトークンを予測する。DeepSeek-V3は位置ごとに第2の損失を追加した：その次のトークンを予測する。追加の14Bパラメータ（671Bモデルの上に）は勾配フローを通じてメインモデルに蒸留され、学習済みMTPヘッドは推論時に80%以上の受容率で投機的デコーディングのドラフターとして再利用された。1.8倍の生成スループットが無料でついてきた。このレッスンはDeepSeekの技術レポートからの逐次MTPモジュールを構築し、損失と共有ヘッドのパラメータレイアウトを計算し、なぜMTPが因果連鎖を保持するのにGloeckle et al.のオリジナルの並列MTPがそれを壊したかを説明する。


## 学習目標

- MTPの学習目標を述べ、予測深度にわたる結合損失を導出する。
- Gloeckle et al.の並列MTPヘッド（2024）とDeepSeek-V3の逐次MTPモジュールの違いを説明し、なぜ逐次設計が因果連鎖を保存するかを述べる。
- 事前学習実行にMTPモジュールを追加するパラメータとメモリのオーバーヘッドを計算する。
- 1つのMTPモジュールをゼロから実装する：共有埋め込み、深度ごとのトランスフォーマーブロック、射影、共有出力ヘッド。

## 課題

次トークン予測は標準的なLLM学習目標だ。すべての隠れ状態は正確に1つのことを予測するよう監督される：直後に続くトークン。これは驚くほど弱いシグナルだ。シーケンスのほとんどの情報は1つのトークンを超えて広がっている——構造、コヒーレンス、事実性、算術フロー。モデルは数兆トークンにわたる多くの1トークンシグナルを蓄積することでこれらを学ばなければならない。

MTPは問う：すべての隠れ状態が一度に複数の将来のトークンを予測するよう監督されたらどうなるか？Gloeckle et al.（Meta、2024）はこれが役立つことを示した。彼らの実装はバックボーンの上にいくつかの独立した出力ヘッドを配置し、それぞれが異なるオフセットを予測する。並列で単純だが、ヘッドは階層的な精緻化なしに同じ隠れ状態を見た——そして予測は因果的に連鎖しないため、投機的デコーディングに使用できなかった。

DeepSeek-V3（2024年12月）はMTPを各予測深度で因果連鎖を保持する逐次モジュールとして再設計した。モデルは`h_i^(0)`から`t+1`を予測し、次に`h_i^(0)`と`E(t+1)`埋め込みを組み合わせた新しい隠れ状態`h_i^(1)`から`t+2`を予測する、といった具合だ。各深度はそれ自身の小さなトランスフォーマーブロックだ。共有埋め込みと共有出力ヘッドがパラメータのオーバーヘッドを控えめに保つ。DeepSeek-V3のスケールでは、671Bのメインモデルの重みに加えてMTPモジュール全体で14Bの追加パラメータ。その2%のオーバーヘッドが、より密な学習シグナルと推論時にすぐに使える投機的デコーディングのドラフトをもたらした。

このレッスンは1つのMTPモジュールとDの深度にわたる損失をゼロから構築する。数学は整然としている。実装は150行だ。

## コンセプト

### 逐次MTPのレシピ

DeepSeek-V3はメインモデルの上に`D`個のMTPモジュールを追加する。各モジュール`k`（`k = 1..D`）は深度kでのトークン——つまり位置`i`までのプレフィックスが与えられた`t_{i+k}`——を予測する。

モジュール`k`は以下から構成される：

- 独自のアテンションとMLPを持つトランスフォーマーブロック`T_k`。
- 前の深度の隠れ状態と次の深度の正解トークンの埋め込みを組み合わせる射影行列`M_k`。
- 共有埋め込み`E`（メインモデルと同じ）。
- 共有出力ヘッド`Out`（メインモデルと同じ）。

学習時に、位置`i`までのプレフィックスに対して、深度ごとの隠れ状態は：

```
h_i^(0) = 位置iでのメインモデルのバックボーン
h_i^(k) = T_k( M_k * concat(RMSNorm(h_i^(k-1)), RMSNorm(E(t_{i+k}))) )   k >= 1の場合
```

深度ごとの予測は：

```
logits_{i+k} = Out(h_i^(k-1))   k = 1..Dの場合
```

深度ごとの損失は正解`t_{i+k}`に対するクロスエントロピー：

```
L_k = CE(logits_{i+k}, t_{i+k})
```

深度にわたる結合損失：

```
L_MTP = (lambda / D) * sum_{k=1..D} L_k
```

`lambda`は小さな重み付け係数——DeepSeek-V3は学習の最初10%に0.3を使い、その後0.1に。総学習損失は`L_main + L_MTP`だ。

### なぜ並列ではなく逐次か

Gloeckleのオリジナルの並列MTPはD個の出力ヘッドを持ち、それぞれが`h_i^(0)`に直接適用された。各ヘッドは同じバックボーンの隠れ状態から`t_{i+k}`を予測する。それは学習に問題ないが、予測は互いに条件付けられない。`head_1`の出力を`head_2`の助けに使えない——ヘッドは並列で動作する。

DeepSeek-V3の逐次設計は`h_i^(k-1)`と実際の次トークン埋め込み`E(t_{i+k})`から`h_i^(k)`を構築する。これにより因果連鎖が保持される：`t_{i+k+1}`を予測するために、深度k+1のモジュールは`t_{i+k}`に何があったかを見る。これは構造的に自己回帰デコーダーが自身の出力を消費する方法と同一だ——MTPモジュールを投機的デコーディングのドラフターとして直接使用可能にする。

推論時：`h_i^(k-1)`と下書きされた`t_{i+k}`をモジュール`k+1`にフィードし、`t_{i+k+1}`の予測を得る。繰り返す。これはまさにEAGLEスタイルのドラフトで、学習済みMTPモジュールをドラフトネットワークとして使用する。DeepSeek-V3は最初のMTPモジュールで80%以上の受容率と約1.8倍のスピードアップを報告する。

### パラメータの計算

hiddenが`h`で語彙が`V`のモデルの場合：

- メインモデル：数十億のパラメータ、プラスサイズ`V * h`の1つの出力ヘッド。
- 共有出力ヘッド：メインモデルのヘッドを再利用。追加パラメータなし。
- 共有埋め込み：メインモデルの埋め込みを再利用。追加パラメータなし。
- MTPモジュールあたり：
  - 射影`M_k`：`(2h) * h = 2h^2`。
  - トランスフォーマーブロック`T_k`：アテンション（MHAで`4h^2`）プラスMLP（通常SwiGLUで`8h^2`の比率）。ブロックあたり約`12h^2`。

モジュールあたりの合計追加：`~14h^2`。DeepSeek-V3の`h = 7168`、D = 1モジュールの場合：`~14 * 7168^2 = ~720M`パラメータ。DeepSeek-V3は14Bを報告——違いは主にMTPモジュールのエキスパートレイヤーもMoEであることによる。

### 投機的デコーディングの見返り

事前学習中、MTPモジュールは学習を約10%遅くする（より多くのフォワード計算、追加の損失）。見返りは2つ：

1. より密な学習シグナル。各隠れ状態はD+1の監督ターゲットを見る。MMLU、GSM8K、MATH、HumanEvalへの測定効果：DeepSeek-V3のアブレーションで一貫した数パーセントポイントの改善。

2. 推論時の無料の投機的デコーディングドラフト。MTPモジュールはすでに次のいくつかのトークンを予測するよう学習されている。ドラフトネットワークとして再利用すると、80%以上の受容率を実現する。そのレベルでN=3またはN=5の投機的デコーディングは1.8倍のスループットを与える。学習時の10%のコストは初めて推論を実行した時に回収される。

### EAGLEとの関係

EAGLEは事前学習後に別途小さなドラフトモデルを学習する。MTPはドラフトを事前学習に組み込む。2つのアプローチは異なるパイプラインを通じて同様の受容率に収束する：

| 次元 | EAGLE-3 | MTP（DeepSeek-V3） |
|-----------|---------|------------------|
| 学習時期 | 事前学習後 | 事前学習中 |
| 既存の重みとの後方互換性 | あり | なし（再学習が必要） |
| ドラフトパラメータ | 1〜2トランスフォーマー層 | 1トランスフォーマーブロック + 射影 |
| 受容率 | 0.88-0.92 | 深度1で0.80以上 |
| スピードアップ以外のメリット | 投機的デコーディングのみ | より密な学習シグナル + スピードアップ |

## 実装する

`code/main.py`は1つのMTPモジュールをエンドツーエンドで構築する：共有埋め込み、射影、トランスフォーマーブロック、共有出力ヘッド。次に短い合成シーケンスで深度ごとのクロスエントロピー損失を計算し、コンポーネントごとのパラメータ数を出力する。おもちゃの語彙サイズ32トークンで数値を読みやすく保つ。

### ステップ1：共有埋め込みテーブル

単一の`vocab_size x hidden`テーブルがメインモデルとすべての深度のすべてのMTPモジュールで使用される。第2のコピーではない——文字通り同じテンソル。

### ステップ2：深度ごとの組み合わせ

```python
def combine(prev_hidden, next_token_embed, M_k):
    # 特徴次元に沿ってconcatし、hiddenにプロジェクト
    concat = rms_norm(prev_hidden) + rms_norm(next_token_embed)  # ベクトル加算のスタンドイン
    projected = matvec(M_k, concat)
    return projected
```

実際のDeepSeek-V3は2つのRMSNormされたベクトルを`[2h]`にconcatし、`h x 2h`行列でプロジェクトする。おもちゃはstdlibの簡潔さのためにベクトル加算を使用する。

### ステップ3：深度kのトランスフォーマーブロック

セルフアテンションプラスMLP。おもちゃでは、1層の線形アテンションブロックとSwiGLU MLPがnumpyなしで構造を見せる。

### ステップ4：共有出力ヘッド

メインモデルの出力射影を再利用する。語彙に対するlogits。

### ステップ5：深度ごとの損失

オフセット`k`での正解トークンに対してsoftmax(logits)のクロスエントロピー。`lambda / D`スケーリング係数で深度にわたって集計する。

### ステップ6：パラメータの計算

総パラメータ数、共有（埋め込み、ヘッド）数、モジュールあたりの追加数を出力する。MTPの追加とメインモデルサイズの比率を示す。

## 使ってみる

MTPはDeepSeek-V3（2024年12月）とDeepSeek-R1シリーズに統合されている。推論時：

- DeepSeekの独自のサービングスタックはMTPモジュールをすぐに使える投機的デコーダーとして消費する。
- vLLMとSGLangは2026年4月時点でDeepSeek-V3 MTPの統合パスを持っている。
- AMDのROCm SGLangチュートリアルはV3チェックポイントで1.8倍のスピードアップを測定した特定のMTP投機的デコーディング設定を示す。

新しい事前学習実行でMTPを使うべき場面：

- フルの事前学習パイプラインを制御していてより密な学習シグナルを蓄えたい場合。
- モデルをスケールでサービングすることがわかっていて投機的デコーディングを無料で欲しい場合。
- hidden sizeが少なくとも4096。1Bスケールではオーバーヘッドがメリットより多く損なう。

使うべきでない場面：

- 既存の事前学習済み密モデルの微調整。MTPモジュールが学習されていない。
- 比較するための清潔なベースラインが欲しい研究モデル。MTPはアーキテクチャを変える。

## 成果物を出す

このレッスンは`outputs/skill-mtp-planner.md`を生成する。事前学習実行仕様（モデルサイズ、データ、計算量）が与えられると、MTP統合の計画を返す：深度Dの数、`lambda`スケジュール、メモリのオーバーヘッド、推論時の投機的デコーディングの接続。

## 演習

1. `code/main.py`を実行する。合成シグナルが強くなるにつれて深度ごとの損失が単調に減少することを示す。固定パターンを使用するように合成を修正し、深度1と深度2の両方の損失が収束することを確認する。

2. D=1 MTPモジュールを持つ密な70Bモデル（hidden 8192、80層）のパラメータオーバーヘッドを計算する。DeepSeek-V3の報告された14Bのオーバーヘッドと比較する。DeepSeekの数値が高い理由を説明する：MTPトランスフォーマーブロックは同じMoE構造を継承し、モジュールあたりのパラメータ数を膨らませる。

3. おもちゃにD=2を実装する：`h^(1)`を取って`t_{i+2}`を予測する2番目のMTPモジュールを追加する。結合損失とパラメータの計算がDeepSeekの論文の式19〜21と一致することを確認する。

4. おもちゃを並列MTP（Gloeckleスタイル）に切り替える：メインの隠れ状態の上にD個の出力ヘッドを追加し、それぞれが異なるオフセットを予測する。同じ合成シグナルで深度ごとの損失が逐次バージョンとどう比較されるかを測定する。逐次バージョンはk > 1での深度k損失が低くなるはずで、中間予測を条件とするためだ。

5. 学習済みMTPモジュールをEAGLEスタイルのドラフトとして使用する：推論時にモジュールkを呼び出して`t_{i+k}`を提案する。保留シーケンスでこれらのドラフトトークンのメインモデルの予測に対する受容率を測定する。おもちゃで50%以上を達成した場合、MTP-as-draftの経験的特性を再現したことになる。

## キーワード

| 用語 | 人々が言うこと | 実際の意味 |
|------|----------------|-----------|
| MTPモジュール | 「追加の損失ブロック」 | メインモデルから`k`位置先のトークンを予測する小さなトランスフォーマーブロックプラス射影 |
| 予測深度 | 「どのオフセット」 | モジュール`k`が位置`i`までのプレフィックスから`t_{i+k}`を予測する整数`k` |
| 並列MTP | 「Gloeckleスタイル」 | 同じバックボーン隠れ状態に対するD個の独立したヘッド、条件連鎖なし |
| 逐次MTP | 「DeepSeek-V3スタイル」 | 各モジュールが前の深度の隠れ状態と次のトークンの埋め込みを条件とする；因果連鎖を保持 |
| 共有出力ヘッド | 「メインヘッドを再利用」 | MTPモジュールは別の出力射影ではなくメインモデルのLMヘッドを呼び出す |
| 共有埋め込み | 「メインテーブルを再利用」 | どこでも同じ語彙埋め込みテーブルが使用される；重複パラメータなし |
| 射影行列M_k | 「隠れ+次トークンを組み合わせる」 | 前の隠れ状態とターゲットトークン埋め込みを次の深度の入力に折り畳む`h x 2h`線形層 |
| 結合損失L_MTP | 「平均化された追加損失」 | `lambda`でスケールされた深度ごとのクロスエントロピー損失の算術平均 |
| 深度1での受容率 | 「MTPドラフトがどれくらい正しいか」 | D=1 MTPモジュールのtop-1予測がメインモデルのtop-1予測と一致する率；DeepSeek-V3で80%以上 |
| Lambdaの重み付け | 「追加損失の重要度」 | 深度ごとのスケーリング係数；DeepSeek-V3では学習開始時0.3、後に0.1 |
