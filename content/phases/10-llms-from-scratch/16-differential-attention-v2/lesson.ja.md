# 差分アテンション（V2）

> Softmaxアテンションは一致しないすべてのトークンにわずかな確率を分散させる。100kトークンにわたって、そのノイズが蓄積しシグナルを溺れさせる。Differential Transformer（Ye et al.、ICLR 2025）は2つのSoftmaxの差としてアテンションを計算し、共有されたノイズフロアを引くことでこれを修正する。DIFF V2（Microsoft、2026年1月）は本番スタックの書き直し：デコードレイテンシをベースラインのTransformerに合わせ、カスタムカーネル不要、FlashAttention互換。このレッスンはV1からV2をエンドツーエンドで辿り、stdlibのPythonで実行できる差分操作の動作するおもちゃ実装を提供する。


## 学習目標

- Softmaxアテンションにノイズフロアがある理由と、それがコンテキスト長と共に成長する理由を正確に述べる。
- 差分アテンションの式を導出し、なぜ引き算が共有ノイズ成分をキャンセルしながらシグナルを保存するかを説明する。
- V1からV2へのdiffを辿る：何が速くなり、何がシンプルになり、何が安定し、なぜ各変更が本番事前学習に必要だったか。
- 純粋なPythonで差分アテンションをゼロから実装し、合成シグナル+ノイズクエリでノイズキャンセレーション特性を経験的に検証する。

## 課題

標準のSoftmaxアテンションには、スケールでの運用上の問題となる数学的な特性がある。クエリ`q`に対して、アテンション重みは`softmax(qK^T / sqrt(d))`だ。Softmaxは正確なゼロを生成できない——一致しないすべてのトークンに正の質量が割り当てられる。その残差質量はノイズであり、コンテキスト長と共にスケールする。128kトークンでは、一致しない各トークンが確率の0.001%しか得ない場合でも、127,999個のトークンが合計で約12%を占める。モデルはコンテキストと共に成長するノイズフロアを回避することを学ばなければならない。

経験的にこれはアテンションヘッドの干渉として現れる：ロングコンテキストRAGでの幻覚した引用、100kトークンの検索タスクでの「中間で迷子」になる障害、32kを超えたneedle-in-haystackベンチマークでの微妙な精度低下。Differential Transformer論文（arXiv:2410.05258、ICLR 2025）はギャップを測定した：DIFF Transformerは同サイズのベースラインより低いパープレキシティ、より高いロングコンテキスト精度、より少ない幻覚を達成した。

DIFF V1にはフロンティア事前学習パイプラインへの参入を妨げる3つの問題があった。そのvalue cacheはデコードステップあたり2回ロードされる必要があり、FlashAttention互換性を壊すカスタムCUDAカーネルが必要で、ヘッドごとのRMSNormが70B以上のスケールでの長時間学習を不安定化させた。DIFF V2（Microsoft unilm blog、2026年1月20日）は3つすべてを修正した。このレッスンは両バージョンを辿り、差分演算子を構築し、おもちゃのクエリでノイズキャンセレーションをベンチマークする。

## コンセプト

### Softmaxのノイズフロア

クエリ`q`とキー`K = [k_1, ..., k_N]`について、アテンション重みは：

```
w_i = exp(q . k_i / sqrt(d)) / sum_j exp(q . k_j / sqrt(d))
```

`w_i`は決してゼロにならない。`k_i`が`q`とまったく無関係な場合、スコア`q . k_i`は0ではない——分散`||q||^2 / d`でゼロ周辺に変動する。Softmax正規化後も、無関係な各トークンは加重和に`O(1/N)`の寄与をする。無関係なトークンの総寄与は`O((N-1)/N) = O(1)`——小さくない量だ。

モデルが欲しいのはハードなtop-kのようなもの：一致するトークンへの高い重み、それ以外への近ゼロ重み。Softmaxはそれを直接行うには滑らかすぎる。

### 差分のアイデア

各ヘッドのQとK射影を2つに分割する：Q = (Q_1, Q_2)とK = (K_1, K_2)。2つのアテンションマップを計算する：

```
A_1 = softmax(Q_1 K_1^T / sqrt(d))
A_2 = softmax(Q_2 K_2^T / sqrt(d))
```

出力：

```
DiffAttn = (A_1 - lambda * A_2) V
```

引き算は2つのマップが共有するノイズ分布をキャンセルする。両方のマップが127kの無関係なトークンに対してほぼ均一な重みを持つ場合（ランダムな初期化時にそうなる）、それらはキャンセルされる。シグナル——少数の実際に関連するトークンへの集中した重み——は同じ大きさで両方のマップに現れた場合のみキャンセルされるが、一度モデルが学習されるとそうはならない。

`lambda`はヘッドごとの学習可能なスカラーで、`lambda = exp(lambda_q1 dot lambda_k1) - exp(lambda_q2 dot lambda_k2) + lambda_init`としてパラメータ化される。負の値も取れる。`lambda_init`はデフォルトで0.8のような小さな正の数だ。

### なぜこれがヘッドのノイズキャンセリングと一致するか

同じ声を録音している2つのノイズの多いマイクを考える。両方が話者とも相関したバックグラウンドノイズを拾う。一方を他方から引き算すると共有ノイズが消える。声は2つのシグナルが位相や振幅で十分に異なるため完全にキャンセルされない。ヘッドごとの`lambda`はまさにこのバランスを学ぶ。

### V1対V2：diff

V1はパラメータ数をベースラインのTransformerと等しく保った。ヘッドあたり2つのクエリを得るためにヘッド次元を半分にした。それはヘッドの表現力を犠牲にし——さらに痛ましいことに——ヘッドあたりのvalue cacheを半分にした。デコードはSoftmaxブランチごとに1回（つまり2回）value cacheをロードしなければならなかった。結果：パラメータ数が一致しているにもかかわらずデコードがベースラインより遅い。

V2はクエリヘッド数を2倍にしてKVヘッドを同じに保つ（up射影からパラメータを借りる）。ヘッド次元はベースラインと同じままだ。引き算の後、余分な次元はベースラインTransformerのO_W射影に合わせて元に戻される。3つのことが同時に起きる：

1. デコード速度がベースラインに一致する（KVキャッシュが一度だけロードされる）。
2. FlashAttentionが変更なしで動作する（カスタムカーネル不要）。
3. デコード時の演算強度が上がる（HBMからロードされたバイトあたりのより多くの計算）。

V2はまたV1が引き算を安定させるために使っていたヘッドごとのRMSNormも削除する。70Bクラスの事前学習スケールでは、そのRMSNormが後半の学習を不安定化させた。V2はそれをカスタムモジュールなしで学習を安定させるシンプルな初期化スキームで置き換える。

### 使うべき場面

| ワークロード | メリット |
|------------|---------|
| ロングコンテキストRAG（64k+） | クリーンなアテンションマップ、幻覚した引用が減る |
| Needle-in-haystackベンチマーク | 32k超での大幅な精度向上 |
| 複数文書QA | 文書間の干渉が減る |
| 8kでのコード補完 | 限界的、アーキテクチャ変更は見合わない |
| 短いチャット（4k未満） | ベースラインと実質的に区別がつかない |

価値はコンテキスト長と共に成長する。4kトークンではノイズフロアは十分小さく標準のアテンションで問題ない。128kではそれが問題になっている。

## 実装する

`code/main.py`は差分アテンションを純粋なPythonで実装する。既知のシグナル+ノイズ構造を持つおもちゃのクエリでノイズキャンセレーション比を直接測定できる。

### ステップ1：標準のSoftmaxアテンション

Stdlibの行列演算：リストのリスト、手動のmatmul、数値安定性のためのmaxを引いたSoftmax。

```python
def softmax(row):
    m = max(row)
    exps = [math.exp(x - m) for x in row]
    s = sum(exps)
    return [e / s for e in exps]
```

### ステップ2：QとKを2つの半分に分割

V1スタイル：ヘッド次元を半分に。V2スタイル：ヘッド次元を保持してヘッド数を2倍に。おもちゃ実装では教育的な明確さのためにV1を使用——数学は同一で、ブックキーピングが異なるだけ。

### ステップ3：2つのSoftmaxブランチ + 引き算

```python
A1 = [softmax([dot(q1, k) / scale for k in K1]) for q1 in Q1]
A2 = [softmax([dot(q2, k) / scale for k in K2]) for q2 in Q2]
diff_weights = [[a1 - lam * a2 for a1, a2 in zip(r1, r2)] for r1, r2 in zip(A1, A2)]
out = [[sum(w * v[j] for w, v in zip(row, V)) for j in range(d_v)] for row in diff_weights]
```

注：出力の重みは負になりうる。問題ない——value cacheは符号付きの寄与を処理する。後続のV射影が符号を吸収する。

### ステップ4：ノイズキャンセレーションの測定

長さ1024の合成シーケンスを構築する。シグナルトークンを既知の位置に配置し、残りをノイズで埋める。（a）標準Softmaxアテンションのシグナル位置での重みと（b）差分アテンションの重みを計算する。それぞれのSNRを測定する。DIFF アテンションは2つのブランチが異なるよう学習されている程度に応じて、3〜10倍の高いSNRを安定的に生成する。

### ステップ5：V1対V2のパラメータ数の計算

設定（hidden=4096、heads=32、d_head=128）が与えられると：

- ベースラインTransformer：Q、K、Vそれぞれ`hidden * hidden`サイズ、MLPは4 * hidden。
- DIFF V1：Q、Kそれぞれ`hidden * hidden`サイズ、V `hidden * hidden`（変更なし）、内部でヘッドdimが半分。ヘッドごとの`lambda`パラメータを追加（O(heads * d_head)）。
- DIFF V2：Qのサイズ`2 * hidden * hidden`、Kのサイズ`hidden * hidden`、Vのサイズ`hidden * hidden`。O_Wの前に余分な次元を元に戻す。同じ`lambda`パラメータを追加。

おもちゃはV2の追加パラメータコスト（アテンションブロックあたり約`hidden * hidden`の追加）を測定して出力する。

## 使ってみる

DIFF V2は2026年4月時点ではすべての本番推論サーバーで出荷されていないが、vLLMとSGLangでの統合が進行中だ。一方、パターンは以下に現れている：

- Microsoftの社内ロングコンテキスト本番モデル。
- 256k以上のコンテキストをターゲットとしたいくつかのオープンモデル学習実行での研究再現。
- 差分アテンションとスライディングウィンドウアテンションを交互の層で組み合わせたハイブリッドアーキテクチャ。

2026年にこれを使う場面：

- 64k以上の有効コンテキストをターゲットとした新しいモデルのゼロからの学習。最初から差分アテンションを追加する；後で再学習するのは高価だ。
- 「中間で迷子」になる障害がevalを支配するロングコンテキストモデルの微調整。Q射影へのLoRAが差分構造を近似できる。

使わない場面：

- 安定したロングコンテキストパフォーマンスを持つ事前学習された密モデルをサービングしている。再学習コストが既存の重みで回収されることはほとんどない。
- コンテキストが常に16k以下。ノイズフロアは無視できる。

## 演習

1. `code/main.py`を実行する。合成クエリで差分アテンションの報告されたSNRが標準Softmaxアテンションより高いことを確認する。ノイズ振幅を変化させ、標準アテンションが使用不可能になる交差点を示す。

2. 7Bクラスモデル（hidden=4096、heads=32、d_head=128、32層）についてベースラインからDIFF V1、ベースラインからDIFF V2へのパラメータ数デルタを計算する。どのコンポーネントがパラメータを増やし、どれが同じままかを示す。

3. DIFF V1論文（arXiv:2410.05258）のセクション3とDIFF V2のHugging Faceブログのセクション2を読む。V1のヘッドごとのRMSNormが必要だった理由と、V2がそれを学習の分散を引き起こさずに削除できた理由を2文で説明する。

4. アブレーションを実装する：`lambda = 0`（純粋な第一Softmax）と`lambda = 1`（完全な引き算）で差分アテンションを計算する。合成クエリで、スイープ全体でSNRがどのように変化するかを測定する。SNRを最大化する`lambda`を特定する。

5. GQA + DIFF V2のおもちゃを拡張する。8 KVヘッドと32 Qヘッドを選ぶ。KVキャッシュサイズが同じ（8、32）設定のベースラインGQAモデルと一致することを示す。

## キーワード

| 用語 | 人々が言うこと | 実際の意味 |
|------|----------------|-----------|
| 差分アテンション | 「2つのSoftmaxを引き算」 | QとKを2つの半分に分割し、2つのSoftmaxマップを計算し、2番目を（lambdaでスケールして）最初から引き、Vを掛ける |
| ノイズフロア | 「Softmaxのゼロでない末尾」 | Softmaxがすべての無関係なトークンに割り当てる`O(1/N)`の重みで、長いコンテキストで`O(1)`に合計される |
| lambda | 「引き算のスケール」 | `exp(lq1.lk1) - exp(lq2.lk2) + lambda_init`としてパラメータ化されたヘッドごとの学習可能なスカラー；負になりうる |
| DIFF V1 | 「ICLR 2025バージョン」 | オリジナルのDifferential Transformer；パラメータ数を保持するためにヘッド次元を半分にし、カスタムカーネルが必要、デコードが遅い |
| DIFF V2 | 「2026年1月の修正」 | KVヘッドを保持してQヘッドを2倍に；ベースラインのデコード速度に一致し、FlashAttentionと動作する |
| ヘッドごとのRMSNorm | 「V1の安定化剤」 | 差分後にV1が適用した追加のノルム；V2は後半の学習不安定化を防ぐためにこれを削除した |
| SNR | 「アテンションの無駄が多いか」 | 真のシグナル位置の重みと無関係な位置の平均重みの比 |
| 中間で迷子 | 「ロングコンテキストの障害モード」 | 長いコンテキストの中間にある文書の検索精度が低下する経験的現象——DIFF アテンションはこれを軽減する |
| 演算強度 | 「バイトあたりのFLOPs」 | V2がデコード時に増加させた比率（KVロードあたりのクエリを2倍に）；メモリバウンドのデコードにとって重要 |
