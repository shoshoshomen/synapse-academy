# DeepSeek-V3アーキテクチャ徹底解説

> Phase 10・レッスン14は、すべてのオープンモデルが回す6つのアーキテクチャノブを列挙した。DeepSeek-V3（2024年12月、総パラメータ数671B、活性化パラメータ37B）は6つすべてを回し、さらに4つを追加する：Multi-Head Latent Attention、補助損失なしの負荷分散、Multi-Token Prediction、そしてDualPipe学習。このレッスンはDeepSeek-V3のアーキテクチャを上から下まで読み、公開された設定からすべてのパラメータ数を導出する。最後には671B/37Bの比率がなぜ正しい賭けなのか、そしてなぜMLA + MoEが単独のどちらかよりもフロンティアで優れているかを説明できる。


## 学習目標

- DeepSeek-V3の設定を上から下まで読み、6つのGPT-2ノブと4つのDeepSeek固有の追加の観点から各フィールドを説明する。
- 総パラメータ数（671B）、活性化パラメータ数（37B）、およびそれぞれに寄与するコンポーネントを導出する。
- 128kコンテキストでのMLAのKVキャッシュフットプリントを計算し、GQAを使った同じ活性化パラメータの密なモデルと比較する。
- 4つのDeepSeek固有のイノベーション（MLA、MTP、補助損失なしルーティング、DualPipe）を述べ、それぞれがアーキテクチャ/学習スタックのどの部分をターゲットとするかを挙げる。

## 課題

DeepSeek-V3はLlamaファミリーとは意味のある意味で異なるアーキテクチャを持つ最初のフロンティアオープンモデルだ。Llama 3 405Bは「6つのノブが回ったGPT-2」だ。DeepSeek-V3は6つすべてのノブが回ったGPT-2に加えて4つがさらに追加されたものだ。Llama 3の設定を読むことはDeepSeekの設定を読むためのウォームアップだが、深い構造——アテンションブロックの形、ルーティングロジック、学習時の目的——は別のウォークスルーが必要なほど異なる。

学ぶ価値：DeepSeek-V3のオープンウェイトリリースは、オープンモデルでの「フロンティア能力」の意味を変えた。このアーキテクチャは多くの2026年の学習実行がコピーしている設計図だ。それを理解することはフロンティアLLMの学習または推論に携わるあらゆる役割にとっての必須事項だ。

## コンセプト

### 不変のコア、再び

DeepSeek-V3はまだ自己回帰だ。まだデコーダーブロックをスタックする。各ブロックにはまだアテンション + MLP + 2つのRMSNormがある。まだMLPでSwiGLUを使う。まだRoPEを使う。Pre-norm。重み共有埋め込み。すべてのLlamaまたはMistralと同じベースライン。

### ひねり：GQAの代わりにMLA

Phase 10・14からGQAがQヘッドのグループ間でKとVを共有することでKVキャッシュを縮小することを知っている。Multi-Head Latent Attention（MLA）はさらに進む：KとVは共有の低ランク潜在表現（`kv_lora_rank`）に圧縮され、オンザフライでヘッドごとに展開される。KVキャッシュは潜在表現のみを保存する——通常トークンあたりレイヤーごとに512フロート。

128kコンテキストで、DeepSeek-V3のMLA（トークンあたりレイヤーごとに1つの共有潜在表現`c^{KV}`；KとVはどちらも後続のmatmulに吸収できる上方射影を介してこの潜在から導出される）：

```
kv_cache = num_layers * kv_lora_rank * max_seq_len * bytes_per_element
         = 61 * 512 * 131072 * 2
         = 7.6 GB
```

仮想的なGQAベースライン（Llama 3 70Bの形状、8 KVヘッド、head dim 128）は：

```
kv_cache = 2 * 61 * 8 * 128 * 131072 * 2
         = 30.5 GB
```

MLAは128kコンテキストでLlama-3-70BスタイルのGQAキャッシュの4倍小さい。

トレードオフ：MLAはアテンション計算ごとに（ヘッドごとに）展開ステップを追加する。追加の計算は節約される帯域幅に比べて小さい。ロングコンテキスト推論での純粋な勝利。

### ルーティング：補助損失なしの負荷分散

MoEルーターは各トークンを処理するトップkエキスパートを決定する。ナイーブなルーターは少数のエキスパートに過負荷をかけ、他をアイドル状態にする。標準的な修正：負荷の不均衡にペナルティを与える補助損失項を追加する。これは機能するが、メインタスクのパフォーマンスをわずかに低下させる。

DeepSeek-V3は補助損失なしのスキームを導入する。ルーターロジットにエキスパートごとのバイアス項が追加され、シンプルなルールで学習中に調整される：エキスパート`e`が過負荷なら`bias_e`を減らし；負荷が低ければ増やす。追加の損失項なし。学習はクリーンなまま。エキスパートの負荷はバランスを保つ。

メイン損失への影響：測定可能なものなし。MoEアーキテクチャへの影響：クリーン、調整する補助損失ハイパーパラメータなし。

### MTP：より密な学習 + 無料のドラフト

Phase 10・18から、DeepSeek-V3がD=1 MTPモジュールを追加して2つ先のトークンを予測することを知っている。推論時に、学習済みモジュールは80%以上の受容率の投機的デコーディングドラフトとして再利用される。学習時に、各隠れ状態はD+1 = 2つのターゲットで監督され、より密なシグナルを提供する。

パラメータ：671Bのメインの上に14B。オーバーヘッド：2.1%。

### 学習：DualPipe

Phase 10・19からDualPipeがフォワードとバックワードチャンクをクロスノードのall-to-all通信と重複させる双方向パイプラインであることを知っている。DeepSeek-V3の2,048 H800スケールで、1F1Bがパイプラインバブルで失っていたであろう約24.5万GPU時間を回収する。

### 設定、フィールドごとに

DeepSeek-V3の設定（簡略版）：

```
hidden_size: 7168
intermediate_size: 18432   （密なMLPの隠れサイズ、最初の数層で使用）
moe_intermediate_size: 2048 （エキスパートMLPの隠れサイズ）
num_hidden_layers: 61
first_k_dense_layers: 3    （最初の3層は密なMLPを使用）
num_attention_heads: 128
num_key_value_heads: 128   （MLAでは正式にnum_headsと等しいが、
                           実際の圧縮はkv_lora_rankにある）
kv_lora_rank: 512          （MLA潜在次元）
num_experts: 256            （ブロックあたりのMoEエキスパート数）
num_experts_per_tok: 8      （top-8ルーティング）
shared_experts: 1           （ブロックあたりの常時オンの共有エキスパート）
max_position_embeddings: 163840
rope_theta: 10000.0
vocab_size: 129280
mtp_module: 1               （深度1での1 MTPモジュール）
```

パース：

- `hidden_size=7168`：埋め込み次元。
- `num_hidden_layers=61`：総ブロック深度。
- `first_k_dense_layers=3`：最初の3ブロックはサイズ18432の密なMLPを使用。残りの58はMoEを使用。
- `num_attention_heads=128`：128クエリヘッド。
- `kv_lora_rank=512`：KとVはこの潜在次元に圧縮され、ヘッドごとに展開される。
- `num_experts=256, num_experts_per_tok=8`：各MoEブロックに256エキスパート、トップ8をルーティング。
- `shared_experts=1`：256個のルーティングされたエキスパートに加えて、1つの常時オンエキスパートがすべてのトークンに寄与する。「密なフロア」として考える。
- `moe_intermediate_size=2048`：各エキスパートのMLP隠れサイズ。256個あるため密なMLPより小さい。

### パラメータの計算

完全な計算は`code/main.py`に存在する。見出し：

- 埋め込み：`vocab * hidden = 129280 * 7168 = ~0.93B`。
- 最初の3つの密なブロック：MLAを使ったアテンション（ブロックあたり~144M）+ 密なMLP（~260M）+ ノルム。合計約1.2B。
- 58個のMoEブロック：MLAを使ったアテンション（~144M）+ 256個のエキスパートそれぞれ（30Mずつ）+ 1つの共有エキスパート（30M）+ ノルム。ブロックあたり合計~7.95B、すべてのエキスパートを含む。58個のMoEブロックの合計461B。
- MTPモジュール：14B。

総計：コアアーキテクチャの~476B + 14B MTP + 公開された671Bの数値には追加の構造的パラメータが含まれる（バイアステンソル、エキスパート固有のコンポーネント、共有エキスパートのスケーリングなど）。カリキュレーターで再現する数値は公開値の3〜5%以内——デルタはDeepSeekのレポートがそのセクション2の付録に記載した細粒度の計算から来る。

フォワードあたりの活性化パラメータ：

- アテンション：レイヤーあたり144M × 61 = 8.8B（すべてのレイヤーが動作）。
- MLP活性化：最初の3レイヤーは密（3 × 260M = 780M）、58個のMoEレイヤーはそれぞれ8個のルーティング + 1つの共有 + ルーティングオーバーヘッドで活性化。レイヤーあたりの活性化MLP：~260M。合計：3 × 260M + 58 × 260M = ~15.9B。
- 埋め込み + ノルム：1.2B。
- 活性化合計：約26Bのコア + 14B MTP（学習済みだが推論時に常に実行されるわけではない）≈ 37B。

### 671B / 37Bの比率

18倍のスパース比（活性化パラメータは総数の5.5%）。DeepSeek-V3はオープンウェイトで出荷された最もスパースなフロンティアMoEモデルだ。比率13/47（28%）のMixtral 8x7Bははるかに密だ。比率17B/400B（4.25%）のLlama 4 Mavericはそれに近い。DeepSeekの賭け：フロンティアスケールで、より低い活性化率のより多くのエキスパートが活性FLOPあたりより良い品質を生む。

### DeepSeek-V3の位置

| モデル | 総計 | 活性化 | 比率 | アテンション | 革新 |
|-------|------|-------|-------|-----------|-------------|
| Llama 3 70B | 70B | 70B | 100% | GQA 64/8 | — |
| Llama 4 Maverick | 400B | 17B | 4.25% | GQA | — |
| Mixtral 8x22B | 141B | 39B | 27% | GQA | — |

### フォローアップ：R1、V4

DeepSeek-R1（2025）はV3バックボーンの推論学習実行だ。R1は同じアーキテクチャを使用する。変わったのは事後学習レシピ（検証可能なタスクでの大規模RL）であり、事前学習アーキテクチャではない。

DeepSeek-V4（リリースされれば）はMLA + MoE + MTPを保持し、Phase 10・17のNSAの後継であるDSA（DeepSeek Sparse Attention）を追加すると予想される。系統は安定している：アーキテクチャレベルのイノベーションが蓄積される；各バージョンが追加のノブを回す。

## 使ってみる

`code/main.py`はDeepSeek-V3の形状に特化したパラメータカリキュレーターだ。実行して、その出力を論文の数値と比較し、仮想的な変種（256エキスパート対512、top-8対top-16、MLAランク512対1024）で使用する。

見るべきもの：

- 公開671Bに対する総パラメータ数。
- 公開37Bに対する活性化パラメータ数。
- 128kコンテキストでのKVキャッシュ——MLAとGQAの比較。
- レイヤーごとの内訳でパラメータバジェットが実際にどこに行くかを見る。

## 成果物を出す

このレッスンは`outputs/skill-deepseek-v3-reader.md`を生成する。DeepSeek系モデル（V3、R1、または任意の将来の変種）が与えられると、コンポーネントごとのアーキテクチャ読解を生成する：設定の各フィールドの名前、コンポーネントごとのパラメータ数の導出、モデルが4つのDeepSeek固有のイノベーションのどれを使用しているかの特定。

## 演習

1. `code/main.py`を実行する。カリキュレーターの総パラメータ見積もりを公開された671Bと比較し、デルタの由来を特定する。論文のセクション2には完全な明細がある。

2. 設定をMLAランク512の代わりに256を使用するように修正する。128kコンテキストでの結果のKVキャッシュサイズを計算する。何パーセントの削減を得られるか、そしてヘッドごとの表現力への代償は何か？

3. DeepSeek-V3の（256エキスパート、top-8）ルーティングを仮想的な（512エキスパート、top-8）変種と比較する。総パラメータは増え；活性化パラメータは同じままだ。追加のエキスパートキャパシティは理論的に何をもたらすか、そして推論時に何のコストがかかるか？

4. DeepSeek-V3技術レポート（arXiv:2412.19437）のセクション2.1でMLAを読む。KとVの展開行列が推論時の効率のために後続のmatmulに「吸収」できる理由を3文で説明する。

5. DeepSeek-V3はほとんどの操作にFP8学習を使用する。671Bの重みを保存するためのFP8とBF16のメモリ節約を計算する。これは14.8Tトークンの学習予算とどのように交差するか？

## キーワード

| 用語 | 人々が言うこと | 実際の意味 |
|------|----------------|-----------|
| MLA | 「Multi-Head Latent Attention」 | KとVを共有の低ランク潜在表現（kv_lora_rank、通常512）に圧縮し、オンザフライでヘッドごとに展開；KVキャッシュは潜在表現のみを保存 |
| kv_lora_rank | 「MLA圧縮次元」 | KとVの共有潜在のサイズ；DeepSeek-V3は512を使用 |
| 最初のk個の密なレイヤー | 「初期レイヤーは密なまま」 | 最初のいくつかのMoEモデルレイヤーはMoEルーターをスキップして安定性のために密なMLPを実行 |
| num_experts_per_tok | 「Top-kルーティング」 | トークンごとに動作するルーティングされたエキスパート数；DeepSeek-V3は8を使用 |
| 共有エキスパート | 「常時オンエキスパート」 | ルーティングに関係なくすべてのトークンを処理するエキスパート；DeepSeek-V3は1を使用 |
| 補助損失なしルーティング | 「バイアス調整負荷分散」 | エキスパートの負荷を損失項を追加せずにバランスを保つために学習中に調整されるエキスパートごとのバイアス項 |
| MTPモジュール | 「追加の予測ヘッド」 | `h^(1)`とE(t+1)からt+2を予測するトランスフォーマーブロック；より密な学習、無料の投機的デコーディングドラフト |
| DualPipe | 「双方向パイプライン」 | フォワード/バックワード計算をクロスノードのall-to-allと重複させる学習スケジュール |
| 活性化パラメータ比率 | 「スパース性」 | active_params / total_params；DeepSeek-V3は5.5%を達成 |
| FP8学習 | 「8ビット学習」 | FP8での学習ストレージと多くの計算操作；品質への小さなコストでBF16に対してメモリをほぼ半分に |
