# ネイティブスパースアテンション（DeepSeek NSA）

> 64kトークンでは、アテンションがデコードレイテンシの70〜80%を占める。すべてのオープンモデルラボがそれを修正する計画を持っている。DeepSeekのNSA（ACL 2025最優秀論文）は定着したものだ：圧縮された粗粒度トークン、選択的に保持された細粒度トークン、ローカルコンテキスト用のスライディングウィンドウという3つの並列アテンションブランチを、学習済みゲートで組み合わせる。ハードウェアに整合（カーネルフレンドリー）で、ネイティブに学習可能（事前学習で動作し、推論時に後付けされない）で、64kのデコードではFlashAttentionよりも速く動作し、フルアテンション品質に一致またはそれを上回る。このレッスンは3つのブランチをエンドツーエンドで構築し、なぜスパース性がエンドツーエンドで微分可能であるかを示す。


## 学習目標

- NSAの3つのアテンションブランチとそれぞれが何をキャプチャするかを述べる。
- NSAが以前のスパースアテンション手法が推論専用だったのに「ネイティブに学習可能」である理由を説明する。
- 圧縮ブロックサイズと選択top-kの関数として、NSAとフルアテンションの64kコンテキストでの計算節約量を計算する。
- 短い合成シーケンスでstdlib Pythonで3ブランチの組み合わせを実装し、ゲーティング重みの動作を検証する。

## 課題

シーケンス長Nでのフルアテンションは時間`O(N^2)`とレイヤーごとにKVキャッシュ`O(N)`のコストがかかる。64kトークンでは、計算とメモリ帯域幅の数値が破滅的だ。NSA論文からの理論的見積もり：アテンションが64kでの総デコードレイテンシの70〜80%を占める。TTFT、tokens/sec、100万トークンあたりのコストなど、すべての下流指標がアテンションコストに支配されている。

スパースアテンションは明白な答えだ。先行試みは2つのバケツに分類される。固定パターンスパース性（スライディングウィンドウ、ストライド、ブロックローカル）は情報を捨て、長距離リコールタスクで失敗する。推論時スパース性（KVキャッシュプルーニング、H2O、StreamingLLM）は密なアテンションで事前学習されたモデルに適用され、モデルがスパースパターンを通じて情報をルーティングするよう求められなかったため、潜在的なスピードアップのほんの一部しか回収できない。

Native Sparse Attention（Yuan et al.、DeepSeek + PKU + UW、ACL 2025最優秀論文、arXiv:2502.11089）は両方を行う：事前学習中にモデルが学習するスパース性パターン、実際に推論時の計算節約を実現するカーネル整合アルゴリズムとして実装される。2年後、NSAまたはその直接の後継者がすべてのフロンティアロングコンテキストモデルのデフォルトアテンションになる。

## コンセプト

### 3つの並列ブランチ

各クエリに対して、NSAは3つの異なるKVキャッシュのビューに対してアテンションを3回実行する：

1. **圧縮ブランチ。** トークンはサイズ`l`のブロックにグループ化される（通常32または64）。各ブロックは小さな学習済みMLPを介して単一のサマリートークンに圧縮される。クエリはこれらの圧縮トークンに対してアテンションし、シーケンス全体の粗粒度なビューを得る。

2. **選択ブランチ。** 圧縮ブランチのアテンションスコアを使用して、現在のクエリに最も関連性の高いトップkブロックが特定される。それらのブロックから細粒度（非圧縮）トークンが読み込まれ、クエリはそれらすべてに対してアテンションする。圧縮ブランチアテンションを選択のルーティングシグナルとして考える。

3. **スライディングウィンドウブランチ。** クエリは最も最近の`W`トークン（通常512）にアテンションしてローカルコンテキストを得る。このブランチは他の2つが見逃す可能性のある構造の多い短距離パターン（構文、ローカル照応）をキャプチャする。

3つのブランチ出力は学習済みの位置ごとのゲートを通じて組み合わされる：

```
out = g_cmp * out_cmp + g_sel * out_sel + g_win * out_win
```

`g_cmp, g_sel, g_win`はクエリの小さなMLPからのゲート重みだ。1に合計する必要はない——ブランチを独立して重み付けできる。

### なぜこれが「ネイティブに学習可能」なのか

選択ステップ（トップkブロック）は離散的だ。離散的な操作は勾配フローを壊す。先行のスパースアテンション研究は選択を通じたバックプロップをスキップする（学習を制限する）か、実際のスパース性を与えない連続的な緩和を使用した。

NSAはこれを回避する：圧縮ブランチアテンションはシーケンス全体に対する微分可能な粗粒度アテンションだ。top-k操作は圧縮ブランチのトップアテンションスコアを再利用してどの細粒度ブロックをロードするかを選択するだけだ。勾配は圧縮ブランチスコアを通じてフローする（圧縮出力と選択ロジックの両方に影響する）し、最終出力への選択されたブロックの寄与も微分可能だ。微分不可能な`top_k`操作は計算グラフ上のフォワードでの無操作だ——どのブロックをメモリからロードするかを制御するだけだ。

これがNSAがエンドツーエンドで事前学習に使用できる理由だ。モデルは3つのブランチを通じて情報をルーティングすることを共同学習し、推論時に実際に約束されたスピードアップを実現するスパースパターンを生成する。

### ハードウェア整合カーネル

NSAのカーネルは現代のGPUメモリ階層向けに設計されている。カーネルはGQAグループごとにクエリをロードし（外側ループ）、グループごとに対応するスパースKVブロックをフェッチし（内側ループ）、SRAMでアテンションを実行する。各クエリグループが同じ選択されたブロックを見るため（選択はクエリヘッドごとではなくクエリグループごと）、KVロードはグループ全体で償却される。演算強度は高く保たれる。

論文は64kデコードでFlashAttentionより9倍速く動作するTritonカーネルを報告し、スピードアップ比はシーケンス長と共に成長する。フォワードとバックワードの両カーネルが提供されている。

### 計算バジェット

`N`をシーケンス長、`l`を圧縮ブロックサイズ、`k`をトップk選択数、`w`をスライディングウィンドウ、`b`を選択されたブロックサイズ（通常`l`と等しい）とする。

- 圧縮ブランチ：クエリあたり`O(N/l)`キー、合計で`O(N * N / l)`。
- 選択ブランチ：クエリあたり`O(k * b)`キー、合計で`O(N * k * b)`。
- スライディングブランチ：クエリあたり`O(w)`キー、合計で`O(N * w)`。

合計：`O(N * (N/l + k*b + w))`。

`N = 64k, l = 64, k = 16, b = 64, w = 512`の場合：クエリあたりのコストは`1000 + 1024 + 512 = 2536`キー。フルアテンションは`64000`キー。25倍の計算削減。

`N = 128k, l = 64, k = 16, b = 64, w = 512`の場合：クエリあたりのコストは`2000 + 1024 + 512 = 3536`キー。フルアテンションは`128000`キー。36倍の削減。メリットはシーケンス長と共に成長する——これがポイントだ。

### 比較

| 手法 | 微分可能 | 実際の推論スピードアップ | 長距離リコール |
|--------|---------|---------------------|-------------|
| スライディングウィンドウのみ | あり | あり | 失敗 |
| ストライド / ブロックスパース | あり | あり | 部分的 |
| KVプルーニング（H2O、StreamingLLM） | N/A（推論時） | あり | 部分的 |
| MoBA（Moonshot） | 部分的 | あり | 良い |
| NSA | あり（ネイティブ） | あり（64kで9倍） | フルアテンションに一致 |

MoBA（Moonshot、arXiv:2502.13189）は同時に公開され、同様の3つが1つより良いアプローチを取り、MoEの原則をアテンションブロックに適用する。NSAとMoBAは2026年のロングコンテキスト事前学習で知っておくべき2つのアーキテクチャだ。

## 実装する

`code/main.py`は短い合成シーケンスで3つのブランチを実装し、以下を示す：

- 圧縮MLP（教育的な明確さのためにシンプルな平均プールベースラインを使用；実際のNSAは学習済みMLPを使用）。
- 圧縮ブランチスコアによって駆動されるトップkブロック選択。
- 最後の`w`トークンへのスライディングウィンドウアテンション。
- ゲートされた組み合わせ。
- フルアテンションと比較した計算数の出力。

### ステップ1：トークンをブロックに圧縮

```python
def compress(K, l):
    n = len(K)
    n_blocks = (n + l - 1) // l
    out = []
    for b in range(n_blocks):
        start, end = b * l, min((b + 1) * l, n)
        block = K[start:end]
        summary = [sum(row[d] for row in block) / len(block) for d in range(len(K[0]))]
        out.append(summary)
    return out
```

### ステップ2：圧縮ブランチアテンション

圧縮されたキーに対してクエリのSoftmaxアテンションを実行する。圧縮ブランチスコアはトップk選択のシグナルとしても機能する。

### ステップ3：トップkブロック選択

最高スコアの`k`個の圧縮ブロックのインデックスを選ぶ。それらのブロックから元の非圧縮トークンをロードしてアテンションを実行する。

### ステップ4：スライディングウィンドウアテンション

最後の`w`トークンを取ってそれらに対して標準アテンションを実行する。

### ステップ5：ゲート + 組み合わせ

クエリを入力として3つのゲート重みを生成する小さなMLP。最終出力は3つのブランチ出力の加重和だ。

### ステップ6：計算カウント

各ブランチについてクエリあたりのアテンドされるキー数の合計を出力する。`N`（フルアテンション）と比較する。1024トークンの合成で`l = 32, k = 4, w = 128`の場合、NSAはクエリあたり`32 + 128 + 128 = 288`キーを見るのに対してフルアテンションは1024——3.5倍少ない。

## 使ってみる

NSAはDeepSeekのロングコンテキスト事前学習パイプラインで出荷されている。2026年4月時点の公開推論スタックでの統合状況：

- **DeepSeek内部**：ネイティブ、公開された重みはNSAまたはその後継のDSA（Deepseek Sparse Attention）を使用。
- **vLLM**：DeepSeek-V3.xの重みのためのNSA実験的サポートを開発中。
- **SGLang**：NSAベンチマーク公開済み；本番パスはvLLMに続く。
- **llama.cpp / CPU**：未サポート；カーネル分解のオーバーヘッドがCPUスループットでは見合わない。

NSAを使うべき場面：

- 本格的な計算予算で64k以上のコンテキストをターゲットとした事前学習または継続学習実行。
- DeepSeek自身のロングコンテキストチェックポイントの推論。重みはNSAネイティブだ。

使うべきでない場面：

- 既存の密アテンション事前学習モデルをサービング中。継続学習なしでNSAを後付けすることはできない。
- 16k以下のコンテキスト。3ブランチのオーバーヘッドが節約を支配する。
- バッチ1のインタラクティブチャット。レイテンシセンシティブなデコードはメリットがあるが、長いコンテキストでのみ。

## 成果物を出す

このレッスンは`outputs/skill-nsa-integrator.md`を生成する。ロングコンテキスト事前学習実行仕様が与えられると、NSA統合計画を生成する：圧縮ブロックサイズ、トップk、スライディングウィンドウ、ゲートMLP幅、カーネル選択、およびアーキテクチャの変更を正当化するための具体的なロングコンテキスト評価。

## 演習

1. 1024トークンの合成で`code/main.py`を実行する。`(l, k, w)`を3つのプリセットでスイープして計算数を出力する。針の中の藁テストでフルアテンションに対して95%のリコールを維持しながら最低のクエリあたりキー数を達成するプリセットを特定する。

2. 平均プールコンプレッサーを小さな学習済みMLP（2層、hidden 32）に置き換える。ブロックの平均がシグナルである合成タスクで学習する。保留データで平均プールベースラインに対するパープレキシティのギャップを測定する。

3. ゲートMLPを実装する。クエリを入力として3つのスカラーを出力する。ゲートが適切に動作することを示す：ランダムクエリで均一に近い重み付け、クエリが遠いブロックにヒットしたときに選択ブランチへの高い重み。

4. 128kコンテキストでのNSA対応70Bモデル（KVヘッド8、ヘッドdim 128、BF16）のKVキャッシュメモリバジェットを計算する。フルアテンションとMLA（Phase 10・14がMLAの数値を示した）と比較する。NSAの細粒度ブランチKVキャッシュがフルアテンションと等しくなるシーケンス長を特定する。

5. NSA論文（arXiv:2502.11089）のセクション4を読む。圧縮ブランチのアテンションスコアが別のルーティングスコアを計算する代わりにトップk選択に再利用される理由を3文で説明する。答えを勾配フローに結びつける。

## キーワード

| 用語 | 人々が言うこと | 実際の意味 |
|------|----------------|-----------|
| 圧縮ブランチ | 「粗いビュー」 | クエリあたりO(N/l)キーでグローバルコンテキストを提供するブロック平均キーに対するアテンション |
| 選択ブランチ | 「トップkブロック」 | 最高の圧縮ブランチスコアを持つ`k`ブロックに対する細粒度アテンション |
| スライディングウィンドウ | 「ローカルコンテキスト」 | 短距離パターンのための最後の`W`トークンに対するアテンション |
| ネイティブ学習可能性 | 「スパース性をオンにして事前学習」 | スパース性パターンが事前学習中に学習され、推論時に後付けされない |
| 圧縮ブロックサイズl | 「粗いビューのグループサイズ」 | いくつのトークンが1つのサマリーにマージされるか；32〜64が典型的 |
| トップk | 「保持するブロック」 | 非圧縮トークンが読まれる圧縮ブロックの数；16が典型的 |
| スライディングウィンドウW | 「ローカルアテンション半径」 | 通常512；短いとローカルコヒーレンスが損なわれ、長いと計算が無駄になる |
| ブランチゲート | 「3つをどう混ぜるか」 | 3つのブランチの寄与を重み付けする位置ごとのMLP出力 |
| ハードウェア整合 | 「カーネルフレンドリーなスパース性」 | 実際のGPUカーネルが理論的なスピードアップを達成するように選ばれたスパースパターン |
| DSA | 「NSAの後継」 | Deepseek Sparse Attention、DeepSeekの系統でNSAに続くアーキテクチャ |
