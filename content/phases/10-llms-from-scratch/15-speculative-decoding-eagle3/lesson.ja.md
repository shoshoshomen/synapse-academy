# 投機的デコーディングとEAGLE-3

> Phase 7・レッスン16は数学を証明した：Leviathan棄却ルールは検証モデルの分布を正確に保存する。このレッスンは2026年の本番投機的デコーディングの学習スタック視点だ。EAGLE-3はドラフトモデルを安価な近似から、検証モデル自身の隠れ状態で学習された専用の小さなネットワークに変え、さらに学習時にトレーンと推論の分布を一致させるテストループを追加した。結果：チャットで3〜6.5倍のエンドツーエンドの高速化、受容率0.9以上、分布上のトレードオフなし。2026年のすべての本番推論スタックがデフォルトでこれを搭載している。


## 学習目標

- Leviathanの定理を1文で述べ、投機的ループが検証モデルと同一の分布のサンプルを生成することを証明する。
- バニラ投機的デコーディング（Leviathan 2023）からEAGLE、EAGLE-2、EAGLE-3への2年間の進歩を辿り、各ステップが除去した正確な制限を挙げる。
- 受容率`α`とドラフト対検証モデルのコスト比`c`から期待されるスピードアップを計算し、各レジームで最適なドラフト長`N`を選ぶ。
- 投機的ループをゼロから実装する：ドラフト、検証、残差からの棄却サンプリング、棄却時のKVキャッシュロールバック、完全受容時のボーナストークン出力。

## 課題

H100上の70Bモデルでの自己回帰デコーディングは毎秒約35トークンで実行される。GPUはほど遠い飽和状態だ。メモリ帯域幅が上限だ：各トークンはHBMから70Bの重みをロードし、一段階の演算を行い、1つの浮動小数点数を生成する。計算ユニットはほぼアイドル状態だ。

投機的デコーディングはそれを実際に解決できるスループット問題に変える。安価なドラフトがN個の小さなフォワードパスで`N`トークンを提案する。検証モデルはプレフィックス+すべての`N`ドラフトで一度実行される。検証モデルの位置`i`での分布がドラフトと（統計的な意味で後に正確に定義する）一致する場合、受容する。しなければ棄却し、残差分布から修正をサンプリングする。1回の大きなモデルのフォワードで1つではなく最大`N+1`個の受容トークンが生成される。

重要な定理はLeviathan、Kalman、Matias（ICML 2023）だ：出力分布は検証モデルから直接サンプリングした場合と同一だ。おおよそではない。同一だ。これが投機的デコーディングが本番で受け入れられる唯一の理由だ——純粋なレイテンシ最適化であり品質のトレードオフがない。

Phase 7・レッスン16があなたに与えたのは数学だった。このレッスンが与えるのは学習スタックだ。良いドラフトは安価なドラフトより2倍以上のスピードアップをもたらす。EAGLE、EAGLE-2、EAGLE-3（Li et al.、2024〜2025）は「ドラフト = 同じモデルの小さなバージョン」を正確なエンジニアリング規律に変えた。2026年の本番推論サーバーはデフォルトでEAGLE-3を搭載する。

## コンセプト

### 不変部分：Leviathanの棄却サンプリング

`p(t)`をあるプレフィックスに対するドラフトの次トークン分布とし、`q(t)`を検証モデルのものとする。ドラフトトークン`d ~ p`をサンプリングする。確率`min(1, q(d) / p(d))`で受容する。棄却時には残差分布`(q - p)_+ / ||(q - p)_+||_1`からサンプリングする。結果のサンプルは`q`に従って分布する。これは`p`がどれだけ悪くても真だ——悪いほどよく棄却するが、出力は正確なままだ。

これらの呼び出しを`prefix + d_1 + ... + d_N`に対する1回の検証モデルフォワードパスを使って`N`回連続して実行する。検証モデルは`q_1, q_2, ..., q_{N+1}`を同時に返す。左から右に進む。位置`j`で最初の棄却があった場合、`residual(q_j, p_j)`からサンプリングして停止する。完全受容の場合、`q_{N+1}`からボーナストークンを1つサンプリングする。

### スピードアップを決めるもの

`α`をドラフトされたトークンあたりの期待受容率とする。`c = cost(draft) / cost(verifier)`をコスト比とする。検証モデルのフォワードあたりの期待受容トークン数は：

```
E[accepted] = (1 - α^(N+1)) / (1 - α)
```

受容トークンあたりの期待総実行時間は`(N * c + 1) / E[accepted]`だ。これを`N`に関して最小化すると最適点が得られる。`α = 0.8, c = 0.05`の場合：最適`N`は約5〜7、スピードアップは3.2倍。`α = 0.95, c = 0.02`の場合：最適`N`は約8〜10、スピードアップは5倍に近づく。

最大のレバーは`α`だ。`α = 0.6`（バニラドラフト）から`α = 0.9`（EAGLE-3）に上げると、固定`N = 5`で検証モデルフォワードあたりの期待受容トークンが2.2から4.1に増える。同じ検証モデルで2倍近くのスループット。

### 2年間の進歩

**バニラ投機（Leviathan、2023）。** ドラフトモデルは同じファミリーから独立して学習された小さなLLMだ。接続が簡単、`α ≈ 0.6`、最良で約2倍のスピードアップ。

**EAGLE-1（Li et al.、2024）。** ドラフトは小さなトランスフォーマー——通常1〜2層——で、検証モデルの最終層の隠れ状態を入力として直接次のトークンを予測する。ドラフトが検証モデルの特徴表現を見るため、分布が検証モデルにはるかに近くなる。`α`は0.7〜0.8まで上昇。

**EAGLE-2（Li et al.、2024）。** 動的ドラフトツリーを追加：`N`トークンの単一シーケンスを提案する代わりに、候補の小さなツリーを提案し、各候補を1回のフォワードパスで検証モデルで採点し（ツリーアテンション）、最高確率のパスを採用する。ドラフト長はステップごとに適応的になる。受容パストークンあたりの`α`は0.85を超える。

**EAGLE-3（Li et al.、2025、NeurIPS）。** さらに2つの変更。第一に、特徴予測損失を完全に削除——EAGLE-1/2は検証モデルの隠れ状態に一致するようにドラフトを学習していたが、これはデータがどれだけ役立つかの上限を設定する。EAGLE-3は直接トークン予測で学習する。第二に、学習時テスト（TTT）：ドラフト学習中に、推論時と同じように複数ステップにわたってドラフト自身の以前の予測をフィードバックする。これにより学習とテストの分布が一致し、エラーの蓄積が止まる。測定されたスピードアップ：チャットで最大6.5倍、H100のSGLangでバッチ64で38%のスループット改善。

### KVキャッシュのロールバック

検証は1回のパスで検証モデルのKVキャッシュを`N`エントリ分拡張する。位置`j`で棄却が発生した場合、位置`j-1`を超えるキャッシュの内容は間違っている。2つの一般的な実装：スクラッチバッファに書き込み、受容時にコミット（vLLM、TensorRT-LLM）、または物理KVキャッシュと論理長を保持して棄却時に切り捨てる。いずれにしても、ロールバックコストはレイヤーあたりヘッドあたりのバイト数であり、フォワードパスコストに比べると無視できる。

EAGLE-2ツリー検索の場合、検証モデルはツリートポロジーを尊重する非因果マスクでアテンションを実行する。エンジニアリングは面倒だが、計算はカスタムマスクを使った標準のflash-attention呼び出しだ。

### 2026年のドラフトアーキテクチャ

| 戦略 | ドラフト型 | `α` | スピードアップ | 学習コスト |
|----------|-----------|-----|---------|-----------|
| バニラ | 別の小さなLLM | 0.55-0.70 | 1.8-2.3倍 | なし（既存の小さなモデルを再利用） |
| Medusa | 検証モデルの追加LMヘッド | 0.65-0.75 | 2-3倍 | ~1B SFTトークン |

| EAGLE-2 | EAGLE-1 + 動的ドラフトツリー | 0.80-0.88 | 3-4倍 | ~60Bトークン |

2026年の本番：vLLMとSGLangは利用可能な場合はEAGLE-3を、そうでなければEAGLE-2をデフォルトにする。TensorRT-LLMはMetaとNVIDIAの公開モデル用の最速Medusaパスを持つ。llama.cppはCPUデプロイメント用にバニラドラフトを搭載する。

## 実装する

`code/main.py`を参照。これはすべての部品を持つ完全なLeviathan投機ループだ：Nのドラフト、検証モデルの並列パス、位置ごとの棄却、残差サンプリング、ボーナストークン、KVロールバック、そして出力分布が`q`からの直接サンプリングと一致することの経験的検証。

### ステップ1：棄却ルール

```python
def accept(q_prob, p_prob, u):
    if p_prob <= 0:
        return True
    return u < min(1.0, q_prob / p_prob)
```

### ステップ2：残差分布

```python
def residual(q, p):
    raw = [max(0.0, qi - pi) for qi, pi in zip(q, p)]
    s = sum(raw)
    if s == 0:
        return list(q)
    return [r / s for r in raw]
```

### ステップ3：完全な投機ステップ

`spec_step`関数は`p`から`N`トークンをドラフトし、1回の並列`q`評価ですべてを検証する。ドラフトされた各トークンに棄却ルールを適用し、最初の棄却で残差から修正をサンプリングする。すべてが受容された場合、`q_{N+1}`からボーナストークンを出力する。

### ステップ4：KVロールバックのブックキーピング

シミュレーターはワーカーごとに論理的な`kv_length`を追跡する。`k`ドラフトの受容時、`kv_length += k`。位置`j`での棄却時、キャッシュはすでに`j`を超えて書き込まれているが、論理的な長さは`prefix_length + j + 1`——修正トークンの1つ先——に設定される。後続の読み取りは論理的な長さに切り捨てる。

### ステップ5：Leviathanのチェック

50,000回の投機的ステップを実行する。受容されたトークンの経験的分布を数える。`q`から50,000回の直接サンプルと比較する。カイ二乗統計は臨界値を大幅に下回るはずだ。定理は実践で成立する。

### ステップ6：スピードアップ対α

`p`を`q`から異なる振幅で摂動させてドラフトの品質をスイープする。`α`を測定し、`α`と`N`の関数として検証モデル呼び出しあたりの期待トークン数をプロットする。コードはEAGLE-3クラスのドラフト品質（`α ≈ 0.9`）が検証モデル呼び出しあたり4〜5トークンを解放することを示すテーブルを出力する。

## 使ってみる

EAGLE-3を使った本番レベルの`vllm serve`：

```bash
vllm serve meta-llama/Llama-3.3-70B-Instruct \
  --speculative-config '{
    "model": "yuhuili/EAGLE3-LLaMA3.3-Instruct-70B",
    "num_speculative_tokens": 5,
    "method": "eagle3"
  }'
```

H100でのバッチ64でのSGLang + EAGLE-3：EAGLE-3の論文によると、バッチ64のバニラデコーディングより約1.38倍のスループット。

投機的デコーディングを使うべき場面：

- p50レイテンシが最大スループットより重要なインタラクティブチャットワークロード。
- コード生成と構造化出力（JSON、SQL）。ターゲット分布が非常に予測可能なので`α`は0.9以上。
- 長文生成（数千トークン）。償却されたスピードアップが継続的に支払われる。

使うべきでない場面：

- 非常に小さなモデル（3B未満）。ドラフトが検証モデルほど安価でない。
- バッチ1の小さなCPUデプロイメント。ドラフトモデルのメモリオーバーヘッドが見合わない場合がある。
- `α`が崩壊する非常に高温度のクリエイティブサンプリング。

## 成果物を出す

このレッスンは`outputs/skill-eagle3-tuner.md`を生成する。推論ワークロード（モデル、バッチサイズ、目標レイテンシ、タスクプロファイル）が与えられると、投機的デコーディング戦略とチューニングパラメータ（ドラフトファミリー、`N`、ツリー深さ、温度に応じた切り替え）を推奨する。

## 演習

1. `code/main.py`を実行する。Leviathan分布チェックのカイ二乗統計が50,000サンプルで95%臨界値を下回ることを確認する。

2. `α`を0.9に固定し`c`を0.04に固定して`N`を1から10までスイープする。検証モデル呼び出しあたりの期待トークン数と実際のトークンあたりの実行時間をプロットする。実行時間を最小化する`N`を見つける。曲線の形状を説明する。

3. EAGLE-2のツリー検索をシミュレートするようにコードを修正する：各ステップでドラフトが`[2, 2, 2]`の形状のツリー（8つの候補パス）を提案する。検証モデルが一度実行され、最高確率の受容されたパスが勝つ。リーフあたりの`α`と検証モデル呼び出しあたりの総トークン数を計算する。同等の計算での線形チェーン投機デコーディングと比較する。

4. 2つの並行シーケンスのバッチKVロールバックシミュレーターを実装する。シーケンスAはすべてのドラフトが受容され、シーケンスBは位置2で棄却される。正しい`kv_length`がシーケンスごとに更新され、無駄な作業がないことを示す。

5. EAGLE-3論文のセクション4（学習時テスト）を読む。TTTなしのナイーブなドラフト学習が露出バイアスに悩まされる理由と、学習中にドラフトに自身の予測をフィードすることで修正される理由を2文で説明する。seq2seqの scheduled-sampling 文献と接続する。

## キーワード

| 用語 | 人々が言うこと | 実際の意味 |
|------|----------------|-----------|
| Leviathanルール | 「qをpで割ってmin 1」 | 確率`min(1, q(d)/p(d))`でベルヌーイ受容/棄却し、棄却時に残差からサンプリングすることで検証モデルの分布を正確に保存 |
| 残差分布 | 「(q-p)の正の部分、正規化済み」 | `(q - p)_+`を0でクランプして再正規化——棄却時にサンプリングすべき正しい分布 |
| 受容率α | 「ドラフトがどれくらい正しいか」 | 棄却ルールの下での期待トークンごとのベルヌーイ成功確率；すべてのスピードアップ計算を支配 |
| EAGLE-1 | 「隠れ状態ドラフト」 | 検証モデルの最終層の隠れ状態を条件とした小さなトランスフォーマードラフト（Li et al.、2024） |
| EAGLE-2 | 「動的ドラフトツリー」 | EAGLE-1に加え、1回の検証モデルパスでツリーアテンションで採点された候補継続のツリー |
| EAGLE-3 | 「学習時テスト」 | 特徴予測損失を削除し、学習中にドラフトに自身の出力をフィードして直接トークン予測で学習 |
| 学習時テスト（TTT） | 「露出バイアス修正」 | 学習中にドラフトを自己回帰的に実行して学習とテストの入力分布を一致させる——scheduled samplingの直接的な類似 |
| KVロールバック | 「棄却されたドラフトを取り消す」 | 棄却後に検証モデルのKVキャッシュを受容済みプレフィックス長にリセットするブックキーピング |
| ボーナストークン | 「無料のもの」 | すべての`N`ドラフトが受容された場合、検証モデルの追加コストなしに`q_{N+1}`から1つ余分にサンプリング |
| ツリーアテンション | 「多くの候補を一度に検証」 | ドラフトツリーのトポロジーを尊重する非因果マスクを使ったアテンション；1回のフォワードパスでツリーのすべてのノードに対して`q_i`を計算 |
