# チャンキング戦略の比較

> チャンキングは検索エンジンが表面化できるものを決定する。境界を誤ると、どんな埋め込みモデルも、再ランカーも、LLM も、下流でそのダメージを修復できない。


## 学習目標
- 5つのチャンキング戦略をゼロから実装する：固定ウィンドウ、文、再帰分割、セマンティッククラスタリング、構造的マークダウンヘッダー。
- ゴールドラベル付き回答スパンを持つフィクスチャコーパスで recall@k を測定し、1つの戦略が散文で勝ち、別の戦略が技術文書で勝つ理由を説明する。
- チャンク長分布を読んで、各戦略が注入する失敗モードを認識する：孤立した文、記号の途中での切断、ヘッダーのみのチャンク、セマンティックドリフト。
- ベンチマークを実行せずに新しいコーパスのデフォルトを3つのプロパティを検査することで選択する：ドキュメントタイプ、平均段落長、フォーマットが明示的な構造を持つかどうか。

## 問題

すべての RAG パイプラインは、埋め込みモデルが収まるほど小さく、各ピースが自己完結したアイデアを持つほど大きいピースにソースドキュメントを切り刻むことから始まる。どこで切るかの選択はハイパーパラメーターではない。検索エンジンが返せるものの上限だ。

「予算中断閾値はどのようなものか」というクエリは、中断閾値を持つチャンクが到達可能である場合にのみ成功できる。固定ウィンドウスプリッターが閾値の値を周囲のコンテキストから切り離した場合、埋め込みが別のクラスターに移動し、BM25スコアが低下し、再ランカーはノイズを見て、LLM が生成する回答は間違いだ。2024年の論文「LongRAG：Long-context LLM を使った検索拡張生成の強化」では、チャンキングの選択のみから検索リコールに35パーセントポイントの絶対的なスイングを測定した。2025年のコンテキストチャンクヘッダーに関するフォローアップ研究がギャップを縮めたが、閉じるには至らなかった。

このレッスンでは5つの戦略を並べて構築し、ゴールドラベル付き回答スパンを持つフィクスチャコーパスに対して実行し、リコール数値を自分で読める。

## コンセプト

```mermaid
flowchart LR
  Doc[ソースドキュメント] --> S1[固定ウィンドウ]
  Doc --> S2[文]
  Doc --> S3[再帰分割]
  Doc --> S4[セマンティッククラスター]
  Doc --> S5[構造的マークダウン]
  S1 --> Chunks1[チャンク]
  S2 --> Chunks2[チャンク]
  S3 --> Chunks3[チャンク]
  S4 --> Chunks4[チャンク]
  S5 --> Chunks5[チャンク]
  Chunks1 --> Index[埋め込みインデックス]
  Chunks2 --> Index
  Chunks3 --> Index
  Chunks4 --> Index
  Chunks5 --> Index
  Index --> Eval[recall@k vs ゴールドスパン]
```

### 固定ウィンドウ

ブルートフォースベースライン。N 文字ごとに切る。オプションでオーバーラップし、位置 N で切られた文が位置 N - overlap から始まるチャンクにそのまま含まれる。高速、決定論的、境界では最悪。コントロールとして使い、デフォルトにはしない。

### 文

正規表現か単純なステートマシンで文の境界で分割する。ターゲット文字数まで1つ以上の文をチャンクに詰める。単語の途中では切らない。それでも段落途中やセクション途中で切れる。初期の多くの RAG パイプラインのデフォルトで、他の構造がない散文には合理的な選択だ。

### 再帰分割

2023年代のライブラリで普及した階層戦略。まず最も強いセパレーター（2重改行、段落）で分割しようとし、次（単改行）にフォールバックし、次に文へ、次に文字へ。チャンクが予算に収まったとき再帰が終了する。一貫性のない構造のドキュメントに強い。領域ごとに適応するから。

### セマンティッククラスタリング

すべての文を埋め込む。トピックセントロイドを共有する連続する文をクラスター化する。セントロイドとの類似度が閾値を下回るたびに切る。境界は文字ではなく意味を反映する。構築が遅く、埋め込みモデルに依存するが、段落内でトピックが切り替わるドキュメントに対して耐性がある。

### 構造的マークダウンヘッダー

明示的な構造を持つドキュメント（マークダウン、reStructuredText、RFC スタイルの番号付きセクション）では、見出しの境界で切る。各チャンクは見出しプラスその下のすべてのものになり、同じレベルまたは上位レベルの次の見出しまで。トピックごとに最小のチャンクだが、コーパスが整形式である場合にのみ利用可能だ。

### recall@k が境界の選択を測定する方法

ゴールドラベル付きクエリはソースドキュメント内の回答スパンの正確な文字オフセットを持つ。チャンキング後に問う：検索エンジンが返したトップ k チャンクのいずれかがゴールドスパンとオーバーラップするか？はいなら、そのクエリの recall@k は1だ。いいえなら0だ。クエリセット全体で平均する。各戦略に対して同じ評価を実行すると、スプレッドがあなたが持っているコーパスでどの境界ポリシーが機能するかを示す。

## 実装する

`code/main.py` が実装するもの：

- `fixed_window(text, size, overlap)` - ベースライン。
- `sentence_chunks(text, target)` - シンプルな文パッカー。
- `recursive_split(text, separators, target)` - 階層的再帰。
- `semantic_chunks(text, similarity_threshold)` - 決定論的モック埋め込みの上のセントロイドベースクラスタリング。
- `structural_markdown(text)` - ヘッダー対応スプリッター。
- `mock_embed(text, dim)` - ループがオフラインで実行されるハッシュベースの埋め込み。
- `DenseIndex` - フェーズ19 Track B のハイブリッド検索レッスンで使用されたのと同じ形状。
- `eval_recall(strategy, corpus, queries, k)` - 比較ループ。
- すべての戦略をフィクスチャコーパスで実行して recall@k テーブルを表示する `main()`。

実行方法：

```bash
python3 code/main.py
```

出力は戦略ごとに1行、k ごとに1列の小テーブルだ。文は構造化フィクスチャで負ける。構造的マークダウンはマークダウンフィクスチャで勝つ。再帰は混合フィクスチャでうまくいく。セマンティッククラスタリングは有用な構造的手がかりがない散文フィクスチャで勝つ。

## テーブルが隠せない失敗モード

**孤立した文。** 文パッキングはトピック文を欠くチャンクを生成する。埋め込みが間違ったクラスターを指す。

**記号の途中での切断。** コードや YAML 内の固定ウィンドウは識別子を半分に切る。2つの半分がノイズに埋め込まれる。

**ヘッダーのみのチャンク。** 構造的マークダウンは `## タイトル` のみを含むチャンクを出力する。それらをフィルタリングするか、次のチャンクの最初の段落を添付する。

**セマンティックドリフト。** セマンティッククラスタリングはコーパスが均一にトピックに沿っていると切り足りない。5000文字のチャンクに多くの具体的な回答が1つの拡散した埋め込みに詰め込まれる。セマンティックとハードな文字上限を組み合わせる。

**古い埋め込み。** セマンティッククラスタリングは埋め込みモデルを使用する。モデルを変えると、チャンクも変わる。チャンクモデルを検索モデルとは別にピン留めするか、一緒にインデックスを再構築する。

## ベンチマークを実行せずにデフォルトを選択する

3つのプロパティが新しいコーパスのデフォルトチャンカーを決める。

| プロパティ | 値 | デフォルト |
|----------|-------|---------|
| ドキュメントタイプ | 構造なしの散文 | 再帰分割、ターゲット800 |
| ドキュメントタイプ | マークダウン / RFC / API ドキュメント | 構造的マークダウン |
| ドキュメントタイプ | コード | AST 対応（スコープ外。フェーズ19 レッスン02参照） |
| 段落長 | 長い、単一トピック | 文、ターゲット500 |
| 段落長 | 短い、混合トピック | セマンティック、閾値0.6 |

迷ったときは再帰分割を選ぶ。最強の単一戦略ベースラインだ。

## 使ってみる

プロダクションパターン：

- 新しいパイプラインを出荷する前に評価を実行する。ライブラリのデフォルト戦略を信頼しない。
- 埋め込みモデルやコーパスミックスを変えるたびに評価を再実行する。勝者はコーパス依存だ。
- 後でリグレッションを帰属できるよう、各チャンクのメタデータに戦略名を永続化する。

## 成果物を出す

Track F エンドツーエンド RAG システム（レッスン69）はここで選択されたチャンカーを最初のステージとして使用する。レッスン68の評価ハーネスはこのレッスンの `eval_recall` が返すのと同じ形状で recall@k を読む。コーパスで勝つ戦略を選択して先に進む。

## 演習

1. 6番目の戦略を追加する：文字数ではなく `tiktoken` を使ったトークンウィンドウ。同じフィクスチャで固定ウィンドウと比較する。
2. 散文フィクスチャにコードブロックを30%注入する。テーブルを再実行する。構造的マークダウン以外のすべての戦略がリコールを失う理由を説明する。
3. 決定論的な埋め込みをプロジェクトの実際のプロバイダーのものに置き換える。セマンティッククラスタリングの recall の差を測定する。戦略間のスプレッドが広がるか縮まるかを報告する。
4. チャンクごとに `summary` フィールドを追加する：1文のセントロイド説明。サマリーをチャンク本文に追加して評価を再実行する。リコールの向上を測定する。

## キーワード

| 用語 | よく言われること | 実際の意味 |
|------|-----------------|------------------------|
| Recall@k | 「正しいチャンクを取得できたか？」 | ゴールド回答スパンとオーバーラップするトップ k チャンクがあるクエリの割合 |
| チャンクオーバーラップ | 「スライディングウィンドウ」 | 前のチャンクの最後の N 文字を次のチャンクに再含める |
| 構造的スプリッター | 「ヘッダー対応チャンク」 | H1/H2/H3 境界で切る。見出しテキストはチャンクの一部 |
| セマンティックチャンカー | 「トピック対応チャンク」 | 文を埋め込み、セントロイド類似度でクラスター化し、ドリフトで切る |
| セントロイドドリフト | 「トピックシフト」 | ランニング平均と次の文のコサイン類似度が閾値を下回る |
