# キャップストーン 02 — コードベースへのRAG（クロスリポジトリセマンティック検索）

> 2026年のすべての真剣なエンジニアリング組織は、文字列だけでなく意味を理解する内部コード検索を運用している。Sourcegraph Amp、CursorのコードベースAnser、Augmentのエンタープライズグラフ、AiderのRepomap、Pinterestの内部MCP — 同じ形だ。多数のリポジトリを取り込み、tree-sitterでパースし、関数・クラスレベルのチャンクを埋め込み、ハイブリッド検索して、リランクし、引用付きで回答する。このキャップストーンでは、2Mラインのコードを10リポジトリにわたって処理し、すべてのgitプッシュでインクリメンタルな再インデックスに耐えるものを構築する。

**演習するフェーズ:** P5 · P7 · P11 · P13 · P17

## 問題

2026年にはすべてのフロンティアコーディングエージェントにコードベース検索レイヤーが搭載されている。コンテキストウィンドウだけではクロスリポジトリの質問を解決できないからだ。Claudeの1Mトークンコンテキストは役立つが、ランク付き検索の必要性をなくすわけではない。生のチャンクに対するナイーブなコサイン検索は、生成されたコード・モノリポの重複・ほとんどインポートされないシンボルのロングテールで結果を汚染する。本番環境の答えは、リランカー付きのAST対応チャンク上でのハイブリッド（密+BM25）検索であり、シンボル参照のグラフを背後に持つ。

実際のフリート（チュートリアルの1リポジトリではなく）をインデックスし、MRR@10、引用忠実度、インクリメンタルな新鮮さを測定することでこれを学ぶ。失敗モードはインフラストラクチャ的だ：100kファイルのモノリポ、ファイルの半分に触れるプッシュ、正しく答えるために4つのリポジトリをまたぐ必要があるクエリ。

## コンセプト

AST対応の取り込みパイプラインは各ファイルをtree-sitterでパースし、関数とクラスのノードを抽出し、固定トークンウィンドウではなくノード境界でチャンク分割する。各チャンクは3つの表現を得る：密な埋め込み（Voyage-code-3またはnomic-embed-code）、スパースなBM25タームの集合、そして短い自然言語サマリー。サマリーは第3の検索可能なモダリティを追加する — ユーザーが「Xはどのように認可されるか」と尋ねると、コードに`check_permission`しかなくてもサマリーには「authz」が言及されている。

検索はハイブリッドだ。クエリは密とBM25の両方の検索を発火し、上位kをマージし、そのユニオンをクロスエンコーダーリランカー（Cohere rerank-3またはbge-reranker-v2-gemma-2b）に渡す。リランクされたリストは、すべての主張をファイルと行範囲で引用するよう指示されたロングコンテキストシンセサイザー（プロンプトキャッシュ付きClaude Sonnet 4.7、またはセルフホストのLlama 3.3 70B）に渡される。引用のない回答は後処理フィルターで拒否される。

インクリメンタルな新鮮さはインフラストラクチャ問題だ。gitプッシュがdiffをトリガーする：どのファイルが変更されたか、どのシンボルが変更されたか。影響を受けたチャンクのみが再埋め込みされる。影響を受けたクロスファイルのシンボルエッジ（インポート、メソッド呼び出し）が再計算される。各コミットで2Mラインを再処理することなくインデックスが一貫性を保つ。

## アーキテクチャ

```
git push --> webhook --> ingest worker (LlamaIndex Workflow)
                           |
                           v
             tree-sitter parse + AST chunk
                           |
            +--------------+----------------+
            v              v                v
          dense        BM25 index       summary (LLM)
        (Voyage / bge)  (Tantivy)        (Haiku 4.5)
            |              |                |
            +------> Qdrant / pgvector <----+
                            |
                            v
                      symbol graph (Neo4j / kuzu)
                            |
  query --> LangGraph agent (retrieve -> rerank -> synth)
                            |
                            v
                 Claude Sonnet 4.7 1M context
                            |
                            v
                 answer + file:line citations
```

## スタック

- パース: 17言語グラマーを持つtree-sitter（Python、TS、Rust、Go、Java、C++など）
- 密な埋め込み: Voyage-code-3（ホスト型）またはnomic-embed-code-v1.5（セルフホスト）、bge-code-v1フォールバック
- スパースインデックス: BM25Fを使ったTantivy（Rust）、シンボル名対ボディのフィールド重み付き
- ベクターDB: ハイブリッド検索を持つQdrant 1.12、または50M以下のベクター用pgvector + pgvectorscale
- チャンクサマリーモデル: Claude Haiku 4.5またはGemini 2.5 Flash、プロンプトキャッシュ付き
- リランカー: Cohere rerank-3またはセルフホストbge-reranker-v2-gemma-2b
- オーケストレーション: 取り込み用LlamaIndex Workflows、クエリエージェント用LangGraph
- シンセサイザー: プロンプトキャッシュ付きClaude Sonnet 4.7（1Mコンテキスト）
- シンボルグラフ: インポートと呼び出しエッジ用Neo4j（マネージド）またはkuzu（組み込み）
- 可観測性: 検索ステップと合成ステップごとのLangfuseスパン

## 実装する

1. **取り込みウォーカー。** すべてのプッシュフックでgit履歴を反復する。変更されたファイルを収集する。各ファイルについて、tree-sitterでパースし、完全なソーススパンと一緒に関数とクラスのノードを抽出する。チャンクレコード`{repo, path, start_line, end_line, symbol, body}`を出力する。

2. **チャンクサマリー生成。** チャンクをシステムプリアンブルのプロンプトキャッシュを使ってHaiku 4.5呼び出しにバッチ処理する。プロンプト：「この関数を1文でサマリーし、パブリックコントラクトと副作用を名前で挙げること。」サマリーをチャンクと一緒に保存する。

3. **埋め込みプール。** 2つの並列キュー：密（Voyage-code-3バッチ128）とサマリー（同じモデル、ただしサマリー文字列に対して）。ペイロード`{repo, path, start_line, end_line, symbol, kind}`と一緒にQdrantにベクターを書き込む。

4. **BM25インデックス。** フィールド重み付きTantivy：シンボル名の重み4、シンボルボディの重み1、サマリーの重み2。「X という名前の関数を探す」クエリと「Xをする関数を探す」クエリの両方を可能にする。

5. **シンボルグラフ。** 各チャンクについて、エッジを記録する：インポート（このファイルはリポジトリZのシンボルYを使用）、呼び出し（この関数はクラスCのメソッドMを呼び出す）、継承。kuzuに保存する。クエリ時にリポジトリをまたいで検索を拡張するために使用する。

6. **クエリエージェント。** 3つのノードを持つLangGraph。`retrieve`は密とBM25を並列に発火し、（repo, path, symbol）で重複排除する。`rerank`はトップ50でクロスエンコーダーを実行し、トップ10を保持する。`synth`はリランクされたチャンクをコンテキストに持つClaude Sonnet 4.7を呼び出し、システムプロンプトをキャッシュし、ファイル:行の引用を要求する。

7. **引用の強制。** モデル出力をパースし、`(repo/path:start-end)`アンカーのない主張は再質問のためにフラグを立てるか削除する。引用済みのみの回答をユーザーに返す。

8. **インクリメンタルな再インデックス。** 各Webhookで、シンボルレベルのdiffを計算する。テキストが変更されたチャンクのみを再埋め込みする。インポートが変更されたチャンクのシンボルエッジを再計算する。測定：2M-LOCフリートの50ファイルのプッシュが60秒以内に再インデックスされる。

9. **評価。** 100件のクロスリポジトリ質問にゴールドファイル:行の答えでラベルを付ける。MRR@10、nDCG@10、引用忠実度（検証可能なアンカーを持つ主張の割合）、p50/p99レイテンシーを測定する。

## 演習

1. Voyage-code-3をセルフホストのnomic-embed-codeに交換する。MRR@10のデルタを測定する。リランクが有効な場合にギャップが縮まるかどうかをレポートする。

2. コーパスに20%の生成されたコード（LLM製のボイラープレート）を注入して再評価する。検索の汚染を観察する。ペイロードに「generated」フラグを追加し、それらのヒットの重みを下げる。

3. 同じコーパスサイズでQdrantハイブリッド検索対pgvector + pgvectorscaleをベンチマークする。バッチサイズ1でのp99をレポートする。

4. サンプリングベースのドリフトチェックを追加する：毎週、100問の評価を再実行する。MRR@10が5%以上下落した場合にアラートを出す。

5. クロス言語シンボル解決に拡張する：gRPCでGoサービスを呼び出すPython関数。シンボルグラフを使ってリンクする。

## キーワード

| 用語 | 一般的な呼び方 | 実際の意味 |
|------|-----------------|------------------------|
| AST対応チャンキング | 「関数レベルの分割」 | 固定トークンウィンドウではなくtree-sitterノード境界でコードを切る |
| ハイブリッド検索 | 「密+スパース」 | BM25とベクター検索を並列に実行し、上位kをマージ、リランク |
| クロスエンコーダーリランク | 「第2段階のランク付け」 | 各（クエリ、候補）ペアを一緒にスコアリングするモデル、コサインより正確 |
| プロンプトキャッシュ | 「キャッシュされたシステムプロンプト」 | 2026年のClaude / OpenAI機能：繰り返しのプレフィックストークンを最大90%割引 |
| シンボルグラフ | 「コードグラフ」 | ファイルとリポジトリをまたいだインポート、呼び出し、継承のエッジ |
| 引用忠実度 | 「根拠付き回答率」 | ユーザーがアンカーをクリックして参照スパンを読むことで検証できる主張の割合 |
| インクリメンタルな再インデックス | 「プッシュから検索までの時間」 | gitプッシュから変更されたシンボルが検索可能になるまでの時間 |
