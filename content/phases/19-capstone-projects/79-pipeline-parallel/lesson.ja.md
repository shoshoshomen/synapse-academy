# パイプライン並列とバブル分析

> テンソル並列は行列乗算をランク間で分割する。パイプライン並列はモデルをランク間で分割し、ランクごとに1ステージを配置する。マイクロバッチがパイプラインを流れる。開始と終了の空き時間がバブルだ。それを最小化することが技術の全てだ。


## 学習目標

- 連続したモデルをN個のステージに分割してN個のランクにわたるフォワードパイプラインをシミュレートする。
- GPipeスケジュール（フォワードのみで充填してからバックワード）を使ってMマイクロバッチをパイプラインに通し、バブル割合を計算する。
- Megatron-LMとPipeDreamで使用されているインタリーブ1F1Bスケジュールに対してバブルを比較する。
- ステージ割り当てを擁護する：ステージごとの等しい計算量がステージごとの等しいパラメータ数より重要だ。

## 問題

fp16の700億パラメータモデルはパラメータだけで140GBが必要だ。どの消費者向けGPUも収容できない。ZeRO-3はランク間でパラメータをシャーディングするが、各フォワードステップで各レイヤーをallgatherするためにすべてのランクが全レイヤーを必要とし、レイヤーごとにlog(N)ホップを払う。パイプライン並列は別のルートを取る：モデルをN個のステージに切り分け、各ランクに1つのステージを配置する。ランク0でのレイヤー1のフォワードが完了して活性化テンソルをランク1に渡し、ランク1がレイヤー2を実行してランク2に渡す。以降同様。バックワードは逆順に流れる。各ランクが1つのステージのみを保持するためメモリは線形に削減される。計算は逐次的だ。これがバブル問題だ。

バブルはパイプラインの開始時（最初のマイクロバッチが最後のステージに到達するまでの待機）と終了時（最後のマイクロバッチが戻って来るまでの待機）のアイドル時間だ。MマイクロバッチとNステージの場合、ステージごとのバブル割合は(N-1)/(M+N-1)だ。M=8、N=4では27%。M=64、N=4では4.5%。バブルはステップごとのマイクロバッチ数が多いほど縮む。これは小さなマイクロバッチサイズを意味し、マイクロバッチ設計を駆動する制約だ。

## コンセプト

```mermaid
flowchart LR
  R0["ランク0: ステージ0 / レイヤー0"] --> R1["ランク1: ステージ1 / レイヤー1"]
  R1 --> R2["ランク2: ステージ2 / レイヤー2"]
  R2 --> R3["ランク3: ステージ3 / 損失"]
  R3 -."バックワード".-> R2
  R2 -."バックワード".-> R1
  R1 -."バックワード".-> R0
```

### GPipeスケジュール

バックワードを開始する前にすべてのMマイクロバッチでパイプラインをフォワード充填し、逆順にバックワードをドレインする。すべてのマイクロバッチの活性化はバックワードまで保持する必要があるため、メモリはMと共に線形に増加する。フォワードはM+N-1サイクルかかり、バックワードはもうM+N-1サイクルかかる。ステージごとの有用な作業は2Mサイクル。ステージごとのバブルは2(N-1)サイクル。フォワードとバックワードがそれぞれ1時間単位かかる場合、バブル割合は(N-1)/(M+N-1)だ。NよりずっとMが大きければバブルが隠れる。

### 1F1Bスケジュール

インタリーブ：マイクロバッチのフォワードが最後のステージに到達したらすぐにそのバックワードを開始し、ストリームして戻させる。スケジュールはステージごとに1フォワードと1バックワードを交互に実行する。バブルはまだN-1だが活性化メモリはマイクロバッチ数ではなくパイプラインの深さで制限される。本番パイプラインは1F1Bを使用する（Megatron、PipeDream）。レッスンは最初にGPipeを実装する（シンプルだから）。1F1Bは演習として。

### なぜステージごとの等しい計算量が重要か

ステージ0が50msかかりステージ1が100msかかると、すべてのサイクルはステージ1でゲートされる。他のステージはステージ1の解放を待って50ms待機する。パラメータ数が等しいことは間違った軸だ：トランスフォーマーの計算はレイヤーごとのアテンション+MLPが支配し、埋め込みレイヤーは多くのパラメータを持つが計算量は少ない。ステージ割り当てはウェイト数ではなくFLOPsを等しくすべきだ。

### マイクロバッチ対バッチ

パイプラインはサイズBのMマイクロバッチを実行する。実効バッチサイズはM*Bだ。パイプラインステップ終了時の勾配はM*Bの例に対する勾配だ。バブル割合はMに依存し、オプティマイザーはM*Bを見る。Mを調整することはバブル（Mが高いと低い）とマイクロバッチごとのメモリ（GPipeではMが高いと活性化メモリが高い）のトレードオフだ。

## 実装する

`code/main.py`は以下を実装する：

- `PipelineStage`：1つのステージのパラメータを保持して`forward(activation)`を公開する小さな`nn.Module`。
- `Pipeline(stages, num_microbatches)`：シミュレートされたステージのシミュレートされたウォールクロックを使ってGPipeスケジュールを調整する。
- `bubble_fraction(num_stages, num_microbatches)`：閉じた形式の(N-1)/(M+N-1)。
- マイクロバッチごとのトレースと測定されたバブル割合を閉じた形式の予測に対して出力する4ステージデモ。

実行：

```bash
python3 code/main.py
```

出力：ステージ×マイクロバッチのガントチャートと、閉じた形式の予測に対するバブルの割合。

## 実際の本番パターン

3つのパターンがパイプライン並列を出荷できるほど堅牢にする。

**活性化チェックポイントはパイプラインと組み合わせる。** GPipeで飛行中のMマイクロバッチで、活性化メモリはMに比例して増加する。活性化チェックポイントはバックワード時にフォワードを再計算し、計算とメモリをトレードする。この組み合わせが長いシーケンスでパイプラインを扱えるようにする。

**ステージバランスは測定され、仮定されない。** 本番チームは対象ハードウェアで実際のレイヤーごとの計算（FLOPsとウォールクロック）を測定するプロファイリングパスを実行し、その測定でパーティショニングする。Megatron-LMの`--num-layers-per-stage`フラグはステージに異なるレイヤーコストがある場合に不均等なレイヤー数を可能にするリストを受け入れる。

**送受信スケジュールはデッドロックを避ける必要がある。** すべてのステージが受信前に送信するパイプラインはワイヤでデッドロックする。標準的な修正はインタリーブ：偶数ランクのステージが最初に送信して受信し、奇数ランクのステージが最初に受信して送信する。レッスンはパターンが見えるようにランクを明示的にスケジュールする。

## 使ってみる

本番パターン：

- **Megatron-LM。** スケールでのパイプライン並列の参照実装。1F1Bを使用してテンソル+パイプライン+データ並列を組み合わせてサポートする。
- **DeepSpeed Pipeline。** ZeROと統合する。ZeRO-1 + パイプラインは最大のオープンモデルに対する一般的な組み合わせだ。
- **PyTorch Pipe。** PyTorchネイティブのパイプラインラッパー。`torch.distributed.pipeline.sync.Pipe`上に構築されている。

## 成果物を出す

レッスン80はシャーディングされたチェックポイントにステージごとのパラメータシャードを保存する。レッスン81がDDP + ZeRO + パイプラインをエンドツーエンドデモに合成する（デモはランタイム用にパイプラインをシミュレートのままにする）。

## 演習

1. 1F1Bを実装し、バブル割合がGPipeと一致するが活性化メモリが制限されることを検証する。
2. 実際のレイヤーごとの時間を深いモデルでプロファイリングし、測定されたウォールクロックでステージを再バランスする。
3. パイプラインのマイクロバッチにわたる勾配累積を追加し、勾配が同等のフルバッチフォワードの勾配と等しいことを確認する。
4. パイプラインを活性化チェックポイントとペアにしてメモリの削減対計算コストを測定する。
5. パイプラインとDDPを組み合わせる（各パイプラインランクはデータ並列グループ間で複製される）。2次元スケジュールを推論する。

## キーワード

| 用語 | 人々が言うこと | 実際の意味 |
|------|----------------|------------------------|
| パイプライン | 「深さ方向のモデル並列」 | ランクごとに1ステージ、活性化がステージからステージへ流れる |
| バブル | 「パイプラインのアイドル時間」 | 一部のステージに作業がない開始と終了の(N-1)ステップ |
| マイクロバッチ | 「バッチのスライス」 | 1つのフォワード/バックワード単位。バブルはMが増えると縮む |
| GPipe | 「充填してドレイン」 | バックワードの前にすべてのMフォワード。高い活性化メモリ |
| 1F1B | 「インタリーブスケジュール」 | ステージごとに1フォワード1バックワード。制限された活性化メモリ |
