# キャップストーン 05 — 自律型研究エージェント（AIサイエンティスト級）

> SakanaのAI-Scientist-v2は完全な論文を公開した。Agent Laboratoryは実験を実行した。Allen AIはトレースを共有した。2026年の形は決まっている：実験に対する計画・実行・検証のツリー探索、予算化されたコスト、サンドボックス化されたコード実行、ビジョンフィードバック付きのLaTeXライター、自動化されたNeurIPSスタイルのレビュアーアンサンブル。1つ構築し、論文あたり$30以内でエンドツーエンドで実行し、Sakanaが文書化したサンドボックスエスケープのレッドチームを生き残れ。

**演習するフェーズ:** P0 · P2 · P3 · P7 · P10 · P14 · P15 · P16 · P18

## 問題

自律型研究エージェントは2026年に閾値を越えた。Sakana AIのAI-Scientist-v2は、ワークショップのピアレビューをクリアした生成された論文でNatureに掲載された。ShinkaEvolve（ICLR 2026）は仮説の進化へとラインを拡張した。AMDのAgent Laboratoryは再現可能なトレースを出荷した。エージェントは魔法ではない — コスト上限・シード固定サンドボックス・自動レビューを持つ候補実験のツリー上で実行する計画・実行・検証ループだ。技術はループ・予算・安全ストーリーにある。

狭いドメインのシード概念（例えば、100Mパラメーターのトランスフォーマーでのアテンションスパース性のアブレーション）に対して実装することでループを学ぶ。価値は最初の実行で何か新しいものを発見することにあるのではない。価値はインフラストラクチャにある：ツリー探索、実験サンドボックス、ライター・レビュアーループ、レッドチームレポート。Sakanaチームはサンドボックスエスケープの失敗を文書化した；あなたのエージェントは同じレッドチームをパスしなければならない。

## コンセプト

エージェントは最良優先ツリー探索だ。ノードは実験仕様：（仮説、設定、コード、期待される結果）。展開ステップは小さな編集で子を提案する（オプティマイザーの交換、バッチサイズのシフト、コンポーネントのアブレーション）。各子は新鮮なサンドボックスでハードなリソース上限付きで実行される。結果は（新規性 × 品質 × 残余予算）でノードをランク付けするスコアリング関数にフィードバックされる。予算が枯渇するまでツリーは成長し、次に最良のブランチが書き上げられる。

ライターはマルチモーダルだ。LaTeXドラフトを生成し、コンパイルし、図をレンダリングし、レンダリングされたPDFをClaude Opus 4.7のビジョンモードに戻してレイアウト・図の読みやすさ・主張とエビデンスの整合性を批評させる。5つのLLMジャッジのレビュアーアンサンブルがNeurIPSスタイルのスコア（新規性、厳密さ、明確さ、再現可能性、インパクト）を出力する；平均値がしきい値を下回ると、論文は批評とともにライターに戻る。

安全性は不可欠だ。すべての実験はネットワーク出力なし・境界付きウォールクロック・固定リソース制限のE2BまたはDaytonaサンドボックスで実行される。エージェントのコード生成ステップはサンドボックスをエスケープするシスコールをブロックするポリシーレイヤーを通過する。レッドチームレポートはSakanaが文書化した攻撃面（フォークボム、ファイルシステムエスケープ、LLM作成のネットワーク呼び出し）を再現する。

## アーキテクチャ

```
seed idea + domain
      |
      v
  literature search (Semantic Scholar + OpenAlex + FAISS cache)
      |
      v
  LangGraph plan-execute-verify tree
      |
      v
  +--- expand node ----+      per-node sandbox
  |                    |      (E2B / Daytona)
  v                    v      resource caps
  child_1           child_k   no network egress
  |                    |      deterministic seeds
  v                    v
  run experiment       run experiment
  |                    |
  v                    v
  score nodes by (novelty, quality, budget)
      |
      v
  best branch -> LaTeX writer
      |
      v
  compile + vision critique (Opus 4.7 vision)
      |
      v
  reviewer ensemble (5 LLM judges, NeurIPS rubric)
      |
      v
  paper.pdf + review.md + trace.json
```

## スタック

- オーケストレーション: チェックポイントと人間承認ゲートを持つLangGraph
- ツリー探索: 実験ノード上のカスタム最良優先（SakanaV2のAB-MCTSスタイル）
- サンドボックス: 実験ごとにE2B、Docker-in-Dockerフォールバック；cgroups経由のリソース上限
- 文献: Semantic Scholar Graph API + OpenAlex + アブストラクトのローカルFAISSキャッシュ
- ライター: LaTeXテンプレート + 図の批評とレイアウト用のClaude Opus 4.7（ビジョンモード）
- レビュアー: 加重集約を持つ5ジャッジのアンサンブル（Opus 4.7、GPT-5.4、Gemini 3 Pro、DeepSeek R1、Qwen3-Max）
- 実験フレームワーク: 物理実験用PyTorch 2.5、ロギング用W&B
- 可観測性: エージェントトレース用Langfuse、論文あたり$30のハード予算

## 実装する

1. **シードとドメインのスコープ設定。** シード概念（例：「1B未満のトランスフォーマーのアテンションマップのスパース性パターンを調査する」）を取る。探索空間を定義する：モデル、データセット、計算予算。

2. **文献パス。** 関連する最も引用された50本の論文をSemantic Scholar + OpenAlex でクエリ；アブストラクトをローカルにキャッシュ；1ページのドメインダイジェストを生成する。

3. **ツリースキャフォールド。** シード仮説でルートを初期化する。ノードごとに小さな編集の提案を持つ`expand(node) -> children`を実装する（子ごとに1つの設定変更）。加重された新規性 × 品質 × 予算の項として`score(node)`を実装する。

4. **サンドボックスラッピング。** すべての実験は`docker run --network=none --memory=8g --cpus=2 --pids-limit=256 --read-only`（または同等のE2Bポリシー）で実行する。シードはサンドボックスに書き込まれ、出力はリードオンリーでマウントされて戻される。

5. **計画・実行・検証ループ。** `plan`は子を提案する。`execute`はサンドボックスを実行し、ログとメトリクスをキャプチャする。`verify`はメトリクスのユニットチェックを実行する（損失は下がったか？アブレーションは効果を隔離したか？）。失敗したノードにはツリーに保存された失敗理由がある。

6. **ライター。** 予算後、最良のブランチを選択する。matplotlibで図をレンダリングする。コンテキストにブランチトレースを持つClaude Opus 4.7経由でLaTeXドラフトを生成する。コンパイルする。コンパイルされたPDFをOpus 4.7ビジョンに批評のために戻す。繰り返す。

7. **レビュアーアンサンブル。** 5ジャッジが（新規性、厳密さ、明確さ、再現可能性、インパクト）をNeurIPSスタイルのルーブリックでスコアリングする。平均 < 4.0/5 の場合、批評とともにライターに戻す。3回の書き直しの後でハードストップ。

8. **レッドチーム。** サンドボックスをターゲットにした敵対的タスクのセットを構築または統合する：フォークボム、ネットワーク流出試み、ファイルシステムエスケープ、LLM作成のシェルメタキャラクター。すべてがブロックされることを確認する。調査結果をまとめる。

9. **再現可能性。** すべての論文はツリー探索トレースJSON・シード・W&B実行リンク・サンドボックス設定・エンドツーエンドで再現するREADMEと一緒に出荷される。

## 成果物を出す

`outputs/skill-ai-scientist.md`が成果物。シードコンセプト + ドメイン + $30の予算を与えると、完全なパイプラインを実行してレビュー可能な論文と再現性バンドルを出力する。

| 配点 | 基準 | 測定方法 |
|:-:|---|---|
| 25 | 論文品質 | 公開されたワークショップ論文に対するブラインドルーブリックレビュー |
| 20 | 実験の厳密さ | ベースライン・シード・アブレーション；すべての主張が結果テーブルのセルに裏付けられている |
| 20 | コストと計算の規律 | 論文あたり$30の上限を実施、Langfuseでトレース |
| 20 | 安全性 | サンドボックスレッドチームをパス；ネットワークポリシーとキルスイッチを確認 |
| 15 | 再現可能性 | 同一シードによる1コマンドの再実行で論文を再現 |
| **100** | | |

## 演習

1. 同じドメインで3つの異なるシードコンセプトに対してパイプラインを実行する。ツリー探索のどの部分が重複しているかを比較する。重複した無駄な計算を特定する。

2. $5を超えると見積もられたノードの実験実行前に人間参加ゲートを追加する。総コストがどれだけ下がるかを測定する。

3. レビュアーアンサンブルを単一のジャッジに交換する。既知の不良論文のホールドアウトセットでの偽受理率を測定する。

4. ネットワーク流出のレッドチームテストを導入する：エージェントが外部アドレスに`curl`しようとするコードを書く。`--network=none`ポリシーがブロックすることを確認する。試みをログに記録する。

5. ツリー探索をフラットなランダムベースライン（同じ予算、展開戦略なし）と比較する。新規性 × 品質の向上をレポートする。

## キーワード

| 用語 | 一般的な呼び方 | 実際の意味 |
|------|-----------------|------------------------|
| ツリー探索 | 「AB-MCTSスタイルの展開」 | 新規性×品質×予算スコアを持つ実験ノード上での最良優先探索 |
| サンドボックス | 「実験の分離」 | ネットワークなし・境界付きCPU/メモリ・固定シード・リードオンリー入力を持つコンテナ |
| ビジョン批評 | 「レンダリング後読み取り」 | 論文をPDFにコンパイルし、PDFをVLMにレイアウトと主張とエビデンスの批評のために戻す |
| レビュアーアンサンブル | 「自動ピアレビュー」 | NeurIPSのルーブリックで論文をスコアリングする複数のLLMジャッジ；加重集計がパイプラインをゲート |
| 新規性スコア | 「これは新しいか？」 | 50本の文献キャッシュへの近接性にペナルティを与えるヒューリスティック |
| コスト上限 | 「$予算」 | 論文あたりの総消費のハード上限；Langfuseカウンター + 事前実行見積もり |
| レッドチーム | 「サンドボックスエスケープ監査」 | ポリシーが誤っていた場合にサンドボックスをエスケープするような敵対的タスク |
