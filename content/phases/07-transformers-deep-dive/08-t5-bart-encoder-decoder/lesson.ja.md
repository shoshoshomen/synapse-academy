# T5、BART — エンコーダ-デコーダモデル

> エンコーダは理解する。デコーダは生成する。両者を組み合わせると、入力 → 出力タスク——翻訳、要約、書き換え、転写——のために構築されたモデルができる。


## 問題

デコーダのみのGPTとエンコーダのみのBERTはそれぞれ異なる目標のために2017年のアーキテクチャを簡略化している。しかし多くのタスクは自然に入出力形式だ：

- 翻訳：英語 → フランス語。
- 要約：5,000トークンの記事 → 200トークンの要約。
- 音声認識：音声トークン → テキストトークン。
- 構造化抽出：文章 → JSON。

これらにはエンコーダ-デコーダが最も自然に合う。エンコーダはソースの密な表現を生成する。デコーダは出力を生成しながら各ステップでその表現にクロスアテンションする。学習は出力側での1つずれだ。GPTと同じ損失、ただしエンコーダ出力を条件として。

2つの論文が現代のプレイブックを定義した：

1. **T5**（Raffel et al. 2019年）。「Text-to-Text Transfer Transformer」。すべてのNLPタスクをテキスト入力、テキスト出力として再フレーム化。単一アーキテクチャ、単一語彙、単一損失。マスク済みスパン予測で事前学習（入力のスパンを破損し、出力でそれらをデコードする）。
2. **BART**（Lewis et al. 2019年）。「Bidirectional and Auto-Regressive Transformer」。デノイジングオートエンコーダ：複数の方法で入力を破損し（シャッフル、マスク、削除、回転）、デコーダに元の文を復元させる。

2026年、エンコーダ-デコーダ形式は入力構造が重要な場所に残っている：

- Whisper（音声 → テキスト）。
- Googleの翻訳スタック。
- 一部のコード補完/修正モデルで明確なコンテキストと編集構造を持つもの。
- 構造化推論タスク用のFlan-T5とその変形。

デコーダのみが脚光を浴びたが、エンコーダ-デコーダは消えていない。

## 概念

![クロスアテンションを持つエンコーダ-デコーダ](../assets/encoder-decoder.svg)

### フォワードループ

```
ソーストークン ─▶ エンコーダ ─▶ (N_src, d_model)  ──┐
                                                 │
ターゲットトークン ─▶ デコーダブロック                   │
                 ├─▶ マスク済みSelf-Attention       │
                 ├─▶ クロスアテンション ◀───────────┘
                 └─▶ FFN
                ↓
              次トークンのロジット
```

重要なことに、エンコーダは入力ごとに1回実行される。デコーダは自己回帰的に実行されるが、各ステップで*同じ*エンコーダ出力にクロスアテンションする。エンコーダ出力をキャッシュすることは長い入力に対する無料のスピードアップだ。

### T5の事前学習——スパン破損

入力のランダムスパンを選ぶ（平均3トークン、合計15%）。各スパンをユニークなセンチネルに置き換える：`<extra_id_0>`、`<extra_id_1>`など。デコーダはセンチネルプレフィックスとともに破損されたスパンのみを出力する：

```
ソース: The quick <extra_id_0> fox jumps <extra_id_1> dog
ターゲット: <extra_id_0> brown <extra_id_1> over the lazy
```

シーケンス全体を予測するより安価な信号。T5論文のアブレーションでMLM（BERT）とprefix-LM（UniLM）と競合する。

### BARTの事前学習——マルチノイズデノイジング

BARTは5つのノイジング関数を試す：

1. トークンマスキング。
2. トークン削除。
3. テキスト埋め込み（スパンをマスクし、デコーダが正しい長さを挿入する）。
4. 文の順序入れ替え。
5. ドキュメント回転。

テキスト埋め込み + 文の順序入れ替えの組み合わせが最も良い下流の数値を出した。デコーダは常に元の文を復元する。BARTの出力は破損されたスパンだけでなく完全なシーケンスなので、T5より事前学習計算量が高い。

### 推論

GPTと同じ自己回帰生成。Greedy/ビーム/Top-pサンプリングが適用される。翻訳と要約には出力分布がチャットより狭いため、ビームサーチ（幅4〜5）が標準だ。

### 2026年に各バリアントを選ぶ場合

| タスク | エンコーダ-デコーダ？ | 理由 |
|------|------------------|-----|
| 翻訳 | 通常はYes | 明確なソースシーケンス；固定出力分布；ビームサーチが機能する |
| 音声→テキスト | Yes（Whisper） | 入力モダリティが出力と異なる；エンコーダが音声特徴を整形する |
| チャット/推論 | No、デコーダのみ | 永続的な「入力」なし——会話がシーケンスだ |
| コード補完 | 通常はNo | 長コンテキストのデコーダのみが勝つ；Qwen 2.5 Coderのようなコードモデルはデコーダのみ |
| 要約 | どちらでも | BART、PEGASUSが以前のデコーダのみベースラインを上回る；現代のデコーダのみLLMが匹敵する |
| 構造化抽出 | どちらでも | T5は「テキスト→テキスト」があらゆる出力形式を吸収するのでクリーン |

〜2022年以降のトレンド：(a) 指示ファインチューニングされたデコーダのみLLMがプロンプトで何にでも汎化する、(b) 1つのアーキテクチャが2つより簡単にスケールする、(c) RLHFがデコーダを前提とするため、デコーダのみがエンコーダ-デコーダが所有していたタスクを引き継ぐ。エンコーダ-デコーダは入力モダリティが異なる場合（音声、画像）またはビームサーチの品質が重要な場合に残る。

## 実装する

`code/main.py`を参照。T5スタイルのスパン破損をトイコーパスに実装する——これはレッスンの最も有用な1つのピースで、それ以来のすべてのエンコーダ-デコーダ事前学習レシピに現れるからだ。

### ステップ1：スパン破損

```python
def corrupt_spans(tokens, mask_rate=0.15, mean_span=3.0, rng=None):
    """マスクレートの合計~mask_rateになるスパンを選ぶ。（破損された入力、ターゲット）を返す。"""
    n = len(tokens)
    n_mask = max(1, int(n * mask_rate))
    n_spans = max(1, int(round(n_mask / mean_span)))
    ...
```

ターゲット形式はT5の規則：`<sent0> span0 <sent1> span1 ...`。破損された入力はスパン位置のセンチネルトークンと変更されていないトークンを交互に配置する。

### ステップ2：ラウンドトリップを確認する

破損された入力とターゲットが与えられたとき、元の文を再構成する。破損が可逆なら、フォワードパスは明確に定義されている。これはサニティチェックだ——実際の学習はこれを決してしないが、テストは安価でスパン記帳のオフバイワンバグを検出する。

### ステップ3：BARTノイジング

5つの関数：`token_mask`、`token_delete`、`text_infill`、`sentence_permute`、`document_rotate`。そのうち2つを組み合わせて結果を示す。

## 使ってみる

HuggingFaceリファレンス：

```python
from transformers import T5ForConditionalGeneration, T5Tokenizer
tok = T5Tokenizer.from_pretrained("google/flan-t5-base")
model = T5ForConditionalGeneration.from_pretrained("google/flan-t5-base")

inputs = tok("translate English to French: Attention is all you need.", return_tensors="pt")
out = model.generate(**inputs, max_new_tokens=32)
print(tok.decode(out[0], skip_special_tokens=True))
```

T5のトリック：タスク名が入力テキストに入る。各タスクがテキスト入力、テキスト出力なので、同じモデルが数十のタスクを処理する。2026年にはこのパターンが指示ファインチューニングされたデコーダのみLLMで一般化されているが、T5が最初にそれを成文化した。

## キーワード

| 用語 | 人々が言うこと | 実際の意味 |
|------|-----------------|-----------------------|
| エンコーダ-デコーダ（Encoder-decoder） | 「Seq2seq Transformer」 | 2つのスタック：入力用の双方向エンコーダ、出力用のクロスアテンション付きCausalデコーダ。 |
| クロスアテンション（Cross-attention） | 「ソースがターゲットと話す場所」 | デコーダのQ × エンコーダのK/V。エンコーダの情報がデコーダに入る唯一の場所。 |
| スパン破損（Span corruption） | 「T5の事前学習トリック」 | ランダムスパンをセンチネルトークンに置き換える；デコーダがスパンを出力する。 |
| デノイジング目標（Denoising objective） | 「BARTのゲーム」 | 入力にノイズ関数を適用し、デコーダにクリーンなシーケンスを復元するよう学習する。 |
| センチネルトークン（Sentinel token） | 「`<extra_id_N>`プレースホルダー」 | ソースの破損されたスパンにタグを付け、ターゲットで再タグ付けする特別なトークン。 |
| Flan | 「指示ファインチューニングされたT5」 | >1,800タスクでファインチューニングされたT5；エンコーダ-デコーダを指示追従で競合させた。 |
| ビームサーチ（Beam search） | 「デコーディング戦略」 | 各ステップで上位k個の部分シーケンスを保持；翻訳/要約の標準。 |
| Teacher forcing | 「学習時入力」 | 学習中、サンプルされたトークンではなく真の前の出力トークンをデコーダに供給する。 |
