# スケーリング則

> 2020年のKaplan論文は言った：より大きなモデル、より低い損失。2022年のHoffmann論文は言った：あなたは学習不足だった。計算は2つのバケツに入る——パラメータとトークン——そして分割は自明ではない。


## 問題

学習計算のCFLOPsがあって最良のモデルが欲しいとき、2つのノブがある：

1. **パラメータ数（N）？** より大きなモデル、より高い容量。
2. **学習トークン数（D）？** より多くのデータ、容量の使用が良くなる。

FLOPsはおおよそ`6 × N × D`でスケールする。Nを押し上げてDを下げる、またはDを押し上げてNを下げる。どちらが良いか？

2022年以前、答えは「Nを強く押す」だった。GPT-3（2020年）は〜300Bトークンで学習された175Bパラメータだった。パラメータあたり約1.7トークンの比率。Kaplanスケーリングがこれをサポートしていた。

Hoffmann et al.（2022年）はChinchillaと呼ばれる小さなモデルファミリーを学習し、異なるものを見つけた：最適な比率はパラメータあたり約**20トークン**に近い。GPT-3は10倍学習不足だった。Chinchilla（70Bパラメータ、1.4Tトークン）はすべてのベンチマークでGPT-3（175B、300Bトークン）を2.5倍低い推論コストで上回った。

2026年はChinchillaの世界だ——1つの重要なひねりを伴う。Llama 3 8Bは15兆トークンで学習され、パラメータあたり1,875トークンの比率だ。Chinchilla最適の94倍。規模でデプロイされるモデルに対して学習コストより推論コストの方が重要なので、小さいデプロイ可能なフットプリントのための過学習（Chinchillaを超えた）が2026年のデフォルトだ。

## 概念

![Chinchillaカーブ：様々なN/D比率での計算に対する損失](../assets/scaling-laws.svg)

### Hoffmann則

Chinchilla論文から、損失は以下に従う：

```
L(N, D) = A / N^α + B / D^β + E
```

- `N` = パラメータ（埋め込み除く）。
- `D` = 学習トークン。
- `α ≈ 0.34`、`β ≈ 0.28`（おおよそ対称）。
- `E ≈ 1.69`、還元不可能な損失の天井。
- `A ≈ 406`、`B ≈ 411`。

2つの項は固定計算（C = 6ND）でスケールする際に競合する。`N`に対して微分し固定計算で解く：

```
N_opt ≈ 0.6 × (C/6)^0.5
D_opt ≈ 0.6 × (C/6)^0.5
D_opt / N_opt ≈ 20
```

計算最適：パラメータあたり20トークン。

### なぜとにかく過学習するのか

Chinchilla最適は学習FLOPあたりの学習損失を最小化する。しかし学習コストは一度支払われる；推論コストは永遠に続く。

月に1兆トークンを提供するチャットボットでは、推論が総コストを支配する。Llamaのアプローチ：より小さく、より長く学習する。8Bを15Tトークンで深く推論最適化する：

- コンシューマーGPUに収まる。
- レイテンシは70Bのフラクション。
- 品質はほとんどのタスクで十分に近い。

DeepMindの2024年論文（「過学習が新しい最適だ」）はこれを形式化した。推論支配ワークロードでは、提供ボリュームに応じてパラメータあたり100〜500トークンの比率が適切だ。

### 出現性 vs 滑らかさ

主張：特定の能力（算術、多ステップ推論、chain-of-thought追従）があるスケールで突然「出現」する。

Schaeffer et al.（2023年）はこれが測定アーティファクトだと主張した：出現メトリックは不連続なスコアリング（完全一致、閾値での精度）を使い、基礎となるロジットの滑らかな改善を隠す。連続メトリック（クロスエントロピー）は滑らかな曲線を示す。

2026年のコンセンサスは：連続損失による予測は信頼できる。ベンチマークジャンプはしばしばスコアラーアーティファクトだ。連続メトリックに対して予算を計画する。

### 2026年の状況

スケーリング則はまだ機能するが：

| 要素 | 変わった方法 |
|--------|-------------|
| データ品質 | 「良い」トークンのキュレーション（Phi風）が>2倍の有効計算で曲線をシフト |
| MoE | 総パラメータがアクティブFLOPsから切り離される；アクティブFLOPあたりのスケーリング則 |
| 事後学習 | 一部の能力（指示追従、コード）が事前学習よりSFT+RLHFでよりシフトする |
| マルチモダリティ | 画像 + テキストトークンが一緒にスケール；モダリティごとに別々の曲線 |
| 合成データ | モデルが学習データを生成する；有効計算が複合できる |

Muonオプティマイザー（Kimi Moonlight、2024年）はAdamWより〜2倍の有効計算向上を示した。一部の2026年の学習ランはデフォルトでMuonを使用する。スケーリング則の絶対定数を変える、漸近線ではない。

## 実装する

`code/main.py`を参照。Chinchillaの損失方程式を実装し、いくつかの計算予算それぞれで計算最適な`(N, D)`を解く。

### ステップ1：Chinchilla損失

```python
def chinchilla_loss(N, D, A=406.4, B=410.7, alpha=0.34, beta=0.28, E=1.69):
    return A / N ** alpha + B / D ** beta + E
```

固定`C = 6ND`での`(N, D)`上の等高線として`L`をプロットする。最小値を見つける。

### ステップ2：計算最適フロンティア

`1e17`から`1e25` FLOPsの計算予算に対して、`6ND = C`を条件として損失を最小化する`(N, D)`を見つける。`D/N ≈ 20`の比率を確認する。

### ステップ3：過学習コスト

10倍小さいモデル（最適Nの1/10、最適Dの10倍）を学習するために支払う追加損失を計算する。交換として推論FLOPsの節約（Nに比例）を報告する。

### ステップ4：実際のモデルと比較する

GPT-3、Chinchilla、Llama 3 8B、DeepSeek-V3（アクティブパラメータ）の既知の`(N, D)`ペアを代入し、予測された損失と報告された損失を比較する。

## 使ってみる

自分でフロンティアモデルを学習することはおそらくないだろう。しかしスケーリング則は以下を教えてくれる：

1. **ファインチューニングに十分なデータがあるかどうか。** タスク固有のデータがベースモデルのパラメータあたり20トークン未満の場合、ある損失フロアでの飽和を予想する。
2. **より大きなベースモデルを選ぶかどうか。** すべての予算を推論に使っているなら、より小さく、より長く学習されたモデルを選ぶ。
3. **収益が逓減する場所。** Chinchilla最適の1000倍を超えると、ログ損失の変化はノイズになる。

**2026年の研究軌道：**

- **データ制約レジーム。** ウェブには有限な数の高品質トークン（フィルタリング後〜5〜10兆の英語）がある。フロンティア事前学習はこの上限に近づいている。合成データ、多言語、マルチモーダル、RLHFスケールのファインチューニングが次のレバーだ。
- **計算乗数トリック。** Muonオプティマイザー、MoE、より良いデータキュレーション——各々が漸近線ではなく絶対定数をシフトする。
- **RLのスケーリング則。** 未解決の問題。初期の証拠はRLサンプルでのべき乗則を示唆するが、事前学習とは非常に異なる指数で。

## 演習

1. **易.** `code/main.py`を実行せよ。計算予算`1e20`、`1e22`、`1e24`のChinchilla最適な`(N, D)`を出力せよ。実際のモデルテーブルと比較せよ。
2. **中.** Hoffmannの計算の関数としての損失曲線を実装せよ。計算最適フロンティアの`log10(C)`に対して損失をプロットせよ。次の0.1クロスエントロピー低下のために`>10^28` FLOPsが必要だと則が予測する時点を特定せよ。
3. **難.** 5つのミニモデル（100Kから10Mパラメータ）を同じデータセットで学習して自分のスケーリング則をフィットせよ。`α`と`E`を推定せよ。指数は公開されているものとどれだけよく一致するか？

## キーワード

| 用語 | 人々が言うこと | 実際の意味 |
|------|-----------------|-----------------------|
| パラメータ（N） | 「モデルサイズ」 | 埋め込みなしの重みカウント；容量を決定する。 |
| トークン（D） | 「学習データ」 | 見た学習トークン数；パラメータがどれだけうまく使われるかを決定する。 |
| 計算（C） | 「消費したFLOPs」 | 標準的なTransformerでおおよそ`6 × N × D`。 |
| Chinchilla最適（Chinchilla-optimal） | 「D/N ≈ 20」 | 事前学習FLOPあたりの損失を最小化する比率。 |
| 過学習（Over-training） | 「Chinchillaを超えて」 | 推論FLOPsを節約するために追加の学習FLOPsを使う；D/N >> 20。 |
| 還元不可能損失（Irreducible loss） | 「フロア」 | スケーリング則の`E`項；データ自体のエントロピー。 |
| 出現能力（Emergent capability） | 「スケールでの突然のジャンプ」 | しばしばスコアラーアーティファクト；連続損失は滑らかだ。 |
| 有効計算（Effective compute） | 「学習効率乗数」 | より良いデータ/オプティマイザー/アーキテクチャがFLOPがどれだけ遠くまで行くかを乗算する。 |
