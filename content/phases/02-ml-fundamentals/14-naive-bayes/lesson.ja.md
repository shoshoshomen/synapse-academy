# ナイーブベイズ

> 「ナイーブ」な仮定は間違っている、それでも機能する。それがその美しさだ。


## 学習目標

- テキスト分類のためにラプラス平滑化を使った多項ナイーブベイズをスクラッチから実装する
- ナイーブな独立性仮定が数学的に間違っているのに実践では正しいクラスランキングを生成する理由を説明する
- 多項、ベルヌーイ、ガウスのナイーブベイズのバリアントを比較し、与えられた特徴量タイプに適切なものを選択する
- 高次元スパースデータでナイーブベイズをロジスティック回帰と比較し、機能しているバイアス・バリアンストレードオフを説明する

## 問題

テキストを分類する必要がある。メールをスパムと非スパムに。カスタマーレビューをポジティブとネガティブに。サポートチケットをカテゴリに。数千の特徴量（単語ごとに1つ）と限られた訓練データがある。

ほとんどの分類器はここで詰まる。ロジスティック回帰は何千もの重みを信頼性高く推定するのに十分なサンプルが必要だ。決定木は1語ずつ分割して激しく過学習する。10,000次元でのKNNは無意味で、すべての点が他のすべての点から等しく遠い。

ナイーブベイズはこれを扱える。数学的に間違った仮定（クラスが与えられたとき、すべての特徴量が他のすべての特徴量から独立している）を立て、それでも特にテキスト分類では、小さな訓練セットでは「賢い」モデルを上回ることが多い。1回のデータパスで訓練できる。数百万の特徴量にスケールする。確率推定を生成する（独立性仮定のため較正が悪いことが多いが）。

間違った仮定が良い予測につながる理由を理解することは、機械学習における根本的なことを教えてくれる：最良のモデルは最も正確なものではなく、データに対してバイアス・バリアンストレードオフが最良のものだ。

## コンセプト

### ベイズの定理（クイックレビュー）

ベイズの定理は条件付き確率を反転する：

```
P(クラス | 特徴量) = P(特徴量 | クラス) * P(クラス) / P(特徴量)
```

`P(クラス | 特徴量)` が欲しい -- 文書に含まれる単語が与えられたときにその文書がクラスに属する確率。これは以下から計算できる：
- `P(特徴量 | クラス)` -- このクラスの文書でこれらの単語を見る尤度
- `P(クラス)` -- クラスの事前確率（一般的にスパムはどれほど多いか？）
- `P(特徴量)` -- 証拠、すべてのクラスで同じなので比較では無視できる

`P(クラス | 特徴量)` が最も高いクラスが勝つ。

### ナイーブな独立性仮定

`P(特徴量 | クラス)` を正確に計算するには、すべての特徴量が一緒になった結合確率を推定する必要がある。10,000語の語彙では、2^10,000の可能な組み合わせの分布を推定する必要がある。不可能だ。

ナイーブな仮定：すべての特徴量はクラスが与えられたとき条件付き独立だ。

```
P(w1, w2, ..., wn | クラス) = P(w1 | クラス) * P(w2 | クラス) * ... * P(wn | クラス)
```

1つの不可能な結合分布の代わりに、n個のシンプルな特徴量ごとの分布を推定する。それぞれはカウントだけが必要だ。

この仮定は明らかに間違っている。どんな文書でも「machine」と「learning」は独立ではない。しかし分類器は正確な確率推定を必要としない。正しいランキングを必要とする -- どのクラスが最も高い確率を持つか。独立性仮定は系統的な誤差を引き起こすが、それらの誤差はすべてのクラスに同様に影響するため、ランキングは正しいままだ。

### それでもなぜ機能するか

3つの理由：

1. **較正よりランキング。** 分類は上位ランクのクラスが正しいことだけを必要とする。P(スパム) = 0.99999 でも真の確率が0.7であっても、分類器は正しくスパムを選ぶ。正確な確率は必要ない。正しい勝者が必要だ。

2. **高バイアス、低バリアンス。** 独立性仮定は強い事前分布だ。モデルを強く制約し、過学習を防ぐ。限られた訓練データでは、わずかに間違っているが安定したモデルが、理論的に正しいが激しく不安定なモデルを上回る。これはバイアス・バリアンストレードオフが機能している様子だ。

3. **特徴量の冗長性が打ち消し合う。** 相関した特徴量は冗長な証拠を提供する。分類器はこの証拠を二重にカウントするが、正しいクラスのために二重にカウントする。「machine」と「learning」が常に一緒に出現するなら、両方が「tech」クラスの証拠を提供する。NB は2回カウントするが、正しいクラスのために2回カウントする。

4つ目の実践的な理由：ナイーブベイズは非常に速い。訓練はデータの1回パスで頻度をカウントするだけだ。予測は行列乗算だ。100万の文書を数秒で訓練できる。この速度は、より多くの特徴量セットを試し、より多くの実験を実行できることを意味する。

### ステップバイステップの数学

具体的な例をたどってみよう。2つのクラスがあるとする：スパムと非スパム。語彙は3語：「free」、「money」、「meeting」。

訓練データ：
- スパムメールは「free」が80回、「money」が60回、「meeting」が10回出現（合計150語）
- 非スパムメールは「free」が5回、「money」が10回、「meeting」が100回出現（合計115語）
- メールの40%がスパム、60%が非スパム

ラプラス平滑化（alpha=1）で：

```
P(free | スパム)    = (80 + 1) / (150 + 3) = 81/153 = 0.529
P(money | スパム)   = (60 + 1) / (150 + 3) = 61/153 = 0.399
P(meeting | スパム) = (10 + 1) / (150 + 3) = 11/153 = 0.072

P(free | 非スパム)    = (5 + 1) / (115 + 3) = 6/118 = 0.051
P(money | 非スパム)   = (10 + 1) / (115 + 3) = 11/118 = 0.093
P(meeting | 非スパム) = (100 + 1) / (115 + 3) = 101/118 = 0.856
```

新しいメール：「free」が2回、「money」が1回、「meeting」が0回。

```
log P(スパム | メール) = log(0.4) + 2*log(0.529) + 1*log(0.399) + 0*log(0.072)
                    = -0.916 + 2*(-0.637) + (-0.919) + 0
                    = -3.109

log P(非スパム | メール) = log(0.6) + 2*log(0.051) + 1*log(0.093) + 0*log(0.856)
                       = -0.511 + 2*(-2.976) + (-2.375) + 0
                       = -8.838
```

スパムが大差で勝つ。「free」が2回出現することはスパムの強い証拠だ。「meeting」が出現しないことは両方のログ合計にゼロを寄与する（0 * log(P)）-- 多項NB では、欠席している単語は効果がない。単語の欠席を明示的にモデル化するのはベルヌーイNBだ。

### 3つのバリアント

ナイーブベイズには3つのフレーバーがある。それぞれ `P(特徴量 | クラス)` を異なる方法でモデル化する。

#### 多項ナイーブベイズ

各特徴量をカウントとしてモデル化する。特徴量が単語頻度やTF-IDF値であるテキストデータに最適。

```
P(word_i | クラス) = (クラスにおける word_i のカウント + alpha) / (クラスの総語数 + alpha * 語彙サイズ)
```

`alpha` はラプラス平滑化（後述）。このバリアントはテキスト分類の主力だ。

#### ガウスナイーブベイズ

各特徴量を正規分布としてモデル化する。連続特徴量に最適。

```
P(x_i | クラス) = (1 / sqrt(2 * pi * var)) * exp(-(x_i - mean)^2 / (2 * var))
```

各クラスは特徴量ごとに独自の平均と分散を持つ。各クラス内で特徴量が実際に釣り鐘曲線に従うときにうまく機能する。

#### ベルヌーイナイーブベイズ

各特徴量を2値（存在または不在）としてモデル化する。短いテキストや2値特徴量ベクトルに最適。

```
P(word_i | クラス) = (クラスで word_i を含む文書数 + alpha) / (クラスの総文書数 + 2 * alpha)
```

多項と異なり、ベルヌーイは単語の不在を明示的にペナルティとする。「free」が通常スパムに出現するがこのメールにない場合、ベルヌーイはそれをスパムに対する証拠としてカウントする。

### 各バリアントの使用タイミング

| バリアント | 特徴量タイプ | 最適な用途 | 例 |
|---------|-----------|----------|---|
| 多項 | カウントまたは頻度 | テキスト分類、bag-of-words | メールスパム、トピック分類 |
| ガウス | 連続値 | 正規分布に近い特徴量を持つ表形式データ | アイリス分類、センサーデータ |
| ベルヌーイ | 2値（0/1） | 短いテキスト、2値特徴量ベクトル | SMSスパム、存在/不在特徴量 |

### ラプラス平滑化

テストデータに特定のクラスの訓練データには一度も出現しなかった単語が出てきたらどうなるか？

平滑化なし：`P(単語 | クラス) = 0/N = 0`。積全体を掛けたゼロが `P(クラス | 特徴量) = 0` を作り、他のすべての証拠に関わらずになる。見たことのない単語1つがどれだけ他の証拠がそれを支持していても、全体の予測を台無しにする。

ラプラス平滑化はすべての特徴量カウントに小さなカウント `alpha`（通常1）を加える：

```
P(word_i | クラス) = (count(word_i, クラス) + alpha) / (クラスの総語数 + alpha * 語彙サイズ)
```

alpha=1 で、すべての単語に少なくとも小さな確率が得られる。テストメールに「discombobulate」という単語が出てもスパム確率を殺さない。平滑化はベイズ解釈がある：それは単語分布への一様ディリクレ事前分布を置くことと同等だ。

alpha が高いほど強い平滑化（より一様な分布）を意味する。alpha が低いほどモデルがデータをより信頼することを意味する。alpha はチューニングするハイパーパラメータだ。

alphaの効果：

| Alpha | 効果 | 使用場面 |
|-------|------|---------|
| 0.001 | ほぼ平滑化なし、データを信頼 | 非常に大きな訓練セット、未知の特徴量が予想されない |
| 0.1 | 軽い平滑化 | 大きな訓練セット |
| 1.0 | 標準ラプラス平滑化 | デフォルトの出発点 |
| 10.0 | 強い平滑化、分布を平坦化 | 非常に小さな訓練セット、多くの未知の特徴量が予想される |

### 対数空間の計算

多くの確率（それぞれ1未満）を乗算すると浮動小数点アンダーフローが起きる。積は真の値が非常に小さい正の数であるにもかかわらず、浮動小数点でゼロになる。

解決策：対数空間で作業する。確率を乗算する代わりに、対数を加算する：

```
log P(クラス | x1, x2, ..., xn) = log P(クラス) + sum_i log P(xi | クラス)
```

これにより予測が内積になる：

```
log_scores = X @ log_feature_probs.T + log_class_priors
prediction = argmax(log_scores)
```

行列乗算。それがナイーブベイズの予測が非常に速い理由だ -- 単一層線形モデルと同じ演算だ。

### ナイーブベイズ vs ロジスティック回帰

テキストではどちらも線形分類器だ。違いはモデル化するものにある。

| 側面 | ナイーブベイズ | ロジスティック回帰 |
|------|------------|----------------|
| タイプ | 生成的（P(X\|Y) をモデル化） | 識別的（P(Y\|X) をモデル化） |
| 訓練 | 頻度をカウント | 損失関数を最適化 |
| 小さなデータ | 良い（強い事前分布が役立つ） | 悪い（重みを推定するのに不十分） |
| 大きなデータ | 悪い（間違った仮定が影響） | 良い（柔軟な境界） |
| 特徴量 | 独立性を仮定 | 相関を扱う |
| 速度 | 1回パス、非常に速い | 反復的最適化 |
| 較正 | 確率が悪い | より良い確率 |

経験則：ナイーブベイズから始める。十分なデータがあってNBがプラトーに達したら、ロジスティック回帰に切り替える。

## 実装する

`code/naive_bayes.py` のコードはスクラッチから MultinomialNB と GaussianNB の両方を実装する。

### MultinomialNB

スクラッチからの実装：

1. **fit(X, y)**：各クラスについて、各特徴量の頻度をカウントする。ラプラス平滑化を追加する。対数確率を計算する。クラス事前分布を保存する（クラス頻度の対数）。

2. **predict_log_proba(X)**：各サンプルについて、すべてのクラスの log P(クラス) + sum log P(特徴量_i | クラス) を計算する。これは行列乗算だ：X @ log_probs.T + log_priors。

3. **predict(X)**：最も高い対数確率を持つクラスを返す。

```python
class MultinomialNB:
    def __init__(self, alpha=1.0):
        self.alpha = alpha

    def fit(self, X, y):
        classes = np.unique(y)
        n_classes = len(classes)
        n_features = X.shape[1]

        self.classes_ = classes
        self.class_log_prior_ = np.zeros(n_classes)
        self.feature_log_prob_ = np.zeros((n_classes, n_features))

        for i, c in enumerate(classes):
            X_c = X[y == c]
            self.class_log_prior_[i] = np.log(X_c.shape[0] / X.shape[0])
            counts = X_c.sum(axis=0) + self.alpha
            self.feature_log_prob_[i] = np.log(counts / counts.sum())

        return self
```

重要な洞察：適合後、予測はただの行列乗算にバイアスを加えたものだ。それがナイーブベイズが非常に速い理由だ。

### GaussianNB

連続特徴量については、クラスごと特徴量ごとに平均と分散を推定する：

```python
class GaussianNB:
    def __init__(self):
        pass

    def fit(self, X, y):
        classes = np.unique(y)
        self.classes_ = classes
        self.means_ = np.zeros((len(classes), X.shape[1]))
        self.vars_ = np.zeros((len(classes), X.shape[1]))
        self.priors_ = np.zeros(len(classes))

        for i, c in enumerate(classes):
            X_c = X[y == c]
            self.means_[i] = X_c.mean(axis=0)
            self.vars_[i] = X_c.var(axis=0) + 1e-9
            self.priors_[i] = X_c.shape[0] / X.shape[0]

        return self
```

予測は特徴量ごとにガウスPDFを使い（対数空間で加算）、特徴量全体で乗算する。

### デモ：テキスト分類

コードは2つのクラス（テック記事 vs スポーツ記事）をシミュレートした合成bag-of-wordsデータを生成する。各クラスは異なる単語頻度分布を持つ。MultinomialNB は単語カウントを使って分類する。

合成データはこのように機能する：200の「単語」（特徴量列）を作成する。単語0〜39はテック記事で頻度が高くスポーツで低い。単語80〜119はスポーツで頻度が高くテックで低い。単語40〜79は両方で中程度の頻度だ。これにより一部の単語が強いクラス指標で他がノイズという現実的なシナリオを作る。

### デモ：連続特徴量

コードはアイリスに似たデータ（3クラス、4特徴量、ガウスクラスタ）を生成する。GaussianNBはクラスごとの平均と分散を使って分類する。各クラスは異なる中心（平均ベクトル）と異なる広がり（分散）を持ち、カテゴリ間で測定値が系統的に異なる現実世界のデータを模倣する。

コードはまた以下を実演する：
- **平滑化の比較：** 異なるalpha値でMultinomialNBを訓練して、平滑化の強度が精度に与える効果を示す。
- **訓練サイズ実験：** 訓練データが20から1600サンプルに増えるにつれたNBの精度の向上。NBは非常に少ないサンプルでも適切な精度に達する -- これがその主な利点だ。
- **混同行列：** クラスごとの精度、再現率、F1スコアでNBのミスを示す。

### 予測速度

ナイーブベイズの予測は行列乗算だ。n個のサンプル、d個の特徴量、k個のクラスで：
- MultinomialNB：1回の行列乗算 (n x d) @ (d x k) = O(n * d * k)
- GaussianNB：n * k のガウスPDF評価、d特徴量にわたって = O(n * d * k)

両方ともすべての次元に対して線形だ。全訓練点への距離計算が必要なKNN（すべての訓練点への距離計算が必要）やRBFカーネルSVM（すべてのサポートベクターに対してカーネル評価が必要）と比較しよう。NBは予測時間において桁違いに速い。

## 使う

sklearnでは、両方のバリアントが1行だ：

```python
from sklearn.naive_bayes import GaussianNB, MultinomialNB

gnb = GaussianNB()
gnb.fit(X_train, y_train)
print(f"GaussianNB 精度: {gnb.score(X_test, y_test):.3f}")

mnb = MultinomialNB(alpha=1.0)
mnb.fit(X_train_counts, y_train)
print(f"MultinomialNB 精度: {mnb.score(X_test_counts, y_test):.3f}")
```

sklearnでのテキスト分類：

```python
from sklearn.feature_extraction.text import CountVectorizer
from sklearn.naive_bayes import MultinomialNB
from sklearn.pipeline import Pipeline

text_clf = Pipeline([
    ("vectorizer", CountVectorizer()),
    ("classifier", MultinomialNB(alpha=1.0)),
])

text_clf.fit(train_texts, train_labels)
accuracy = text_clf.score(test_texts, test_labels)
```

`naive_bayes.py` のコードは正確性を確認するためにスクラッチからの実装をsklearnと同じデータで比較する。

### TF-IDFとナイーブベイズ

生の単語カウントは出現ごとにすべての単語に等しい重みを与える。しかし「the」や「is」のような一般的な単語はすべてのクラスで頻繁に出現する -- 情報を持たない。TF-IDF（Term Frequency - Inverse Document Frequency）は一般的な単語の重みを下げ、稀で識別性の高い単語の重みを上げる。

```python
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.naive_bayes import MultinomialNB
from sklearn.pipeline import Pipeline

text_clf = Pipeline([
    ("tfidf", TfidfVectorizer()),
    ("classifier", MultinomialNB(alpha=0.1)),
])
```

TF-IDF値は非負なので、MultinomialNBで機能する。TF-IDF + MultinomialNBの組み合わせはテキスト分類の最強のベースラインの1つだ。10,000以下の訓練サンプルのデータセットでは複雑なモデルを頻繁に上回る。

### 短いテキスト向けBernoulliNB

短いテキスト（ツイート、SMS、チャットメッセージ）では、BernoulliNBがMultinomialNBを上回ることがある。短いテキストは単語カウントが少ないため、MultinomialNBが依存する頻度情報がノイズになりやすい。BernoulliNBは存在または不在だけを気にするため、短いテキストでより信頼できる。

```python
from sklearn.naive_bayes import BernoulliNB
from sklearn.feature_extraction.text import CountVectorizer

text_clf = Pipeline([
    ("vectorizer", CountVectorizer(binary=True)),
    ("classifier", BernoulliNB(alpha=1.0)),
])
```

CountVectorizerの `binary=True` フラグはすべてのカウントを0/1に変換する。これなしでもBernoulliNBは機能するが、設計目的でないカウントを見ている。

### NB確率の較正

NB確率は較正が悪い。NBがP(スパム) = 0.95と言っても、真の確率は0.7かもしれない。信頼できる確率推定が必要な場合（例：閾値を設定するか他のモデルと組み合わせる）、sklearnの CalibratedClassifierCV を使う：

```python
from sklearn.calibration import CalibratedClassifierCV

calibrated_nb = CalibratedClassifierCV(MultinomialNB(), cv=5, method="sigmoid")
calibrated_nb.fit(X_train, y_train)
proba = calibrated_nb.predict_proba(X_test)
```

これはクロスバリデーションを使ってNBの生スコアの上にロジスティック回帰を適合させる。結果として得られる確率は真のクラス頻度にはるかに近い。

### 一般的な落とし穴

1. **負の特徴量値。** MultinomialNBは非負の特徴量を必要とする。負の値がある場合（特定の設定のTF-IDF、または標準化された特徴量など）、代わりにGaussianNBを使うか、特徴量を正にシフトする。

2. **ゼロ分散の特徴量。** GaussianNBは分散で割る。あるクラスで特徴量がゼロ分散（すべての値が同一）の場合、確率計算が崩壊する。コードはすべての分散に小さな平滑化項（1e-9）を加えてこれを防ぐ。

3. **クラスの不均衡。** メールの99%が非スパムなら、事前確率P(非スパム) = 0.99が非常に強いため、尤度の証拠を圧倒する。クラス事前確率を手動で設定するか、sklearnのclass_priorパラメータを使う。

4. **特徴量スケーリング。** MultinomialNBはスケーリングを必要としない（カウントで機能）。GaussianNBもスケーリングを必要としない（特徴量ごとの統計を推定する）。これはロジスティック回帰やSVMに対する利点で、これらは特徴量スケールに敏感だ。

### ナイーブベイズが失敗するとき

NBは独立性仮定が正しくないランキングを引き起こすとき（単に間違った確率だけでなく）に失敗する。これは次の場合に起きる：

1. **強い特徴量相互作用。** クラスが2つの特徴量の組み合わせに依存するが、どちら単体には依存しない（XORのようなパターン）場合、NBは完全に見逃す。各特徴量単体は証拠を提供しないため、NBはそれらを非線形に組み合わせることができない。

2. **対立する証拠を持つ高い相関特徴量。** 特徴量Aが「スパム」と言い、特徴量Bが「非スパム」と言うが、AとBが完全に相関している（現実では常に一致する）場合、NBはどこにもないはずの矛盾した証拠を見る。

3. **非常に大きな訓練セット。** 十分なデータがあれば、ロジスティック回帰などの識別モデルは真の決定境界を学習し、NBを上回る。小さなデータで役立った独立性仮定が今度はモデルを制約する。

実践的には、これらの失敗モードはテキスト分類では稀だ。テキスト特徴量は多数で、個別には弱く、独立性仮定の誤差は打ち消し合う傾向がある。強い相関した特徴量が少ない表形式データでは、最初にロジスティック回帰またはツリーベースのモデルを検討する。

2. **特徴量独立性テスト。** 実際のテキストデータセットを取る。明らかに相関している2つの単語（「machine」と「learning」）を選ぶ。P(word1 | クラス) * P(word2 | クラス) を計算してP(word1 AND word2 | クラス) と比較する。独立性仮定はどれほど間違っているか？分類精度に影響するか？

## 主要用語

| 用語 | 人々がよく言うこと | 実際の意味 |
|------|----------------|-----------|
| ナイーブベイズ | 「シンプルな確率的分類器」 | クラスが与えられたとき特徴量が条件付き独立であるという仮定でベイズの定理を適用する分類器 |
| 条件付き独立 | 「特徴量は互いに影響しない」 | P(A, B \| C) = P(A \| C) * P(B \| C) -- Cがわかれば、BはAについて何も新しいことを教えない |
| ラプラス平滑化 | 「加算1平滑化」 | すべての特徴量にゼロ確率が予測を支配するのを防ぐための小さなカウントを追加する |
| 事前確率 | 「データを見る前の信念」 | P(クラス) -- 特徴量を観測する前の各クラスの確率 |
| 尤度 | 「データがどれほど適合するか」 | P(特徴量 \| クラス) -- クラスがわかっているときにこれらの特徴量を観測する確率 |
| 事後確率 | 「データを見た後の信念」 | P(クラス \| 特徴量) -- 特徴量を観測した後のクラスの更新された確率 |
| 生成モデル | 「データがどう生成されるかをモデル化」 | P(X \| Y) と P(Y) を学習し、ベイズの定理を使って P(Y \| X) を得るモデル |
| 識別モデル | 「決定境界をモデル化」 | X がどう生成されるかをモデル化せずに P(Y \| X) を直接学習するモデル |
| 対数確率 | 「アンダーフローを避ける」 | 多くの小さな数の積が浮動小数点でゼロになるのを防ぐためにP の代わりに log P で作業する |
