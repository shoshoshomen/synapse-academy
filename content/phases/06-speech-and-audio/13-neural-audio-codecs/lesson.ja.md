# 神経音声コーデック — EnCodec・SNAC・Mimi・DACとセマンティック-アコースティック分割

> 2026年の音声生成はほぼすべてトークンだ。EnCodec・SNAC・Mimi・DACは連続した波形をTransformerが予測できる離散シーケンスに変換する。最初のコードブックをセマンティック、残りをアコースティックとするセマンティック対アコースティックトークンの分割は、音声にとってTransformer以来最も重要なアーキテクチャの変化だ。


## 問題

言語モデルは離散トークンで動作する。音声は連続的だ。LLMスタイルのモデルを音声/音楽に使いたい——MusicGen・Moshi・Sesame CSM・VibeVoice・Orpheus——なら、まず**神経音声コーデック**が必要だ: 音声を小さな語彙のトークンに離散化する学習済みエンコーダと、波形を再構成するマッチングデコーダ。

2つのファミリーが登場した:

1. **再構成優先コーデック** — EnCodec・DAC。知覚的な音声品質を最適化する。トークンは「アコースティック」——話者のアイデンティティ・ティンバー・バックグラウンドノイズを含むすべてをキャプチャする。
2. **セマンティック優先コーデック** — Mimi（Kyutai）・SpeechTokenizer。最初のコードブックが言語的/音素的なコンテンツをエンコードするように強制する（WavLMから蒸留することが多い）。後続のコードブックはアコースティックの詳細だ。

2024〜2026年の洞察: **純粋な再構成コーデックはテキストから生成しようとするとぼやけた音声を生成する。** コーデックトークンに対するLLMは言語構造とアコースティック構造の両方を同じコードブックで学習しなければならず、スケールしない。それらを分離する——セマンティックコードブック0、アコースティックコードブック1-N——がMoshiとSesame CSMを機能させる鍵だ。

## 概念

![4つのコーデックの比較: EnCodec・DAC・SNAC（マルチスケール）・Mimi（セマンティック+アコースティック）](../assets/codec-comparison.svg)

### コアの技法: 残差ベクトル量子化（RVQ）

1つの大きなコードブック（良質なものには数百万のコードが必要）の代わりに、現代のすべての音声コーデックは**RVQ**を使用する: 小さなコードブックのカスケード。最初のコードブックがエンコーダ出力を量子化し、2番目が残差を量子化する；以下同様。各コードブックは1024コード。8コードブック = 有効語彙サイズ1024^8 = 10^24。

推論時、デコーダはフレームごとに選択された全コードを足し合わせて再構成する。

### 2026年の重要な4つのコーデック

**EnCodec（Meta、2022年）。** ベースライン。波形に対するエンコーダ-デコーダ、RVQボトルネック。24 kHz、最大32コードブック、デフォルト4コードブック @ 1.5 kbps。`1D conv + transformer + 1D conv` アーキテクチャを使用。MusicGenが使用する。

**DAC（Descript、2023年）。** L2正規化コードブック、周期活性化関数、改善された損失を持つRVQ。12コードブックでのオープンコーデックで最高の再構成忠実度——元の音声と見分けがつかないこともある。44.1 kHzフルバンド。

**SNAC（Hubert Siuzdak、2024年）。** マルチスケールRVQ——粗いコードブックは細かいコードブックより低いフレームレートで動作する。音声を階層的にモデル化する: 約12 Hzでの粗い「スケッチ」＋50 Hzでの詳細。Orpheus-3Bが使用する（階層構造がLMベースの生成に適しているため）。

**Mimi（Kyutai、2024年）。** 2026年のゲームチェンジャー。12.5 Hzフレームレート（非常に低い）、8コードブック @ 4.4 kbps。コードブック0は**WavLMから蒸留されている**——WavLMの音声コンテンツ特徴量を予測するように学習される。コードブック1〜7はアコースティックの残差だ。この分割がMoshi（レッスン15）とSesame CSMを支えている。

### フレームレートが言語モデリングにとって重要な理由

フレームレートが低い = シーケンスが短い = LMが高速。

| コーデック | フレームレート | 1秒 = Nフレーム | 適した用途 |
|----------|-------------|---------------|----------|
| EnCodec-24k | 75 Hz | 75 | 音楽・汎用音声 |
| DAC-44.1k | 86 Hz | 86 | 高忠実度音楽 |
| SNAC-24k（粗い） | 約12 Hz | 12 | AR-LM効率的 |
| Mimi | 12.5 Hz | 12.5 | ストリーミング音声 |

12.5 Hzで、10秒の発話はわずか125コーデックフレーム——Transformerが容易に予測できる。

### セマンティック対アコースティックトークン

```
frame_t → [semantic_token_t, acoustic_token_0_t, acoustic_token_1_t, ..., acoustic_token_6_t]
```

- **セマンティックトークン（Mimiのコードブック0）。** 言われた内容をエンコード——音素・単語・コンテンツ。補助予測損失を通じてWavLMから蒸留。
- **アコースティックトークン（コードブック1〜7）。** ティンバー・話者のアイデンティティ・プロソディ・バックグラウンドノイズ・細かい詳細をエンコード。

ARのLMはまずセマンティックトークンを予測し（テキストを条件に）、次にアコースティックトークンを予測する（セマンティック＋話者リファレンスを条件に）。この因数分解が現代のTTSがゼロショット音声クローンできる理由だ: セマンティックモデルがコンテンツを扱い、アコースティックモデルがティンバーを扱う。

### 2026年の再構成品質（ビット/秒、低ビットレートほど良い）

| コーデック | ビットレート | PESQ | ViSQOL |
|----------|-----------|------|--------|
| Opus-20kbps | 20 kbps | 4.0 | 4.3 |
| EnCodec-6kbps | 6 kbps | 3.2 | 3.8 |
| DAC-6kbps | 6 kbps | 3.5 | 4.0 |
| SNAC-3kbps | 3 kbps | 3.3 | 3.8 |
| Mimi-4.4kbps | 4.4 kbps | 3.1 | 3.7 |

従来のOpusのようなコーデックは1ビットあたりの知覚品質で依然優れている。神経コーデックは**離散トークン**（Opusは生成しない）と**生成モデルの品質**（LMがそれらのトークンでできること）で勝る。

## 実装する

### ステップ1: EnCodecでエンコードする

```python
from encodec import EncodecModel
import torch

model = EncodecModel.encodec_model_24khz()
model.set_target_bandwidth(6.0)  # kbps

wav = torch.randn(1, 1, 24000)
with torch.no_grad():
    encoded = model.encode(wav)
codes, scale = encoded[0]
# codes: (1, n_codebooks, n_frames), dtype=int64
```

6 kbpsで `n_codebooks=8`。各コードは0〜1023（10ビット）。

### ステップ2: デコードして再構成を測定する

```python
with torch.no_grad():
    wav_recon = model.decode([(codes, scale)])

from torchaudio.functional import compute_deltas
import torch.nn.functional as F

mse = F.mse_loss(wav_recon[:, :, :wav.shape[-1]], wav).item()
```

### ステップ3: セマンティック-アコースティック分割（Mimiスタイル）

```python
from moshi.models import loaders
mimi = loaders.get_mimi()

with torch.no_grad():
    codes = mimi.encode(wav)  # shape (1, 8, frames@12.5Hz)

semantic = codes[:, 0]
acoustic = codes[:, 1:]
```

セマンティックコードブック0はWavLMアラインされている。テキスト対セマンティックTransformerを学習できる——音声への直接変換より語彙がずっと小さい。その後、別のアコースティック対波形デコーダが話者リファレンスを条件に処理する。

### ステップ4: コーデックトークンに対するAR LMが機能する理由

Mimiの12.5 Hz × 8コードブックでの10秒の音声クリップ:

```
N_tokens = 10 * 12.5 * 8 = 1000 tokens
```

1000トークンはTransformerにとって些細なコンテキストだ。2.56億パラメータのTransformerが現代のGPUで数ミリ秒で10秒の音声を生成できる。

## 使ってみる

問題→コーデックのマッピング:

| タスク | コーデック |
|--------|----------|
| 汎用音楽生成 | EnCodec-24k |
| 最高忠実度の再構成 | DAC-44.1k |
| 音声に対するAR LM（TTS） | SNACまたはMimi |
| ストリーミングフルデュプレックス音声 | Mimi（12.5 Hz） |

目安: **生成モデルを構築するならMimiまたはSNACから始めよ。圧縮パイプラインを構築するならOpusを使え。**

## 落とし穴

- **コードブックが多すぎる。** コードブックを追加すると忠実度は線形に増加するが、LMのシーケンス長も線形に増加する。8〜12で止めること。
- **フレームレートの不一致。** 12.5 Hz MimiでLMを学習してから50 Hz EnCodecでファインチューニングすると無音の失敗が起きる。
- **すべてのコードブックが等しいと思い込む。** Mimiではコードブック0がコンテンツを運ぶ；失うと理解度が破壊される。コードブック7を失ってもほとんど気づかない。
- **再構成品質だけを指標として使う。** コーデックは優れた再構成を持ちながら、セマンティック構造が悪ければLMベースの生成には役立たない場合がある。

## 演習

1. **簡単。** `code/main.py` を実行する。おもちゃのスカラー＋残差量子化器を実装し、コードブックを追加するにつれて再構成誤差を測定する。
2. **中級。** `encodec` をインストールし、ホールドアウトの音声クリップで1・4・8・32コードブックを比較する。ビットレートに対するPESQまたはMSEをプロットする。
3. **難しい。** Mimiをロードする。クリップをエンコードする。コードブック0をランダムな整数に置き換え、デコードする。次にコードブック7を同様に置き換える。2つの破損を比較する——コードブック0の破損は理解度を破壊するはずで、コードブック7の破損はほとんど何も変えないはずだ。

## キーワード

| 用語 | よく言われること | 実際の意味 |
|------|-----------------|-----------|
| RVQ | 残差量子化 | 小さなコードブックのカスケード；各コードブックが前の残差を量子化する。 |
| フレームレート | コーデックの速度 | 1秒あたりのトークンフレーム数。低いほどLMが高速。 |
| セマンティックコードブック | コードブック0（Mimi） | SSLの特徴量から蒸留されたコードブック；コンテンツをエンコード。 |
| アコースティックコードブック | それ以外のすべて | ティンバー・プロソディ・ノイズ・細かい詳細。 |
| PESQ / ViSQOL | 知覚品質 | MOSと相関する客観的指標。 |
| EnCodec | Metaのコーデック | RVQベースライン；MusicGenが使用。 |
| Mimi | Kyutaiのコーデック | 12.5 Hzフレームレート；セマンティック-アコースティック分割；Moshiを支える。 |
