# コスト削減プリミティブとしてのモデルルーティング

> 動的なブローカーがすべてのリクエストを評価し（タスクタイプ、トークン長、埋め込み類似度、信頼度）、シンプルなクエリは安価なモデルに送り、複雑なものはフロンティアモデルにエスカレートする。モデルカスケードとも呼ばれる。本番環境の事例研究では、米国・英国・EU展開で同等品質を保ちながら20〜60%のコスト削減が示されており、高ボリュームSaaSでのルーティング効率30%改善は年間6桁の節約につながる。2026年の文脈では、LLM推論価格は年10倍のペースで下落し——GPT-4クラスのトークンは2022年末の$20/Mから2026年の約$0.40/Mに下がった。この大部分はより良いサービングスタック（フェーズ17の04〜09）によるもので、ハードウェアではない。ルーティングとは、その価格下落をプロダクトの退行なしにマージンに変換する方法だ。失敗パターンは安価モデルへのドリフト：ルートが40%をより弱いモデルに送り、推論タスクの品質が3〜5%低下するが、誰も四半期間は気づかない。オフラインの評価セットだけでなく、オンライン品質メトリクスでルートを管理せよ。


## 学習目標

- モデルカスケードを説明する：低信頼度時に安価モデルを先に試してエスカレート。
- 4つのルーティングシグナルを列挙する（タスク分類、プロンプト長、既知の困難セットへの埋め込み類似度、最初のパスからの自己信頼度）。
- 目標のルーティング分割と品質損失許容度での期待ブレンドコストを計算する。
- 安価モデルのクリープを検出するドリフト監視メトリクス（オンライン品質ゲート）を挙げる。

## 問題の背景

サービスのGPT-5コストが月$80,000。分析によると70%のクエリはシンプルだ：「パリの現在時刻は？」「この文章を言い換えて」。Haikuクラスのモデルはコストの3%でそれらを完璧にこなせる。30%はGPT-5の推論が必要——コーディング、数学、マルチステップ計画。

70%を安価なモデルにルーティングし、30%を高価なモデルに回せば、同じプロダクト品質を保ちながら請求が約65%下がる。これがルーティングだ。コツはブローカーを品質退行なしに構築することだ。

## コンセプト

### 4つのルーティングシグナル

1. **タスク分類**：シンプル／複雑／コード生成／数学／チャット。ルールベースの分類器、小規模LLM（$0.25/MのHaikuクラス）、またはラベル付きバケツへの埋め込み類似度で実装できる。出力：route = cheap / balanced / frontier。

2. **プロンプト長**：4Kトークンを超えるプロンプトは多くの場合、一貫性のためにフロンティアが必要。500トークン未満は通常不要。

3. **既知の困難セットへの埋め込み類似度**：クエリが既知の困難なバケツに近い（コサイン > 0.88）場合は、フロンティアに直接エスカレート。

4. **最初のパスからの自己信頼度**：安価なモデルに送り、モデルのlog-probが低信頼度を示す、または拒否する、または曖昧な言語を出力する場合はフロンティアで再試行。約10%のトラフィックでP95レイテンシが増加するが、残り90%で50%以上の節約。

### 3つのパターン

**プリルート**（前段の分類器）：約5〜10msのレイテンシ追加；全体として最速。

**カスケード**（安価先行、低信頼度時にエスカレート）：中央値レイテンシ約1.2倍（安価な実行＋検証）、エスカレートした場合は約2倍。最良の品質フロアを実現。

**アンサンブルルート**（サンプルで安価とフロンティアを並列実行し、報酬モデルが選択）：最高品質、最高コスト；重要なA/Bにのみ使用。

### 実装

AIゲートウェイ（フェーズ17・19）がルーティングを公開している。LiteLLMはフォールバックとコストルーティング付きの`router`設定がある。Portkeyにはガード＋ルーティングがある。Kong AIゲートウェイにはプラグインベースのルーティングがある。OpenRouterのモデルマーケットプレイスは推奨APIを公開している。

オープンソース：RouteLLM（LMSYS）、Not Diamond（商用）、Prompt Mule。

### 2026年の価格カーブ

| モデルクラス | 2022年末 | 2026年 | 変化 |
|-------------|----------|--------|------|
| GPT-4レベル品質 | 約$20/M | 約$0.40/M | 50倍安価 |
| フロンティア（GPT-5、Claude 4） | — | 約$3〜10/M | 新ティア |

改善のほとんどはサービング効率によるもの——フェーズ17の04〜09のコアレッスンがプロバイダー側のコスト削減につながった。ルーティングにより、すべてのユーザーを安価なティアに移行させるのを待つ代わりに、アプリ層でその利益を取り込める。

### ドリフトが本当のリスク

ルートが40%を安価なモデルに送っている。6ヶ月後、タスクの分布が変化する（ユーザーがより洗練され、より長い質問をするようになる）。ルーターは分類器がQ1データで訓練されたため気づかない。品質がサイレントに低下する。誰も十分に声を上げない。競合のベンチマークで負けて初めて気づく。

オンライン品質メトリクスでルートを管理する：

- ルートごとのユーザーのサムズアップ／ダウン。
- ルートごとの保留サンプル（5%）での自動LLM判定。
- エスカレーション率：カスケードが30%以上を上位ルートにキックしている場合、安価なモデルへの過剰ルーティング。
- ルートごとの拒否率。

### 覚えておくべき数値

- 2026年の同等品質でのルーティング節約：事例研究で20〜60%。
- 2022〜2026年のLLM価格下落：年間約10倍。
- GPT-4レベル2022年対2026年：約$20/M → 約$0.40/M。
- カスケードのレイテンシ影響：中央値約1.2倍、エスカレートした場合（トラフィックの約10%）約2倍。

## 演習

1. `code/main.py`を実行する。カスケードがプリルートに勝つ精度フロアはどこか？
2. ユーザーベースが30%エンタープライズ（複雑なクエリ）、70%フリーティア（シンプルなクエリ）。ルーティング分割を設計する。どのオンラインメトリクスがゲートになるか？
3. ルートが品質を2%下げるが40%節約する。出荷するか？プロダクトによるが——両方の主張をせよ。
4. OpenAI / AnthropicのAPIのlogprobsを使って信頼度チェックを実装する。どんな閾値から始めるか？
5. 6ヶ月間でエスカレーション率が8%から22%に上昇する。3つの原因を診断し、それぞれの修正方法を示す。

## キーワード

| 用語 | よく言われる表現 | 実際の意味 |
|------|----------------|------------|
| Model routing | 「コストブローカー」 | リクエストごとの動的なモデル選択 |
| Model cascade | 「安価先行エスカレート」 | 安価に実行、低信頼度時にフロンティアにフォールスルー |
| Pre-route | 「先行分類」 | 前段の分類器；再実行なし |
| Ensemble route | 「並列選択」 | 複数実行して報酬モデルが最適を選択 |
| Escalation rate | 「上位ルート率%」 | カスケードリクエストのうちエスカレートした割合 |
| RouteLLM | 「LMSYSルーター」 | OSSルーターライブラリ |
| Not Diamond | 「商用ルーター」 | SaaSモデルルーティング製品 |
| Drift | 「安価モデルクリープ」 | ルーターが気づかない分布シフト |
| Online quality gate | 「ライブチェック」 | ライブトラフィックをサンプリングする自動LLM判定 |
