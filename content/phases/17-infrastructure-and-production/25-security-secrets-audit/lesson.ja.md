# セキュリティ — シークレット、APIキーのローテーション、監査ログ、ガードレール

> 集中型vaultによるシークレットの拡散を排除する（HashiCorp Vault、AWS Secrets Manager、Azure Key Vault）。クレデンシャルを設定ファイル、VCS内のenvファイル、スプレッドシートに保存しない。静的キーよりIAMロールを使う；CI/CDにはOIDC。AIゲートウェイパターンが2026年のソリューションだ：アプリ→ゲートウェイ→モデルプロバイダー、ゲートウェイが実行時にvaultからクレデンシャルを取得する。vaultでローテーションすれば数分でアプリすべてが新しいキーを使う——再デプロイなし、「新しいキーは誰が持ってる？」というSlackメッセージなし。ローテーションポリシー≦90日；すべてのコミットでTruffleHog / GitGuardian / Gitleaksでスキャン。ゼロトラスト：MFA、SSO、RBAC/ABAC、短命なトークン、デバイスポスチャー。PII除去はエンティティ認識を使ってPHI/PIIを転送前にマスクする；一貫したトークン化（Meshアプローチ）が同じ値を安定したプレースホルダーにマッピングするのでLLMがコード/関係のセマンティクスを保持する。ネットワークエグレス：専用のVPC/VNetサブネット内のLLMサービスで`api.openai.com`、`api.anthropic.com`などのみをホワイトリスト；他のすべてのアウトバウンドをブロック。2026年のインシデントドライバー：侵害されたCI/CDクレデンシャル経由のVercelサプライチェーン攻撃で何千もの顧客デプロイメントからenv varsを流出させた。


## 学習目標

- 4つのシークレット管理のアンチパターン（VCS内の設定ファイル、ハードコードされたenv、スプレッドシート、静的キー）を列挙してその代替を挙げる。
- AIゲートウェイがvaultから取得するパターンを2026年の本番標準として説明する。
- 一貫したトークン化（同じ値→同じプレースホルダー）でセマンティクスが保持されるPII除去を実装する。
- 2026年のVercelサプライチェーンインシデントとCI/CDクレデンシャルの衛生について学んだことを挙げる。

## 問題の背景

インターンが`.env`をAPIキーとともにコミットする。すぐに削除する。キーはすでにgitの履歴にある——GitGuardianのスキャンが検出し、ローテーションプロセスが「チームにSlackして、40の設定ファイルを更新して、すべてのサービスを再デプロイする」になる。8時間後、サービスの半分がライブで残り半分はデプロイウィンドウを待っている。

別途、ユーザーのプロンプトに「私のSSNは123-45-6789」が含まれている。プロンプトがOpenAIに送られる。BAAはあるが内部ポリシーは転送前にPIIをマスクすることだ。していなかった。

別途、EKSクラスターのLLMポッドが任意のインターネットホストに到達できる。誰かがDNSルックアップを通じて攻撃者がコントロールするドメインにデータを流出させる。何もブロックしなかった。

LLMサービスのセキュリティはこれら3つのベクターすべてに対処しなければならない。vaultバックドのクレデンシャル。PII除去。ネットワークエグレスフィルタリング。監査ログ。

## コンセプト

### 集中型vault＋IAMロールプル

**Vault**：HashiCorp Vault、AWS Secrets Manager、Azure Key Vault、GCP Secret Manager。唯一の真実の源。

**IAMロール**：アプリ/ゲートウェイが静的キーではなくIAMアイデンティティで認証する。Vaultがトークンの有効期間のシークレットを返す。

**AIゲートウェイパターン**：ゲートウェイがリクエスト時にvaultから`OPENAI_API_KEY`を取得する。vaultでローテーションすれば、次のリクエストで新しいキーが使われる。再デプロイなし。

### ローテーションポリシー≦90日

すべてのAPIキー、vaultルートトークン、CI/CDクレデンシャル。可能な限り自動ローテーション。手動ローテーションはログに記録して追跡。

### シークレットスキャン

- **TruffleHog** — コミットの正規表現＋エントロピー。
- **GitGuardian** — 商用、高精度。
- **Gitleaks** — OSS、CIで実行。

すべてのコミットで実行する。新しいシークレットが検出されたらPRをブロックする。

### ゼロトラストポスチャー

- すべてのアカウントでMFA必須。
- SAML/OIDCによるSSO。
- きめ細かいアクセスのためのRBAC（ロールベース）またはABAC（属性ベース）。
- 短命なトークン（日単位ではなく時間単位）。
- デバイスポスチャー——ディスク暗号化付きの企業デバイスのみ。

### PII/PHI除去

プロンプトがインフラを離れる前に：

1. エンティティ認識（spaCy NER、Presidio、商用）。
2. マッチしたエンティティをマスク：`"私のSSNは123-45-6789"` → `"私のSSNは[SSN_TOKEN_A3F]"`。
3. 一貫したトークン化（Meshアプローチ）：同じ値が同じプレースホルダーにマッピングされるのでLLMが関係性を保持する。
4. LLMレスポンスの逆マッピングはオプション。

静的な正規表現フィルターが基本的なパターンをキャッチし；NERがより多くをキャッチする。両方使う。

### 入力＋出力ガードレール

入力：既知のジェイルブレーク、禁止トピックをブロック；ユーザーごとのレート制限。

出力：流出したシークレット（拒否コンテキスト内のAPIキーパターン、メールパターン）の正規表現スクラブ、ポリシー違反の分類器。

### ネットワークエグレスホワイトリスト

専用サブネット内のLLMサービス：
- ホワイトリスト：`api.openai.com`、`api.anthropic.com`、ベクトルDBエンドポイント、vaultエンドポイント。
- それ以外すべて：ドロップ。
- ホワイトリストのみのリゾルバー経由のDNS（DNSトンネリングの流出を回避）。

### 監査ログ

すべてのLLM呼び出しの不変ログ：
- タイムスタンプ。
- ユーザー/テナント。
- プロンプトハッシュ（プライバシーのため生のプロンプトではない）。
- モデル＋バージョン。
- トークン数。
- コスト。
- レスポンスハッシュ。
- ガードレールのトリップ。

規制要件に従って保持（SOC 2は1年、HIPAAは6年）。

### 2026年のVercelインシデント

サプライチェーン攻撃：侵害されたCI/CDクレデンシャルが何千もの顧客デプロイメントからenv varsを流出させた。教訓：CI/CDクレデンシャルは本番相当だ。vaultに保存する。スコープを狭く。積極的にローテーションする。

### 覚えておくべき数値

- ローテーションポリシー：≦90日。
- すべてのコミットでスキャン：TruffleHog / GitGuardian / Gitleaks。
- Vercel 2026：CI/CDクレデンシャルが侵害→何千もの顧客のenv varsが流出。
- 監査ログ保持：SOC 2 = 1年、HIPAA = 6年。

## 演習

1. `code/main.py`を実行する。同じSSNを参照する2つのプロンプトを送る。両方が同じプレースホルダーを得ることを確認する。
2. OpenAI＋Anthropic＋Weaviateを呼び出すvLLM-on-EKSデプロイメントのネットワークエグレスポリシーを設計する。
3. gitの履歴（2年前）にキーを発見した。正しいレスポンスは何か——キーをローテーションする、履歴をスクラブする、両方？正当化する。
4. 監査ログが1日10 GB成長する。保持ティアを設計する（ホット30日、ウォーム12ヶ月、コールド6年）。
5. 逆トークン化（LLMレスポンスに実際の値を代入）がプレースホルダーを見えた状態にしておくことに比べて複雑さに値するかどうかを議論する。

## キーワード

| 用語 | よく言われる表現 | 実際の意味 |
|------|----------------|------------|
| Vault | 「シークレットストア」 | 集中型クレデンシャル管理サービス |
| IAM role | 「アイデンティティベースの認証」 | アプリが引き受けるロール；短命なクレデンシャルを返す |
| OIDC for CI/CD | 「クラウド発行トークン」 | CIに静的キーなし——OIDCによるアイデンティティ |
| TruffleHog / GitGuardian / Gitleaks | 「シークレットスキャナー」 | コミット時のシークレット検出 |
| RBAC / ABAC | 「アクセスコントロール」 | ロールベース対属性ベース |
| PII scrubbing | 「データマスキング」 | 機密エンティティを削除またはトークン化 |
| Consistent tokenization | 「安定したプレースホルダー」 | 同じ値→毎回同じトークン |
| Mesh approach | 「Meshトークン化」 | セマンティクス保持トークン化パターン |
| Egress whitelist | 「アウトバウンド許可リスト」 | 許可されたドメインのみ到達可能 |
| Audit log | 「不変履歴」 | コンプライアンスのための追記のみ記録 |
