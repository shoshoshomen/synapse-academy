# LLM機能のA/Bテスト — GrowthBook、Statsig、感覚的判断問題

> 従来のA/Bテストは非決定的なLLMのために設計されていなかった。重要な区別：evalは「モデルは仕事ができるか？」に答え、A/Bテストは「ユーザーは気にするか？」に答える。どちらも必要だ；感覚的判断でリリースする時代は終わった。2026年にテストすべきこと：プロンプトエンジニアリング（文言）、モデル選択（GPT-4対GPT-3.5対OSS；精度対コスト対レイテンシ）、生成パラメーター（temperature、top-p）。実際の事例：チャットボットの報酬モデルバリアントが会話の長さ+70%、リテンション+30%を実現；NextdoorのAI件名実験が報酬関数の改良後にCTR+1%を達成；カーンアカデミーのKhanmigoがレイテンシ対数学精度の軸で反復した。プラットフォームの分布：**Statsig**（2025年9月にOpenAIが11億ドルで買収）——逐次テスト、CUPED、オールインワン。**GrowthBook** ——オープンソース、ウェアハウスネイティブ、Bayesian＋Frequentist＋逐次エンジン、CUPED、SRMチェック、Benjamini-Hochberg＋Bonferroni補正。ウェアハウスSQLの好みと「OpenAIに買収された」ことが組織に関係するかどうかで選択する。


## 学習目標

- evals（「モデルは仕事ができるか」）とA/Bテスト（「ユーザーは気にするか」）を区別する。
- 3つのテスト可能な軸（プロンプト、モデル、パラメーター）を列挙し、それぞれのメトリクスを選択する。
- CUPED、逐次テスト、Benjamini-Hochberg多重比較補正を説明する。
- ウェアハウスSQLの姿勢と企業買収スタンスに基づいてStatsigかGrowthBookかを選ぶ。

## 問題の背景

システムプロンプトを手動でチューニングした。より良く感じる。リリースした。コンバージョンがノイズで変化した。メトリクスのせいにした。または新しいモデルをリリースしてコンバージョンが変わらなかった——モデルが劣化したのか、変化が検出できないほど小さかったのか？A/Bなしでリリースしたのでわからない。

evalはラベル付きセット上でモデルがタスクをこなせるかどうかを答える。ユーザーが出力を好むかどうかには答えない。それに答えられるのは管理されたオンライン実験だけだ——十分なパワーがあり、非決定性をコントロールし、多重比較を補正している場合に限る。

## コンセプト

### evalとA/Bテスト

**eval** — オフライン、ラベル付きセット、判定（ルーブリック、LLM-as-judge、または人間）。答え：「この固定分布上で出力は正しい/役立つ/安全か？」

**A/Bテスト** — オンライン、ライブユーザー、ランダム化。答え：「新しいバリアントは重要なユーザーレベルのメトリクスを動かすか？」

両方が必要だ。evalはエクスポージャー前に後退を検出し、A/Bはリリース後のプロダクトインパクトを確認する。

### テストするもの

1. **プロンプトエンジニアリング** — 文言、システムプロンプトの構造、例。メトリクス：タスクの成功、ユーザーリテンション、リクエストあたりのコスト。
2. **モデル選択** — GPT-4対GPT-3.5-Turbo対Llama-OSS。メトリクス：精度（タスク）＋リクエストあたりのコスト＋レイテンシP99。多目的。
3. **生成パラメーター** — temperature、top-p、max_tokens。メトリクス：タスク固有（出力の多様性対決定論性）。

### CUPED — 分散削減

事前実験データを使ったコントロール実験（Controlled-experiments Using Pre-Experiment Data）。事後期間を比較する前に事前期間の分散を回帰して除く。典型的な分散削減：30〜70%。有効サンプルサイズが無料で上昇する。

実装：StatsigとGrowthBookの両方が実装している。

### 逐次テスト

従来のA/Bは固定サンプルサイズを想定している。逐次テスト（「覗き見と判断」）は繰り返し見る場合の偽陽性率をコントロールする。常に有効な逐次手続き（mSPRT、Howardの信頼シーケンス）は明確な勝者での早期停止を可能にする。

### 多重比較補正

95%信頼度で20件のA/Bテストを実行すると偶然に1件の偽陽性が生まれる。Bonferroni補正はテストごとにαを厳しくし、Benjamini-Hochbergは偽発見率をコントロールする。GrowthBookは両方を実装している。

### SRM — サンプル比率ミスマッチ

割り当てハッシュがユーザーをバリアントにランダム化する。50/50分割が47/53を配信した場合、何かが壊れている——SRMチェックがフラグを立てる。両プラットフォームが実装している。

### StatsigとGrowthBookの比較

**Statsig**：
- OpenAIが11億ドルで買収（2025年9月）。ホスト型SaaS。
- 逐次テスト、CUPED、ホールドアウト集団。
- オールインワン：フィーチャーフラグ＋実験＋オブザーバビリティ。
- 最適用途：バンドル製品を望むチーム、OpenAI所有を気にしない場合。

**GrowthBook**：
- オープンソース（MIT）；ウェアハウスネイティブ（Snowflake/BigQuery/Redshiftから直接読み込む）。
- 複数エンジン：Bayesian、Frequentist、逐次。
- CUPED、SRM、Bonferroni、BH補正。
- セルフホストまたはマネージドクラウド。
- 最適用途：ウェアハウスSQLショップ、データチームがメトリクス層をコントロール、OSSを望む場合。

### 非決定性はパワーを複雑にする

同じプロンプトが異なる出力を生む。従来のパワー計算はIID観察を想定している。LLMの非決定性では、有効サンプルサイズは名目より低い。安全マージンとして必要サンプルサイズに約1.3〜1.5倍を掛ける。

### 実際の事例結果

- チャットボット報酬モデルバリアント：会話の長さ+70%、リテンション+30%。
- Nextdoorの件名：報酬関数の改良後にCTR+1%。
- カーンアカデミーKhanmigo：レイテンシ対数学精度のトレードオフで反復。

### アンチパターン：感覚的判断でリリース

シニアエンジニアは誰でも「より良く感じる」という理由でA/Bなしでリリースされた機能の名前を挙げられる。その大部分はチームが数ヶ月間気づかなかったプロダクトメトリクスの後退をもたらした。A/Bは強制関数だ。

### 覚えておくべき数値

- StatsigのOpenAIによる買収：11億ドル、2025年9月。
- GrowthBook：オープンソースMIT；Bayesian＋Frequentist＋逐次。
- CUPEDの分散削減：30〜70%。
- LLMの非決定性 → +30〜50%のサンプルサイズバッファ。

## キーワード

| 用語 | よく言われる表現 | 実際の意味 |
|------|----------------|------------|
| Eval | 「オフラインテスト」 | モデルの能力のラベル付きセット評価 |
| A/B test | 「実験」 | ユーザーでのライブランダム化比較 |
| CUPED | 「分散削減」 | 分散を削減するための事前期間回帰 |
| Sequential test | 「覗き見OKテスト」 | 早期停止を可能にする常に有効な手続き |
| Multiple comparison | 「ファミリーエラー」 | 多くのテストの実行が偽陽性を膨らませる |
| Bonferroni | 「厳しい補正」 | テスト数でαを割る |
| Benjamini-Hochberg | 「BH FDR」 | 偽発見率コントロール、より保守的でない |
| SRM | 「悪い分割」 | サンプル比率ミスマッチ；割り当てバグ |
| Statsig | 「OpenAI所有」 | 商用オールインワン、2025年買収 |
| GrowthBook | 「OSSのもの」 | MITウェアハウスネイティブプラットフォーム |
| mSPRT | 「逐次確率比テスト」 | 古典的な逐次手続き |
