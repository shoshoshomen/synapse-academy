# 推論メトリクス — TTFT、TPOT、ITL、グッドプット、P99

> 4つのメトリクスが推論デプロイメントが機能しているかどうかを決める。TTFTはプリフィル + キュー + ネットワークだ。TPOT（ITLと同等）はトークンあたりのメモリバウンドデコードコストだ。エンドツーエンドレイテンシはTTFTにTPOT × 出力長を加えたものだ。スループットはフリート全体で集計されたトークン/秒だ。しかしプロダクトで重要なのはグッドプット — すべてのSLOを同時に満たしたリクエストの割合だ。グッドプットが低い高スループットは、時間どおりにユーザーに届かないトークンを処理していることを意味する。2026年のTRT-LLM上のLlama-3.1-8B-Instructの参照数値：平均TTFT 162ms、平均TPOT 7.33ms、平均E2E 1,093ms。P50、P90、P99を常に報告する — 平均だけは絶対にダメ。そして測定の罠に気をつける：GenAI-PerfはITL計算からTTFTを除外し、LLMPerfは含む。2つのツールが同じ実行で異なるTPOTを出す。


## 学習目標

- TTFT、TPOT、ITL、E2E、スループット、グッドプットを正確に定義し、各メトリクスが測定するコンポーネントを挙げる。
- LLM配信で平均が誤った統計である理由と、P50/P90/P99の読み方を説明する。
- SLOのマルチ制約（例：TTFT<500ms かつ TPOT<15ms かつ E2E<2s）を構築し、それに対してグッドプットを計算する。
- 同じ実行でTPOTについて意見が異なる2つのベンチマークツールを挙げ、その理由を説明する。

## 問題

「スループットは毎秒15,000トークンだ。」それで何？40%のリクエストが2秒のエンドツーエンドを超えたなら、ユーザーはセッションを中断した。スループットだけではプロダクトが機能しているかを教えてくれない。

推論にはレイテンシの複数の軸があり、それぞれ異なる方法で失敗する。プリフィルはコンピュートバウンドでプロンプト長に比例する。デコードはメモリバウンドでバッチサイズに比例する。キュー遅延は運用上の問題だ。ネットワークは物理的距離の問題だ。それぞれに対して別個のメトリクスが必要で、パーセンタイルが必要で、「ユーザーが期待するものを得たか」という単一の複合指標 — それがグッドプットだ。

## コンセプト

### TTFT — ファーストトークン時間

`TTFT = queue_time + network_request + prefill_time`

プロンプトが長い場合にプリフィルが支配する。H100上のLlama-3.3-70B FP8の32kプロンプトは純粋なプリフィルに約800msかかる。キュー時間は負荷下のスケジューラー動作だ。ネットワークリクエストはTLSを含むワイヤー時間だ。TTFTはユーザーが何かがストリームバックするまでに見るレイテンシだ。

### TPOT / ITL — インタートークンレイテンシ

1つの量のさまざまな名前。`TPOT`（タイムパーアウトプットトークン）、`ITL`（インタートークンレイテンシ）、`デコードレイテンシパートークン` — すべて同じものだ。最初のトークンの後にストリームされた連続トークン間の時間だ。

`TPOT = (decode_forward_time + scheduler_overhead) / tokens_produced`

同じLlama-3.3-70B H100スタックとチャンクプリフィルで、TPOT平均は約7ms。チャンクプリフィルなしで、隣のシーケンス上の長いプリフィル中にTPOTは50msに急上昇することがある。平均ではなくP99を見ること。

### E2Eレイテンシ

`E2E = TTFT + TPOT * output_tokens + network_response`

長い出力（>500トークン）ではE2EはTPOT支配。長いプロンプトを持つ短い出力ではE2EはTTFT支配。出力長条件付きE2Eを報告する。

### スループット

`throughput = total_output_tokens / elapsed_time`

集計メトリクス。フリート効率を教える。個別リクエストの健全性は教えない。

### グッドプット — 実際に重要なメトリクス

`goodput = (TTFT <= a) かつ (TPOT <= b) かつ (E2E <= c) を満たすリクエストの割合`

SLOはマルチ制約だ。リクエストはすべての制約が成立した場合のみ「良い」。グッドプットはその割合だ。60%グッドプットでの高スループットは失敗だ。99%グッドプットでの低スループットがターゲットだ。

2026年、グッドプットはMLPerf Inference v6.0の提出とAIプラットフォームプロバイダーの内部SLAトラッキングで使用されるメトリクスだ。

### 平均が誤った統計である理由

LLMレイテンシの分布は右に歪んでいる。長いプリフィルの隣人を持つデコードバッチは、TPOT約7msで500トークンと、TPOT約60msで20トークンを出荷することがある。平均TPOTは9ms。P99 TPOTは65ms。ユーザーはP99に定期的にぶつかる — それが離脱する理由だ。

常にトリプル（P50、P90、P99）を報告する。ユーザー体験においてP99が最適化する指標だ。

### 参照数値 — 2026年のTRT-LLM上のLlama-3.1-8B-Instruct

- 平均TTFT：162ms
- 平均TPOT：7.33ms
- 平均E2E：1,093ms
- P99 TPOT：チャンクプリフィル設定によって10〜25msで変動

これらはNVIDIAの公開参照ポイントだ。モデルサイズ（70Bでは3〜5倍）、ハードウェア（H100 vs B200で約3倍）、負荷で変化する。

### 測定の罠

最も多く使われる2026年のベンチマークツール2つが同じ実行でTPOTについて意見が異なる：

- **NVIDIA GenAI-Perf**：ITL計算からTTFTを除外する。ITLはトークン2から始まる。
- **LLMPerf**：TTFTを含む。ITLはトークン1から始まる。

TTFT 500ms、100出力トークンを700ms合計デコードのリクエストについて、GenAI-Perfは`ITL = 700/99 = 7.07ms`を報告し、LLMPerfは`ITL = 1200/100 = 12.00ms`を報告する。ツールの選択で数値が変わる。

常にどのツールかを明記する。常に定義を公開する。

### SLOの構築

2026年の70Bチャットモデルの合理的な消費者向けSLO：

- TTFT P99 <= 800ms
- TPOT P99 <= 25ms
- <300トークン出力に対してE2E P99 <= 3s
- グッドプットターゲット >= 99%

エンタープライズSLOはTTFTを厳しくし（200〜400ms）E2Eを緩める。ポイントはこれらを書き下し、3つすべてを測定し、グッドプットを単一の複合指標として追跡することだ。

### 測定方法

- 実際のトラフィックまたはリアリスティックな合成（LLMPerf with `--mean-input-tokens 800 --stddev-input-tokens 300 --mean-output-tokens 150`）を実行する。
- ベンチマーク実行には2倍のピーク並行を目標にする。
- 30〜50イテレーション実行し、結合サンプルのパーセンタイルを取る。
- ツール名、ツールバージョン、モデル、ハードウェア、並行数、プロンプト分布を一緒に公開する。

## キーワード

| 用語 | よく言われること | 実際の意味 |
|------|----------------|------------|
| TTFT | 「ファーストトークン時間」 | キュー + ネットワーク + プリフィル。長いプロンプトではプリフィルが支配 |
| TPOT | 「タイムパーアウトプットトークン」 | 最初のトークン後のトークンあたりのメモリバウンドデコードコスト |
| ITL | 「インタートークンレイテンシ」 | ほとんどのツールでTPOTと同じ（すべてではない — GenAI-Perfを参照） |
| E2E | 「エンドツーエンド」 | TTFT + TPOT × 出力長。上にレスポンス側ネットワーク |
| スループット | 「tok/s」 | フリート効率。レイテンシパーセンタイルなしでは無意味 |
| グッドプット | 「SLO達成率」 | すべてのSLO制約を同時に満たすリクエストの割合 |
| P99 | 「テール」 | 100回に1回の最悪ケースレイテンシ。ユーザー体験メトリクス |
| SLOマルチ制約 | 「結合」 | すべての3つのレイテンシ境界のAND。1つでも違反するとリクエストは失敗 |
| GenAI-Perf vs LLMPerf | 「ツールの罠」 | ITLがTTFTを含むかどうかでツールが意見が異なる |
