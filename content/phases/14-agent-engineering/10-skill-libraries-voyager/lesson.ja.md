# スキルライブラリと生涯学習（Voyager）

> Voyager（Wang et al.、TMLR 2024）は実行可能なコードをスキルとして扱う。スキルは名前付き、取得可能、合成可能で、環境フィードバックで精製される。これはClaude Agent SDKスキル、skillkit、2026年のスキルライブラリパターンのリファレンスアーキテクチャだ。


## 学習目標

- Voyagerの3つのコンポーネント—自動カリキュラム、スキルライブラリ、反復プロンプト—とそれぞれの役割に名前を付けられる。
- Voyagerがアクションスペースをプリミティブコマンドではなくコードにする理由を説明できる。
- 登録、取得、合成、失敗駆動の精製を持つstdlibスキルライブラリを実装できる。
- VoyagerのパターンをClaude Agent SDKの2026年スキルとskillkitエコシステムにマッピングできる。

## 課題

すべてのセッションで最初から能力を再構築するエージェントは3つのことを間違える:

1. **トークンを無駄にする。** すべてのタスクが同じ推論を再引き出しする。
2. **進捗を失う。** セッションAで学習した修正はセッションBに転送されない。
3. **長期的な合成に失敗する。** 複雑なタスクは能力の階層が必要だ; ワンショットのプロンプトはそれらを表現できない。

Voyagerの答え: 各再利用可能な能力を類似性で取得可能、他のスキルと合成可能、実行フィードバックで精製されるライブラリに保存された名前付きコードチャンクとして扱う。

## コンセプト

### 3つのコンポーネント

Voyager（arXiv:2305.16291）はエージェントを以下を中心に構造化する:

1. **自動カリキュラム。** 好奇心駆動の提案者はエージェントの現在のスキルセットと環境状態に基づいて次のタスクを選ぶ。探索はボトムアップだ。
2. **スキルライブラリ。** 各スキルは実行可能なコードだ。タスクが成功すると新しいスキルが追加される。スキルはクエリから説明への類似性で取得される。
3. **反復プロンプトメカニズム。** 失敗時、エージェントは実行エラー、環境フィードバック、自己検証出力を受け取り、スキルを精製する。

Minecraftの評価（Wang et al.、2024年）: ベースラインに対して3.3倍の一意アイテム、8.5倍速い石のツール、6.4倍速い鉄のツール、2.3倍長いマップ横断。数値はMinecraft固有だが、パターンは転送される。

### アクションスペース = コード

ほとんどのエージェントはプリミティブコマンドを出力する。Voyagerはジャバスクリプト関数を出力する。スキルは:

```
async function craftIronPickaxe(bot) {
  await mineIron(bot, 3);
  await mineStick(bot, 2);
  await placeCraftingTable(bot);
  await craft(bot, 'iron_pickaxe');
}
```

サブスキルから合成される。説明と埋め込みをキーとして保存される。プロンプトではなくプログラムとして取得される。

これが2026年のClaude Agent SDKスキルだ: エージェントが要求に応じてロードする名前付き、取得可能なコードと命令のチャンク。

### スキル取得

新しいタスク「ダイヤモンドのピッケルを作る」。エージェント:

1. タスクの説明を埋め込む。
2. top-k類似スキルのスキルライブラリをクエリする。
3. `craftIronPickaxe`、`mineDiamond`、`placeCraftingTable` などを取得する。
4. 取得したプリミティブ + 新しいロジックから新しいスキルを合成する。

これはMCPリソース（フェーズ13）とAgent SDKスキルが実装するパターンだ: 現在のタスクにスコープされた知識/コードサーフェスに対する取得。

### 反復的な精製

Voyagerのフィードバックループ:

1. エージェントがスキルを書く。
2. スキルが環境に対して実行される。
3. 3つのシグナルのうちの1つが返る: `success`、`error`（スタックトレースを持つ）、`self-verification failure`。
4. エージェントはシグナルをコンテキストとして使ってスキルを書き直す。
5. 成功または最大ラウンドまでループする。

これはSelf-Refine（レッスン05）を環境根拠の検証を持つコード生成に適用したものだ。CRITIC（レッスン05）は外部ツールを検証器として使う同じパターンだ。

### カリキュラムと探索

Voyagerのカリキュラムモジュールは、エージェントが持っているものとまだ行っていないことに基づいて「湖の近くに避難所を建てる」のようなタスクを提案する。提案者は環境状態 + スキルインベントリを使って現在の能力のすぐ上のタスクを選ぶ—探索のスイートスポット。

本番エージェントにとって、これは「不足しているもの」オペレーターに変換される: 現在のスキルライブラリとドメインが与えられた場合、何のスキルをまだカバーしていないか？チームは通常これをカリキュラムレビューとして手動で実装する。

### このパターンが間違いになる場所

- **スキルライブラリの腐敗。** わずかに異なる説明で同じスキルが10回追加される。書き込み時に重複排除を追加; 取得は1つのみを返す。
- **合成スキルのドリフト。** 親スキルは精製された子に依存する。スキルをバージョン管理する; v1にピンされた親はv3を魔法のように選択しない。
- **取得品質。** スキル説明に対するベクター取得は、ライブラリが数百を超えて成長するにつれ劣化する。タグフィルターとハードな制約（「`category=tooling` のスキルのみ」）で補完する。

## 実装する

`code/main.py` はstdlibスキルライブラリを実装している:

- `Skill` — 名前、説明、コード（文字列として）、バージョン、タグ、依存関係。
- `SkillLibrary` — 登録、検索（トークンオーバーラップ）、合成（deps のトポロジカルソート）、精製（更新時のバージョンバンプ）。
- 3つのプリミティブスキルを登録し、4番目を合成し、失敗にぶつかり、精製するスクリプト化エージェント。

実行:

```
python3 code/main.py
```

トレースはライブラリへの書き込み、取得、合成、失敗した実行、v2精製を示す—Voyagerのループをエンドツーエンドで。

## 使ってみる

- **Claude Agent SDKスキル**（Anthropic）— 2026年のリファレンス: 各スキルには説明、コード、命令がある; エージェントセッション中にオンデマンドでロードされる。
- **skillkit**（npm: skillkit）— 32以上のAIコーディングエージェント向けのクロスエージェントスキル管理。
- **カスタムスキルライブラリ** — ドメイン固有（データエージェントのためのSQLスキル、インフラエージェントのためのTerraformスキル）。Voyagerパターンはスケールダウンする。
- **OpenAI Agents SDKの`tools`** — 低端; 各ツールは軽量なスキルだ。

## 成果物を出す

`outputs/skill-skill-library.md` は、任意のターゲットランタイム向けに登録、取得、バージョン管理、精製を組み込んだVoyager形状のスキルライブラリを生成する。

## 演習

1. `compose()` に依存関係サイクル検出器を追加する。スキルAがBに依存し、BがAに依存する場合何が起こるか？エラー vs 警告？
2. スキルごとのバージョンピンニングを実装する。親スキルが子 `crafting@1` を合成する場合、`crafting@2` への精製は親を黙ってアップグレードしてはならない。
3. トークンオーバーラップ取得をsentence-transformers埋め込み（またはBM25 stdlib実装）に置き換える。50スキルのトイライブラリでretrieval@5を測定する。
4. 「カリキュラム」エージェントを追加する: 現在のライブラリとドメインの説明が与えられた場合、5つの不足しているスキルを提案する。週次で呼び出す。
5. AnthropicのClaude Agent SDKスキルのドキュメントを読む。トイライブラリをSDKのスキルスキーマにポートする。発見可能性について何が変わるか？

## キーワード

| 用語 | よく聞く言い方 | 実際の意味 |
|------|----------------|------------|
| Skill（スキル） | "再利用可能な能力" | 名前付きのコードチャンク + 説明、類似性で取得可能 |
| Skill library（スキルライブラリ） | "ハウツーのエージェントメモリ" | スキルの永続ストア、検索可能で合成可能 |
| Curriculum（カリキュラム） | "タスク提案者" | 現在の能力ギャップによって駆動されるボトムアップゴールジェネレーター |
| Composition（合成） | "スキルDAG" | スキルがスキルを呼び出す; 実行時のトポロジカルソート |
| Iterative refinement（反復的精製） | "自己修正ループ" | 環境フィードバック + エラー + 自己検証が次のバージョンに折り返される |
| Action-space-as-code（コードとしてのアクションスペース） | "プログラム的アクション" | 時間的に延長された動作のためにプリミティブコマンドではなく関数を出力 |
| Dedup on write（書き込み時の重複排除） | "スキルの折りたたみ" | ほぼ重複した説明は1つの標準的なスキルに折りたたまれる |
