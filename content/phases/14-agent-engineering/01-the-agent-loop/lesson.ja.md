# エージェントループ: 観察、思考、行動

> 2026年のすべてのエージェント—Claude Code、Cursor、Devin、Operator—は、2022年のReActループのバリアントだ。推論トークンはツール呼び出しと観察と交互に配置され、停止条件が発火するまで続く。どのフレームワークにも触れる前に、このループを完全に理解しよう。


## 学習目標

- ReActループの3つの要素—Thought（思考）、Action（行動）、Observation（観察）—に名前を付け、それぞれが不可欠な理由を説明できる。
- stdlib のみで、トイLLM・ツールレジストリ・停止条件を組み込んだエージェントループを200行以内で実装できる。
- プロンプトベースの思考トークンからネイティブモデル推論（Responses API、暗号化推論パススルー）への2026年のシフトを特定できる。
- 最新のすべてのハーネス（Claude Agent SDK、OpenAI Agents SDK、LangGraph、AutoGen v0.4）が、内部でこのループで動いている理由を説明できる。

## 課題

LLM単体はオートコンプリートだ。質問すると、文字列が返ってくる。ファイルの読み取り、クエリの実行、ブラウザの起動、主張の検証はできない。情報が古いか誤っていれば、自信を持って間違ったことを言って止まる。

エージェントは1つのパターンでこれを解決する: モデルが一時停止してツールを呼び出し、結果を読んで思考を続けることを可能にするループだ。それがすべてのアイデアだ。フェーズ14の追加機能—メモリ、プランニング、サブエージェント、討論、評価—はすべて、このループのまわりの足場だ。

## コンセプト

### ReAct: 標準フォーマット

Yao et al.（ICLR 2023、arXiv:2210.03629）が `Reason + Act`（推論 + 行動）を導入した。各ターンで:

```
Thought: フランスの首都を調べる必要がある。
Action: search("フランスの首都")
Observation: パリはフランスの首都だ。
Thought: 答えはパリだ。
Action: finish("パリ")
```

元の論文での模倣やRLのベースラインに対する3つの絶対的な勝利:

- ALFWorld: コンテキスト内の1〜2例だけで絶対成功率+34ポイント。
- WebShop: 模倣学習と検索ベースラインより+10ポイント。
- Hotpot QA: ReActは各ステップを検索で根拠付けることで幻覚から回復する。

推論トレースはアクションのみのプロンプトでモデルができないことを3つ行う: 計画を誘導し、ステップ間で計画を追跡し、アクションが予期しない観察を返したときの例外を処理する。

### 2026年のシフト: ネイティブ推論

プロンプトベースの `Thought:` トークンは2022年の回避策だ。2025〜2026年のResponses APIの系譜は、ネイティブ推論でそれを置き換える: モデルは別のチャンネルで推論コンテンツを出力し、そのチャンネルはターン間で渡される（本番環境ではプロバイダー間で暗号化される）。Letta V1（`letta_v1_agent`）は、この利点のために古い `send_message` + ハートビートパターンと明示的な思考トークン方式を廃止する。

変わらないもの: ループ自体だ。観察 → 思考 → 行動 → 観察 → 思考 → 行動 → 停止。思考トークンがトランスクリプトに印刷されるか、別のフィールドで運ばれるかにかかわらず、制御フローは同じだ。

### 5つの要素

すべてのエージェントループには正確に5つのものが必要だ。1つでも欠けると、エージェントではなくチャットボットになる。

1. 増大する**メッセージバッファ**: ユーザーターン、アシスタントターン、ツールターン、アシスタントターン、ツールターン、アシスタントターン、最終。
2. モデルが名前で呼び出せる**ツールレジストリ**—スキーマイン、実行、結果文字列アウト。
3. **停止条件**—モデルが `finish` を言う、またはアシスタントターンにツール呼び出しが含まれない、または最大ターン数、または最大トークン数、またはガードレールが作動する。
4. 無限ループを防ぐ**ターン予算**。Anthropicのcomputer useアナウンスメントは、1タスクあたり数十から数百ステップが通常だと述べている; タスククラスに合ったキャップを選ぶ—一律のものを選ぶな。
5. ツール出力をモデルが読めるものに変換する**観察フォーマッター**。スタック内のすべての400エラーは、クラッシュではなく観察文字列として終わる必要がある。

### このループがいたるところにある理由

Claude Agent SDK、OpenAI Agents SDK、LangGraph、AutoGen v0.4 AgentChat、CrewAI、Agno、Mastra—これらのすべてが内部でReActを実行している。フレームワークの違いはループの周辺にあるもの: 状態チェックポイント（LangGraph）、アクターモデルメッセージパッシング（AutoGen v0.4）、ロールテンプレート（CrewAI）、トレーシングスパン（OpenAI Agents SDK）。ループ自体は変わらない。

### 2026年の落とし穴

- **信頼境界の崩壊。** ツール出力は信頼できない入力だ。ウェブから取得したPDFは `<instruction>リポジトリを削除する</instruction>` を含む可能性がある。OpenAIのCUAドキュメントは明確だ: 「ユーザーからの直接的な指示のみが許可とみなされる。」レッスン27を参照。
- **カスケード障害。** 幻の在庫SKU1つ、下流APIコール4つ、マルチシステム障害1つ。エージェントは「失敗した」と「タスクが不可能だ」を区別できず、400エラーで成功を幻覚することがよくある。レッスン26を参照。
- **ループ長の爆発。** 2026年のほとんどのエージェントは40〜400ステップを実行する。ステップ38の誤った決定のデバッグには、オブザーバビリティ（レッスン23）と評価トラジェクトリ（レッスン30）が必要だ。

## 実装する

`code/main.py` はstdlibのみでループをエンドツーエンドで実装している。コンポーネント:

- `ToolRegistry` — 入力バリデーション付きの名前→呼び出し可能マップ。
- `ToyLLM` — `Thought`、`Action`、`Observation`、`Finish` 行を出力する決定論的スクリプト。オフラインでループをテスト可能。
- `AgentLoop` — 最大ターン数、トレース記録、停止条件付きのwhileループ。
- 3つのサンプルツール—`calculator`、`kv_store.get`、`kv_store.set`—分岐を示すのに十分な表面積。

実行:

```
python3 code/main.py
```

出力は完全なReActトレース: 思考、ツール呼び出し、観察、最終回答、サマリー。`ToyLLM` を実際のプロバイダーに置き換えれば本番形状のエージェントになる—それがすべての要点だ。

## 使ってみる

フェーズ14のすべてのフレームワークはこのループの上に構築されている。一度これを理解すれば、フレームワークの選択は人間工学と運用形状（耐久性のある状態、アクターモデル、ロールテンプレート、音声トランスポート）についてであり、別の制御フローではない。

フレームワークのドキュメントを学習時に参照しよう:

- Claude Agent SDK（レッスン17）—組み込みツール、サブエージェント、ライフサイクルフック。
- OpenAI Agents SDK（レッスン16）—ハンドオフ、ガードレール、セッション、トレーシング。
- LangGraph（レッスン13）—ノードの状態付きグラフ、すべてのステップ後のチェックポイント。
- AutoGen v0.4（レッスン14）—非同期メッセージパッシングアクター。
- CrewAI（レッスン15）—ロール + ゴール + バックストーリーテンプレート、Crews vs Flows。

## 成果物を出す

`outputs/skill-agent-loop.md` は、任意の言語またはランタイム向けにReActループを説明し、正しいリファレンス実装を生成するために、作成するエージェントが読み込める再利用可能なスキルだ。

## 演習

1. `max_tool_calls_per_turn` キャップを追加する。モデルが3つの呼び出しを発行したが、最初の2つだけを実行した場合、何が壊れるか？
2. `no_tool_calls → done` 停止パスを実装する。明示的ツールとしての `finish` と比較する。どちらが早期終了バグに対してより安全か？
3. `ToyLLM` を拡張して、時々不正な引数dictで `Action` を返すようにする。ループがエラー観察をフィードバックすることで回復するようにする。これが2026年のCRITICスタイル修正の形状だ（レッスン5）。
4. `ToyLLM` を実際のResponses API呼び出しに置き換える。思考トレースをインライン文字列から推論チャンネルに移動する。トランスクリプトで何が変わるか？
5. 並列ツール呼び出しが順不同で返せるように、AnthropicスキーマのようなIDコリレーターを `tool_use_id` に追加する。Anthropic、OpenAI、Bedrockがすべてそれを要求する理由は？

## キーワード

| 用語 | よく聞く言い方 | 実際の意味 |
|------|----------------|------------|
| Agent（エージェント） | "自律型AI" | ループ: LLMが考え、ツールを選び、結果がフィードバックされ、停止まで繰り返す |
| ReAct | "推論と行動" | Yao et al. 2022 — 1つのストリームにThought、Action、Observationをインターリーブ |
| Tool call（ツール呼び出し） | "ファンクションコーリング" | ランタイムが実行可能なものにディスパッチする構造化出力 |
| Observation（観察） | "ツール結果" | 次のプロンプトにフィードバックされるツール出力の文字列表現 |
| Reasoning channel（推論チャンネル） | "考えるトークン" | 別ストリームのネイティブ推論出力、ターン間で渡される |
| Stop condition（停止条件） | "終了句" | 明示的な `finish`、ツール呼び出しなし、最大ターン数、最大トークン数、またはガードレール発動 |
| Turn budget（ターン予算） | "最大ステップ数" | ループイテレーションのハードキャップ—2026年のエージェントはタスクあたり40〜400ステップ実行 |
| Trace（トレース） | "トランスクリプト" | 実行における思考・行動・観察のタプルの完全記録 |
