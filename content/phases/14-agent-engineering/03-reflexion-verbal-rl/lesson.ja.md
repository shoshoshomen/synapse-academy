# Reflexion: 言語的強化学習

> 勾配ベースのRLは、ある失敗モードを修正するのに数千回の試行とGPUクラスターが必要だ。Reflexion（Shinn et al.、NeurIPS 2023）は自然言語でそれを行う: 各失敗試行の後、エージェントはリフレクションを書き、エピソードメモリに保存し、次の試行でそのメモリを条件付けにする。これはLettaのsleep-time compute、Claude CodeのCLAUDE.mdの学習、pro-workflowのlearn-ruleの背後にあるパターンだ。


## 学習目標

- Reflexionの3つのコンポーネント（Actor、Evaluator、Self-Reflector）とエピソードメモリの役割に名前を付けられる。
- 二値評価器、リフレクションバッファ、新鮮な再試行を持つstdlib Reflexionループを実装できる。
- 特定のタスクに対してスカラー、ヒューリスティック、自己評価のフィードバックソースの中から選択できる。
- 言語的強化がなぜ勾配ベースのRLが修正するのに数千回の試行が必要なエラーを捕捉できるかを説明できる。

## 課題

エージェントがタスクに失敗する。標準的なRLでは、数千回の試行を実行し、勾配を計算し、重みを更新する。コストがかかり、時間がかかり、ほとんどの本番エージェントにはすべての失敗に対するトレーニング予算がない。

Reflexion（Shinn et al.、arXiv:2303.11366）は別の質問をする: エージェントが失敗した理由について考え、次回はその思考をプロンプトに入れて試みたらどうなるか？重みの更新なし。勾配なし。ただ試行間に保存される自然言語だけ。

結果: ALFWorldではReActや他の非ファインチューンベースラインに勝る。HotpotQAではReActより改善する。コード生成（HumanEval/MBPP）ではその時点での最先端を設定する。1つの勾配ステップなしで。

## コンセプト

### 3つのコンポーネント

```
Actor         : トラジェクトリを生成する（ReActスタイルループ）
Evaluator     : トラジェクトリをスコアリングする—二値、ヒューリスティック、または自己評価
Self-Reflector: 失敗に関する自然言語のリフレクションを書く
```

1つのデータ構造を追加:

```
Episodic memory: 以前のリフレクションのリスト、次の試行のプロンプトに先付けされる
```

1回の試行でActorを実行する。Evaluatorがスコアリングする。スコアが低い場合、Self-Reflectorがリフレクションを生成する（「Xについて尋ねているのにYについて尋ねていると読み誤ったため間違ったツールを選んだ」）。リフレクションはエピソードメモリに入る。次の試行は新鮮に始まるが、リフレクションを見る。

### 3つの評価器タイプ

1. **スカラー** — 外部の二値シグナル。ALFWorldは成功か失敗か。HumanEvalのテストは通るか失敗か。最もシンプルで、最も高いシグナル。
2. **ヒューリスティック** — 事前定義された失敗シグネチャ。「エージェントが連続して同じアクションを2回生成した場合、スタックとしてマークする。」「トラジェクトリが50ステップを超えた場合、非効率としてマークする。」
3. **自己評価** — LLMが自分のトラジェクトリをスコアリングする。グラウンドトゥルースが利用できない場合に必要。シグナルが弱い; ツール根拠の検証（レッスン05—CRITIC）と組み合わせると良い。

2026年のデフォルトはミックスだ: 利用可能な場合はスカラー、そうでない場合は自己評価、ヒューリスティックをセーフティレールとして。

### なぜこれが一般化するか

Reflexionは新しいアルゴリズムというよりも命名されたパターンだ。ほぼすべての本番「自己修復」エージェントは何らかのバリアントを実行している:

- Lettaのsleep-time compute（レッスン08）: 別のエージェントが過去の会話を振り返り、メモリブロックに書き込む。
- Claude Codeの`CLAUDE.md` / 「メモリを保存する」パターン: 将来のセッションに先付けされる学習としてキャプチャされたリフレクション。
- pro-workflowの`/learn-rule`コマンド: 明示的なルールとしてキャプチャされた修正。
- LangGraphのリフレクションノード: 出力をスコアリングし、必要に応じて精製にルーティングするノード。

すべてが同じ洞察から派生している: 自然言語は実行間で「失敗から学んだこと」を運ぶのに十分なほどリッチなメディアだ。

### 機能する場合と機能しない場合

Reflexionが機能する場合:

- 明確な失敗シグナルがある（テスト失敗、ツールエラー、誤った回答）。
- タスククラスが再現可能（同じタイプの質問を再び尋ねることができる）。
- リフレクションがトラジェクトリを改善する余地がある（十分なアクション予算）。

Reflexionが役に立たない場合:

- エージェントが最初の試行で成功する。
- 失敗が外部的だ（ネットワークダウン、ツール壊れている）—「ネットワークがダウンしていた」についてのリフレクションは将来の実行に役立たない。
- リフレクションが迷信になる—一度限りのフレーキーな実行に関する物語を保存する。

2026年の落とし穴: メモリ腐敗。リフレクションが蓄積し、一部は古くなったり間違っていたりする; 再実行はエピソードバッファが増大するにつれ遅くなる。軽減策: 定期的な圧縮（レッスン06）、リフレクションのTTL、または別のsleep-timeクリーンアップエージェント（Letta）。

## 実装する

`code/main.py` はトイパズルでReflexionを実装している: 目標値に合計する3要素リストを生成する。ActorはリストI候補を出力し、EvaluatorはSumをチェックし、Self-Reflectorは何が間違っていたかを1行で書く。リフレクションは次の試行のエピソードメモリに入る。

コンポーネント:

- `Actor` — リフレクションを見ると改善するスクリプト化ポリシー。
- `Evaluator.binary()` — 目標値に対するパス/フェイル。
- `SelfReflector` — 失敗の1行診断を生成する。
- `EpisodicMemory` — TTLセマンティクスを持つ境界付きリスト。

実行:

```
python3 code/main.py
```

トレースは3つの試行を示す。試行1が失敗し、リフレクションが保存され、試行2はリフレクションを見て改善するが失敗し、試行3は成功する。ベースライン実行（リフレクションなし）と比較する—試行1の回答にスタックしたままだ。

## 使ってみる

LangGraphはリフレクションをノードパターンとして出荷する。Claude Codeの`/memory`コマンドとpro-workflowの`/learn-rule`はエピソードバッファをmarkdownファイルとして外部化する。Lettaのsleep-time computeはSelf-Reflectorをダウンタイムに実行し、プライマリエージェントはレイテンシ制約のままになる。OpenAI Agents SDKはReflexionを直接出荷しない; スコアでトラジェクトリを拒否するカスタムGuardrailと実行間で生き残るメモリ`Session`でそれを構築する。

## 成果物を出す

`outputs/skill-reflexion-buffer.md` は、リフレクションキャプチャ、TTL、および重複排除を持つエピソードバッファを作成および維持する。タスククラスと失敗が与えられると、次の試行に実際に役立つリフレクション（汎用的な「もっと注意する」ではない）を出力する。

## 演習

1. 距離メトリクスを返すスカラー評価器（目標からどれだけ遠いか）に切り替える。より速く収束するか？
2. リフレクションにTTLを10試行追加する。その後、古いリフレクションは役立つか、それとも害になるか？
3. ヒューリスティック評価器を実装する: 同じアクションが繰り返す場合、試行をスタックとしてマークする。これはSelf-Reflectorとどのように相互作用するか？
4. リフレクションを無視する敵対的なActorでReflexionを実行する。Actorにそれらに気付かせる最小限のリフレクションプロンプトエンジニアリングは何か？
5. AlfWorldでのReflexion論文のセクション4を読む。130%の成功率改善を概念的に再現する: バニラReActと比べた主要なデルタは何か？

## キーワード

| 用語 | よく聞く言い方 | 実際の意味 |
|------|----------------|------------|
| Reflexion | "自己修正" | Shinn et al. 2023 — Actor、Evaluator、Self-Reflector + エピソードメモリ |
| Verbal reinforcement（言語的強化） | "勾配なしの学習" | 次の試行のプロンプトに先付けされる自然言語のリフレクション |
| Episodic memory（エピソードメモリ） | "タスクごとのリフレクション" | 1つのタスククラスのための以前のリフレクションの境界付きバッファ |
| Scalar evaluator（スカラー評価器） | "二値成功シグナル" | グラウンドトゥルースからのパス/フェイルまたは数値スコア |
| Heuristic evaluator（ヒューリスティック評価器） | "パターンベース検出器" | 事前定義された失敗シグネチャ（スタックループ、多すぎるステップなど） |
| Self-evaluator（自己評価器） | "自分のトレースに対するLLMジャッジ" | グラウンドトゥルースがない場合の低シグナルフォールバック—ツール根拠の検証と組み合わせる |
| Memory rot（メモリ腐敗） | "古いリフレクション" | エピソードバッファが古いエントリで埋まる; 圧縮/TTLで修正 |
| Sleep-time reflection（sleep-timeリフレクション） | "非同期自己リフレクション" | ホットパス外でSelf-Reflectorを実行し、プライマリエージェントを高速に保つ |
