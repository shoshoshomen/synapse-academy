# ハイブリッドメモリ: ベクター + グラフ + KV（Mem0）

> Mem0（Chhikara et al.、2025）はメモリを3つの並列ストアとして扱う—ベクターは意味的類似性、KVは高速なファクトルックアップ、グラフはエンティティ関係の推論のため。スコアリングレイヤーが取得時に3つを融合する。これが外部メモリの2026年の本番標準だ。


## 学習目標

- 単一のストア（ベクターのみ、グラフのみ、KVのみ）がエージェントメモリに不十分な理由を説明できる。
- Mem0の3つの並列ストアとそれぞれが最適化するものに名前を付けられる。
- Mem0の融合スコアリング—関連性、重要性、最新性—とそれが階層ではなく重み付き合計である理由を説明できる。
- すべての3つに書き込む `add()` と結果を融合する `search()` を持つstdlibでトイ3ストアメモリを実装できる。

## 課題

1つのストアは3つのクエリクラスの1つで間違っている:

- **意味的類似性** — 「先週エージェントドリフトについて何を議論したか？」ベクターが勝つ; KVとグラフは見逃す。
- **ファクトルックアップ** — 「ユーザーの電話番号は何か？」KVが勝つ; ベクターは無駄、グラフは過剰。
- **関係推論** — 「同じ請求エンティティを共有する顧客は？」グラフが勝つ; ベクターとKVは答えられない。

本番エージェントは1つのセッションで3つすべてを発行する。シングルストアのメモリは常にそのうち2つで間違っている。Mem0の貢献は、融合するスコアリング関数を持つ単一の `add`/`search` サーフェスの後ろにすべての3つを配線することだ。

## コンセプト

### 並列での3つのストア

Mem0（arXiv:2504.19413、2025年4月）は `add(text, user_id, metadata)` で:

1. テキストから候補ファクトを抽出する（LLM駆動のステップ）。
2. 各ファクトを意味的検索のためにベクターストアに書き込む（埋め込み）。
3. 各ファクトをO(1)ルックアップのためにKVストアに（user_id、fact_type、entity）をキーとして書き込む。
4. 各ファクトをグラフストア（Mem0g）に関係クエリのための型付きエッジとして書き込む。

`search(query, user_id)` で:

1. ベクターストアが埋め込みコサインでtop-kを返す。
2. KVストアがクエリから導出した（user_id、type、entity）にキーとした直接ヒットを返す。
3. グラフストアがクエリエンティティから到達可能なサブグラフを返す。
4. スコアリングレイヤーが3つを融合する。

### 融合スコアリング

```
score = w_relevance * relevance(q, record)
      + w_importance * importance(record)
      + w_recency * recency(record)
```

- **関連性** — ベクターコサイン、KV完全一致、グラフパス重み。
- **重要性** — 書き込み時にタグ付けまたは学習（一部のファクトはより重要: 名前、ID、ポリシー）。
- **最新性** — 最後の書き込みまたは読み取りからの時間に対する指数減衰。

ウェイトは製品ごとにチューニングされる。チャットエージェントには高い `w_recency`; コンプライアンスエージェントには高い `w_importance`; 取得エージェントには高い `w_relevance`。

### Mem0gと時間的推論

Mem0gは競合検出器を追加する。新しいファクトが既存のエッジと矛盾する場合、既存のエッジは無効としてマークされるが削除されない。時間的クエリ（「3月時点でのユーザーの都市は？」）はvalid-at-timeサブグラフをトラバースする。

これはLettaの無効化パターンが一般化するコンプライアンスグレードの動作だ。

### ベンチマーク数値

Mem0論文が報告する（2025年）:

- **LoCoMo**（長文会話メモリ）: 91.6
- **LongMemEval**（長期エピソードメモリ）: 93.4
- **BEAM 1M**（1Mトークンメモリベンチマーク）: 64.1

比較ベースライン（フルコンテキスト128k LLM、フラットベクターストア、フラットKV）はすべて10ポイント以上差をつけられる。ベンチマークだけでは選択を正当化しない—運用形状が正当化する—が、数値は融合設計が丸め誤差でないことを示す。

### スコープ分類

Mem0はスコープごとにメモリを分割する:

- **ユーザーメモリ** — セッション間で永続、`user_id` にキーイング。
- **セッションメモリ** — 1つのスレッド内で永続。
- **エージェントメモリ** — エージェントインスタンスごとの状態。

すべての書き込みは1つのスコープを選ぶ。取得はスコープごとのウェイトでスコープを横断してクエリできる。考えずにスコープを混在させることが「アシスタントがBobのプロジェクトについてAliceに話した」事件の原因だ。

### このパターンが間違いになる場所

- **埋め込みドリフト。** 最初の数百クエリで正しく見えるベクター結果は、コーパスが成長するにつれ劣化する。最もよく使用されるレコードのtop-Nの定期的な再埋め込みを追加する。
- **KVスキーマクリープ。** `(user_id、type、entity)` は各チームが独自の `type` を追加するまで単純に見える。タイプセットを四半期ごとに監査する。
- **グラフの爆発。** ノイジーな抽出器がメッセージごとに50のエッジを追加する。`add` 呼び出しごとのグラフ書き込みをキャップ; 低信頼度のエッジを削除する。

## 実装する

`code/main.py` はstdlibで3ストアパターンを実装している:

- `VectorStore` — 埋め込みスタンドインとしてナイーブなトークンオーバーラップ類似性。
- `KVStore` — `(user_id、fact_type、entity)` にキーイングされたdict。
- `GraphStore` — 型付きエッジ（subject、relation、object、valid）。
- `Mem0` — `add()`、`search()`、融合スコアリング、スコープ対応取得を持つトップレベルファサード。
- マルチユーザー、マルチセッション会話でのワークトレース。

実行:

```
python3 code/main.py
```

出力は3つの別々のリコールパスと融合されたtop-kを示す。`main()` の上部でスコアリングウェイトを反転させてランキングの変化を観察する。

## 使ってみる

- **Mem0（Apache 2.0）** — 本番対応。Postgres + Qdrant + Neo4jでセルフホスト、またはマネージドクラウドを使用。
- **Letta** — 3層コア/リコール/アーカイブ; 独自のベクターとグラフバックエンドを持ち込む。
- **Zep** — 時間的KGとファクト抽出を持つ商用代替。
- **カスタムビルド** — 抽出器（コンプライアンス）または融合ウェイト（最新性が支配する音声エージェント）を正確に制御する必要がある場合。

## 成果物を出す

`outputs/skill-hybrid-memory.md` は、融合スコアラー、スコープ分類、時間的無効化を組み込んだ3ストアメモリスキャフォールドを生成する。

## 演習

1. トイベクター類似性を実際の埋め込みモデル（sentence-transformers、Ollama、OpenAI埋め込み）に置き換える。合成長会話でrecall@10を測定する。1000回の書き込みでランキングはドリフトするか？
2. 時間的クエリを追加する: `search(query, as_of=timestamp)`。その時間以前に有効なレコードのみを返す。どのストアが最も作業が必要か？
3. 競合検出器を実装する: 入力ファクトがグラフエッジと矛盾する場合、古いエッジを無効にして両方をログする。「ユーザーはベルリンに住んでいる」->「ユーザーはリスボンに住んでいる」でテストする。
4. 融合スコアラーに `user_feedback` 次元（取得されたレコードへの親指アップ）を追加するようにポートする。ゲームプレイを防ぐ方法は（エージェントが既にいいねしたレコードのみを返す）？
5. Mem0ドキュメント（`docs.mem0.ai`）を読む。トイを `mem0` クライアント呼び出しにポートする。同じ20のテストクエリで取得品質を比較する。

## キーワード

| 用語 | よく聞く言い方 | 実際の意味 |
|------|----------------|------------|
| Hybrid memory（ハイブリッドメモリ） | "ベクター + グラフ + KV" | 並列で書き込まれ、取得時に融合される3つのストア |
| Fact extraction（ファクト抽出） | "メモリインジェスト" | テキストを（entity、relation、fact）タプルに分解するLLMステップ |
| Fusion scoring（融合スコアリング） | "関連性ランキング" | 関連性、重要性、最新性の重み付き合計 |
| Scope（スコープ） | "メモリ名前空間" | ユーザー / セッション / エージェント — 誰が何を見るかを決定 |
| Mem0g（メモリグラフ） | "メモリグラフ" | 関係クエリのための時間的有効性を持つ型付きエッジ |
| Temporal invalidation（時間的無効化） | "ソフト削除" | 矛盾したエッジを無効としてマーク; 削除しない |
| Embedding drift（埋め込みドリフト） | "取得の腐敗" | コーパスが成長するにつれベクター品質が劣化; 定期的に再埋め込みする |
