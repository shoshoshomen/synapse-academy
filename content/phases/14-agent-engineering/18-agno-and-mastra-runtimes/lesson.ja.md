# Agno と Mastra: 本番ランタイム

> Agno（Python）と Mastra（TypeScript）は 2026 年の本番ランタイムペアリングです。Agno はマイクロ秒レベルのエージェントインスタンス化とステートレス FastAPI バックエンドを目指しています。Mastra は Vercel AI SDK 基盤の上で、エージェント、ツール、ワークフロー、統合モデルルーティング、コンポジットストレージを提供します。


## 学習目標

- Agno のパフォーマンスターゲットと、それが重要になる場面を特定できる。
- Mastra の3つのプリミティブ（Agents、Tools、Workflows）とサポートされているサーバーアダプターを説明できる。
- なぜステートレスなセッションスコープの FastAPI バックエンドが Agno の推奨本番パスなのかを説明できる。
- 指定されたスタック（Python ファーストか TypeScript ファーストか）に対して Agno か Mastra かを選択できる。

## 問題設定

LangGraph、AutoGen、CrewAI はフレームワークが重い。「エージェントループだけが欲しい、速く、自分のランタイムで」というチームは Agno（Python）または Mastra（TypeScript）に手を伸ばします。どちらもフレームワーク所有のプリミティブのいくつかをトレードして、生速度と周辺スタックへのより緊密なフィットを得ています。

## コンセプト

### Agno

- Python ランタイム。元は Phi-data。
- 「グラフなし、チェーンなし、複雑なパターンなし — 純粋な Python だけ。」
- ドキュメントに記載されたパフォーマンスターゲット: エージェントインスタンス化 約 2μs、エージェントあたり 約 3.75 KiB、約 23 のモデルプロバイダー。
- 本番パス: ステートレスなセッションスコープの FastAPI バックエンド。各リクエストで新鮮なエージェントを開始し、セッション状態は DB に保存。
- ネイティブなマルチモーダル（テキスト、画像、音声、動画、ファイル）とエージェンティック RAG。

速度ターゲットは、1秒間に何千もの短命なエージェントを持つ場合（チャットのファンイン、評価パイプライン）に重要です。1つのエージェントが10分間実行する場合には重要ではありません。

### Mastra

- TypeScript。Vercel AI SDK 上に構築。
- 3つのプリミティブ: **Agents**、**Tools**（Zod 型付き）、**Workflows**。
- 統合モデルルーター — 94 のプロバイダー全体で 3,300 以上のモデル（2026年3月）。
- コンポジットストレージ: メモリ、ワークフロー、オブザーバビリティを異なるバックエンドに。大規模なオブザーバビリティには ClickHouse が推奨。
- Apache 2.0。ただし `ee/` ディレクトリはソース利用可能エンタープライズライセンス下。
- Express、Hono、Fastify、Koa 用のサーバーアダプター。Next.js と Astro の第一級統合。
- デバッグ用の Mastra Studio（localhost:4111）を同梱。
- 22k 以上の GitHub スター、1.0（2026年1月）で週間 npm ダウンロード 30 万以上。

### ポジショニング

どちらも LangGraph になろうとしていません。競争する軸:

- **言語フィット.** Python ファーストのチームには Agno。TypeScript ファーストには Mastra。
- **ランタイムエルゴノミクス.** Agno = ほぼゼロオーバーヘッド。Mastra = Vercel エコシステムとの統合。
- **オブザーバビリティ.** どちらも Langfuse/Phoenix/Opik（レッスン24）と統合しますが、Mastra Studio はファーストパーティです。

### どちらを選ぶか

- **Agno** — Python バックエンド、多数の短命なエージェント、強いパフォーマンス要件、FastAPI ショップ。
- **Mastra** — TypeScript バックエンド、Next.js / Vercel デプロイ、統合マルチプロバイダーモデルルーティング、Zod 型付きツール。
- **LangGraph**（レッスン13）— durable な状態と明示的なグラフ推論が生速度より重要な場合。
- **OpenAI / Claude Agent SDK** — プロバイダーの製品化された形状が欲しい場合（レッスン16〜17）。

### このパターンが失敗するケース

- **パフォーマンスのためのパフォーマンス.** ワークロードがリクエストあたり1つの遅いエージェント呼び出しで、オーバーヘッドがボトルネックでない場合に「2μs」という理由で Agno を選ぶ。
- **エコシステムロックイン.** Mastra の Vercel 寄りの統合は Vercel では利点、それ以外では欠点。
- **エンタープライズライセンスの混乱.** Mastra の `ee/` ディレクトリはソース利用可能であり、Apache 2.0 ではありません。フォークを計画している場合はライセンスを読んでください。

## 実装する

このレッスンは主に比較的です — 1つのコードアーティファクトで両フレームワークを公平に示すことはできません。`code/main.py` には並列の玩具実装があります: 「エージェントを実行し、出力をストリームし、セッションを永続化する」フローを2回実装（Agno 形状と Mastra 形状で1回ずつ）。

実行:

```
python3 code/main.py
```

構造的には異なりますが機能的に等価な2つのトレース。

## 使ってみる

- **Agno** — 速度と FastAPI 形状が必要な Python バックエンド。
- **Mastra** — 多数のプロバイダーとワークフロープリミティブを持つ TypeScript バックエンド。
- どちらもファーストパーティのオブザーバビリティフックを搭載。どちらも Langfuse と統合。

## 成果物を出す

`outputs/skill-runtime-picker.md` はスタック、レイテンシ予算、運用形状に基づいて Agno、Mastra、LangGraph、またはプロバイダー SDK を選択します。

## 演習

1. Agno のドキュメントを読みます。標準ライブラリの ReAct ループ（レッスン01）を Agno に移植します。何が消えましたか？何が残りましたか？
2. Mastra のドキュメントを読みます。同じループを Mastra に移植します。ツール型付け（Zod vs なし）は何が変わりましたか？
3. ベンチマーク: 自分のスタックでエージェントインスタンス化のレイテンシを計測します。Agno の 2μs は自分のワークロードに重要ですか？
4. 移行の設計: CrewAI を Python で実行してきた場合、Agno に移動すると何が壊れますか？
5. Mastra の `ee/` ライセンス条件を読みます。オープンソースのフォークに影響する制限はありますか？

## キーワード

| 用語 | 一般的な言い方 | 実際の意味 |
|------|----------------|------------|
| Agno | "高速な Python エージェント" | ステートレスなセッションスコープのエージェントランタイム |
| Mastra | "Vercel AI SDK 上の TypeScript エージェント" | Agents + Tools + Workflows + モデルルーター |
| 統合モデルルーター | "マルチプロバイダーアクセス" | 94 のプロバイダー全体で 3,300 以上のモデルを持つ単一クライアント |
| コンポジットストレージ | "複数バックエンド" | メモリ・ワークフロー・オブザーバビリティをそれぞれ異なるストアに |
| Mastra Studio | "ローカルデバッガー" | エージェントを内省するための localhost:4111 UI |
| ソース利用可能 | "OSS ではない" | ライセンスはソースの閲覧を許可するが商用利用を制限する |
