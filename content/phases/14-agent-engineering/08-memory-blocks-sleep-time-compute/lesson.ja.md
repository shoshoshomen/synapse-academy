# メモリブロックとSleep-Time Compute（Letta）

> MemGPTは2024年にLettaになった。2026年の進化は2つのアイデアを追加する: モデルが直接編集できる離散的な機能的メモリブロックと、プライマリエージェントがアイドル中に非同期でメモリを統合するsleep-timeエージェント。これが1つの会話を超えてメモリをスケールする方法だ。


## 学習目標

- Lettaが使用する3つのメモリ層（コア、リコール、アーカイブ）とそれぞれの役割に名前を付けられる。
- メモリブロックパターンを説明できる: ヒューマンブロック、ペルソナブロック、ユーザー定義ブロックをファーストクラスの型付きオブジェクトとして。
- sleep-time computeとは何か、なぜクリティカルパスから外れているか、プライマリエージェントよりも強いモデルを実行できる理由を説明できる。
- プライマリエージェントがレスポンスを提供し、sleep-timeエージェントがターン間でブロックを統合するスクリプト化された2エージェントループを実装できる。

## 課題

MemGPT（レッスン07）は仮想メモリの制御フローを解決した。3つの本番問題が出現した:

1. **レイテンシ。** すべてのメモリ操作がクリティカルパスにある。エージェントがユーザーが待っている間にプルーン、サマライズ、または調整しなければならない場合、テールレイテンシが爆発する。
2. **メモリ腐敗。** 書き込みが蓄積する。矛盾した事実が残る。取得が古いコンテンツに溺れる。
3. **構造の損失。** フラットなアーカイブストアは「ヒューマンブロックは常にプロンプトにある; ペルソナブロックは常にプロンプトにある; タスクブロックはセッションごとに交換される」を表現できない。

Letta（letta.com）は2026年のリライトだ。メモリブロックは構造を明示的にし; sleep-time computeは統合をクリティカルパスから外す。

## コンセプト

### 3つの層

| 層 | スコープ | どこにあるか | 誰が書くか |
|------|-------|----------------|------------|
| コア | 常に見える | メインプロンプト内 | エージェントツール呼び出し + sleep-timeリライト |
| リコール | 会話履歴 | 取得可能 | 自動ターンログ |
| アーカイブ | 任意の事実 | ベクター + KV + グラフ | エージェントツール呼び出し + sleep-timeインジェスト |

コアはMemGPTのコアだ。リコールは退避された末尾を持つ会話バッファだ。アーカイブは外部ストアだ。この分割はMemGPTの2層の過負荷をきれいにする。

### メモリブロック

ブロックはコア層の型付き、永続的、編集可能なセクションだ。元のMemGPT論文は2つを定義した:

- **ヒューマンブロック** — ユーザーについての事実（名前、役割、好み、目標）。
- **ペルソナブロック** — エージェントの自己概念（アイデンティティ、トーン、制約）。

Lettaは任意のユーザー定義ブロックに一般化する: 現在の目標のための `Task` ブロック、コードベースの事実のための `Project` ブロック、ハードな制約のための `Safety` ブロック。各ブロックは `id`、`label`、`value`、`limit`（文字キャップ）、`description`（モデルがいつ編集するかを知るように）を持つ。

ブロックはツール表面を介して編集可能:

- `block_append(label, text)`
- `block_replace(label, old, new)`
- `block_read(label)`
- `block_summarize(label)` — リミット近くのブロックを凝縮する。

### Sleep-time compute

2025年のLettaの追加: クリティカルパスから外れた、バックグラウンドで第2エージェントを実行する。Sleep-timeエージェントは会話トランスクリプトとコードベースのコンテキストを処理し、`learned_context` を共有ブロックに書き込み、アーカイブレコードを統合または無効化する。

出てくる特性:

- **レイテンシコストなし。** プライマリレスポンスはメモリ操作を待たない。
- **より強いモデルが許可される。** sleep-timeエージェントはレイテンシ制約がないため、より高価で遅いモデルを使用できる。
- **自然な統合ウィンドウ。** ユーザーが待っていない間に重複排除、サマライズ、矛盾した事実の無効化。

形状は人間の働き方に一致する: タスクをこなし、眠り、長期記憶は一晩かけて定着する。

### Letta V1とネイティブ推論

Letta V1（`letta_v1_agent`、2026年）は `send_message`/ハートビートとインラインの `Thought:` トークンを廃止し、ネイティブ推論の利点のために。Responses API（OpenAI）とextended thinkingを持つMessages API（Anthropic）は別のチャンネルで推論を出力し、ターン間で渡される（本番環境ではプロバイダー間で暗号化）。コントロールループは依然としてReActだ。思考トレースは構造的であり、プロンプト形状ではない。

### このパターンが間違いになる場所

- **ブロックの膨張。** 無限の `block_append` はすぐにリミットに達する。キャップを超えて押し込む書き込みの前にブロックサマライザーを配線する。
- **サイレントドリフト。** Sleep-timeエージェントがブロックを書き直し、プライマリエージェントが気づかない。ブロックをバージョン管理し、トレースにdiffを表示する。
- **汚染された統合。** Sleep-timeエージェントが攻撃者がアクセスできるコンテンツをコアに処理する。レッスン27はsleep-timeサーフェスにも適用される。

## 実装する

`code/main.py` は以下を実装している:

- `Block` — id、label、value、limit、description。
- `BlockStore` — CRUD + `near_limit(label)` ヘルパー。
- 2つのスクリプト化エージェント — `PrimaryAgent` がターンを提供し、`SleepTimeAgent` がターン間で統合する。
- ブロック書き込みを持つ3ターンの会話を示すトレース、plus古い事実を要約して無効化するsleepパス。

実行:

```
python3 code/main.py
```

トランスクリプトは分割を示す: プライマリターンは高速で生のライトを生成し; sleepパスはコンパクトにしてクリーンアップする。

## 使ってみる

- リファレンス実装のための **Letta**（letta.com）。セルフホストまたはマネージドクラウド。
- ブロック形状の知識としての **Claude Agent SDKのスキル** — スキルはエージェントが要求に応じてロードする命名、バージョン管理、取得可能な指示のブロックだ。
- ストレージバックエンドを正確に制御したいチームのための **カスタムビルド**。後で移行できるようにLetta APIコントラクトを使用する。

## 成果物を出す

`outputs/skill-memory-blocks.md` は、安全ルールと引用配線を含む任意のランタイム向けにLetta形状のブロックシステムとsleep-timeフックを生成する。

## 演習

1. `near_limit` が真を返したときにモデル生成サマリーでブロック値を置き換える `block_summarize` ツールを追加する。サマリー呼び出しとブロックオーバーフローの両方を最小化するトリガー閾値はどれか？
2. アーカイブ上でsleep-timeの重複排除を実装する: テキストのトークンオーバーラップが>90%の2つのレコードを1つに折りたたむ。クリティカルパスではなく、sleepパスでのみ行う。
3. ブロックをバージョン管理する。すべての書き込みで古い値とdiffを記録する。「エージェントがXを忘れた理由」をオペレーターがデバッグできるよう `block_history(label)` を公開する。
4. Sleep-timeエージェントを信頼できない書き込み者として扱う。ペルソナまたは安全ブロックに触れる場合、コミット前に第2エージェントのレビューを要求する。
5. 例をLetta API（`letta_v1_agent`）を使うようにポートする。ブロックスキーマの何が変わり、ネイティブ推論はトレース形状をどのように変えるか？

## キーワード

| 用語 | よく聞く言い方 | 実際の意味 |
|------|----------------|------------|
| Memory block（メモリブロック） | "編集可能なプロンプトセクション" | 型付き、永続的、LLM編集可能なコアメモリのセグメント |
| Human block（ヒューマンブロック） | "ユーザーメモリ" | ユーザーについての事実、コアにピン留め |
| Persona block（ペルソナブロック） | "エージェントアイデンティティ" | 自己概念、トーン、制約、コアにピン留め |
| Sleep-time compute（sleep-time compute） | "非同期メモリ作業" | クリティカルパス外で統合を行う第2エージェント |
| Core / Recall / Archival（コア/リコール/アーカイブ） | "層" | 3層メモリ分割: 常に見える / 会話 / 外部 |
| Block limit（ブロックリミット） | "キャップ" | ブロックごとの文字制限; サマリー化を強制する |
| Native reasoning（ネイティブ推論） | "思考チャンネル" | プロンプトレベルの `Thought:` ではなく、プロバイダーレベルの推論出力 |
| Learned context（学習されたコンテキスト） | "sleepの出力" | sleep-timeエージェントが共有ブロックに書き込む事実 |
