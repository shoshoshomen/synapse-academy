# LangGraph: ステートフルグラフと耐久実行

> LangGraphは低レベルなステートフルオーケストレーションの2026年リファレンスだ。エージェントはステートマシン; ノードは関数; エッジはトランジション; 状態はイミュータブルで各ステップ後にチェックポイントされる。どの障害からも、まさにそこから再開できる。


## 学習目標

- LangGraphのコアモデルを説明できる: イミュータブルな状態、関数ノード、条件付きエッジ、ポストステップチェックポイントを持つステートマシン。
- ドキュメントが強調する4つの機能を挙げられる: 耐久実行、ストリーミング、human-in-the-loop、包括的メモリ。
- LangGraphがサポートする3つのオーケストレーショントポロジを説明できる: スーパーバイザー、ピアツーピア（スウォーム）、階層型（ネストされたサブグラフ）。
- stdlibでイミュータブルな状態、条件付きエッジ、チェックポイント/再開サイクルを持つステートグラフを実装できる。

## 課題

エージェントとワークフローは共通の問題を抱えている: 40ステップの実行がステップ38で失敗した場合、ステップ38から再開したい、最初からやり直したくない。二流の状態モデルはフレッシュな実行を前提とするライブラリの周りにリトライをハックするオペレーターを生む。

LangGraphの設計上の答え: 状態は第一級の型付きオブジェクトで、ミューテーションは明示的で、チェックポイントはすべてのノードの後に永続化される。再開は `load_state(session_id)` の呼び出しだ。

## コンセプト

### グラフ

グラフは以下によって定義される:

- **状態型。** すべてのノードが読み書きする型付きdict（またはPydanticモデル）。
- **ノード。** `(state) -> state_update` の純粋関数。更新は返り値後に状態にマージされる。
- **エッジ。** ノード間の条件付きまたは直接のトランジション。
- **エントリーとエグジット。** `START` と `END` センチネルノードが境界をマークする。

例: `classify`、`refund`、`bug`、`sales`、`done` ノードを持つエージェント—グラフとしてのルーティングワークフロー。

### 耐久実行

各ノードが返った後、ランタイムは状態をシリアライズしてチェックポインター（SQLite、Postgres、Redis、カスタム）に書き込む。ステップNで失敗した場合、ランタイムは `resume(session_id)` を呼び出して正確な状態でステップN+1から再開できる。

LangGraphのドキュメントはこれが重要な本番ユーザーを明示的に強調する: Klarna、Uber、J.P. Morgan。主張はグラフ形状ではなく、グラフ形状プラスチェックポインティングがリカバリーを安価にするということだ。

### ストリーミング

すべてのノードは部分的な出力をyieldできる。グラフはグラフが実行される間にUIが更新されるよう、呼び出し元にノード単位のデルタイベントをストリームする。

### Human-in-the-loop

ノード間で状態を検査して修正する。実装: クリティカルなノードの前にポーズし、人間に状態を提示し、修正を受け入れ、再開する。チェックポインターは状態がすでにシリアライズされているためこれを容易にする。

### メモリ

短期（実行内—状態内の会話履歴）と長期（実行をまたぐ—チェックポインター加えて別の長期ストアで永続化）。LangGraphはツール経由で外部メモリシステム（Mem0、カスタム）と統合する。

### 3つのトポロジ

1. **スーパーバイザー。** 中央ルーターLLMが専門サブエージェントにディスパッチする。`langgraph-supervisor` の `create_supervisor()`（ただしLangChainチームは2026年に、より多くのコンテキスト制御のためにツール呼び出しを通じて直接これを行うことを推奨している）。
2. **スウォーム/ピアツーピア。** エージェントは共有ツールサーフェス経由で直接ハンドオフする。中央ルーターなし。
3. **階層型。** ネストされたサブグラフとして実装された、サブスーパーバイザーを管理するスーパーバイザー。

### このパターンがうまくいかない場所

- **チェックポイントが小さすぎる。** 会話ターンのみをチェックポインティングするとツール状態とメモリ書き込みが回復不能になる。完全な状態をシリアライズしなければならない。
- **非決定論的ノード。** 再開は同じ入力が同じ状態更新を生成することを前提とする。ランダムシード、ウォールクロック、外部APIはキャプチャしなければならない。
- **条件付きエッジの過剰使用。** すべてのエッジが条件付きのグラフは推論できないステートマシンだ。時折分岐を持つ線形チェーンを優先する。

## 実装する

`code/main.py` はstdlibステートフルグラフを実装している:

- `State` — `messages`、`step`、`route`、`output`、`human_approval` を持つ型付きdict。
- `Node` — 状態を受け取り更新dictを返す呼び出し可能オブジェクト。
- `StateGraph` — ノード + エッジ + 条件付きエッジ + 実行 + 再開。
- `SQLiteCheckpointer`（インメモリフェイク）— すべてのノード後に状態をシリアライズ; `load(session_id)` が復元する。
- デモグラフ: classify -> branch(refund / bug / sales) -> human gate -> send。

実行:

```
python3 code/main.py
```

トレースは最初の実行がhuman gateで失敗すること、永続化、次に最終出力を生成する再開を示す。

## 使ってみる

- **LangGraph** — リファレンス、本番対応。`create_react_agent`、`create_supervisor` を使うか自分のグラフを構築する。
- **AutoGen v0.4**（レッスン14）— 高並行シナリオ向けのアクターモデルの代替。
- **Claude Agent SDK**（レッスン17）— 組み込みセッションストアを持つマネージドハーネス。
- **カスタム** — 状態形状またはチェックポインターバックエンドの正確な制御が必要な場合。

## 成果物を出す

`outputs/skill-state-graph.md` はチェックポインティングと再開が配線された任意のターゲットランタイムでLangGraph形状のステートグラフを生成する。

## 演習

1. 分類信頼度が閾値未満の時に `classify` から `end` への条件付きエッジを追加する。人間が `route` を手動で設定した後に実行を再開する。
2. SQLiteライクなフェイクを本物のSQLiteチェックポインターに置き換える。ステップ単位のシリアライゼーションオーバーヘッドを計測する。
3. 並列エッジを実装する: 2つのノードが同時に実行され、カスタムリデューサーでマージされる。イミュータブルな状態はここで何をもたらすか？
4. `langgraph-supervisor` リファレンスを読む。トイを `create_supervisor` に移植する。トレース形状を比較する。
5. ストリーミングを追加する: 各ノードが実行中に部分的な状態をyieldする。デルタが届いたら印刷する。

## キーワード

| 用語 | よく聞く言い方 | 実際の意味 |
|------|----------------|------------|
| State graph（ステートグラフ） | "エージェントとしてのステートマシン" | 型付き状態 + ノード + エッジ + リデューサー |
| Checkpointer（チェックポインター） | "永続化バックエンド" | すべてのノード後に状態をシリアライズ; 再開を可能にする |
| Reducer（リデューサー） | "状態マージャー" | 現在の状態とノードの更新を組み合わせる関数 |
| Conditional edge（条件付きエッジ） | "分岐" | 状態の関数によって選ばれるエッジ |
| Subgraph（サブグラフ） | "ネストされたグラフ" | 別のグラフの中のノードとして使用されるグラフ |
| Durable execution（耐久実行） | "障害からの再開" | 正確な状態で最後に成功したノードから再起動する |
| Supervisor（スーパーバイザー） | "ルーターLLM" | 専門サブエージェントの中央ディスパッチャー |
| Swarm（スウォーム） | "P2Pエージェント" | エージェントが共有ツール経由でハンドオフ; 中央ルーターなし |
