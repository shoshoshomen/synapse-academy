# AutoGen v0.4: アクターモデルとエージェントフレームワーク

> AutoGen v0.4（Microsoft Research、2025年1月）はエージェントオーケストレーションをアクターモデルを中心に再設計した。非同期メッセージ交換、イベント駆動エージェント、アクター単位の障害分離、自然な並行性。このフレームワークは現在メンテナンスモードにあり、Microsoft Agent Framework（2025年10月パブリックプレビュー）が後継となる。


## 学習目標

- アクターモデルを説明できる: アクターとしてのエージェント、唯一のIPCとしてのメッセージ、アクター単位の障害分離。
- AutoGen v0.4の3つのAPIレイヤー—Core、AgentChat、Extensions—とそれぞれの用途を挙げられる。
- メッセージ配信とハンドリングのデカップリングが障害分離と自然な並行性をもたらす理由を説明できる。
- stdlibアクターランタイムをPythonで実装し、2エージェントのコードレビューフローをその上に移植できる。

## 課題

ほとんどのエージェントフレームワークは同期的だ: 1つのエージェントが生成し、1つのエージェントがコールスタックで消費する。障害がスタックをクラッシュさせる。並行性はボルトオンだ。分散には書き直しが必要だ。

AutoGen v0.4の答え: アクターモデル。各エージェントはプライベートなインボックスを持つアクターだ。メッセージが唯一のインタラクションだ。ランタイムが配信とハンドリングをデカップルする。障害は1つのアクターに分離される。並行性はネイティブだ。分散は単に異なるトランスポートだ。

## コンセプト

### アクター

アクターは以下を持つ:

- プライベートな状態（外部から直接触れられない）。
- インボックス（メッセージキュー）。
- ハンドラー: `receive(message) -> effects`。エフェクトは「返信」、「他のアクターに送る」、「新しいアクターをスポーン」、「状態を更新」、「自分を停止」になりえる。

2つのアクターはメモリを共有できない。メッセージを送り合うだけだ。

### AutoGen v0.4の3つのAPIレイヤー

1. **Core。** 低レベルアクターフレームワーク。`AgentRuntime`、`Agent`、`Message`、`Topic`。非同期メッセージ交換、イベント駆動。
2. **AgentChat。** タスク駆動の高レベルAPI（v0.2のConversableAgentの後継）。`AssistantAgent`、`UserProxyAgent`、`RoundRobinGroupChat`、`SelectorGroupChat`。
3. **Extensions。** インテグレーション—OpenAI、Anthropic、Azure、ツール、メモリ。

### デカップリングが重要な理由

v0.2モデルでは、`agent_a.chat(agent_b)` を呼び出すとagent_bが返るまでagent_aが同期的にブロックされる。v0.4では、`send(agent_b, msg)` はagent_bのインボックスにメッセージを入れて返る。ランタイムは後で配信する。3つの結果:

- **障害分離。** エージェントBがクラッシュしてもエージェントAはクラッシュしない—ランタイムはBのハンドラーの障害をキャッチし、何をするかを決める（ログ、リトライ、デッドレター）。
- **自然な並行性。** 多くのメッセージが同時にインフライト; アクターはインボックスを並行して処理する。
- **分散対応。** インボックス + トランスポートは、アクターがインプロセスでも別のホストにいても同じ抽象化だ。

### トポロジ

- **RoundRobinGroupChat。** エージェントが固定の順番でターンを取る。
- **SelectorGroupChat。** セレクターエージェントが会話コンテキストに基づいて次に誰が進むかを選ぶ。
- **Magentic-One。** Webブラウジング、コード実行、ファイル処理のためのリファレンスマルチエージェントチーム。AgentChatの上に構築されている。

### オブザーバビリティ

OpenTelemetryサポートが組み込まれている。すべてのメッセージがスパンを発行する; ツール呼び出しは2026年のOTel GenAIセマンティックコンベンション（レッスン23）に従った `gen_ai.*` 属性を持つ。

### ステータス: メンテナンスモード

2026年初頭: AutoGen v0.7.xはリサーチとプロトタイピングに安定している。Microsoftはアクティブな開発をMicrosoft Agent Framework（2025年10月1日パブリックプレビュー; 2026年Q1末GA目標）にシフトした。AutoGenのパターンはフォワードポートがきれいにできる—アクターモデルが耐久性のあるアイデアだ。

## 実装する

`code/main.py` はstdlibアクターランタイムを実装している:

- `Message` — `sender`、`recipient`、`topic`、`body` を持つ型付きペイロード。
- `Actor` — `receive(message, runtime)` を持つ抽象クラス。
- `Runtime` — 共有キュー、配信、障害分離を持つイベントループ。
- 2アクターデモ: `ReviewerAgent` がコードをレビューし、`ChecklistAgent` がチェックリストを実行する; 合意するまでメッセージを交換する。

実行:

```
python3 code/main.py
```

トレースはメッセージ配信、他のアクターをクラッシュさせない1つのアクターのシミュレートされた障害、および共有評決への収束を示す。

## 使ってみる

- **AutoGen v0.4/v0.7**（メンテナンス）— リサーチ、プロトタイピング、マルチエージェントパターンに安定している。
- **Microsoft Agent Framework**（パブリックプレビュー）— フォワードパス; 刷新されたAPIで同じアクターモデルのアイデア。
- **LangGraphスウォームトポロジ**（レッスン13）— 共有ツールハンドオフ経由の類似パターン。
- **カスタムアクターランタイム** — 特定のトランスポート（NATS、RabbitMQ、gRPC）が必要な場合。

## 成果物を出す

`outputs/skill-actor-runtime.md` は与えられたマルチエージェントタスクのための最小アクターランタイムとチームテンプレート（RoundRobinまたはSelector）を生成する。

## 演習

1. デッドレターキューを追加する: ハンドラーが例外を投げたとき、失敗したメッセージを人間の検査のためにパークする。トイではDLQがどのくらいの頻度でヒットするか？
2. `SelectorGroupChat` を実装する: セレクターアクターが会話状態に基づいて次のメッセージを処理する人を選ぶ。
3. 分散トランスポートを追加する: インプロセスキューをJSON-over-HTTPサーバーに置き換え、アクターが別々のプロセスで実行できるようにする。
4. メッセージ単位でOTelスパンを配線する（またはno-opスタンドイン）。レッスン23に従って `gen_ai.agent.name`、`gen_ai.operation.name` を発行する。
5. AutoGen v0.4のアーキテクチャポストを読む。トイを本物の `autogen_core` APIに移植する。本番で重要なものを何をスキップしたか？

## キーワード

| 用語 | よく聞く言い方 | 実際の意味 |
|------|----------------|------------|
| Actor（アクター） | "エージェント" | プライベートな状態 + インボックス + ハンドラー; 共有メモリなし |
| Message（メッセージ） | "イベント" | 型付きペイロード; アクターが互いに関わる唯一の方法 |
| Inbox（インボックス） | "メールボックス" | 保留中のメッセージのアクター単位キュー |
| Runtime（ランタイム） | "エージェントホスト" | メッセージをルーティングして障害を分離するイベントループ |
| Topic（トピック） | "チャンネル" | アクター間の名前付きパブリッシュ-サブスクライブルート |
| Fault isolation（障害分離） | "クラッシュさせろ" | 1つのアクターの障害が他のアクターをクラッシュさせない |
| RoundRobinGroupChat | "固定ローテーションチーム" | エージェントが順番にターンを取る |
| SelectorGroupChat | "コンテキストルーティングチーム" | セレクターが次に誰が進むかを選ぶ |
| Magentic-One | "リファレンスチーム" | Web + コード + ファイルのためのマルチエージェント部隊 |
