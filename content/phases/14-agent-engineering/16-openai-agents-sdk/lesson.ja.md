# OpenAI Agents SDK: ハンドオフ、ガードレール、トレーシング

> OpenAI Agents SDK は Responses API を基盤とした軽量なマルチエージェントフレームワークです。5つのプリミティブ: Agent, Handoff, Guardrail, Session, Tracing。ハンドオフは `transfer_to_<agent>` という名前のツールです。ガードレールは入力または出力でトリップします。トレーシングはデフォルトで有効です。


## 学習目標

- OpenAI Agents SDK の5つのプリミティブを説明できる。
- ハンドオフを説明できる: なぜツールとしてモデル化されるか、モデルが見る名前の形式、コンテキストの転送方法。
- 入力ガードレール、出力ガードレール、ツールガードレールを区別し、`run_in_parallel` とブロッキングモードの違いを説明できる。
- ハンドオフ + ガードレール + スパンスタイルのトレーシングを持つ標準ライブラリランタイムを実装できる。

## 問題設定

きれいに委譲できないエージェントは、すべてを1つのプロンプトに詰め込むことになります。ガードレールのないエージェントは PII、ポリシー違反の出力、または無限ループを出荷します。OpenAI の SDK はマルチエージェントを扱いやすくする3つのプリミティブを体系化しています。

## コンセプト

### 5つのプリミティブ

1. **Agent.** LLM + 指示 + ツール + ハンドオフ。
2. **Handoff.** 別のエージェントへの委譲。`transfer_to_<agent_name>` という名前のツールとしてモデルに表示されます。
3. **Guardrail.** 入力（最初のエージェントのみ）、出力（最後のエージェントのみ）、またはツール呼び出し（関数ツールごと）に対する検証。
4. **Session.** ターンをまたいだ会話履歴の自動管理。
5. **Tracing.** LLM 生成、ツール呼び出し、ハンドオフ、ガードレールに対する組み込みスパン。

### ツールとしてのハンドオフ

モデルはツールリストに `transfer_to_billing_agent` を見ます。これを呼び出すとランタイムは以下を実行します:

1. 会話コンテキストをコピーします（または `nest_handoff_history` ベータで折り畳みます）。
2. ターゲットエージェントをその指示で初期化します。
3. ターゲットエージェントで実行を継続します。

これはスーパーバイザーパターン（レッスン13・レッスン28）を製品化したものです。

### ガードレール

3種類:

- **入力ガードレール.** 最初のエージェントの入力で実行されます。LLM 呼び出しの前に安全でない、またはスコープ外のリクエストを拒否します。
- **出力ガードレール.** 最後のエージェントの出力で実行されます。PII 漏洩、ポリシー違反、不正なレスポンスをキャッチします。
- **ツールガードレール.** 関数ツールごとに実行されます。引数を検証し、権限を確認し、実行を監査します。

モード:

- **並列**（デフォルト）。ガードレール LLM がメイン LLM と並行して実行されます。テールレイテンシが低い。トリップした場合、メイン LLM の作業は破棄されます（トークン無駄）。
- **ブロッキング**（`run_in_parallel=False`）。ガードレール LLM が先に実行されます。トリップした場合、メイン呼び出しにトークンは無駄になりません。

トリップワイヤーは `InputGuardrailTripwireTriggered` / `OutputGuardrailTripwireTriggered` を発生させます。

### トレーシング

デフォルトで有効です。すべての LLM 生成、ツール呼び出し、ハンドオフ、ガードレールがスパンを発行します。`OPENAI_AGENTS_DISABLE_TRACING=1` でオプトアウトできます。`add_trace_processor(processor)` は OpenAI の他に独自のバックエンドにもスパンを転送します。

### Sessions

`Session` は会話履歴をバックエンド（SQLite、Redis、カスタム）に保存します。`Runner.run(agent, input, session=session)` で自動的にロードして追記します。

### このパターンが失敗するケース

- **ハンドオフドリフト.** エージェント A がエージェント B にハンドオフし、B が A に戻す。ホップカウンターを追加してください。
- **ガードレールのバイパス.** ツールガードレールは関数ツールにのみ発動します。組み込みツール（ファイルリーダー、Web フェッチ）には別途ポリシーが必要です。
- **過剰トレーシング.** スパン内の機密コンテンツ。OTel GenAI コンテキストキャプチャルール（レッスン23）と組み合わせてください。外部保存、ID による参照を行います。

## 実装する

`code/main.py` は SDK の形式を標準ライブラリで実装しています:

- `Agent`、`FunctionTool`、`Handoff`（転送セマンティクスを持つ関数ツールとして）。
- 入力・出力・ツールガードレール、ハンドオフディスパッチ、ホップカウンターを持つ `Runner`。
- トレース形状を示すシンプルなスパンエミッター。
- ユーザーのクエリに基づいて billing または support にハンドオフするトリアージエージェント。1つの入力でガードレールがトリップします。

実行:

```
python3 code/main.py
```

トレースは2つの成功したハンドオフ、1つの入力ガードレールトリップ、実際の SDK が発行するものを模倣したスパンツリーを示します。

## 使ってみる

- **OpenAI Agents SDK** は OpenAI ファーストのプロダクトに。
- **Claude Agent SDK**（レッスン17）は Claude ファーストのプロダクトに。
- **LangGraph**（レッスン13）は明示的な状態と durable な再開が必要な場合に。
- **カスタム** は正確な制御が必要な場合（音声、マルチプロバイダー、フェデレーテッドデプロイメント）。

## 成果物を出す

`outputs/skill-agents-sdk-scaffold.md` は、トリアージエージェント、ハンドオフ、入力・出力・ツールガードレール、セッションストア、トレースプロセッサーを持つ Agents SDK アプリを足場として提供します。

## 演習

1. ハンドオフホップカウンターを追加します: N 回の転送後に拒否します。動作をトレースします。
2. `nest_handoff_history` をオプションとして実装します — 転送前に過去のメッセージを1つのサマリーに折り畳みます。
3. ブロッキング出力ガードレールを書きます。トリップするプロンプトとパスするプロンプトでレイテンシを比較します。
4. `add_trace_processor` を JSON ロガーに接続します。スパンごとにどんな形式で出力されますか？
5. SDK のドキュメントを読みます。標準ライブラリの玩具実装を `openai-agents-python` に移植します。何をモデル化し間違えていましたか？

## キーワード

| 用語 | 一般的な言い方 | 実際の意味 |
|------|----------------|------------|
| Agent | "LLM + 指示" | SDK のエージェントタイプ。ツールとハンドオフを所有 |
| Handoff | "転送" | モデルが別のエージェントに委譲するために呼び出すツール |
| Guardrail | "ポリシーチェック" | 入力・出力・ツール呼び出しに対する検証 |
| Tripwire | "ガードレールトリップ" | ガードレールが拒否したときに発生する例外 |
| Session | "履歴ストア" | 実行間で永続化される会話メモリ |
| Tracing | "スパン" | LLM + ツール + ハンドオフ + ガードレールに対する組み込みオブザーバビリティ |
| ブロッキングガードレール | "逐次チェック" | ガードレールが先に実行。トリップ時のトークン無駄なし |
| 並列ガードレール | "並行チェック" | ガードレールが並行実行。レイテンシ低いが、トリップ時にトークン無駄あり |
